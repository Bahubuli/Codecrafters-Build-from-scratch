# Stage 44: Programmable Completion - Unregister a completion

## In one line
Implement the `-r` option for the `complete` shell builtin to remove registered completion specifications for specified commands.

---

## Self-test
Can you answer these questions from memory?
1. What does `complete -r <command>` do in bash and in this shell?
2. What should `complete -p <command>` output after `complete -r <command>` is executed?
3. How should the shell behave when `<TAB>` is pressed for a command that was just unregistered?
4. What happens if `complete -r <command>` is invoked on a command that has no registered completion specification?

---

## Problem Solved
In previous stages, the shell implemented `complete -C <script> <cmd>` to register completions and `complete -p <cmd>` to query them. In bash, users and scripts also require the capability to deregister completion functions using `complete -r <cmd>`. Without `-r`, users cannot revert to default completion behavior without restarting the shell session.

---

## Concepts
- **Completion Registry Mutation**: Deregistering involves deleting the mapping from the in-memory map (`COMPLETION_SPECS.remove(command)`).
- **Idempotent Removal**: Invoking `-r` on an unregistered command should silently succeed with exit status 0 and produce no stdout or stderr.
- **Fallback to Default / No Candidates**: Once a completion rule is removed, typing `<cmd> <TAB>` no longer invokes any custom script; it either attempts default file completion or rings the bell when no matching entries exist.

---

## The Solution
In `codecrafters-shell-java/src/main/java/Main.java`:
```java
} else if (command.equals("complete")) {
    if (cmdArgs.size() >= 3 && cmdArgs.get(1).equals("-p")) {
        String target = cmdArgs.get(2);
        if (COMPLETION_SPECS.containsKey(target)) {
            out.println("complete -C '" + COMPLETION_SPECS.get(target) + "' " + target);
        } else {
            err.println("complete: " + target + ": no completion specification");
        }
    } else if (cmdArgs.size() >= 3 && cmdArgs.get(1).equals("-r")) {
        String target = cmdArgs.get(2);
        COMPLETION_SPECS.remove(target);
    } else if (cmdArgs.size() >= 4 && cmdArgs.get(1).equals("-C")) {
        String scriptPath = cmdArgs.get(2);
        String target = cmdArgs.get(3);
        COMPLETION_SPECS.put(target, scriptPath);
    }
}
```

---

## Failure Modes
- **NullPointer or Exception on Missing Key**: Using `COMPLETION_SPECS.remove(target)` is safe on `java.util.HashMap` (returns `null` without throwing if the key is absent).
- **Unintended Output**: Outputting any error or confirmation on `complete -r` would fail the CodeCrafters tester check for zero output.

---

## Tradeoffs
- Using `Map.remove(key)` performs an $O(1)$ removal in memory.

---

## CLI / Protocol format
```bash
$ complete -C /path/to/script git
$ git ch<TAB>               # autocompletes to git checkout
$ complete -r git           # produces no output
$ complete -p git           # produces "complete: git: no completion specification" on stderr
$ git <TAB>                 # rings bell \u0007, no completion
```

---

## Java specifics
- `Map.remove(Object key)` removes the mapping for a key from this map if it is present, returning the previous value associated with key, or `null` if there was no mapping.

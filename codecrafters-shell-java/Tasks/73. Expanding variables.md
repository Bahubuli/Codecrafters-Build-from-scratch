# Stage 73: Expanding variables

## In one line
Expand `$NAME` parameter expressions inside command-line words (both unquoted and double-quoted) with the corresponding variable value before executing builtins or external processes.

## The problem it solved
Shells allow dynamic parameter passing by expanding `$VAR` references in commands into their assigned runtime values. Without expansion happening during the lexical tokenization phase, utilities receive literal `$VAR` strings instead of dynamic values, breaking basic shell scripting, environment forwarding, and argument parametrization.

## Concepts (the transferable part)
- **Token-Level Expansion** — Parameter substitution occurs during word parsing rather than via global raw string replacement (`input.replace(...)`), preserving token boundaries, whitespace escaping, and quote semantics.
- **Quote Hierarchy in Shell Grammars**:
  - *Single quotes (`'...'`)*: Literal preservation; `$` has no expansion semantics.
  - *Double quotes (`"..."`)*: Variable expansion active (`$VAR` replaced); escaped dollar signs (`\$`) stay literal.
  - *Unquoted words*: Variable expansion active; unset or empty variables without adjoining text do not emit empty tokens.
- **Identifier Boundary Detection** — A parameter name starts with a letter or underscore and continues through alphanumeric characters and underscores (`[a-zA-Z_][a-zA-Z0-9_]*`). Characters after the valid identifier boundary remain intact in the token stream.

## What breaks it (failure modes)
- Global string substitution — Replacing `$VAR` across the raw input line corrupts quoted instances like `'echo $VAR'` or `\$VAR`.
- Emitting empty arguments for unset unquoted variables — In standard POSIX shells, unquoted `$UNSET` expands to nothing (zero words), not an empty string `""`.
- Expanding within single quotes — Single quotes must completely suppress all expansion.

## Tradeoffs
- Parsing expansion directly in `parseArguments` vs multi-pass AST — In-stream character scanning during tokenizer evaluation cleanly tracks quotation state (`inSingleQuote`, `inDoubleQuote`) and escape backslashes without the complexity of constructing and traversing an abstract syntax tree.

## CLI / Protocol format
```bash
$ declare Variable_1=value
$ declare Variable_2=value2
$ echo $Variable_1 $Variable_2
value value2

$ declare Variable_1=Value_1
$ declare Variable_2=Value2
$ custom_exe_1234 $Variable_1 $Variable_2
Program was passed 3 args (including program name).
Arg #0 (program name): custom_exe_1234
Arg #1: Value_1
Arg #2: Value_2
```

              }

## Rebuild checklist
1. Locate `parseArguments(String input)` tokenizer.
2. In double-quote state (`inDoubleQuote`), check `c == '$'`. If followed by a valid identifier start character, scan the identifier, resolve against `SHELL_VARIABLES` (or `System.getenv`), and append value to `current`.
3. In unquoted state, check `c == '$'`. If followed by a valid identifier start character, scan the identifier, resolve value, and if non-empty append to `current` and set `hasToken = true`.
4. Leave single-quote state unchanged (`$` treated as literal character).

# Stage 10: The cd builtin - Absolute paths

---

## In one line
Implement the `cd` (change directory) shell builtin for absolute paths by resolving targets against the filesystem root, validating directory existence, and mutating shell working directory state.

---

## Self-test (cover the answers below and answer these first)

- What happens when a child process calls `chdir(2)` in Unix, and does it affect the parent shell?
- How does `Path.resolve()` in Java NIO behave when passed an absolute path versus a relative path?
- What exact error message must `cd` output when attempting to switch to a non-existent directory?
- If a directory transition fails, should the shell's current working directory mutate or remain unchanged?

## The problem it solved
A shell without `cd` confines the user and all child processes to the single directory where the shell was launched. Users must navigate directory trees to inspect files and execute scripts in context. Because directory changes must mutate the shell's own process state, `cd` must be built directly into the command interpreter loop.

---

## Concepts (the transferable part)

- **[CONCEPT] Process Isolation & Working Directory State** — In POSIX and modern operating systems, every process maintains its own current working directory (CWD) in kernel process memory. A child process receives a copy of its parent's CWD upon creation, but process isolation strictly prohibits a child from modifying its parent's environment or CWD. Thus, `cd` can never be an external binary (`/bin/cd`) because running it in a child process would only change the child's CWD before it exits, leaving the parent shell untouched.
- **[CONCEPT] Absolute Paths vs Relative Paths** — An absolute path defines a file or directory location starting from the root of the filesystem hierarchy (`/` on Unix). It is invariant regardless of what directory the process currently occupies.
- **[CONCEPT] Directory State Mutation & Invariance on Failure** — When changing directory, the shell must verify that the target directory exists and is accessible. If the target does not exist or is not a directory, the shell must report an error (`cd: <path>: No such file or directory`) and preserve its existing working directory without side effects.
- **[CONCEPT] Builtin Command Registry** — Any command that inspects or mutates shell-internal state (`cd`, `pwd`, `exit`) or configures the shell environment must be registered in the shell's builtin lookup table so utilities like `type` identify them accurately.

## The Solution

```java
import java.io.File;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Arrays;
import java.util.Scanner;
import java.util.Set;
import java.util.regex.Pattern;

public class Main {
    private static final Set<String> BUILTINS = Set.of("echo", "exit", "type", "pwd", "cd");
    private static Path currentDir = Paths.get(System.getProperty("user.dir")).toAbsolutePath().normalize();

    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String trimmed = input.trim();
            if (trimmed.isEmpty()) {
                continue;
            }
            String[] parts = trimmed.split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            } else if (command.equals("echo")) {
                String output = String.join(" ", Arrays.copyOfRange(parts, 1, parts.length));
                System.out.println(output);
            } else if (command.equals("type")) {
                if (parts.length > 1) {
                    String target = parts[1];
                    if (BUILTINS.contains(target)) {
                        System.out.println(target + " is a shell builtin");
                    } else {
                        Path executable = findExecutable(target);
                        if (executable != null) {
                            System.out.println(target + " is " + executable);
                        } else {
                            System.out.println(target + ": not found");
                        }
                    }
                }
            } else if (command.equals("pwd")) {
                System.out.println(currentDir);
            } else if (command.equals("cd")) {
                if (parts.length > 1) {
                    String targetPath = parts[1];
                    Path target = currentDir.resolve(targetPath).normalize();
                    if (Files.isDirectory(target)) {
                        currentDir = target;
                    } else {
                        System.out.println("cd: " + targetPath + ": No such file or directory");
                    }
                }
            } else {
                Path executable = findExecutable(command);
                if (executable != null) {
                    ProcessBuilder pb = new ProcessBuilder(parts);
                    pb.directory(currentDir.toFile());
                    pb.inheritIO();
                    Process process = pb.start();
                    process.waitFor();
                } else {
                    System.out.println(input + ": command not found");
                }
            }
        }
    }

    private static Path findExecutable(String command) {
        if (command.contains("/") || command.contains(File.separator)) {
            try {
                Path path = currentDir.resolve(command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
            return null;
        }
        return findExecutableInPath(command);
    }

    private static Path findExecutableInPath(String command) {
        String pathEnv = System.getenv("PATH");
        if (pathEnv == null || pathEnv.isEmpty()) {
            return null;
        }
        String[] dirs = pathEnv.split(Pattern.quote(File.pathSeparator));
        for (String dir : dirs) {
            if (dir.isEmpty()) {
                continue;
            }
            try {
                Path path = Paths.get(dir, command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
        }
        return null;
    }
}
```

## What breaks it (failure modes)

- **Mutating `currentDir` before validating existence** — Updating the working directory variable before verifying `Files.isDirectory(target)` leaves the shell in an invalid phantom state where subsequent `pwd` or relative lookups fail.
- **Failing to preserve the exact raw target in the error message** — Printing a normalized or canonical path instead of the user's raw input argument (`targetPath`) fails test assertions expecting `cd: <targetPath>: No such file or directory`.
- **Missing `"cd"` in the `BUILTINS` set** — If `"cd"` is omitted from `BUILTINS`, running `type cd` attempts to search `PATH` or outputs `cd: not found`, violating standard shell behavior.
- **Targeting regular files instead of directories** — Using `Files.exists(target)` instead of `Files.isDirectory(target)` allows `cd` to succeed on regular files, creating an invalid state where the working directory points to a non-directory.

---

## Tradeoffs

- **`Path.resolve()` unified resolution vs explicit branch check** — Java NIO's `Path.resolve(other)` automatically returns `other` if `other` is absolute, while resolving against `currentDir` if `other` is relative. Using `resolve` provides a uniform API for both relative and absolute paths without requiring conditional branching.
- **In-memory `Path currentDir` tracking vs JVM `user.dir` property** — Changing `System.setProperty("user.dir", ...)` does not invoke the underlying OS C-level `chdir(2)` in standard JVMs. Tracking an explicit `Path currentDir` in the shell and injecting it into `ProcessBuilder.directory(...)` ensures reliable, cross-platform subprocess management.

## CLI / Protocol format

- **`cd` invocation with valid absolute path**:
  ```
  $ pwd
  /home/user
  $ cd /usr/local/bin
  $ pwd
  /usr/local/bin
  $ 
  ```
- **`cd` invocation with non-existent path**:
  ```
  $ cd /does_not_exist
  cd: /does_not_exist: No such file or directory
  $ pwd
  /usr/local/bin
  $ 
  ```
- **`type cd` output**:
  ```
  $ type cd
  cd is a shell builtin
  $ 
  ```

## Java specifics — lookup, don't memorize

- `Path.resolve(String other)` / `Path.resolve(Path other)` — Resolves the given path against this path; if `other` is absolute, returns `other` directly.
- `Files.isDirectory(Path path, LinkOption... options)` — Checks whether a path points to an existing file that is a directory, following symlinks by default.
- `Path.normalize()` — Eliminates redundant name elements such as `.` and `..` from the path without accessing the filesystem.
- `Set.of(...)` — Returns an unmodifiable set containing the specified elements.

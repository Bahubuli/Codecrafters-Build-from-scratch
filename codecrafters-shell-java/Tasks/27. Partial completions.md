# Stage 27: Partial completions

## In one line
Extends autocompletion to complete commands up to their Longest Common Prefix (LCP) when multiple ambiguous candidates share a longer common prefix, omitting the trailing space until exactly one match remains.

## The problem it solved
Previously, when the user pressed `<TAB>` on a prefix with multiple matching candidates, the shell immediately treated the input as ambiguous—ringing the bell on the first Tab and dumping all candidates on the second. However, in real-world shells, multiple executables often share a common prefix beyond what the user typed (e.g., `xyz_` matching `xyz_foo`, `xyz_foo_bar`, `xyz_foo_bar_baz`). In standard shells like Bash, pressing `<TAB>` progressively completes text up to the longest shared common prefix without ringing a bell, greatly reducing repetitive keystrokes.

## Concepts (the transferable part)
- **[CONCEPT] Longest Common Prefix (LCP) Reduction** — When a candidate set contains multiple matches, the optimal deterministic extension of the user's input buffer is the greatest lower bound in the prefix poset (partially ordered set): the maximum contiguous substring from index 0 common to every candidate.
- **[CONCEPT] Non-Terminal Completion vs Terminal Completion** — A completion is *terminal* when exactly one candidate remains, indicating the command name is complete and appending a delimiter (a space ` `) so the user can immediately type arguments. A completion is *non-terminal* (partial) when multiple possibilities remain; no delimiter is appended, allowing subsequent characters and further progressive Tab presses.
- **[CONCEPT] State Transition between Extension and Ambiguity** — When a Tab press extends the input buffer (`lcp.length() > current.length()`), the keystroke was productive: characters are emitted and `consecutiveTabs` is reset to 0 without ringing the bell. Only when the input is already at the divergence point (`lcp.length() <= current.length()`) does the keystroke enter the two-stage ambiguity protocol (first press rings the bell, second press displays candidate options).

## What breaks it (failure modes)
- **Premature Trailing Space on Partial Completion** — If the shell appends `" "` when completing to an intermediate prefix (e.g. producing `xyz_foo ` instead of `xyz_foo`), the space commits the token as a finished command, breaking further sub-word typing and progressive completion.
- **Ringing Bell on Successful Partial Completion** — Ringing `\u0007` when partial characters are appended gives a false signal to the terminal and automated testers that the input was uncompletable or rejected, violating standard shell UX.
- **LCP Index Out of Bounds** — Comparing strings of differing lengths without bounding the comparison loop to `min(s1.length(), s2.length())` triggers `StringIndexOutOfBoundsException`.
- **Desynchronized Buffer vs Screen Length** — Emitting `lcp` to stdout instead of the delta `lcp.substring(current.length())` duplicates already-typed characters on screen (e.g., typing `xyz_` displaying `xyz_xyz_foo`).
- **Consecutive Tab State Leak across Partial Steps** — If `consecutiveTabs` is not reset to 0 after completing an LCP segment, pressing Tab immediately after typing a separator would count as a second tab and dump completion candidates prematurely rather than completing the next prefix segment.

## Tradeoffs
- **Pairwise Min-Scan vs Lexicographic First/Last vs Trie** — Finding LCP across small candidate lists (typically < 1,000 matches in PATH) via linear pairwise reduction is O(N * M) with zero auxiliary memory, whereas building a Radix Trie adds allocation overhead unnecessary for interactive shell completions.
- **Progressive Character-by-Character vs Word-Boundary Completion** — POSIX shells (Readline) complete to the exact character-level LCP rather than breaking at token/hyphen boundaries (unlike Zsh's path-segment completion), keeping terminal behavior simple, portable, and predictable.

## CLI / Protocol format
- Given executables: `xyz_rat`, `xyz_rat_owl`, `xyz_rat_owl_cow`
- User types `xyz_` and presses `<TAB>`:
  - Input: `xyz_<TAB>`
  - Action: computes LCP = `xyz_rat`. Since `xyz_rat.length() > 4`, emits `rat` (no space, no bell).
  - Terminal display: `$ xyz_rat`
- User types `_` and presses `<TAB>`:
  - Input: `_<TAB>`
  - Action: buffer is `xyz_rat_`. Candidates: `xyz_rat_owl`, `xyz_rat_owl_cow`. LCP = `xyz_rat_owl`. Emits `owl`.
  - Terminal display: `$ xyz_rat_owl`
- User types `_` and presses `<TAB>`:
  - Input: `_<TAB>`
  - Action: buffer is `xyz_rat_owl_`. Candidates: `xyz_rat_owl_cow`. Single match! Emits `cow `.
  - Terminal display: `$ xyz_rat_owl_cow `

# Stage 46: Background Jobs - Starting background jobs

## In one line
Detect the trailing `&` token to start commands asynchronously in the background and print `[<job_id>] <pid>`.

---

2. What format is used when reporting a newly started background job?
3. How is the job number assigned?
4. How do you obtain the operating system process ID of a spawned `Process` in modern Java?
5. Why must the shell not call `process.waitFor()` when running in the background?

---

## Problem Solved
When running long-running jobs (like `sleep 500 &`), the user does not want the shell prompt blocked. By recognizing the trailing `&` token, the shell spawns the process in the background, prints the job identifier and OS process ID (e.g. `[1] 108`), and immediately prompts for the next command without waiting.

---

## Concepts
- **Background Operator (`&`)**: When appearing as the last argument in the command list, it signifies asynchronous execution. It is stripped from the argument list before passing to `ProcessBuilder`.
- **Job ID vs PID**: The job ID is a sequential integer managed internally by the shell starting at 1. The PID is the OS-level process identifier.
- **Process Spawning**: Calling `ProcessBuilder.start()` initiates the process. For background execution, the shell avoids invoking `process.waitFor()` and instead proceeds directly to the prompt.

---

## The Solution
In `codecrafters-shell-java/src/main/java/Main.java`:
```java
private static final AtomicInteger nextJobId = new AtomicInteger(1);

...
// Check for background job operator (& at the end)
boolean isBackground = false;
if (!parsedArgs.isEmpty() && parsedArgs.get(parsedArgs.size() - 1).equals("&")) {
    isBackground = true;
    parsedArgs.remove(parsedArgs.size() - 1);
}

...
if (isBackground) {
    ProcessBuilder pb = new ProcessBuilder(cmdArgs);
    pb.directory(currentDir.toFile());
    if (outPath != null) {
        pb.redirectOutput(appendOut ? ProcessBuilder.Redirect.appendTo(outPath.toFile()) : ProcessBuilder.Redirect.to(outPath.toFile()));
    } else {
        pb.redirectOutput(ProcessBuilder.Redirect.DISCARD);
    }
    if (errPath != null) {
        pb.redirectError(appendErr ? ProcessBuilder.Redirect.appendTo(errPath.toFile()) : ProcessBuilder.Redirect.to(errPath.toFile()));
    } else {
        pb.redirectError(ProcessBuilder.Redirect.DISCARD);
    }
    Process process = pb.start();
    int jobId = nextJobId.getAndIncrement();
    long pid = process.pid();
    System.out.println("[" + jobId + "] " + pid);
    System.out.flush();
} else {
    // synchronous execution with process.waitFor()
}
```

---

## Failure Modes
- **Passing `&` to the executable**: Failing to remove `&` from `cmdArgs` passes `&` as a literal argument to the target program (e.g. `sleep: invalid time interval '&'`).
- **Using `ProcessBuilder.Redirect.DISCARD` on `redirectInput`**: Java throws `IllegalArgumentException: Redirect invalid for reading: WRITE` because `DISCARD` is an output-only redirect.
- **Blocking on background process**: Calling `process.waitFor()` hangs the shell and prevents the immediate prompt.

---

## Tradeoffs
- Using `process.pid()` (introduced in Java 9) cleanly provides the OS PID without needing JNI or OS-specific wrappers.
- In this stage, background jobs are spawned independently; subsequent stages will maintain a jobs table to report status in the `jobs` builtin.

---

## CLI / Protocol format
```bash
$ sleep 500 &
[1] 108
$ 
```

---

## Java specifics
- `process.pid()` returns a `long` containing the native operating system process ID.
- `AtomicInteger` safely allocates sequential job numbers.

---

## Rebuild checklist
1. Parse arguments and check if `parsedArgs.get(parsedArgs.size() - 1).equals("&")`.
2. Remove `&` and set `isBackground = true`.
3. In `pb.start()`, do not call `process.waitFor()`.
4. Print `[<jobId>] <pid>` and return to prompt.

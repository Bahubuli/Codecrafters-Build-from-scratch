# Stage 7: Locate executable files

---

## In one line
Extend the `type` builtin to search for external executable programs across directories specified in the `PATH` environment variable.

---

## The problem it solved
Up to this stage, `type` only knew about internal shell builtins (`echo`, `exit`, `type`). Any external program like `ls`, `grep`, or `cat` was falsely reported as `<command>: not found`. Real shells interact with an ecosystem of standalone executable programs residing on the filesystem. By resolving the `PATH` environment variable and testing filesystem metadata for execute permissions, the shell can now introspect external commands and locate their exact absolute paths.

---

## Concepts (the transferable part)

- **[CONCEPT] The `PATH` Environment Variable** — An environment variable containing an ordered, delimited list of directory paths. When an unqualified command name (e.g. `grep`) is requested, the shell sequentially iterates through these directories from left to right, stopping at the first matching executable binary.
- **[CONCEPT] Command Resolution Hierarchy** — Shells evaluate builtins before searching external filesystem paths. Builtins take precedence because they execute within the shell's own process address space without spawning new processes or incurring filesystem I/O.
- **[CONCEPT] Executable File Attributes vs Directory Permissions** — On POSIX systems, directories need execute (`+x`) permissions for traversing / searching them, whereas regular files need execute permissions to be run as programs. A command lookup must verify both that the candidate is a regular file (`isRegularFile`) and that the current user has execution permissions (`isExecutable`).
- **[CONCEPT] First-Match-Wins Semantics** — Earlier directories in `PATH` shadow identically named binaries in later directories. Once a valid executable match is found, iteration terminates immediately.

## The Solution

```java
import java.io.File;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Arrays;
import java.util.Scanner;
import java.util.Set;
import java.util.regex.Pattern;

public class Main {
    private static final Set<String> BUILTINS = Set.of("echo", "exit", "type");

    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String trimmed = input.trim();
            if (trimmed.isEmpty()) {
                continue;
            }
            String[] parts = trimmed.split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            } else if (command.equals("echo")) {
                String output = String.join(" ", Arrays.copyOfRange(parts, 1, parts.length));
                System.out.println(output);
            } else if (command.equals("type")) {
                if (parts.length > 1) {
                    String target = parts[1];
                    if (BUILTINS.contains(target)) {
                        System.out.println(target + " is a shell builtin");
                    } else {
                        Path executable = findExecutableInPath(target);
                        if (executable != null) {
                            System.out.println(target + " is " + executable);
                        } else {
                            System.out.println(target + ": not found");
                        }
                    }
                }
            } else {
                System.out.println(input + ": command not found");
            }
        }
    }

    private static Path findExecutableInPath(String command) {
        String pathEnv = System.getenv("PATH");
        if (pathEnv == null || pathEnv.isEmpty()) {
            return null;
        }
        String[] dirs = pathEnv.split(Pattern.quote(File.pathSeparator));
        for (String dir : dirs) {
            if (dir.isEmpty()) {
                continue;
            }
            try {
                Path path = Paths.get(dir, command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
        }
        return null;
    }
}
```

## What breaks it (failure modes)

- **Treating a directory as an executable program** — Calling `Files.isExecutable(path)` without `Files.isRegularFile(path)` causes directories with `+x` permissions (which allow directory traversal) to be falsely reported as executables.
- **Hardcoding path delimiters (`:` or `;`)** — Using `:` directly fails on Windows (which uses `;`), while using `;` fails on POSIX. Always use `File.pathSeparator`.
- **Crashing on non-existent directories in `PATH`** — Users frequently have non-existent or stale directories in their `PATH`. Attempting filesystem checks on these entries must fail gracefully without throwing unhandled exceptions.
- **Missing execute permissions** — A file with the matching name may exist in a `PATH` directory but lack executable permission (e.g. `chmod -x`). The shell must skip it and continue searching subsequent `PATH` entries.
- **Null or empty `PATH` variable** — If an environment has an unset or empty `PATH`, `System.getenv("PATH")` returns `null`. Dereferencing it without a null check causes a `NullPointerException`.
- **Not breaking on first match** — Continuing the search across later directories would report the wrong path or shadow resolution order. Search must stop immediately upon finding the first valid executable.

---

## Tradeoffs

- **Reusable helper method (`findExecutableInPath`) vs inlined lookup in `type`** — Isolating path resolution in a helper method adheres to single-responsibility principles and allows immediate reuse in Stage 8 when executing external commands via `ProcessBuilder`.
- **`java.nio.file.Path` & `Files` vs `java.io.File`** — `Files.isRegularFile` and `Files.isExecutable` handle symlinks, modern filesystem attributes, and security managers cleanly, whereas `File.canExecute()` in legacy I/O has platform-dependent quirks on certain filesystems.
- **Eager on-demand search vs PATH caching / hash table** — Real shells (like bash `hash`) maintain a lookup table for resolved command paths to avoid repeated disk scans. For a simple shell, on-demand traversal is fast enough and guarantees immediate reflection of filesystem changes without cache invalidation complexity.

## CLI / Protocol format

- **Type Command Output for Builtins**:
  ```
  <target> is a shell builtin
  ```
- **Type Command Output for PATH Executables**:
  ```
  <target> is <full_path>
  ```
  Examples:
  - `$ type ls` -> `ls is /usr/bin/ls`
  - `$ type custom_cmd` -> `custom_cmd is /usr/local/bin/custom_cmd`
- **Type Command Output for Unrecognized Target**:
  ```
  <target>: not found
  ```
  Example:
  - `$ type invalid_command` -> `invalid_command: not found`

## Java specifics — lookup, don't memorize

- `System.getenv("PATH")` — Retrieves the value of the specified system environment variable, returning `null` if undefined.
- `File.pathSeparator` — The system-dependent path-separator character (`:` on POSIX, `;` on Windows), represented as a string.
- `Pattern.quote(String s)` — Returns a literal pattern String for the specified String, escaping any regex metacharacters safely.
- `Paths.get(String first, String... more)` — Converts a path string or sequence of strings into a `Path` object.
- `Files.isRegularFile(Path path)` — Tests whether a file is a regular file with basic file attributes, resolving symbolic links.
- `Files.isExecutable(Path path)` — Tests whether a file exists and the JVM has execution rights to execute it.

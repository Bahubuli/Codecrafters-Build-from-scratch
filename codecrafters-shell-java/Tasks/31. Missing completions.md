# Stage 31: Missing completions (#vs5)

## In one line
Emits a bell character (`\u0007`) when tab-completing an argument with zero matching filesystem entries, leaving the typed input line untouched.

---

## Self-test
- **Prompt**: What should the shell output when the user types `cat absent_file` and presses `<TAB>`?
- **Answer**: The shell must keep the terminal line unchanged (`$ cat absent_file`) and emit ASCII byte `\u0007` (BEL) to standard output without appending any characters or whitespace.

---

## Problem Solved
When typing arguments (such as filenames or paths), users expect feedback if no directory or file matches their prefix. Printing nothing can leave users wondering if the terminal froze or missed keystrokes; modifying the buffer erroneously mutates valid user input. Emitting the standard terminal bell alert (`\u0007`) signals a failed match cleanly.

---

## Key Concepts
1. **ASCII Bell Control Character (`\u0007` or `\x07`)**:
   - Transmitted to standard output to trigger auditory or visual alerts in terminal emulators.
2. **Buffer Invariance on Missed Autocomplete**:
   - Preserves the user's cursor and typed text exactly as-is without mutating the internal `StringBuilder` line buffer.
3. **Consecutive Tab State Reset**:
   - Any completion attempt yielding 0 matches clears any multi-tab listing counters so subsequent keystrokes start afresh.

---

## The Solution
In `readLineWithCompletion()`:
1. When `<TAB>` is pressed on an argument (`lastSpace != -1`), call `getFileCompletions(word)`.
2. When `matches.isEmpty()`:
   - Print `\u0007` to standard output.
   - Flush `System.out`.
   - Reset `consecutiveTabs = 0`.
   - Leave `line` buffer unmodified.

```java
if (matches.size() == 1) {
    String match = matches.iterator().next();
    if (match.endsWith("/")) {
        String completion = match.substring(word.length());
        line.append(completion);
        System.out.print(completion);
    } else {
        String completion = match.substring(word.length()) + " ";
        line.append(completion);
        System.out.print(completion);
    }
    System.out.flush();
    consecutiveTabs = 0;
} else if (matches.size() > 1) {
    // LCP and double-tab handling...
} else {
    // Missing completions
    System.out.print("\u0007");
    System.out.flush();
    consecutiveTabs = 0;
}
```

---

## Failure Modes & Bugs Prevented
1. **Accidentally Appending Null or Empty Suffix**:
   - If missing matches did not short-circuit, code attempting `matches.iterator().next()` would throw `NoSuchElementException`.
2. **Missing Bell Alert**:
   - Simply ignoring the tab press fails the test requirements; terminal emulators specifically expect `\u0007`.
3. **Flushing Neglect**:
   - Failing to immediately call `System.out.flush()` after printing `\u0007` can cause the byte to remain buffered in the JVM stream.

---

## Tradeoffs
- Emitting `\u0007` synchronously on missing matches vs. terminal-specific beep APIs (`java.awt.Toolkit.getDefaultToolkit().beep()`):
  - Emitting `\u0007` to stdout works uniformly across headless containers, SSH sessions, and CLI testers without requiring AWT or GUI subsystems.

---

## CLI / Protocol Format
```text
$ cat absent_filenam<TAB>
# Standard output receives \u0007
# Cursor remains at end of 'absent_filenam'
$ cat absent_filenam
```

---

## Java Specifics
- `System.out.print("\u0007")` sends the standard bell character.
- Calling `System.out.flush()` forces the byte out through the JVM standard output buffer immediately.

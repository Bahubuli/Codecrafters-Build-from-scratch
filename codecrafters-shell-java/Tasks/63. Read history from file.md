# Stage 63: Read history from file

## In one line
Implement the `history -r <file>` command option to load saved commands from an external file and append them directly to the in-memory shell history list.

## Self-test (cover the answers below and answer these first)
- Does `history -r <path>` print anything to standard output or does it execute silently?
- Does the invocation `history -r <path>` itself get recorded in the shell's command history?
- What happens to empty lines when reading historical entries from a file?

## The problem it solved
Shell sessions lose their context once exited unless command history can be preserved and restored. Before this stage, `history` was strictly ephemeral and reset on each run; adding `-r` enables loading a persisted command history file back into memory.

## Concepts (the transferable part)
- **History File Deserialization** — Storing command history line-by-line in plain text files and deserializing it sequentially into the shell's runtime history data structure.
- **Silent Utility Operation** — In standard POSIX shells, history manipulation options (`history -r`, `history -w`, `history -a`) operate silently without printing entries or status messages unless an error occurs.
- **Sequential In-Memory Append** — Appending entries read from the file preserves relative chronological order while updating the global history index for arrow-key navigation and subsequent `history` listings.

## What breaks it (failure modes)
- Printing the history list when `-r` is passed — `history` with no arguments prints the history table, but `history -r <file>` must only load the file silently without printing anything.
- Failing to resolve relative paths — If the given file path is relative (e.g. `./history.txt` or `dir/history`), it must be resolved against the shell's current working directory (`currentDir`).
- Non-existent files throwing unhandled exceptions — If the target history file doesn't exist, it should be handled gracefully without crashing the shell process.

## Tradeoffs
- Appending directly to runtime history vs replacing current history — `history -r` in Bash appends lines from the file to the current session history, allowing users to aggregate history files across multiple environments or sessions without wiping existing session commands.

## CLI / Protocol format
- Syntax: `history -r <path_to_history_file>`
- Output: None (silent operation)
- Subsequent `history` command reflects both prior session commands, the `history -r` invocation itself, and all loaded file entries.

## Java specifics — lookup, don't memorize
- `Files.readAllLines(path)` — Reads all lines from a file into a `List<String>` using UTF-8 charset.
- `currentDir.resolve(filePath).normalize()` — Resolves a path string relative to the active working directory.

# Stage 70: Printing missing variables

## In one line
Implement the `-p` inspection flag for `declare` to output an error message to standard error when an undeclared variable name is queried.

## Self-test (cover the answers below and answer these first)
- What output does `declare -p <variable>` generate when `<variable>` has not been defined?
- Which stream (stdout vs stderr) does the shell use to report missing variable definitions, and why?
- What should the exit status of `declare -p missing_var` be?

## The problem it solved
Users and shell scripts use `declare -p <name>` to inspect a variable's attributes and value. When the specified variable has not been declared or exported, the shell must report an informative error (`declare: <name>: not found`) to standard error and return a non-zero exit status, allowing caller scripts to verify variable presence via standard error streams or conditional testing.

## Concepts (the transferable part)
- **Attribute & Value Inspection Flag (`-p`)** — In POSIX/Bash-compatible shells, `-p` (print) queries the variable symbol table.
- **Diagnostic Error Reporting** — Distinguishing informational output from diagnostics: diagnostic messages (`declare: var: not found`) are routed to `stderr` (`System.err`), while successful variable descriptions belong on `stdout` (`System.out`).
- **Non-zero Error Exit Code** — Builtin commands that fail must return `1` (or appropriate non-zero error code) so that pipelines and subshell conditionals (`if declare -p VAR; then ...`) can branch accordingly.

## What breaks it (failure modes)
- Printing to `stdout` instead of `stderr` — If error diagnostics are printed to `out` rather than `err`, standard stream redirections (`declare -p var 2> /dev/null`) fail to suppress the error.
- Hardcoding the variable name — If the error message does not dynamically interpolate `varName`, queries for any arbitrary variable name will fail the tester.
- Missing exit status — Returning `0` when a variable is missing violates standard shell behavior for command status tests.

## Tradeoffs
- Immediate Error Reporting vs Full Symbol Table — In early stages without full variable assignment parsing, checking queries against the known variable store and reporting missing variables establishes the inspection interface before adding complex typing/scoping rules.

## CLI / Protocol format
```bash
$ declare -p missing_variable
declare: missing_variable: not found
```

## Java specifics — lookup, don't memorize
- Handling variable arguments in `-p`:
  ```java
  if (cmdArgs.size() >= 2 && cmdArgs.get(1).equals("-p")) {
      int exitCode = 0;
      if (cmdArgs.size() > 2) {
          for (int i = 2; i < cmdArgs.size(); i++) {
              String varName = cmdArgs.get(i);
              err.println("declare: " + varName + ": not found");
              exitCode = 1;
          }
      }
      err.flush();
      out.flush();
      return exitCode;
  }
  ```

## Rebuild checklist
1. Inspect `cmdArgs` in `executeBuiltin()` when `command.equals("declare")`.
2. Check for the `-p` argument (`cmdArgs.get(1).equals("-p")`).
3. For each variable name argument from index 2 onwards, print `declare: <varName>: not found` to `err`.
4. Flush `err` and `out`, and return `1` when any requested variable is not found.

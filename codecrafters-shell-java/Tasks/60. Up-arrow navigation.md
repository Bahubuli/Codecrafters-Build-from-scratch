# Stage 60: Up-arrow navigation

## In one line
Intercept terminal ANSI escape sequences `\u001b[A` (up arrow) and `\u001b[B` (down arrow) in raw mode to cycle backward and forward through command history on the interactive prompt line.

## Self-test (cover the answers below and answer these first)
- What byte sequence does the terminal send when the Up arrow key is pressed?
- How does the shell visually erase the existing text on the prompt before printing the recalled command?
- Where does the history pointer start before any Up arrow key is pressed, and what happens when you press Down arrow back to the bottom?

## The problem it solved
Users expect interactive shells to support pressing the Up arrow key to quickly recall and re-execute recent commands instead of retyping them. Without intercepting ANSI escape sequences in raw mode, pressing Up prints raw characters like `^[[A` or `[A` directly to the terminal screen.

## Concepts (the transferable part)
- **ANSI Escape Sequences** — Terminal cursor keys and navigation send 3-byte escape sequences starting with ESC (`27` or `0x1B`), followed by `[` (`91` or `0x5B`), followed by a directional character (`A` for Up, `B` for Down, `C` for Right, `D` for Left).
- **In-place Line Editing & Visual Redraw** — Clearing previously rendered text using backspace-space-backspace sequences (`\b \b`) or ANSI clear sequences before rendering the newly recalled line.
- **History Pointer State Machine** — Tracking an index pointer bounded between `0` and `history.size()`, where `history.size()` represents the currently typed draft line.

## What breaks it (failure modes)
- Leaving leftover trailing characters — If the previously displayed line was longer than the recalled line, simply printing the new line without first clearing the old length leaves phantom characters at the end.
- Index underflow/overflow — Pressing Up repeatedly when already at index 0 or Down past the end must be bounded gracefully without throwing exceptions.
- Blocking on incomplete escape sequences — Reading bytes synchronously when an ESC byte arrives must cleanly identify whether it is an arrow sequence.

## Tradeoffs
- Full Readline/JLine library vs custom ANSI parser — Using custom raw mode handling allows lightweight, zero-dependency control without introducing external JARs or complex terminal binding layers.

## CLI / Protocol format
- Key sequence for Up Arrow: `\u001b[A` (bytes `27`, `91`, `65`)
- Key sequence for Down Arrow: `\u001b[B` (bytes `27`, `91`, `66`)
- Visual line clear: `\b \b` for each character in current line length.

## Java specifics — lookup, don't memorize
- `System.in.read()` — Reads raw byte from stdin (in raw mode).
- `line.deleteCharAt(line.length() - 1)` — Truncates `StringBuilder` character by character.

# Stage 29: Nested file completion

## In one line
Extends filename autocompletion across arbitrary directory hierarchies by splitting target tokens at the final slash delimiter, resolving the directory prefix against the shell's working directory, and appending the completed filename to preserve the user's path structure.

## The problem it solved
Previously, filename autocompletion only scanned the flat current working directory (`currentDir`). Pressing `<TAB>` on arguments referencing subdirectories or absolute paths (e.g. `cat path/to/f<TAB>`) failed to complete or searched the top-level working directory for a literal file starting with `path/to/f`. Real-world shells navigate directory trees hierarchically: autocompletion must resolve directory path segments and match filenames within the designated target directory while maintaining the typed path prefix on the input line.

## Concepts (the transferable part)
- **[CONCEPT] Hierarchical Path Decomposition (Dirname / Basename Boundary)** — Paths in POSIX and modern operating systems are trees represented linearly with delimiter `/`. When completing a path token, the rightmost `/` separates the traversal context (`dirPart`, dirname) from the candidate filter prefix (`namePrefix`, basename).
- **[CONCEPT] Scoped Directory Traversal** — Instead of scanning the entire filesystem or flat current directory, the completion engine isolates query scope strictly to `dirPart`. If `dirPart` is relative, it is resolved against `currentDir`; if absolute, it is rooted at filesystem root `/`.
- **[CONCEPT] Path Prefix Preservation in Candidate Emitted Delta** — Terminal line editing buffers display the full token as typed. Because the buffer already holds `dirPart`, candidate strings stored in the candidate set must preserve `dirPart + entry.getName()` so that calculating completion delta `match.substring(word.length())` correctly computes only the missing characters without corrupting earlier path segments.

## What breaks it (failure modes)
- **Emitting Basename Only Instead of Full Token** — If candidates only hold `entry.getName()` (`file.txt`), then `match.substring(word.length())` will throw `StringIndexOutOfBoundsException` or emit garbage since `word` (`path/to/f`, length 9) is longer than the leaf name (`file.txt`, length 8). Candidates must be `dirPart + entry.getName()`.
- **Failing to Handle Trailing Slash** — When the token ends in `/` (`path/to/`), `namePrefix` is empty `""`. The search must list all non-hidden entries inside `path/to/` rather than throwing an exception or finding nothing.
- **Unchecked Non-Existent or Inaccessible Directory** — If the user types a non-existent directory `nonexistent/f<TAB>`, `targetDir.toFile().listFiles()` returns `null`. Without null guarding, calling methods on `files` triggers `NullPointerException`.
- **Absolute vs Relative Directory Resolution** — Attempting to resolve absolute paths like `/tmp/f` via `currentDir.resolve("/tmp/")` on some platforms or without checking `startsWith("/")` can erroneously nest the path under the working directory (e.g. `/current/dir/tmp/`).
- **Leaking Dotfiles on Subdirectory Queries** — Subdirectories contain hidden metadata (`.`, `..`, `.git`). Filtering out entries starting with `.` when `namePrefix` does not start with `.` is vital to avoid spurious matches or polluting tab suggestions.

## Tradeoffs
- **Synchronous Filesystem Inode Scan vs Cached Directory Tree** — Reading `targetDir.toFile().listFiles()` on demand ensures zero stale file cache issues at minimal cost for local interactive shells. Maintaining a cached directory tree would require filesystem watches (`WatchService`) and introduce memory overhead and invalidation bugs.
- **`dirPart` String Concatenation vs `java.nio.file.Path` Normalization in Buffers** — Preserving the exact string form of `dirPart` (including `./` or `../` as typed by the user) when forming candidate completions ensures the command line reflects user intent without unexpected path normalization changes on screen.

## CLI / Protocol format
- Current working directory contains: `pineapple/strawberry/raspberry.txt`
- User types `du pineapple/strawberry/` and presses `<TAB>`:
  - Input: `du pineapple/strawberry/<TAB>`
  - Path parsing: `lastSlash` = 20, `dirPart` = `pineapple/strawberry/`, `namePrefix` = `""`
  - Target directory: `/app/pineapple/strawberry`
  - Scan result: `raspberry.txt` matches `""` (single match)
  - Candidate: `pineapple/strawberry/raspberry.txt`
  - Delta: `raspberry.txt `
  - Screen output: `du pineapple/strawberry/raspberry.txt `

## Java specifics — lookup, don't memorize
- `String.lastIndexOf(int ch)` — Returns the rightmost index of character `ch` in the string, or -1 if not found.
- `Path.resolve(String other)` — Resolves a given path against this path; if `other` is absolute, returns the absolute path.
- `Path.normalize()` — Returns a path with redundant name elements (like `.` or `..`) eliminated.
- `File.listFiles()` — Returns array of `File` objects inside directory, or `null` if path does not denote a directory or is unreadable.

## Rebuild checklist
- [ ] In `getFileCompletions(prefix)`:
  - Find `lastSlash = prefix.lastIndexOf('/')`.
  - If `lastSlash != -1`:
    - Split `dirPart = prefix.substring(0, lastSlash + 1)` and `namePrefix = prefix.substring(lastSlash + 1)`.
    - Handle `~` expansion if `dirPart.startsWith("~")`.
    - If `searchPath.startsWith("/")`, `targetDir = Paths.get(searchPath).normalize()`.
    - Else, `targetDir = currentDir.resolve(searchPath).normalize()`.
  - Else:
    - `dirPart = ""` and `namePrefix = prefix`.
    - `targetDir = currentDir`.
  - Scan `targetDir.toFile().listFiles()`:
    - Guard against `null` returns from `listFiles()`.
    - Filter dotfiles: if `!namePrefix.startsWith(".") && name.startsWith(".")`, skip.
    - If `name.startsWith(namePrefix)`, add `dirPart + name` to `TreeSet<String>`.
- [ ] In `readLineWithCompletion()`:
  - Extract argument `word = current.substring(lastSpace + 1)`.
  - Retrieve `matches = getFileCompletions(word)`.
  - If `matches.size() == 1`:
    - Append `match.substring(word.length()) + " "` to line buffer.

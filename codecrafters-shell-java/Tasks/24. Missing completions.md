# Missing completions

## In one line
Emits an audible or visual terminal bell (`\x07`) when tab autocompletion yields zero candidates, leaving the current user input line unmodified.

---

## Self-test
1. What ASCII character code is the terminal bell character?
2. When the user types `xyz<TAB>`, how should the terminal prompt line appear?
3. Why must `System.out.flush()` be called immediately following `\u0007`?

---

## Problem Solved
When a user presses `<TAB>` on an unrecognized command prefix (e.g. `xyz<TAB>`), the shell should neither alter the buffer nor print errant text. Instead, standard shells alert the user that no autocompletions match by emitting the ASCII bell character (`\x07` or `\u0007`) to the terminal, leaving the input prompt intact so the user can continue typing or editing.

---

## Concepts
- **ASCII Bell Character (`\x07`)**: A non-printable control character in ASCII and Unicode (`\u0007`) that instructs the terminal emulator to trigger an audio beep or visual alert flash.
- **Buffer Invariance on Non-Match**: If candidate resolution yields empty matches, no characters are appended to the internal buffer and no characters are echoed to standard output, preserving terminal line state.
- **Terminal Control Sequencing**: In raw/non-canonical mode, control characters sent to stdout are interpreted directly by the controlling terminal emulator or test harness.

---

## The Solution
In `readLineWithCompletion()`, candidate matches against builtin targets are evaluated:
```java
String current = line.toString();
List<String> candidates = List.of("echo", "exit");
List<String> matches = candidates.stream()
        .filter(cmd -> cmd.startsWith(current))
        .toList();
if (matches.size() == 1) {
    String match = matches.get(0);
    String completion = match.substring(current.length()) + " ";
    line.append(completion);
    System.out.print(completion);
    System.out.flush();
} else {
    System.out.print("\u0007");
    System.out.flush();
}
```
When `matches.isEmpty()`, `line` remains unchanged, `\u0007` is written to `System.out`, and output is flushed immediately.

---

## Failure Modes
- **Modifying Line Buffer**: Appending or clearing buffer characters when completions are missing would corrupt user input.
- **Unflushed Bell Character**: If `\u0007` is written without `flush()`, the terminal tester may time out waiting for the bell control signal.

---

## Tradeoffs
- **Immediate Bell**: Ringing the bell directly upon empty match avoids unnecessary candidate scans while providing instant sensory feedback.

---

## CLI / Protocol Format
```bash
$ xyz<TAB>
$ xyz
```
- Upon pressing `<TAB>`, the terminal rings a bell (`\u0007`) and leaves `$ xyz` unchanged.

---

## Java Specifics
- `\u0007` is Java's Unicode escape representation of ASCII code 7 (`\a` in C/Bash).
- `System.out.print("\u0007"); System.out.flush();` reliably writes the control code to the process output descriptor.

# Stage 69: The declare builtin

## In one line
Register `declare` as a recognized shell builtin so that `type declare` correctly identifies it as a builtin command.

## Self-test (cover the answers below and answer these first)
- What is the purpose of the `declare` builtin in POSIX and modern shells like Bash?
- How does the shell differentiate between external executables and builtins when querying with `type`?
- Why is it helpful to register builtin dispatch hooks before completing parameter assignment features?

## The problem it solved
Shells require internal management of variable attributes, scope, and definitions. Before variable declaration and inspection commands like `declare var=value` or `declare -p var` can be executed, the shell's command dispatch and inspection mechanisms (such as `type`) must recognize `declare` as an internal command rather than attempting to look for an external executable in `$PATH`.

## Concepts (the transferable part)
- **Builtin Registration Table** — Shells keep an immutable or reserved set of identifiers (the builtin table). Before looking up binaries in directories specified by `$PATH`, the command parser checks this set.
- **Incremental Builtin Introduction** — In complex systems, introducing the symbol into the command resolution table first validates namespace integrity and CLI introspection before implementing heavy state mutations.

## What breaks it (failure modes)
- Omitting from the `BUILTINS` set — If `declare` is not added to the `BUILTINS` set, `type declare` will search `$PATH` and report `declare: not found`.
- Missing in command evaluation dispatcher — If the command router in `executeBuiltin` does not handle `declare`, invocations will either fail or trigger an unhandled condition.

## Tradeoffs
- Builtin vs External Utility — Shell variables exist exclusively in the memory space of the current shell process. An external process could never modify or read non-exported shell variables, so `declare` must inherently be a builtin.

## CLI / Protocol format
```bash
$ type declare
declare is a shell builtin
```

## Java specifics — lookup, don't memorize
- `Set.of(...)` — Constructing an immutable set containing all recognized builtin names:
  ```java
  private static final Set<String> BUILTINS = Set.of(
      "echo", "exit", "type", "pwd", "cd", "complete", "jobs", "history", "declare"
  );
  ```

## Rebuild checklist
1. Add `"declare"` to the `BUILTINS` set in `Main.java`.
2. Add a branch for `command.equals("declare")` in `executeBuiltin()` to handle execution and flush outputs cleanly.
3. Verify that running `type declare` outputs `declare is a shell builtin`.

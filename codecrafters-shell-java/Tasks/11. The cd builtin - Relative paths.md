# Stage 11: The cd builtin - Relative paths

---

## In one line
Extend the `cd` builtin to resolve relative paths (`./`, `../`, and relative subdirectories) against the shell's current working directory using path resolution and normalization.

## The problem it solved
Users and automated scripts frequently navigate filesystem trees relatively rather than typing full absolute paths. Without relative path support, common navigation paradigms like `cd ../` (move up to parent directory), `cd ./local` (stay explicit within current scope), and `cd subfolder` fail. Relative path traversal allows natural navigation from the context of the current working directory.

---

## Concepts (the transferable part)

- **[CONCEPT] Relative Paths vs Absolute Paths** — While an absolute path starts from the root (`/` on POSIX) and unambiguously specifies a file system location independently of process context, a relative path is evaluated strictly relative to the current working directory (`CWD`).
- **[CONCEPT] Special Directory Entries (`.` and `..`)** — In POSIX filesystems, every directory table contains at least two standard directory entries:
  - `.` represents the directory itself (current directory).
  - `..` represents the parent directory in the filesystem tree hierarchy. At the filesystem root (`/`), `..` points back to `/` itself (the root directory is its own parent).
- **[CONCEPT] Path Normalization** — Normalization removes redundant segments (`.` and `..` collapses, redundant separators `//`) algebraically without contacting the underlying filesystem. For example, `/usr/local/bin/../../` normalizes to `/usr`.
- **[CONCEPT] Directory Invariance on Failure** — If a relative path resolves to a location that does not exist or is not a directory (e.g., a regular file or broken symlink), the command must report an error (`cd: <path>: No such file or directory`) and leave the shell's working directory completely untouched.

## The Solution

```java
import java.io.File;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Arrays;
import java.util.Scanner;
import java.util.Set;
import java.util.regex.Pattern;

public class Main {
    private static final Set<String> BUILTINS = Set.of("echo", "exit", "type", "pwd", "cd");
    private static Path currentDir = Paths.get(System.getProperty("user.dir")).toAbsolutePath().normalize();

    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String trimmed = input.trim();
            if (trimmed.isEmpty()) {
                continue;
            }
            String[] parts = trimmed.split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            } else if (command.equals("echo")) {
                String output = String.join(" ", Arrays.copyOfRange(parts, 1, parts.length));
                System.out.println(output);
            } else if (command.equals("type")) {
                if (parts.length > 1) {
                    String target = parts[1];
                    if (BUILTINS.contains(target)) {
                        System.out.println(target + " is a shell builtin");
                    } else {
                        Path executable = findExecutable(target);
                        if (executable != null) {
                            System.out.println(target + " is " + executable);
                        } else {
                            System.out.println(target + ": not found");
                        }
                    }
                }
            } else if (command.equals("pwd")) {
                System.out.println(currentDir);
            } else if (command.equals("cd")) {
                if (parts.length > 1) {
                    String targetPath = parts[1];
                    Path target = currentDir.resolve(targetPath).normalize();
                    if (Files.isDirectory(target)) {
                        currentDir = target;
                    } else {
                        System.out.println("cd: " + targetPath + ": No such file or directory");
                    }
                }
            } else {
                Path executable = findExecutable(command);
                if (executable != null) {
                    ProcessBuilder pb = new ProcessBuilder(parts);
                    pb.directory(currentDir.toFile());
                    pb.inheritIO();
                    Process process = pb.start();
                    process.waitFor();
                } else {
                    System.out.println(input + ": command not found");
                }
            }
        }
    }

    private static Path findExecutable(String command) {
        if (command.contains("/") || command.contains(File.separator)) {
            try {
                Path path = currentDir.resolve(command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
            return null;
        }
        return findExecutableInPath(command);
    }

    private static Path findExecutableInPath(String command) {
        String pathEnv = System.getenv("PATH");
        if (pathEnv == null || pathEnv.isEmpty()) {
            return null;
        }
        String[] dirs = pathEnv.split(Pattern.quote(File.pathSeparator));
        for (String dir : dirs) {
            if (dir.isEmpty()) {
                continue;
            }
            try {
                Path path = Paths.get(dir, command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
        }
        return null;
    }
}
```

## What breaks it (failure modes)

- **Not normalizing resolved paths (`.normalize()`)** — Failing to call `.normalize()` leaves `.` and `..` segments embedded within `currentDir` (e.g. `/usr/local/bin/../../`). While the OS filesystem API may traverse it, `pwd` will display redundant unresolved components rather than clean canonical directory paths (`/usr`).
- **Printing the normalized path in the error message** — If `cd invalid/../ghost` fails, outputting `cd: invalid/ghost: No such file or directory` instead of the raw argument `cd: invalid/../ghost: No such file or directory` will fail exact string matching tests.
- **Accidentally navigating above the root directory** — On POSIX systems, `Path.resolve()` and `Path.normalize()` correctly cap parent traversal at root: `/..` normalizes to `/`. Attempting manual string splitting on `/` without handling root can cause index out of bounds or empty paths.
- **Symlink traversal loops or non-directory file targets** — Checking `Files.isDirectory(target)` correctly verifies that the resolved path points to a directory (resolving symlinks) rather than a regular file.

---

## Tradeoffs

- **`currentDir.resolve(targetPath).normalize()` vs manual segment parsing** —
  - `Path.resolve(...)` handles both absolute paths (returning the absolute path directly) and relative paths (appending to `currentDir`).
  - `.normalize()` handles `.`, `..`, and path separators cleanly across platforms according to POSIX and host semantics.
  - Manual string manipulation (e.g. splitting by `/` and managing a stack) is error-prone and requires complex platform-specific separator handling.
- **Logical vs Physical directory resolution (`cd -L` vs `cd -P`)** — Standard shells provide flags to decide whether `..` navigates logical directory structure (following symlinks symbolically) or physical filesystem hierarchy. Java NIO's `Path.normalize()` performs purely logical syntactic path simplification. For basic shells, logical normalization matches standard default shell behavior.

## CLI / Protocol format

- **Relative subdirectory navigation**:
  ```
  $ pwd
  /usr
  $ cd ./local/bin
  $ pwd
  /usr/local/bin
  $ 
  ```
- **Parent directory navigation (`..`)**:
  ```
  $ pwd
  /usr/local/bin
  $ cd ../../
  $ pwd
  /usr
  $ 
  ```
- **Shorthand relative path without `./`**:
  ```
  $ pwd
  /usr
  $ cd local
  $ pwd
  /usr/local
  $ 
  ```
- **Invalid relative path error message**:
  ```
  $ cd ./nonexistent
  cd: ./nonexistent: No such file or directory
  $ pwd
  /usr/local
  $ 
  ```

## Java specifics — lookup, don't memorize

- `Path.resolve(String other)` — Resolves the given path string against this `Path`. If `other` is absolute, returns `other`. If `other` is relative, joins it to `this`.
- `Path.normalize()` — Returns a path that is this path with redundant name elements eliminated (e.g., `.` and `..`). Does not access the filesystem.
- `Files.isDirectory(Path path)` — Tests whether a path points to a directory, following symbolic links.
- `ProcessBuilder.directory(File dir)` — Sets the working directory of subprocesses created by the `ProcessBuilder`.

# Stage 34: Multi-argument completions (#bf8)

## In one line
Extends autocompletion to arbitrary argument positions by always slicing the current line at the final space character and completing relative to the current working directory.

---

## Self-test
- **Prompt**: If the input buffer is `$ stat dir1/ f` and the CWD contains `foo.txt`, what does pressing `<TAB>` complete to, and why doesn't `dir1/` change the search folder for `f`?
- **Answer**: It completes to `$ stat dir1/ foo.txt `. Each argument is completed independently based on its own path prefix; preceding arguments are distinct tokens and do not alter the base directory for subsequent tokens unless the token itself contains a path separator.

---

## Problem Solved
Previously, completion only distinguished between command mode (no space) and first argument mode. In command invocations with multiple arguments (e.g. `cat file1 file2` or `stat foo/ bar/ baz`), the user needs completion for subsequent arguments past position 1 without losing prior arguments or causing incorrect directory resolution.

---

## Key Concepts
1. **Token Boundary Extraction**:
   - `int lastSpace = current.lastIndexOf(' ')`: Slices the command line buffer into everything before the active argument and the active argument itself (`current.substring(lastSpace + 1)`).
2. **Current Working Directory Scope**:
   - The token being completed defines its own directory lookup root (either relative to `currentDir` or as a subfolder if it contains slashes). Prior arguments do not alter the current lookup context.
3. **Consistency Across Positions**:
   - All rules from previous stages (LCP partial completions, single match space/slash appending, missing completion bell ringing, consecutive tab candidate listing) operate seamlessly on the active token regardless of argument index.

---

## The Solution
In `readLineWithCompletion()`:
```java
String current = line.toString();
int lastSpace = current.lastIndexOf(' ');
String word;
Set<String> matches;
if (lastSpace == -1) {
    word = current;
    matches = getCommandCompletions(word);
} else {
    word = current.substring(lastSpace + 1);
    matches = getFileCompletions(word);
}
```

Because `line.append(completion)` only appends the uncompleted suffix of `word` and `matches` is computed from `word = current.substring(lastSpace + 1)`, the prompt line remains intact up to `lastSpace` while smoothly completing the active argument.

---

## Failure Modes & Bugs Prevented
1. **Accumulation of Leading Arguments in Search**:
   - If the entire line `current` was passed into file completion rather than `current.substring(lastSpace + 1)`, directory resolution would fail because spaces in Unix filenames are either escaped or quoted, causing `Paths.get("stat foo bar")` to look for a non-existent path.
2. **Line Buffer Corruption**:
   - Appending `completion` (which is `match.substring(word.length())`) rather than replacing the whole line preserves previous arguments perfectly without redraw artifacts.

---

## Tradeoffs
- Simple `lastIndexOf(' ')` vs full quote-aware tokenizer during tab completion:
  - For standard argument completion, `lastIndexOf(' ')` is fast and lightweight. Quoting within completion can be layered when completion of quoted arguments is required.

---

## CLI / Protocol Format
```text
$ ls bar/ f<TAB>
# Completes to foo (file) with trailing space
$ ls bar/ foo 

$ ls bar/ foo x<TAB>
# No match in CWD: bell rings, buffer unchanged
$ ls bar/ foo x
```

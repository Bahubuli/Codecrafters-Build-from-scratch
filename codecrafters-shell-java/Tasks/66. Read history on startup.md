## The problem it solved
Shells are expected to maintain persistent history across sessions. When a new shell instance launches, standard shells (like Bash or Zsh) inspect the `HISTFILE` environment variable to restore past commands into the in-memory history buffer, allowing commands like `history` or up/down arrow recall to access past sessions immediately.

## Concepts (the transferable part)
- **Environment-Driven Configuration** — Reading system environment variables via `System.getenv("HISTFILE")` at initialization to discover external file state.
- **Session State Hydration** — Prepopulating memory structures (`commandHistory`) on startup prior to initiating user interactions or reading standard input.
- **Path Normalization and Resolution** — Safely resolving relative or absolute paths using NIO (`currentDir.resolve(histFile).normalize()`) to reliably locate resources regardless of execution context.

## What breaks it (failure modes)
- Crashing when `HISTFILE` is unset or empty — `System.getenv("HISTFILE")` returns `null` if not set; attempting file operations without checking for `null` or empty string throws `NullPointerException`.
- Crashing when the target file does not exist — Checking `Files.exists(p)` before reading avoids `NoSuchFileException`.
- Loading blank or empty lines — History files typically terminate with trailing newlines; blank lines should not be added as valid command history entries.
- Double appending on subsequent `history -a` calls — If `lastAppendedHistoryIndex` is not synchronized to `commandHistory.size()` after initial file load, subsequent `history -a` calls would redundantly re-append the entire startup history.

## Tradeoffs
- Full In-Memory Loading vs Streaming/Lazy Loading — Reading all lines eagerly into an `ArrayList<String>` is simple and fast for typical history file sizes (thousands of lines). Extremely large history files (e.g. millions of entries) might warrant capped buffers (`HISTSIZE`) or streaming windows.

## CLI / Protocol format
- Startup Environment: `HISTFILE=<path_to_history_file> ./your_program.sh`
- Initial State: Before the first `$ ` prompt is displayed, lines from `<path_to_history_file>` are loaded in order into in-memory history.
- Verification: Running `history` immediately shows the loaded entries starting from index 1.

## Java specifics — lookup, don't memorize
- `System.getenv(String name)` — Retrieves the value of the specified environment variable, returning `null` if undefined.
- `Files.readAllLines(Path path)` — Reads all lines from a file into a `List<String>`, automatically handling standard line separators.
- `Path.resolve(String other)` — If `other` is absolute, returns `other` unchanged; if relative, resolves against the calling `Path`.

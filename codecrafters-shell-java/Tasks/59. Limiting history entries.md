# Stage 59: Limiting history entries

## In one line
Support an optional integer argument `<n>` to the `history` builtin to display only the most recent `n` recorded commands.

## Self-test (cover the answers below and answer these first)
- When `history <n>` is run, how are the displayed command lines numbered (original 1-based index or 1 to n)?
- How does the shell calculate the starting index when `n` is greater than the total number of items in history?
- Does `history <n>` include itself in the returned list of commands?

## The problem it solved
In long interactive shell sessions, running `history` outputs hundreds or thousands of lines, flooding the terminal screen. Allowing users to supply a numerical argument `history <n>` restricts the output to the last `n` commands, matching standard Bash behavior.

## Concepts (the transferable part)
- **Windowing / Tail Slicing** — Displaying a sliding tail window `[max(0, total - n), total)` over a linear history stream while preserving global 1-based indices.
- **Argument Parsing for Builtins** — Inspecting optional positional arguments, parsing strings into integers with fallback handling, and adjusting output bounds.
- **Consistent Global Indexing** — Even when output is truncated/sliced, the identity of commands remains tied to their monotonic session sequence numbers.

## What breaks it (failure modes)
- Slicing bounds out of range — If `n > total`, naive indexing could cause negative start indices or `IndexOutOfBoundsException`. Clamping with `Math.max(0, total - n)` prevents underflow.
- Re-indexing from 1 — Numbering entries 1 through n instead of their true global index breaks history lookup.
- Negative or invalid integers — Handling non-numeric or negative inputs gracefully without crashing the shell.

## Tradeoffs
- Bash semantics (`history <n>` = last n commands) vs zsh semantics (`history <n>` = start from line n) — Adhering to Bash convention aligns with standard POSIX terminal expectations.

## CLI / Protocol format
- Syntax: `history [<n>]`
- Example: `history 2`
- Output:
  ```text
      3  invalid_command
      4  history 2
  ```
  Numbered with original `%5d  %s\n` format.

## Java specifics — lookup, don't memorize
- `Integer.parseInt(cmdArgs.get(1))` — Parses string to signed decimal integer.
- `Math.max(0, commandHistory.size() - limit)` — Clamps lower slice bound to zero.

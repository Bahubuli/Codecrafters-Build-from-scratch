# Stage 12: The cd builtin - Home directory

---

## In one line
Expand the `cd` builtin to support tilde expansion (`~` and `~/...`) and default parameter-less navigation to the user's home directory retrieved from the `HOME` environment variable.

## The problem it solved
Navigating deep directory hierarchies repeatedly requires typing verbose absolute paths. In Unix/POSIX shells, the tilde `~` serves as a universal shortcut for the current user's home directory. Furthermore, running `cd` without arguments is the standard Unix convention for quickly returning home. Without handling `~` and `HOME`, users cannot leverage standard shell ergonomics or run scripts relying on home directory navigation.

---

## Concepts (the transferable part)

- **[CONCEPT] Tilde Expansion** — In shell syntax, the tilde (`~`) character at the start of a word is treated specially. If the word is solely `~` or starts with `~/`, the shell substitutes it with the current user's home directory path before path resolution occurs.
- **[CONCEPT] The `HOME` Environment Variable** — In POSIX environments, `HOME` is set by the login process (from `/etc/passwd` or PAM) to define the initial working directory of the user. Shells and user utilities consult `HOME` to determine where user configuration, data, and relative personal workspaces live.
- **[CONCEPT] Parameter-less Builtin Defaults** — Many shell builtins have standardized default behaviors when invoked without arguments. In POSIX `cd`, passing no arguments defaults to navigating to `$HOME`.
- **[CONCEPT] Fallback Strategies in Portable Software** — Environment variables can be unset, empty, or altered in embedded or test environments. Robust software provides a fallback chain (e.g. `System.getenv("HOME")` -> Java's `System.getProperty("user.home")`).

## The Solution

```java
import java.io.File;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Arrays;
import java.util.Scanner;
import java.util.Set;
import java.util.regex.Pattern;

public class Main {
    private static final Set<String> BUILTINS = Set.of("echo", "exit", "type", "pwd", "cd");
    private static Path currentDir = Paths.get(System.getProperty("user.dir")).toAbsolutePath().normalize();

    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String trimmed = input.trim();
            if (trimmed.isEmpty()) {
                continue;
            }
            String[] parts = trimmed.split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            } else if (command.equals("echo")) {
                String output = String.join(" ", Arrays.copyOfRange(parts, 1, parts.length));
                System.out.println(output);
            } else if (command.equals("type")) {
                if (parts.length > 1) {
                    String target = parts[1];
                    if (BUILTINS.contains(target)) {
                        System.out.println(target + " is a shell builtin");
                    } else {
                        Path executable = findExecutable(target);
                        if (executable != null) {
                            System.out.println(target + " is " + executable);
                        } else {
                            System.out.println(target + ": not found");
                        }
                    }
                }
            } else if (command.equals("pwd")) {
                System.out.println(currentDir);
            } else if (command.equals("cd")) {
                String home = System.getenv("HOME");
                if (home == null || home.isEmpty()) {
                    home = System.getProperty("user.home");
                }
                String targetPath = parts.length > 1 ? parts[1] : home;
                if (targetPath.equals("~")) {
                    targetPath = home;
                } else if (targetPath.startsWith("~/")) {
                    targetPath = home + targetPath.substring(1);
                }

                Path target = currentDir.resolve(targetPath).normalize();
                if (Files.isDirectory(target)) {
                    currentDir = target;
                } else {
                    System.out.println("cd: " + targetPath + ": No such file or directory");
                }
            } else {
                Path executable = findExecutable(command);
                if (executable != null) {
                    ProcessBuilder pb = new ProcessBuilder(parts);
                    pb.directory(currentDir.toFile());
                    pb.inheritIO();
                    Process process = pb.start();
                    process.waitFor();
                } else {
                    System.out.println(input + ": command not found");
                }
            }
        }
    }

    private static Path findExecutable(String command) {
        if (command.contains("/") || command.contains(File.separator)) {
            try {
                Path path = currentDir.resolve(command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
            return null;
        }
        return findExecutableInPath(command);
    }

    private static Path findExecutableInPath(String command) {
        String pathEnv = System.getenv("PATH");
        if (pathEnv == null || pathEnv.isEmpty()) {
            return null;
        }
        String[] dirs = pathEnv.split(Pattern.quote(File.pathSeparator));
        for (String dir : dirs) {
            if (dir.isEmpty()) {
                continue;
            }
            try {
                Path path = Paths.get(dir, command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
        }
        return null;
    }
}
```

## What breaks it (failure modes)

- **`HOME` environment variable is unset or empty** — In minimal container environments or non-POSIX platforms (like raw Windows CMD environments), `System.getenv("HOME")` may return `null` or `""`. Without falling back to `System.getProperty("user.home")`, a `NullPointerException` or invalid path navigation occurs.
- **String replacement on arbitrary tildes** — Using a naive `targetPath.replace("~", home)` would improperly corrupt paths like `my~file` or `cd dir/~backup`. Tilde expansion must only apply at the start of the argument when followed by nothing or `/`.
- **Target path normalization when home contains trailing slashes** — If `home` is `/` or ends with `/`, concatenating `home + targetPath.substring(1)` can introduce `//`. Path normalization (`.normalize()`) ensures clean path resolution regardless of trailing delimiters.
- **Navigating to a non-existent path starting with `~`** — If `~/ghost` does not exist, the shell must reject navigation and print `cd: <path>: No such file or directory` without altering `currentDir`.

---

## Tradeoffs

- **Manual Tilde Expansion in `cd` vs Global Word Expansion** — In full POSIX shells (like Bash or Zsh), tilde expansion is a general word expansion phase performed across all commands and arguments before execution (e.g., `cat ~/file.txt`). Handling it inside `cd` solves the immediate navigation requirement cleanly with minimal complexity, while preparing for a generalized expansion engine later.
- **`System.getenv("HOME")` vs `System.getProperty("user.home")`** — `System.getenv("HOME")` reflects the live POSIX environment variable passed by the parent process, allowing test harnesses or users to override the home directory temporarily (`HOME=/tmp/test ./shell`). `System.getProperty("user.home")` is JVM-cached and platform-dependent, serving as a reliable fallback.

## CLI / Protocol format

- **Navigate to home directory with `cd ~`**:
  ```
  $ pwd
  /usr/local/bin
  $ cd ~
  $ pwd
  /home/user
  $ 
  ```
- **Navigate to home directory without arguments**:
  ```
  $ pwd
  /usr/local/bin
  $ cd
  $ pwd
  /home/user
  $ 
  ```
- **Navigate to subdirectory inside home**:
  ```
  $ cd ~/documents
  $ pwd
  /home/user/documents
  $ 
  ```
- **Invalid path error message**:
  ```
  $ cd ~/nonexistent
  cd: /home/user/nonexistent: No such file or directory
  $ pwd
  /home/user
  $ 
  ```

## Java specifics — lookup, don't memorize

- `System.getenv("HOME")` — Retrieves the value of the specified environment variable from the operating system environment.
- `System.getProperty("user.home")` — Retrieves the Java system property for the user's home directory.
- `String.startsWith(String prefix)` — Tests if this string starts with the specified prefix.
- `String.substring(int beginIndex)` — Returns a substring that begins with the character at the specified index and extends to the end of this string.
- `Path.resolve(String other)` — Resolves the given path against this path; returns the target path directly if it is absolute.

# Stage 4: Implement the exit builtin

---

## In one line
Distinguish shell builtins from external executable commands and implement process termination with optional status code propagation using `exit [n]`.

## The problem it solved
In Stage 3, the REPL ran indefinitely until standard input hit EOF (e.g. stream termination). There was no mechanism for a user or script to command the shell session to terminate cleanly with an intentional exit status code. Implementing the `exit` builtin provides programmatic and interactive session termination and introduces the fundamental concept of shell builtins.

---

## Concepts (the transferable part)

- **[CONCEPT] Builtin Commands vs. External Executables** — In any UNIX-like shell, commands fall into two categories: external executables (separate binaries residing on `$PATH` executed via `fork`/`exec`) and builtins (routines executed directly inside the shell process memory). Commands that modify shell internal state (`cd`, `export`, `set`) or control shell lifecycle (`exit`, `exec`) *must* be builtins because child processes cannot alter parent process state or terminate the parent process.
- **[CONCEPT] Process Exit Status (Return Codes)** — When a process terminates, it returns an integer status code (0–255) to its parent process. Conventionally, `0` indicates successful execution (`EXIT_SUCCESS`), while any non-zero value (typically `1` to `255`) denotes an error or abnormal termination (`EXIT_FAILURE`).
- **[CONCEPT] Command Tokenization & Delimitation** — Shell input lines consist of a command name followed by zero or more arguments separated by whitespace. Tokenizing into words (`command` and `arguments[]`) is necessary before command dispatch so that argument parameters are not conflated with command identifiers.

## The Solution

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String[] parts = input.trim().split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            }

            System.out.println(input + ": command not found");
        }
    }
}
```

---

## What breaks it (failure modes)

- **Prefix matching instead of token matching** — Using `input.startsWith("exit")` mistakenly catches commands like `exit_code` or `exited`, treating them as `exit` instead of reporting `<command>: command not found`. Always match the command name token (`parts[0]`).
- **Crashing on non-numeric exit codes** — If a user runs `exit abc`, attempting an unchecked `Integer.parseInt` throws an unhandled `NumberFormatException`, causing an ungraceful JVM crash rather than handling invalid numeric arguments.
- **Hardcoding exit 0** — Failing to inspect following argument tokens (`parts[1]`) prevents scripts and users from returning non-zero failure exit codes (e.g. `exit 1`).
- **Ignoring empty inputs or extra whitespace** — Inputs with leading spaces (e.g., `"  exit"`) will fail string equality checks unless trimmed or properly tokenized.

---

## Tradeoffs

- `System.exit(exitCode)` vs `break` — `break` exits the loop and falls off `main()`, which Java always finishes with status code `0`. `System.exit(n)` allows the shell to return arbitrary status codes (`exit 0`, `exit 1`, `exit 127`) to the operating system or calling shell test harness.
- Whitespace regex split (`\\s+`) vs dedicated lexer — Splitting on `\\s+` is simple and sufficient for space-separated tokens in early stages, but will require replacement later once the shell must support single quotes, double quotes, and escaped spaces.

---

## CLI / Protocol format

- **Exit Command Syntax**: `exit [status_code]`
  - `exit`: Terminates shell with exit status `0`.
  - `exit 0`: Terminates shell with exit status `0`.
  - `exit <n>`: Terminates shell with exit status `n` (0–255).
- **Other Commands**:
  - `<command>: command not found`

---

## Java specifics — lookup, don't memorize

- `System.exit(int status)` — Terminates the currently running Java Virtual Machine. The argument serves as the status code; by convention, a nonzero status code indicates abnormal termination.
- `String.trim()` — Returns a string whose value is this string, with all leading and trailing space removed.
- `String.split("\\s+")` — Splits this string around matches of the regular expression for one or more consecutive whitespace characters.
- `Integer.parseInt(String s)` — Parses the string argument as a signed decimal integer. Throws `NumberFormatException` if the string cannot be parsed as an integer.

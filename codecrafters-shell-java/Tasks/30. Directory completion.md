# Stage 30: Directory completion

## In one line
Distinguishes directory entries from regular files during path autocompletion by appending a trailing slash `/` without a trailing space to directory matches, enabling progressive drill-down navigation through folder hierarchies.

## The problem it solved
Previously, all filename completions appended a trailing space (`match.substring(word.length()) + " "`) upon resolving a single match. When a user autocompleted a directory (e.g. `ls ant<TAB>`), the shell inserted `ant ` with a space, forcing the user to backspace, type `/`, and press `<TAB>` again to inspect its contents. Stage 30 fixes this by appending a trailing slash `/` with NO trailing space when completing directory names, allowing consecutive `<TAB>` presses to naturally descend into nested directory trees.

## Concepts (the transferable part)
- **[CONCEPT] Terminal State Machine for Hierarchical Inodes** — A filesystem entry is either a leaf node (regular file, device, FIFO) or an internal branch node (directory). Shell UX dictates that leaf completions terminate the argument token (signaled by a trailing space), whereas directory completions indicate an open path trajectory (signaled by `/` with no space) inviting further path continuation.
- **[CONCEPT] Inode Metadata Classification during Completion Gathering** — Autocompletion gathers candidate tokens from filesystem stat/metadata calls (`stat`, `lstat`, or `File.isDirectory()`). Annotating directory candidates with a canonical trailing slash `/` inside the candidate collection standardizes downstream substring delta computation and rendering.
- **[CONCEPT] Chained / Continuous Autocompletion** — When a directory match emits `path/`, the trailing slash naturally becomes the `lastSlash` on the very next `<TAB>` event without requiring manual user keystrokes. The completion subsystem instantly pivots to scanning inside the newly completed folder with `namePrefix = ""`.

## What breaks it (failure modes)
- **Appending Space to Directories** — Appending `" "` after directory autocompletion breaks continuous navigation: pressing `<TAB>` again treats the trailing space as token separation, causing the shell to parse an empty second argument rather than expanding nested children.
- **Missing Slash on Directory Candidate** — If the candidate string does not end in `/`, the shell cannot differentiate between a file named `folder` and a directory named `folder`. Subsequent tabs would fail to recognize the path boundary.
- **Empty Directory Tab Trap** — If the target directory contains zero files, `listFiles()` returns an empty array. The shell must gracefully detect zero matches, emit an audio bell (`\u0007`), flush, and avoid crashing or outputting corrupted text.
- **Inconsistent Prefix Length Slicing** — If the candidate contains `dirPart + name + "/"` (e.g. `ant/fox/`) and `word` is `ant/`, computing `match.substring(word.length())` cleanly yields `fox/`. If `dirPart` were omitted or mismatched, `substring` would slice at the wrong index or throw `IndexOutOfBoundsException`.

## Tradeoffs
- **Trailing Slash Inside Candidate String vs Flag/Wrapper Object** — Encoding directory semantics via a trailing `/` directly in `Set<String>` keeps candidate collections simple, uniform with `TreeSet<String>`, compatible with `longestCommonPrefix()`, and trivial to test via `match.endsWith("/")`. Creating a custom `CompletionItem` class adds object allocation overhead and boilerplate without practical benefit for a lightweight shell.
- **`File.isDirectory()` vs `Files.isDirectory(Path, LinkOption...)`** — `File.isDirectory()` uses existing `File` objects returned by `File.listFiles()`, avoiding redundant `Path` allocations for each child inode during directory scans.

## CLI / Protocol format
- Current directory structure:
  ```
  .
  └── ant/
      └── fox/
  ```
- User interaction flow:
  1. User types `ls ` (space after `ls`).
  2. User presses `<TAB>`:
     - Argument token: `word` = `""`
     - Matches: `["ant/"]` (single match, directory)
     - Suffix appended: `"ant/"` (no trailing space)
     - Prompt line: `$ ls ant/`
  3. User presses `<TAB>` again:
     - Argument token: `word` = `"ant/"`
     - Traversal directory: `targetDir` = `/app/ant`
     - Matches inside `ant/`: `["ant/fox/"]` (single match, directory)
     - Suffix appended: `"fox/"` (`"ant/fox/".substring(4)`)
     - Prompt line: `$ ls ant/fox/`

## Java specifics — lookup, don't memorize
- `File.isDirectory()` — Returns `true` if the file denoted by this abstract pathname exists and is a directory.
- `String.endsWith(String suffix)` — Tests if this string ends with the specified suffix.
- `StringBuilder.append(String str)` — Appends the characters of the string argument to this sequence.

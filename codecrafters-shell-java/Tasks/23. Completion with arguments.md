# Completion with arguments

## In one line
Extends the raw-mode tab completion mechanism to allow continuous editing and execution of command argument vectors after builtin command autocomplete.

---

## Self-test
1. When autocompleting `ech<TAB>`, why is appending a trailing space ` ` critical for downstream UX?
2. How does `readLineWithCompletion()` ensure arguments typed after a tab completion are preserved in the command buffer?
3. What prevents subprocess execution from breaking when terminal raw mode is used?

---

## Problem Solved
In Stage 22, tab autocompletion completed `ech` to `echo ` and `exi` to `exit `. In Stage 23, the requirement extends this flow to full command execution: once `echo ` is completed, the user continues typing arbitrary arguments (such as `hello` or `foo bar`), followed by `<ENTER>`. The shell must preserve both the autocompleted command prefix and all subsequent argument tokens, executing the composite command vector cleanly.

---

## Concepts
- **Continuous Buffer Accumulation**: The buffer `line` in `readLineWithCompletion()` retains all keystrokes, seamlessly appending completion text into `line` before accepting subsequent argument characters.
- **Terminal Control Sequences**: Printable characters continue echoing directly to standard output, while Enter (`\n` or `\r`) flushes the buffered line to the parser.
- **Parser Decoupling**: The argument parser (`parseArguments`) receives the final merged string (e.g. `echo foo bar`) and tokenizes arguments identically regardless of whether the command prefix was typed or autocompleted.

---

## The Solution
Our existing raw-mode implementation in `readLineWithCompletion()` already appends the completed word and trailing space directly to the `StringBuilder line`:
```java
if (ch == '\t') {
    String current = line.toString();
    List<String> candidates = List.of("echo", "exit");
    List<String> matches = candidates.stream()
            .filter(cmd -> cmd.startsWith(current))
            .toList();
    if (matches.size() == 1) {
        String match = matches.get(0);
        String completion = match.substring(current.length()) + " ";
        line.append(completion);
        System.out.print(completion);
        System.out.flush();
    } else {
        System.out.print("\u0007");
        System.out.flush();
    }
}
```
Subsequent keypresses (`h`, `e`, `l`, `l`, `o`) are read by `System.in.read()` and appended to `line`. When `<ENTER>` arrives, the entire line `echo hello` is returned and processed by the REPL loop.

---

## Failure Modes
- **Buffer Inconsistency**: If the tab completion logic prints `echo ` to the terminal but fails to append it to `StringBuilder line`, the executing command would only receive the subsequent arguments without the command prefix.
- **Terminal Echo Loss**: Failing to call `System.out.flush()` after printing the autocompletion leaves terminal output buffered, causing tester timeouts.

---

## Tradeoffs
- **In-Memory Line Buffer**: Appending completions directly into `StringBuilder` keeps the architecture lightweight without requiring complex cursor-movement tracking libraries for basic end-of-line tab completions.

---

## CLI / Protocol Format
```bash
$ ech<TAB>
$ echo 
$ echo hello<ENTER>
hello

$ ech<TAB>
$ echo 
$ echo foo bar<ENTER>
foo bar
```

---

## Java Specifics
- `StringBuilder.append()` seamlessly handles dynamic string extensions.
- `System.out.flush()` forces output bytes to the terminal descriptor immediately.

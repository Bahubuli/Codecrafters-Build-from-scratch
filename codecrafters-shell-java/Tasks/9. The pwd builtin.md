# Stage 9: The pwd builtin

## In one line

## The problem it solved
Users and automated scripts frequently need to query their current location in the filesystem hierarchy. While Unix systems often provide an external `/bin/pwd` utility, `pwd` must also be built into the shell itself to report the shell's own authoritative internal working directory state (crucial once `cd` mutates the directory). Furthermore, without maintaining an explicit working directory reference (`currentDir`), any future directory transitions (`cd`) would not propagate to spawned child processes. This stage establishes the `pwd` builtin and tracks the shell's active working directory.

---

## Concepts (the transferable part)

- **[CONCEPT] Current Working Directory (CWD)** — Every operating system process has an associated working directory in kernel process memory. All relative filesystem lookups (e.g. `./script`, `data/input.txt`, `../config`) are resolved relative to this directory.
- **[CONCEPT] Working Directory Inheritance & Isolation** — In POSIX, child processes created via `fork()` inherit a copy of the parent's working directory at spawn time. However, a child process cannot change its parent's working directory; changes made by a child affect only the child.
- **[CONCEPT] Builtin vs External `pwd`** — If `pwd` were executed only as an external utility (`/bin/pwd`), it would rely on inspecting its own inherited CWD or reading the `PWD` environment variable. Providing `pwd` as a shell builtin allows immediate in-memory reporting without process spawning overhead, and ensures exact synchronization with internal shell state.
- **[CONCEPT] Path Normalization** — Paths can contain redundant components such as `.` (current directory), `..` (parent directory), or duplicate slashes. Normalizing paths collapses these redundant segments into a canonical hierarchical representation without touching the filesystem.

## The Solution

```java
import java.io.File;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Arrays;
import java.util.Scanner;
import java.util.Set;
import java.util.regex.Pattern;

public class Main {
    private static final Set<String> BUILTINS = Set.of("echo", "exit", "type", "pwd");
    private static Path currentDir = Paths.get(System.getProperty("user.dir")).toAbsolutePath().normalize();

    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String trimmed = input.trim();
            if (trimmed.isEmpty()) {
                continue;
            }
            String[] parts = trimmed.split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            } else if (command.equals("echo")) {
                String output = String.join(" ", Arrays.copyOfRange(parts, 1, parts.length));
                System.out.println(output);
            } else if (command.equals("type")) {
                if (parts.length > 1) {
                    String target = parts[1];
                    if (BUILTINS.contains(target)) {
                        System.out.println(target + " is a shell builtin");
                    } else {
                        Path executable = findExecutable(target);
                        if (executable != null) {
                            System.out.println(target + " is " + executable);
                        } else {
                            System.out.println(target + ": not found");
                        }
                    }
                }
            } else if (command.equals("pwd")) {
                System.out.println(currentDir);
            } else {
                Path executable = findExecutable(command);
                if (executable != null) {
                    ProcessBuilder pb = new ProcessBuilder(parts);
                    pb.directory(currentDir.toFile());
                    pb.inheritIO();
                    Process process = pb.start();
                    process.waitFor();
                } else {
                    System.out.println(input + ": command not found");
                }
            }
        }
    }

    private static Path findExecutable(String command) {
        if (command.contains("/") || command.contains(File.separator)) {
            try {
                Path path = currentDir.resolve(command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
            return null;
        }
        return findExecutableInPath(command);
    }

    private static Path findExecutableInPath(String command) {
        String pathEnv = System.getenv("PATH");
        if (pathEnv == null || pathEnv.isEmpty()) {
            return null;
        }
        String[] dirs = pathEnv.split(Pattern.quote(File.pathSeparator));
        for (String dir : dirs) {
            if (dir.isEmpty()) {
                continue;
            }
            try {
                Path path = Paths.get(dir, command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
        }
        return null;
    }
}
```

## What breaks it (failure modes)

- **Missing `pwd` in `BUILTINS` set** — Forgetting to add `"pwd"` to the set causes `type pwd` to search `PATH` instead of recognizing it as a shell builtin, violating shell specification requirements.
- **Printing relative paths instead of absolute paths** — Calling `Paths.get("").toString()` without `.toAbsolutePath()` yields an empty string `""` or `"."`, violating the requirement that `pwd` must output the full absolute path from filesystem root.
- **Failing to configure `ProcessBuilder.directory()`** — If the shell does not explicitly set `pb.directory(currentDir.toFile())` on child processes, children execute under the initial JVM launch directory rather than reflecting any updated working directory.
- **Unnormalized paths with redundant trailing segments** — Storing raw paths containing `/./` or trailing slashes produces inconsistent output across environments. `normalize()` standardizes the path structure cleanly.

---

## Tradeoffs

- **Explicit `Path currentDir` state vs reading `System.getProperty("user.dir")` dynamically** — Java's `System.setProperty("user.dir", ...)` modifies JVM system properties but does not actually change the underlying OS process working directory via POSIX `chdir(2)`. Maintaining an explicit `Path currentDir` in the shell and explicitly passing it to `ProcessBuilder.directory()` cleanly decouples shell state from JVM limitations.
- **`Path.normalize()` vs `toRealPath()`** — `toRealPath()` resolves symbolic links against the live filesystem. Standard `pwd` in POSIX defaults to logical path reporting (`pwd -L`), preserving navigated symlink structures. Storing and normalizing the logical `Path` matches standard shell expectations without requiring filesystem I/O.

## Java specifics — lookup, don't memorize

- `System.getProperty("user.dir")` — Returns a string representing the current working directory of the JVM at startup time.
- `Paths.get(String first, String... more)` / `Path.of(...)` — Constructs a `Path` object from a path string or sequence of path components.
- `Path.toAbsolutePath()` — Resolves the path to an absolute path based on the default filesystem if it is not already absolute.
- `Path.normalize()` — Eliminates redundant name elements such as `.` and `..` from the path without accessing the filesystem.
- `ProcessBuilder.directory(File dir)` — Configures the working directory for subprocesses spawned by this `ProcessBuilder`.

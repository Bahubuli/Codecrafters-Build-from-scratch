# Stage 32: Multiple matches (#no5)

## In one line
Emits a bell on the first tab when multiple filesystem matches exist, and lists all matching files and directories (directories suffixed with `/`) separated by two spaces on the second consecutive tab before restoring the prompt.

---

## Self-test
- **Prompt**: What happens when a user types `stat <TAB><TAB>` and entries `bar.txt` and `foo/` exist in the directory?
- **Answer**: On the first `<TAB>`, the terminal bell (`\u0007`) rings. On the second consecutive `<TAB>`, the shell prints `bar.txt  foo/` on a new line, followed by a new prompt showing `$ stat ` with the cursor at the end.

---

## Problem Solved
When completing path arguments where multiple files or directories share a common prefix, the shell cannot resolve ambiguity without user interaction. Rather than guessing, the shell alerts the user via a bell on the first tab press and provides the full candidate list on the second tab press, allowing the user to inspect available entries and type more distinguishing characters.

---

## Key Concepts
1. **Consecutive Tab State Machine**:
   - `consecutiveTabs == 1`: Rings terminal bell (`\u0007`).
   - `consecutiveTabs >= 2`: Formats all candidates alphabetically separated by two spaces (`"  "`), prints them on a new line, and re-prints the prompt line (`$ <line>`).
2. **Directory Suffix Distinction**:
   - Matching directories retain their trailing `/` in the listing (e.g. `foo/`), while regular files do not have trailing characters (e.g. `bar.txt`).
3. **Prompt Preservation**:
   - The user's input buffer remains unmodified, letting them type the next character (e.g., typing `2` after `stat pig_` -> `stat pig_2`) and immediately tab-complete the resolved candidate.

---

## The Solution
In `readLineWithCompletion()`:
```java
} else if (matches.size() > 1) {
    String lcp = longestCommonPrefix(matches);
    if (lcp.length() > word.length()) {
        String completion = lcp.substring(word.length());
        line.append(completion);
        System.out.print(completion);
        System.out.flush();
        consecutiveTabs = 0;
    } else {
        consecutiveTabs++;
        if (consecutiveTabs == 1) {
            System.out.print("\u0007");
            System.out.flush();
        } else if (consecutiveTabs >= 2) {
            System.out.print("\n");
            System.out.print(String.join("  ", matches));
            System.out.print("\n");
            System.out.print("$ " + current);
            System.out.flush();
            consecutiveTabs = 0;
        }
    }
}
```

---

## Failure Modes & Bugs Prevented
1. **Losing Directory Slash Indicator in Multi-Match List**:
   - `getFileCompletions()` appends `/` directly to candidate names when `file.isDirectory()`, guaranteeing directories display as `foo/` while regular files remain `bar.txt`.
2. **Buffer Corruption Across Redisplay**:
   - The prompt re-display emits `"$ " + current` without altering `StringBuilder line`, ensuring typing continues at the exact same buffer offset.
3. **Sticky Consecutive Tab State**:
   - Pressing any character other than `<TAB>` resets `consecutiveTabs = 0`, ensuring future tab presses start cleanly from the first tab bell.

---

## Tradeoffs
- Separating entries with two spaces vs columnar grid formatting:
  - Two spaces (`"  "`) matches POSIX shell specifications and satisfies CodeCrafters test runner output parsing without needing terminal width calculation via `TIOCGWINSZ`.

---

## CLI / Protocol Format
```text
$ stat pig_<TAB>
# [stdout: \u0007]
$ stat pig_<TAB>
pig_1.txt  pig_2/
$ stat pig_
```

---

## Java Specifics
- `String.join("  ", matches)` joins candidate strings from a `TreeSet` (guaranteed natural alphabetical order) with standard double-space padding.
- `System.out.print("\n" + String.join("  ", matches) + "\n$ " + current)` writes out the candidate list and prompt cleanly before `System.out.flush()`.

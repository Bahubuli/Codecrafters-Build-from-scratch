# Stage 33: Partial completions (#jp8)

## In one line
Autocompletes argument and filename inputs up to the Longest Common Prefix (LCP) when multiple matches share a prefix longer than the current input, omitting any trailing character until exactly one match remains.

---

## Self-test
- **Prompt**: Suppose the directory has `xyz_foo/`, `xyz_foo_bar/`, and `xyz_foo_bar_baz/`. What does `$ ls xyz_<TAB>` complete to? Does it have a trailing `/`?
- **Answer**: It completes to `$ ls xyz_foo`. It does NOT have a trailing `/` because multiple matches remain. Trailing slashes or spaces only append when a completion resolves to exactly 1 candidate.

---

## Problem Solved
When completing file/directory names with multiple ambiguous candidates that nonetheless share common initial characters beyond what the user typed (e.g., `xyz_dog/` and `xyz_dog_cow/` matching `xyz_`), completing up to that shared prefix saves repetitive keystrokes without forcing the user to type common substrings manually.

---

## Key Concepts
1. **Longest Common Prefix (LCP)**:
   - Evaluated over all candidates in `matches`.
   - Trailing indicators (`/` or spaces) are stripped or kept consistent during LCP calculation so the shared path prefix is accurate.
2. **Intermediate vs Final Completion**:
   - Multiple matches (`matches.size() > 1`): If `lcp.length() > word.length()`, autocomplete the delta `lcp.substring(word.length())` without trailing character and reset consecutive tab counter.
   - Single match (`matches.size() == 1`): Complete remaining name and append `/` (if directory) or space (if file).
3. **No Common Extension (Divergence Point)**:
   - If `lcp.length() <= word.length()`, ring bell `\u0007` on 1st tab and print candidates on 2nd consecutive tab.

---

## The Solution
In `readLineWithCompletion()`:
```java
} else if (matches.size() > 1) {
    String lcp = longestCommonPrefix(matches);
    if (lcp.length() > word.length()) {
        String completion = lcp.substring(word.length());
        line.append(completion);
        System.out.print(completion);
        System.out.flush();
        consecutiveTabs = 0;
    } else {
        consecutiveTabs++;
        if (consecutiveTabs == 1) {
            System.out.print("\u0007");
            System.out.flush();
        } else if (consecutiveTabs >= 2) {
            System.out.print("\n");
            System.out.print(String.join("  ", matches));
            System.out.print("\n");
            System.out.print("$ " + current);
            System.out.flush();
            consecutiveTabs = 0;
        }
    }
}
```

---

## Failure Modes & Bugs Prevented
1. **Premature Trailing Slashes / Spaces**:
   - Appending a trailing space or slash when completing to an LCP that happens to be an exact name of one candidate (e.g. `foo` and `foobar/`) would prevent further completion of `foobar/`. Restricting trailing characters to `matches.size() == 1` prevents this.
2. **Double Tab Interference**:
   - Resetting `consecutiveTabs = 0` whenever an LCP completion occurs guarantees that typing additional narrowing characters allows the next tab to evaluate a fresh single match or deeper LCP cleanly.

---

## Tradeoffs
- Character-by-character scanning vs trie-based prefix lookup:
  - Linear scan across sorted `TreeSet` candidates using `first.charAt(i) == last.charAt(i)` executes in `O(min(len))` time with zero memory overhead, which is optimal for candidate sets within a single directory.

---

## CLI / Protocol Format
```text
$ ls xyz_<TAB>
$ ls xyz_foo
# User types "_"
$ ls xyz_foo_<TAB>
$ ls xyz_foo_bar
# User types "_"
$ ls xyz_foo_bar_<TAB>
$ ls xyz_foo_bar_baz/
```

---

## Java Specifics
- `longestCommonPrefix(Set<String> strings)` compares the lexicographically first and last elements of the sorted set, since any prefix common to both extreme entries is guaranteed common to all intermediate entries.

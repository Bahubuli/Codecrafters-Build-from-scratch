# Stage 52: Background Jobs - Reap before the next prompt

## In one line
Inspect background jobs right before issuing the `$ ` prompt, print status notifications for any completed jobs (`[id]+  Done  command`), and reap them from the active jobs table before displaying the prompt.

---

## Self-test
Can you answer these questions from memory?
1. When a background job terminates while a foreground command or user action is taking place, when is its completion notification displayed if the user doesn't call `jobs`?
2. Does pre-prompt reaping print anything for still-running background jobs?
3. How many times is a completed job reported as `Done` across prompt reaps and `jobs` commands?
4. What happens to the job table after a finished job is announced before the prompt?

---

## Problem Solved
Real Unix shells (like Bash and Zsh) asynchronously monitor child processes or poll their statuses before printing the primary prompt (`$ `). When a background process terminates while waiting for or executing user commands, the shell notifies the user about the reaped job on the line immediately preceding the prompt, rather than waiting for an explicit `jobs` invocation.

---

## Concepts
- **Pre-Prompt Reaping**: Before each `$ ` prompt is printed, scan all background jobs. For any job where `!process.isAlive()`, emit the completion line to `System.out` and purge it from the tracked list.
- **Silent Running Jobs**: Unlike the `jobs` builtin, pre-prompt reaping only outputs information about finished jobs. Running jobs remain silent and unprinted.
- **Single Notification Guarantee**: Because completed jobs are removed from `backgroundJobs` as soon as they are reported before a prompt, subsequent prompts or calls to `jobs` will not duplicate the notification.

---

## The Solution
In `codecrafters-shell-java/src/main/java/Main.java`:
```java
// Inside main REPL loop:
while (true) {
    reapCompletedJobs(System.out);
    System.out.print("$ ");
    System.out.flush();
    String input = readLineWithCompletion();
    ...
}

// Helper method:
private static void reapCompletedJobs(PrintStream out) {
    int n = backgroundJobs.size();
    List<Job> remainingJobs = new ArrayList<>();
    for (int j = 0; j < n; j++) {
        Job job = backgroundJobs.get(j);
        String marker = " ";
        if (j == n - 1) {
            marker = "+";
        } else if (j == n - 2) {
            marker = "-";
        }
        boolean isAlive = job.process != null && job.process.isAlive();
        if (!isAlive) {
            out.printf("[%d]%s  %-24s%s%n", job.id, marker, "Done", job.command);
        } else {
            remainingJobs.add(job);
        }
    }
    backgroundJobs.clear();
    backgroundJobs.addAll(remainingJobs);
}
```

---

## Failure Modes
- **Printing running jobs**: Leaking `Running` lines before the prompt breaks REPL UX and fails tests.
- **Outputting after prompt**: If notification prints after `$ ` without re-printing the prompt, the input line becomes garbled. Notification MUST occur *before* `$ `.
- **Double reaping**: If a job was already reaped before the prompt, it must not appear as `Done` when the user enters `jobs`. Removing it immediately upon notification prevents this.

---

## Tradeoffs
- Checking `isAlive()` sequentially across background jobs at the start of each prompt loop is fast ($O(N)$ with typically small $N$) and does not require complex signal handling or background watchdog threads.

---

## CLI / Protocol format
```bash
$ sleep 500 &
[1] 1481
$ cat /tmp/orange &
[2] 1482
$ jobs
[1]-  Running                 sleep 500 &
[2]+  Running                 cat /tmp/orange &
$ # /tmp/orange receives data and cat finishes
$ echo pineapple
pineapple
[2]+  Done                    cat /tmp/orange
$ jobs
[1]+  Running                 sleep 500 &
$ 
```

---

## Java specifics
- `Process.isAlive()` checks if the underlying OS process has terminated.
- `out.printf("[%d]%s  %-24s%s%n", ...)` formats width-aligned job notices identically across both Windows and Unix terminals using `%n` for system newline.

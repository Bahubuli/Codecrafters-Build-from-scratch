# Stage 56: Multi-command pipelines

## In one line
Chains an arbitrary number ($N \ge 3$) of concurrent commands together by plumbing intermediate stdout-to-stdin anonymous pipes across all pipeline stages.

## Self-test (cover the answers below and answer these first)
- Why does `ProcessBuilder.startPipeline(List<ProcessBuilder>)` scale seamlessly to $N$ external commands without requiring intermediate disk files or custom thread pumps?
- How are file descriptor write ends closed in parent and intermediate stages to ensure that subsequent consumers encounter `EOF` rather than deadlocking?
- In a pipeline like `cat file | head -n 3 | wc`, which command dictates the ultimate pipeline termination and standard output presentation?

## The problem it solved
Previous stages supported dual-command pipelines ($N=2$) and pipelines involving built-ins. Real-world shell usage frequently combines three or more stages (e.g. `cat file | head -n 3 | wc`, `ls -la | tail -n 5 | head -n 3 | grep "file"`). The pipeline orchestrator must generalize to an arbitrary sequence of $N$ commands, wiring standard streams sequentially from stage $0$ through stage $N-1$.

## Concepts (the transferable part)
- **Pipeline Topologies ($N$-stage chaining)** — A multi-stage pipeline forms a linear directed acyclic graph:
  $$\text{Stage}_0 \xrightarrow{\text{pipe}_0} \text{Stage}_1 \xrightarrow{\text{pipe}_1} \cdots \xrightarrow{\text{pipe}_{N-2}} \text{Stage}_{N-1}$$
  - $\text{Stage}_0$ reads from parent standard input (unless redirected).
  - Each intermediate $\text{Stage}_k$ ($0 < k < N-1$) reads from $\text{pipe}_{k-1}$ and writes to $\text{pipe}_k$.
  - Terminal $\text{Stage}_{N-1}$ writes to parent standard output (or redirected destination file).
- **Subprocess Descriptor Inheritance** — When calling `ProcessBuilder.startPipeline(builders)`:
  - Java configures anonymous pipes between consecutive process builders where `redirectInput()` and `redirectOutput()` are kept at `Redirect.PIPE`.
  - The runtime closes internal pipe descriptors in the parent shell process so only the child processes maintain references to the pipe endpoints.

## What breaks it (failure modes)
- **Premature Pipe Leakage** — If any intermediate write descriptor is left open by the host shell process, reading stages will never see `EOF` and will hang indefinitely.
- **Process Termination Order** — In POSIX shells, intermediate consumers like `head` may exit before upstream producers like `cat` or `ls`. The shell supervisor must wait for the consumer, then ensure all active upstream processes in the pipeline group are politely reaped (`destroy()` followed by `waitFor()`).
- **Raw Mode Interference** — Interactive raw terminal mode can interfere with newline translation in piped child stdout. Raw mode must be suspended while foreground pipelines run and restored upon pipeline completion.

## Tradeoffs
- **Kernel-Level Pipe vs Userland Thread Pumps** — `ProcessBuilder.startPipeline()` creates native OS pipes via kernel `pipe()` / `dup2()` system calls, eliminating user-space memory buffers, context switches, and Java garbage collection overhead.

## CLI / Protocol format
```bash
$ cat /tmp/owl/file-12 | head -n 3 | wc
       3       3      25

$ ls /tmp/cow | tail -n 5 | head -n 3 | grep "f-81"
f-81
$
```

## Java specifics — lookup, don't memorize
- `ProcessBuilder.startPipeline(List<ProcessBuilder> builders)` — Launches a list of processes chained in a pipeline. The standard output of each process is sent to the standard input of the next.
- `builder.redirectInput(Redirect.INHERIT)` — Configures the first process in the pipeline to inherit standard input.
- `builder.redirectOutput(Redirect.INHERIT)` — Configures the final process in the pipeline to inherit standard output.
- `process.destroy()` — Sends a termination signal (`SIGTERM`) to active processes.

## Rebuild checklist
- [ ] Tokenize the command line and split on unquoted, unescaped `|` operators into $N$ distinct command specifications.
- [ ] For pure external multi-command pipelines, instantiate $N$ `ProcessBuilder` instances.
- [ ] Set `Redirect.INHERIT` (or redirection files) for the first stage input and last stage output.
- [ ] Leave all intermediate inputs/outputs configured as `Redirect.PIPE`.
- [ ] Execute `ProcessBuilder.startPipeline(builders)`.
- [ ] Await completion of the terminal pipeline process (`last.waitFor()`).
- [ ] Clean up any remaining alive processes (`p.destroy()` and `p.waitFor()`).

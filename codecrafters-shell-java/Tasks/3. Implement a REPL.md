# Stage 3: Implement a REPL

---

## In one line
Convert single-shot command execution into a continuous Read-Eval-Print Loop (REPL) that accepts multiple commands until EOF or termination.

---

## Self-test (cover the answers below and answer these first)
- What are the four discrete phases of a REPL, and how does the shell transition between them?
- How should a shell handle an End-Of-File (EOF / Ctrl+D) condition on standard input? What happens if you call `scanner.nextLine()` without checking?
- Why must the prompt (`$ `) be displayed before waiting for input on every iteration of the loop?

---

## The problem it solved
In Stage 2, the shell processed a single command and terminated immediately, forcing the user (or caller) to restart the process for every interaction. An interactive shell must remain alive and responsive across multiple command invocations. Wrapping the read-eval-print cycle in a persistent loop transforms the program from a one-off utility into an interactive command-line environment.

---

## Concepts (the transferable part)

- **[CONCEPT] Read-Eval-Print Loop (REPL)** — An architectural pattern for interactive computing where the program repeatedly prompts for input (Read), parses and executes the command (Eval), outputs results or errors (Print), and repeats (Loop) until an exit signal is received.
- **[CONCEPT] Stream Termination & EOF** — In stream-oriented I/O, `stdin` is not infinite; it can be closed by the user (e.g., `Ctrl+D`) or piped input stream completion. A well-behaved process must detect EOF and exit gracefully without raising uncaught exceptions.
- **[CONCEPT] Interactive State & Lifecycle** — Unlike batch or CLI filters that run once to completion, a shell maintains an interactive session lifecycle where process state, working directory, and environment persist across command cycles.

## The Solution

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            System.out.println(input + ": command not found");
        }
    }
}
```

---

## What breaks it (failure modes)

- **Unchecked `nextLine()` on EOF** — Calling `scanner.nextLine()` when the stream has terminated causes a `NoSuchElementException`. Always verify `scanner.hasNextLine()` before attempting to read.
- **Printing the prompt after input read** — Displaying `$ ` after waiting for input stalls interactive users because there is no visual cue that the shell is ready for input.
- **Buffered output hiding the prompt** — In some runtime environments without auto-flushing, `System.out.print` without a trailing newline may buffer until filled or flushed. While standard terminals flush on read from `System.in`, explicit flushing (`System.out.flush()`) prevents hidden prompt bugs in non-standard streams.
- **Infinite busy-looping** — If the input check does not block on `stdin` or fails to break on EOF, the loop spins at 100% CPU. `scanner.hasNextLine()` or `scanner.nextLine()` properly blocks waiting for user input.

---

## Tradeoffs

- `while (true)` with explicit EOF check vs `while (scanner.hasNextLine())` — Placing `System.out.print("$ ")` inside a `while (true)` before checking `scanner.hasNextLine()` ensures the prompt is printed prior to blocking for input on every cycle, and properly displays the prompt for subsequent interactions.
- Reusing a single `Scanner` vs creating a `Scanner` per iteration — Instantiating `Scanner(System.in)` outside the loop reuses the stream buffer and prevents closing or resetting underlying standard input stream descriptors.

---

## CLI / Protocol format

- **Prompt**: `$ ` (printed without trailing newline at each cycle)
- **Input Cycle**:
  1. Print `$ `
  2. Read line: `user_command\n`
  3. Output: `user_command: command not found\n`
  4. Repeat steps 1-3 until `EOF` or process exit.

---

## Java specifics — lookup, don't memorize

- `scanner.hasNextLine()` — Returns `true` if there is another line in the input of this scanner; blocks if waiting on standard input, returns `false` on stream closure (EOF).
- `while (true) { ... break; }` — Infinite loop structure broken explicitly when loop termination conditions (such as stream exhaustion) are met.

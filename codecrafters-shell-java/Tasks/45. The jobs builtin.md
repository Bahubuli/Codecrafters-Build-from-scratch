# Stage 45: Background Jobs - The jobs builtin

## In one line
Register `jobs` as a shell builtin that produces empty output when no background jobs exist.

## Problem Solved
Unix shells support running commands asynchronously in the background using `&`. The `jobs` builtin lists active and completed background tasks. In this introductory stage of the Background Jobs extension, we register `jobs` as a shell builtin so that `type jobs` recognizes it, and executing `jobs` produces no output when there are no jobs.

---

## Concepts
- **Shell Builtin Registration**: Adding `"jobs"` to `BUILTINS = Set.of(..., "jobs")`.
- **Command Dispatch**: When `command.equals("jobs")`, the shell intercepts the command rather than searching `$PATH`. Since no jobs exist yet, it returns immediately without writing anything to `stdout` or `stderr`.

## Failure Modes
- **Missing from BUILTINS**: Forgetting to add `"jobs"` to `BUILTINS` makes `type jobs` report `jobs: not found` and causes the shell to attempt searching `$PATH`.
- **Spurious Output**: Printing headers or newlines when no jobs exist fails tests.

---

## Tradeoffs
- Registering a minimal no-op builtin satisfies Stage 45 while preparing the architecture for tracking background `Process` handles in future stages.

## Java specifics

- The `else if (command.equals("jobs"))` branch executes inside the builtin dispatch block without writing to `System.out`.

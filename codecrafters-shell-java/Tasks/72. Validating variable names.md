# Stage 72: Validating variable names

## In one line
Validate that shell variable names declared with `declare NAME=VALUE` are valid identifiers (`^[a-zA-Z_][a-zA-Z0-9_]*$`), reporting an error to stderr and rejecting invalid definitions.

## Self-test (cover the answers below and answer these first)
- What characters are allowed in a valid shell variable identifier?
- Can a variable identifier start with a digit?
- What exact format does the error message follow when an invalid identifier is provided to `declare`?
- To which stream (stdout or stderr) does the error message go, and what exit code should be returned?

## The problem it solved
Shell variable names must adhere to lexical identifier rules so they can be parsed unambiguously during parameter expansions (`$NAME`) and avoid conflict with special positional parameters (`$1`, `$2`, etc.) or arithmetic evaluation. When an invalid identifier is passed to `declare`, the shell must emit a diagnostic error (`declare: `foo=bar': not a valid identifier`) to standard error and decline to update the variable store.

## Concepts (the transferable part)
- **Identifier Grammar** — Valid identifiers must start with an ASCII letter (`a-z`, `A-Z`) or underscore (`_`), followed by any number of ASCII letters, digits (`0-9`), or underscores (`_`).
- **Error Formatting with Quotation Markers** — Classical Unix error messages quote problematic tokens with a backtick opening and single quote closing: `` `token': not a valid identifier ``.
- **Diagnostic Stream Separation** — Parsing errors and warnings must be routed to `stderr` (`System.err` / `err.println(...)`), maintaining clean pipeline behavior on `stdout`.

## What breaks it (failure modes)
- Validating the entire argument instead of just the name — In `declare 23=x`, the identifier being validated is `23` (before the `=`), but the quoted token in the error message is the full argument `` `23=x' ``.
- Accepting leading digits — Digits in identifier names are only permitted starting from index 1.
- Writing error messages to stdout — The tester specifically checks stderr for diagnostic reporting.

## Tradeoffs
- Character loops vs Regular Expressions — Iterating characters via ASCII boundary comparisons (`>= 'a' && <= 'z'`) avoids regex compilation overhead and provides optimal performance inside REPL loops.

## CLI / Protocol format
```bash
# Valid variable declarations
$ declare foo=bar
$ declare _FOO=BAR

# Invalid variable declarations
$ declare 67=x
declare: `67=x': not a valid identifier
$ declare 23=x
declare: `23=x': not a valid identifier
```

## Java specifics — lookup, don't memorize
- Checking identifier validity:
  ```java
  private static boolean isValidIdentifier(String name) {
      if (name == null || name.isEmpty()) return false;
      char first = name.charAt(0);
      if (!((first >= 'a' && first <= 'z') || (first >= 'A' && first <= 'Z') || first == '_')) {
          return false;
      }
      for (int i = 1; i < name.length(); i++) {
          char c = name.charAt(i);
          if (!((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || (c >= '0' && c <= '9') || c == '_')) {
              return false;
          }
      }
      return true;
  }
  ```
- Rejecting invalid assignments in `declare`:
  ```java
  int eqIndex = arg.indexOf('=');
  String name = eqIndex != -1 ? arg.substring(0, eqIndex) : arg;
  String value = eqIndex != -1 ? arg.substring(eqIndex + 1) : null;
  if (!isValidIdentifier(name)) {
      err.println("declare: `" + arg + "': not a valid identifier");
      exitCode = 1;
      continue;
  }
  if (eqIndex != -1 && !inSubshell) {
      SHELL_VARIABLES.put(name, value);
  }
  ```

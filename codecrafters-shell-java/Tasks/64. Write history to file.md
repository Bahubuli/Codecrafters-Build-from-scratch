# Stage 64: Write history to file

## In one line
Implement the `history -w <file>` command option to write the current in-memory shell history out to a persistent file on disk.

## Self-test (cover the answers below and answer these first)
- Does `history -w <path>` print anything to standard output or does it execute silently?
- Does the invocation `history -w <path>` itself get recorded in the shell's command history?
- If the destination file already exists, does history -w append to it or overwrite/truncate it?

## The problem it solved
Shell sessions lose their context once exited unless command history can be preserved and restored. Before this stage, `history` was strictly ephemeral and reset on each run; adding `-w` enables loading a persisted command history file back into memory.

## Concepts (the transferable part)
- **History File Serialization** — Storing command history line-by-line in plain text files and serializing it directly from the shell's runtime history data structure to disk.
- **Silent Utility Operation** — In standard POSIX shells, history manipulation options (`history -w`, `history -w`, `history -a`) operate silently without printing entries or status messages unless an error occurs.
- **Truncating Write Semantics** — Appending entries read from the file preserves relative chronological order while updating the global history index for arrow-key navigation and subsequent `history` listings.

## What breaks it (failure modes)
- Printing the history list when `-w` is passed — `history` with no arguments prints the history table, but `history -w <file>` must only write the file silently without printing anything.
- Failing to resolve relative paths — If the given file path is relative (e.g. `./history.txt` or `dir/history`), it must be resolved against the shell's current working directory (`currentDir`).
- Creating missing parent directories — If destination directories do not exist, ensure parent directories are created cleanly before writing.

## Tradeoffs
- Truncating (-w) vs Appending (-a) — `history -w` in Bash appends lines from the file to the current session history, allowing users to aggregate history files across multiple environments or sessions without wiping existing session commands.

## CLI / Protocol format
- Syntax: `history -w <path_to_history_file>`
- Output: None (silent operation)
- Subsequent `history` command reflects both prior session commands, the `history -w` invocation itself, and all loaded file entries.

## Java specifics — lookup, don't memorize
- `Files.writeString(path, content, StandardOpenOption.CREATE, StandardOpenOption.TRUNCATE_EXISTING, StandardOpenOption.WRITE)` — Reads all lines from a file into a `List<String>` using UTF-8 charset.
- `currentDir.resolve(filePath).normalize()` — Resolves a path string relative to the active working directory.

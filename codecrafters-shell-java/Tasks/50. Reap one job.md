# Stage 50: Background Jobs - Reap one job

## In one line
Extend `jobs` builtin to inspect background process termination (`process.isAlive()`), report terminated processes as `Done` without trailing `&`, and remove terminated jobs from the active job table.

---

## Self-test
Can you answer these questions from memory?
1. How does `jobs` display a completed background job when queried for the first time after exit?
2. Does a `Done` job entry print a trailing ampersand (`&`)?
3. What happens to the completed job entry on subsequent calls to `jobs`?
4. How do you non-blockingly check if a child process has finished running in Java?

---

## Problem Solved
When background jobs finish executing, shells report them as `Done` upon the next job table inspection and reap them so zombie processes do not linger in the process table. In this stage, `jobs` checks `process.isAlive()`, formats the job as `Running ... &` if alive, or `Done ...` (no `&`) if finished, and prunes exited jobs from `backgroundJobs`.

---

## Concepts
- **Reaping**: Calling process status queries (such as `isAlive()` or `waitpid(..., WNOHANG)`) and discarding finished child jobs from shell tracking.
- **Output Difference**:
  - Running: `[1]+  Running                 sleep 1 &`
  - Done: `[1]+  Done                    sleep 1` (no trailing `&`)
- **Lifecycle**: Exited jobs are displayed as `Done` exactly once, then dropped from subsequent queries.

---

## The Solution
In `codecrafters-shell-java/src/main/java/Main.java`:
```java
} else if (command.equals("jobs")) {
    int n = backgroundJobs.size();
    List<Job> remainingJobs = new ArrayList<>();
    for (int j = 0; j < n; j++) {
        Job job = backgroundJobs.get(j);
        String marker = " ";
        if (j == n - 1) {
            marker = "+";
        } else if (j == n - 2) {
            marker = "-";
        }
        boolean isAlive = job.process != null && job.process.isAlive();
        String status = isAlive ? "Running" : "Done";
        String trailing = isAlive ? " &" : "";
        out.printf("[%d]%s  %-24s%s%s\n", job.id, marker, status, job.command, trailing);
        if (isAlive) {
            remainingJobs.add(job);
        }
    }
    backgroundJobs.clear();
    backgroundJobs.addAll(remainingJobs);
}
```

---

## Failure Modes
- **Printing trailing `&` for `Done`**: CodeCrafters tester explicitly asserts that `Done` entries do not end in `&`.
- **Reassigning final List**: In Java, attempting `backgroundJobs = remainingJobs` triggers compilation failure if `backgroundJobs` is declared `final`. Using `clear()` and `addAll()` cleanly updates in place.
- **Premature removal**: The finished job must be shown once with `Done` before removal, not silently dropped beforehand.

---

## Tradeoffs
- Filtering into `remainingJobs` during the iteration loop provides O(N) single-pass display and table update without concurrent modification exceptions.

---

## CLI / Protocol format
```bash
$ cat /tmp/grape-22 &
[1] 108
$ jobs
[1]+  Running                 cat /tmp/grape-22 &
$ # process terminates
$ jobs
[1]+  Done                    cat /tmp/grape-22
$ jobs
# (empty)
```

---

## Java specifics
- `java.lang.Process.isAlive()` returns `false` non-blockingly when the native OS process has exited.
- Updating `static final List<Job> backgroundJobs` via `clear()` and `addAll()` mutates the underlying list without reassigning the reference.

---

## Rebuild checklist
1. When handling `jobs`, iterate over active jobs.
2. Check `job.process.isAlive()`.
3. Set `status = isAlive ? "Running" : "Done"` and `trailing = isAlive ? " &" : ""`.
4. Print formatted job row.
5. Filter surviving alive jobs and clear/addAll into `backgroundJobs`.

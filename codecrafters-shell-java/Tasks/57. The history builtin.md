# Stage 57: The history builtin

## In one line
Implement shell command history tracking and the `history` builtin command to display numbered past commands.

## Self-test (cover the answers below and answer these first)
- Why must `history` be implemented as a shell builtin rather than an external binary?
- At what point in the shell execution loop should an input line be appended to history?
- How is the history list formatted when displayed by the builtin?

## The problem it solved
Before this stage, users had no way of inspecting or listing previously executed commands across the current shell session. By introducing the `history` builtin, the shell maintains an ordered record of user inputs and formats them on demand.

## Concepts (the transferable part)
- **Session Command History** — An in-memory append-only sequence of user command strings recorded as each input line is submitted.
- **Builtin vs External State Inspection** — External binaries run in separate child processes and cannot inspect the parent shell's internal memory; history inspection inherently requires builtin execution inside the shell process.

## What breaks it (failure modes)
- Empty or whitespace-only lines — Appending empty or blank lines can clutter history; in standard shells only meaningful commands (or raw user submissions) are recorded.
- In-flight concurrent access — If background jobs or subshells execute `history`, accessing the history list without synchronization could cause concurrent modification exceptions.
- 1-based indexing formatting — Format mismatch where indices are not right-aligned or start from 0 instead of 1 breaks POSIX/bash compatibility.

## Tradeoffs
- In-memory `ArrayList` vs persistent history file (`.bash_history`) — An in-memory list is simple and fast for session lifecycle; file persistence requires file I/O, locking, and truncation policies (handled in later stages).

## CLI / Protocol format
- Command: `history`
- Identification: `type history` outputs `history is a shell builtin`
- Display format: `%5d  %s\n` (1-based integer right-aligned in 5 characters, followed by two spaces and the command text).

## Java specifics — lookup, don't memorize
- `List<String> commandHistory` — Append-only collection storing command lines.
- `out.printf("%5d  %s\n", i + 1, commandHistory.get(i))` — Formatted string printing with right-aligned index padding.

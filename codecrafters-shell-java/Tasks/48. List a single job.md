# Stage 48: Background Jobs - List a single job

## In one line
Implement background job tracking and the `jobs` builtin to display running background processes with status padded to 24 characters and the current job marker.

---

3. What information must be stored for each background job?
4. When should a job entry be added to the job table?

---

## Problem Solved
Previously, running background jobs via trailing `&` spawned the asynchronous process and returned a prompt, but the `jobs` builtin was a no-op stub. In this stage, we implement job tracking to record background processes (`id`, `pid`, `command`, `process`) and report them when the user runs `jobs`.

---

## Concepts
- **Job Table**: An internal data structure (e.g. `List<Job>`) maintaining the metadata of all background processes started by the shell.
- **Job Identifiers**: Sequential numbers (starting at 1) assigned to background jobs as they are initiated.
- **Current Job Marker**: The `+` symbol denotes the current (most recently invoked or foreground-eligible) job in job control specifications.
- **Fixed-width Formatting**: Using format specifiers like `%-24s` to ensure consistent column alignment across job listings.

---

## The Solution
In `codecrafters-shell-java/src/main/java/Main.java`:
```java
static class Job {
    int id;
    long pid;
    String command;
    Process process;

    Job(int id, long pid, String command, Process process) {
        this.id = id;
        this.pid = pid;
        this.command = command;
        this.process = process;
    }
}

private static final List<Job> backgroundJobs = new ArrayList<>();

// When launching background process:
Process process = pb.start();
int jobId = nextJobId.getAndIncrement();
long pid = process.pid();
backgroundJobs.add(new Job(jobId, pid, String.join(" ", cmdArgs), process));
System.out.println("[" + jobId + "] " + pid);
System.out.flush();

// In jobs builtin:
} else if (command.equals("jobs")) {
    for (int j = 0; j < backgroundJobs.size(); j++) {
        Job job = backgroundJobs.get(j);
        String marker = "+";
        out.printf("[%d]%s  %-24s%s &\n", job.id, marker, "Running", job.command);
    }
}
```

---

## Failure Modes
- **Incorrect padding**: Failing to pad "Running" to 24 characters (`%-24s`) causes mismatch against standard shell formats expected by the tester.
- **Missing or wrong marker**: Not providing `+` immediately following `[<id>]`.
- **Misaligned spaces**: Standard format requires 2 spaces after the marker (`[%d]%s  `).

---

## Tradeoffs
- Storing commands as `String.join(" ", cmdArgs)` produces clean representations for execution tracking.
- Retaining process references allows future stages to query `.isAlive()` or `.exitValue()`.

---

## CLI / Protocol format
```bash
$ sleep 10 &
[1] 84470
$ jobs
[1]+  Running                 sleep 10 &
```

---

## Java specifics
- `String.format("%-24s", "Running")` left-aligns and pads the status with trailing spaces to 24 chars total length.
- `PrintStream.printf(...)` directly writes formatted output to standard output or the redirected output stream.

---

## Rebuild checklist
1. Define a `Job` record/class holding `id`, `pid`, `command`, and `process`.
2. When launching background job with `isBackground = true`, add the new `Job` to `backgroundJobs`.
3. In `jobs` builtin handler, iterate `backgroundJobs` and print each job using format `[%d]%s  %-24s%s &\n`.

# Stage 35: Register complete builtin (#ne7)

## In one line
Registers `complete` as a shell builtin recognized by `type` and reserved for programmable argument completion logic.

---

## Self-test
- **Prompt**: What should `type complete` output, and what role does `complete` play in Unix shells?
- **Answer**: It outputs `complete is a shell builtin`. In shells like Bash, `complete` registers programmable completion handlers (e.g. scripts or functions) for specified commands (such as `complete -C /path/to/script git`).

---

## Problem Solved
To support programmable completion for commands like Git or custom CLIs, the shell must provide the `complete` command as a recognized builtin instead of searching the filesystem `PATH` or reporting "command not found".

---

## Key Concepts
1. **Builtin Registration**:
   - Inclusion in `BUILTINS = Set.of("echo", "exit", "type", "pwd", "cd", "complete")` ensures `type complete` correctly outputs `complete is a shell builtin`.
2. **Builtin Dispatch Hook**:
   - Adding `else if (command.equals("complete"))` prepares the shell for parsing flags (such as `-C` or `-F`) and registering completion hooks in future stages without throwing errors.

---

## The Solution
In `Main.java`:
```java
private static final Set<String> BUILTINS = Set.of("echo", "exit", "type", "pwd", "cd", "complete");
```

Inside command execution loop:
```java
} else if (command.equals("complete")) {
    // complete builtin implementation (stubbed for now)
}
```

---

## Failure Modes & Bugs Prevented
- **Missing Builtin Classification**:
  - If `complete` is not included in `BUILTINS`, `type complete` will scan the `PATH` and report `complete: not found`.
- **Unhandled Execution**:
  - Having a dedicated branch inside `if (BUILTINS.contains(command))` ensures running `complete` does not fall through or trigger an unhandled branch.

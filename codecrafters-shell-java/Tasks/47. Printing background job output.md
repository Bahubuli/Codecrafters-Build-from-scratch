# Stage 47: Background Jobs - Printing background job output

## In one line
Allow background processes to inherit stdout and stderr so their asynchronous output appears directly in the shell terminal.

---

## Self-test
Can you answer these questions from memory?
1. What happens to child process stdout/stderr when `ProcessBuilder.Redirect.INHERIT` is used?
2. Why should background processes retain stdout and stderr connection to the shell terminal by default?
3. How does file redirection (`>`, `>>`, `2>`, `2>>`) interact with background jobs?
4. What mechanism do tests typically use to asynchronously verify background output interleaved with foreground execution?

---

## Problem Solved
When commands are started asynchronously using the `&` operator, any output they generate (such as delayed notifications, completions, or reads from named pipes/FIFOs) must remain visible in the terminal rather than being swallowed or discarded.

---

## Concepts
- **Standard Stream Inheritance**: When `Redirect.INHERIT` is set on standard out and standard error (in the absence of explicit redirection files), the child process writes directly to the parent process's file descriptors.
- **Interleaved Output**: Since background jobs run concurrently with foreground commands and the REPL prompt, output from background jobs can appear asynchronously in the terminal.

---

## The Solution
In `codecrafters-shell-java/src/main/java/Main.java`:
```java
if (isBackground) {
    ProcessBuilder pb = new ProcessBuilder(cmdArgs);
    pb.directory(currentDir.toFile());
    if (outPath != null) {
        pb.redirectOutput(appendOut ? ProcessBuilder.Redirect.appendTo(outPath.toFile()) : ProcessBuilder.Redirect.to(outPath.toFile()));
    } else {
        pb.redirectOutput(ProcessBuilder.Redirect.INHERIT);
    }
    if (errPath != null) {
        pb.redirectError(appendErr ? ProcessBuilder.Redirect.appendTo(errPath.toFile()) : ProcessBuilder.Redirect.to(errPath.toFile()));
    } else {
        pb.redirectError(ProcessBuilder.Redirect.INHERIT);
    }
    Process process = pb.start();
    int jobId = nextJobId.getAndIncrement();
    long pid = process.pid();
    System.out.println("[" + jobId + "] " + pid);
    System.out.flush();
}
```

---

## Failure Modes
- **Using `ProcessBuilder.Redirect.DISCARD`**: The background process runs, but its output is silently dropped and never reaches the user terminal.
- **Overriding explicit file redirections**: If the user specified `command &> out.txt &`, overriding it with `INHERIT` would violate the redirection request.

---

## Tradeoffs
- Inheriting stdio allows simple, native forwarding without extra thread pool overhead for streaming buffers.
- Terminal output may interleave with current user input line typing, which is standard POSIX shell behavior when raw line discipline isn't managing job control.

---

## CLI / Protocol format
```bash
$ cat /path/to/fifo1 &
[1] 84470
$ cat /path/to/fifo2
Hello from FIFO#1
Hello from FIFO#2
```

---

## Java specifics
- `ProcessBuilder.Redirect.INHERIT` configures the subprocess to use the same I/O source or destination as the current Java process.

---

## Rebuild checklist
1. Verify if `outPath` or `errPath` is provided.
2. If provided, use file redirection (`to` or `appendTo`).
3. Otherwise, set `pb.redirectOutput(ProcessBuilder.Redirect.INHERIT)` and `pb.redirectError(ProcessBuilder.Redirect.INHERIT)`.
4. Do not block on `process.waitFor()`.

# Stage 61: Down-arrow navigation

## In one line
Intercept terminal ANSI escape sequence `\u001b[B` (down arrow) in raw mode to advance forward through command history, restoring newer entries or any saved uncommitted draft text when returning to the newest prompt line.

## Self-test (cover the answers below and answer these first)
- What byte sequence does the terminal send when the Down arrow key is pressed?
- What text should appear when pressing Down arrow past the newest historical command?
- How is the current in-progress input line preserved when the user begins navigating up into history?

## The problem it solved
Once users navigate back in time through command history using the Up arrow key, they need a way to navigate forward again using Down arrow, all the way down to whatever draft text they were typing before they began recalling history.

## Concepts (the transferable part)
- **Bidirectional History Pointer** — Maintaining a cursor `historyIndex` with lower bound `0` and upper bound `commandHistory.size()`.
- **Draft Line Buffering** — Stashing `savedCurrentLine` when `historyIndex == commandHistory.size()` before moving backward, so moving forward back to `historyIndex == commandHistory.size()` restores the exact draft input.
- **Dynamic Terminal Line Erase** — Clearing the current terminal line dynamically (`\b \b` for line length) so shorter historical entries cleanly overwrite longer ones without artifact characters.

## What breaks it (failure modes)
- Pressing Down arrow beyond `commandHistory.size()` — Must be clamped at `commandHistory.size()`, preventing `IndexOutOfBoundsException`.
- Failing to restore unsubmitted input — If the user typed `ls -la` and pressed Up then Down, losing the typed `ls -la` degrades terminal usability.
- Stale visual artifacts — If previous recalled text was longer than next recalled text, failure to backspace out the entire previous buffer length leaves dangling text.

## Tradeoffs
- Simple in-memory list tracking vs full GNU readline state — In-memory list indexing requires minimal code footprint and no external C native JNI bindings.

## CLI / Protocol format
- Up arrow sequence: `\u001b[A` (bytes `27`, `91`, `65`)
- Down arrow sequence: `\u001b[B` (bytes `27`, `91`, `66`)

## Java specifics — lookup, don't memorize
- `System.in.read()` — Reads raw byte from terminal input stream.
- `StringBuilder.deleteCharAt()` / `StringBuilder.append()` — Modifies in-flight line buffer.

## Rebuild checklist
- [ ] Save draft text to `savedCurrentLine` when leaving `historyIndex == commandHistory.size()`.
- [ ] When `\u001b[B` is detected and `historyIndex < commandHistory.size()`:
  - [ ] Increment `historyIndex`.
  - [ ] Clear previous line with `\b \b` loops.
  - [ ] If `historyIndex == commandHistory.size()`, target is `savedCurrentLine`. Otherwise, target is `commandHistory.get(historyIndex)`.
  - [ ] Append target to line buffer and output to terminal with `System.out.flush()`.

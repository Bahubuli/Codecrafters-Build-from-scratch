# Stage 39: Handling no completions (#qf1)

## In one line
Prevents fallback to file completion when a registered completer produces empty output, leaving the prompt input unchanged and ringing the terminal bell (`\u0007`).

---

## Self-test
- **Prompt**: If `complete -C /path/empty.py docker` is registered and the script outputs nothing, what must happen when the user presses `<TAB>` on `docker xyz`?
- **Answer**: The input line `docker xyz` remains unchanged, no files are searched or listed, and the bell character `\u0007` is printed to stdout and flushed.

---

## Problem Solved
Avoids erroneous fallback behavior where an empty candidate list from a custom completer would unintentionally trigger default filesystem completion, ensuring the user gets clear negative feedback (bell) instead of misleading file suggestions.

---

## Key Concepts
1. **Registered Completer Exclusivity**:
   - When a command has an explicit `complete -C` specification registered, the script is solely responsible for argument completions.
   - If the script emits zero lines, the candidate set `matches` is empty (`TreeSet<>(List.of())`), rather than `null`.
2. **Bell Character Feedback**:
   - `\u0007` (ASCII 7, Bell/Alert) provides terminal auditory/visual indication that completion was attempted but resulted in 0 candidates.
   - The buffer `line` is untouched.

---

## The Solution
In `readLineWithCompletion()`:
```java
String firstWord = current.trim().split("\\s+")[0];
if (COMPLETION_SPECS.containsKey(firstWord)) {
    String script = COMPLETION_SPECS.get(firstWord);
    List<String> scriptOutput = runCompleterScript(script);
    matches = new TreeSet<>(scriptOutput);
} else {
    matches = getFileCompletions(word);
}
```
When `matches.isEmpty()`:
```java
} else {
    System.out.print("\u0007");
    System.out.flush();
    consecutiveTabs = 0;
}
```

---

## Failure Modes & Bugs Prevented
- **Unintended Filesystem Fallback**:
  - Previously, checking `if (!scriptOutput.isEmpty())` caused empty completer output to leave `matches == null`, which inadvertently invoked `getFileCompletions(word)`.
  - Storing `new TreeSet<>(scriptOutput)` directly ensures an empty set correctly routes to the `else` branch (bell).

---

## CLI / Protocol Format
```bash
$ complete -C /tmp/noCandidatesCompleter systemctl
$ systemctl xyz<TAB>
# Bell rings, prompt stays as:
$ systemctl xyz
```

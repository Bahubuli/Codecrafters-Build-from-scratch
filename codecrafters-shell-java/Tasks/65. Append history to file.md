# Stage 65: Append history to file

## In one line
Implement `history -a <path>` to append newly executed commands from memory since the last `history -a` invocation directly to a history file on disk.

## Self-test (cover the answers below and answer these first)
- Does `history -a <path>` print anything to standard output or does it execute silently?
- Does the invocation `history -a <path>` itself get recorded in the history file?
- If `history -a` is called multiple times within a shell session, which commands are appended to the file on subsequent calls?

## The problem it solved
In long-running shell sessions or multi-terminal environments, users need incremental history persistence. Rewriting the entire file each time with `history -w` overwrites concurrent entries and does redundant I/O. `history -a` tracks unwritten commands since the last append and writes only the delta out to the file.

## Concepts (the transferable part)
- **Incremental State Syncing** — Maintaining a cursor or tracking offset (`lastAppendedHistoryIndex`) in memory representing the last synchronized point so repeated writes only sync newly recorded delta entries.
- **Append-Only File Persistence** — Writing data without truncating the destination file (`StandardOpenOption.APPEND`), preserving historical commands written by prior sessions or concurrent processes.
- **Self-Recording Invocation** — Because the shell REPL appends every executed command line into session history before running builtins, `history -a <path>` is already part of history and therefore gets written to disk.

## What breaks it (failure modes)
- Appending all session commands again on repeated `history -a` invocations — Calling `history -a` multiple times without updating the tracking cursor causes duplicate entries in the history file.
- Truncating or overwriting existing history — Using truncation flags instead of append mode wipes existing lines stored in the history file.
- Printing output during execution — Like `-w` and `-r`, `history -a` operates silently without printing command history or status messages.
- Forgetting missing parent directories — If the destination file path contains directories that don't exist yet, `Files.createDirectories(p.getParent())` ensures the path can be written.

## Tradeoffs
- Offset Cursor vs Set Tracking — Using an integer index (`lastAppendedHistoryIndex`) assumes command history grows append-only in sequence. If history is deleted or cleared in-memory (`history -c`), the cursor must be reset accordingly.

## CLI / Protocol format
- Command: `history -a <path_to_history_file>`
- Output: None (silent execution)
- Result in file: Appends commands from `lastAppendedHistoryIndex` through current `commandHistory.size()` to `<path_to_history_file>`, then advances `lastAppendedHistoryIndex = commandHistory.size()`.

## Java specifics — lookup, don't memorize
- `Files.writeString(Path path, CharSequence csq, OpenOption... options)` — Writes string data to disk using options `StandardOpenOption.CREATE`, `StandardOpenOption.APPEND`, `StandardOpenOption.WRITE`.
- `Path.getParent()` and `Files.createDirectories(Path dir)` — Ensures parent folder structure exists before creating or appending to the file.

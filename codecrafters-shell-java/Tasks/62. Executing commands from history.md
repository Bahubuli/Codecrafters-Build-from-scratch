# Stage 62: Executing commands from history

## In one line
Return the recalled command line upon receiving Enter (`\n` or `\r`), triggering standard execution and recording into command history.

## Self-test (cover the answers below and answer these first)
- When Enter is pressed while displaying a recalled historical command, what string does `readLineWithCompletion()` return?
- Does executing a historical command append it again to the history log?
- How does the interactive prompt move to the next line after Enter is pressed?

## The problem it solved
Users who navigate through command history via Up/Down arrow keys need to execute the chosen command simply by pressing Enter, exactly like typing the command fresh.

## Concepts (the transferable part)
- **Unified Input Return Contract** — Whether characters entered the prompt via typing, autocomplete, or arrow recall, the underlying buffer `line.toString()` is identical. Pressing Enter exits raw input reading, prints `\n`, and sends `line.toString()` directly to the execution loop.
- **History Growth Invariant** — Every submitted command line (including recalled commands) gets added to `commandHistory`, preserving an accurate chronological record of what was run.

## What breaks it (failure modes)
- Disconnecting the recalled buffer from the returned value — If the line buffer wasn't updated in place when Up/Down was pressed, pressing Enter would submit stale or empty input.
- Missing newline print on Enter — If `\n` isn't printed when exiting raw mode on Enter, subsequent program output runs into the prompt text.

## Tradeoffs
- Duplicating identical consecutive commands vs deduplication — Bash by default preserves every entered command unless `HISTCONTROL=ignoredups/ignoreboth` is active. Maintaining standard chronological append fulfills tester expectations without extra configuration overhead.

## CLI / Protocol format
- Up Arrow: `\u001b[A`
- Down Arrow: `\u001b[B`
- Enter / Return: `\r` (`13`) or `\n` (`10`)

## Java specifics — lookup, don't memorize
- `line.toString()` produces the current prompt string ready for command parsing.

# Stage 5: Implement the echo builtin

---

## In one line
Implement the `echo` builtin utility to format and write command-line argument operands to standard output separated by single spaces and terminated with a newline.

---

## Self-test (cover the answers below and answer these first)
- Why does the POSIX `echo` specification dictate separating operands by spaces rather than passing through raw whitespace from the command line?
- What should `echo` output when invoked with no arguments (e.g. `$ echo`)?
- What is the difference between parsing arguments via raw string slicing (`input.substring(5)`) versus tokenizing arguments (`parts[1..n]`)? What fails if leading spaces precede `echo`?
- Which standard stream (`stdout` vs `stderr`) does `echo` write to, and what line terminator is expected at the end?

---

## The problem it solved
Prior to this stage, the shell could only recognize `exit` or reject commands as unrecognized. Real shells provide a set of essential built-in utilities for user inspection, debugging, and script output. Implementing `echo` introduces command argument consumption, argument concatenation/formatting, and output generation to `stdout`.

---

## Concepts (the transferable part)

- **[CONCEPT] Command Operands / Arguments** — Shell commands generally consist of an executable or builtin identifier (`argv[0]`) followed by zero or more arguments or operands (`argv[1 ... n]`). The shell's responsibility is parsing these tokens from the input stream and passing them to the appropriate handler.
- **[CONCEPT] POSIX Echo Semantics** — The standard `echo` utility writes each of its operands to standard output separated by single space characters (`0x20`), followed by a newline (`\n`). If no arguments are provided, `echo` writes only the trailing newline.
- **[CONCEPT] Robust Token Extraction vs Brittle Slicing** — Relying on fixed character index slicing (e.g. `substring(5)`) couples argument extraction to assuming exactly one whitespace character between the command and arguments, and breaks when inputs contain leading whitespace (e.g. `   echo hello`). Decomposing input into tokens or properly trimming guarantees clean separation between command resolution and argument processing.

## The Solution

```java
import java.util.Arrays;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String trimmed = input.trim();
            if (trimmed.isEmpty()) {
                continue;
            }
            String[] parts = trimmed.split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            } else if (command.equals("echo")) {
                String output = String.join(" ", Arrays.copyOfRange(parts, 1, parts.length));
                System.out.println(output);
            } else {
                System.out.println(input + ": command not found");
            }
        }
    }
}
```

---

## What breaks it (failure modes)

- **Hardcoded substring indexing (`input.substring(5)`)** — If the user enters `echo` with no arguments, `input.substring(5)` throws `StringIndexOutOfBoundsException`. If the input has leading spaces (e.g. `  echo hi`), index 5 cuts into the command name itself (`"o hi"`).
- **Missing newline termination** — Using `print()` instead of `println()` leaves the cursor on the same line, preventing subsequent prompts from rendering on a new line and failing test assertions.
- **Printing extra space when no arguments are provided** — When `echo` is called without operands, it must print an empty line (just a newline `\n`), not a single space character (`" "`).
- **Ignoring empty inputs** — If a user presses Enter without typing any command, splitting on whitespace could yield an empty command string and incorrectly output `: command not found` instead of simply presenting the prompt again.

---

## Tradeoffs

- `String.join(" ", Arrays.copyOfRange(parts, 1, parts.length))` vs Custom StringBuilder loop — `String.join` with `Arrays.copyOfRange` is declarative, concise, and avoids manual index checking, with negligible memory overhead for typical shell command lines.
- Token splitting by `\\s+` vs Preserving spaces in quoted strings — Splitting by `\\s+` conforms to basic whitespace tokenization and collapses unquoted multiple spaces (consistent with POSIX word splitting). However, handling quoted arguments (such as `echo "foo   bar"`) will require a dedicated lexer in later stages.

## CLI / Protocol format

- **Echo Command Syntax**: `echo [string ...]`
  - `echo hello world` -> outputs `hello world\n`
  - `echo pineapple strawberry` -> outputs `pineapple strawberry\n`
  - `echo` -> outputs `\n` (blank line)
- **Exit Command Syntax**: `exit [status_code]`
- **Unrecognized Commands**: `<input>: command not found`

---

## Java specifics — lookup, don't memorize

- `Arrays.copyOfRange(T[] original, int from, int to)` — Copies the specified range of the specified array into a new array. When `from == to` (e.g. when no arguments exist), it cleanly returns an empty array of length 0.
- `String.join(CharSequence delimiter, CharSequence... elements)` — Returns a new `String` composed of copies of the `CharSequence` elements joined together with a copy of the specified delimiter. Returns an empty string `""` if the elements array is empty.
- `System.out.println(String x)` — Prints a string and then terminates the line with the system line separator.

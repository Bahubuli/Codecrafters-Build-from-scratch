# Stage 8: Run a program

---

## In one line
Execute external programs with arguments found via `PATH` (or direct path) by spawning child processes and connecting their standard streams to the shell.

## The problem it solved
Prior to this stage, the shell could only evaluate builtins (`echo`, `exit`, `type`) or locate binaries via `type`. If a user attempted to execute an external tool such as `ls`, `grep`, or a custom binary, the shell merely reported `<command>: command not found`. This stage equips the shell with core process execution capabilities: locating the executable, spawning an isolated child process with passed arguments, streaming its output directly to the terminal, and waiting for it to finish before displaying the next prompt.

---

## Concepts (the transferable part)

- **[CONCEPT] Child Process Spawning & Lifecycle (`fork` / `exec` / `wait`)** — In Unix operating systems, new processes are created by duplicating the caller process (`fork`), replacing the child's address space and program image with the target binary (`execve`), and having the parent block until termination (`waitpid`). The parent shell remains alive and resumes execution upon process exit.
- **[CONCEPT] Standard Streams & Descriptor Inheritance (`inheritIO`)** — By default, child processes inherit file descriptors (stdin: 0, stdout: 1, stderr: 2). Connecting the child's standard I/O directly to the shell's console streams allows the child process to render output and receive terminal input interactively without manual pipe buffering by the shell.
- **[CONCEPT] Command-Line Arguments & `argv` Vector** — When a command is invoked (e.g. `custom_exe arg1 arg2`), the arguments are passed as an array of strings to the executable. By POSIX convention, `argv[0]` is the invoked command name as typed by the caller, while `argv[1..n]` are the positional arguments.
- **[CONCEPT] Synchronous Execution vs Background Execution** — A foreground interactive command occupies the shell; the shell must block until the child process completes (`waitFor()`) before yielding control back to the user with a new prompt.

## The Solution

```java
import java.io.File;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.util.Arrays;
import java.util.Scanner;
import java.util.Set;
import java.util.regex.Pattern;

public class Main {
    private static final Set<String> BUILTINS = Set.of("echo", "exit", "type");

    public static void main(String[] args) throws Exception {
        Scanner scanner = new Scanner(System.in);

        while (true) {
            System.out.print("$ ");
            if (!scanner.hasNextLine()) {
                break;
            }
            String input = scanner.nextLine();
            String trimmed = input.trim();
            if (trimmed.isEmpty()) {
                continue;
            }
            String[] parts = trimmed.split("\\s+");
            String command = parts[0];

            if (command.equals("exit")) {
                int exitCode = 0;
                if (parts.length > 1) {
                    try {
                        exitCode = Integer.parseInt(parts[1]);
                    } catch (NumberFormatException ignored) {
                    }
                }
                System.exit(exitCode);
            } else if (command.equals("echo")) {
                String output = String.join(" ", Arrays.copyOfRange(parts, 1, parts.length));
                System.out.println(output);
            } else if (command.equals("type")) {
                if (parts.length > 1) {
                    String target = parts[1];
                    if (BUILTINS.contains(target)) {
                        System.out.println(target + " is a shell builtin");
                    } else {
                        Path executable = findExecutable(target);
                        if (executable != null) {
                            System.out.println(target + " is " + executable);
                        } else {
                            System.out.println(target + ": not found");
                        }
                    }
                }
            } else {
                Path executable = findExecutable(command);
                if (executable != null) {
                    ProcessBuilder pb = new ProcessBuilder(parts);
                    pb.inheritIO();
                    Process process = pb.start();
                    process.waitFor();
                } else {
                    System.out.println(input + ": command not found");
                }
            }
        }
    }

    private static Path findExecutable(String command) {
        if (command.contains("/") || command.contains(File.separator)) {
            try {
                Path path = Paths.get(command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
            return null;
        }
        return findExecutableInPath(command);
    }

    private static Path findExecutableInPath(String command) {
        String pathEnv = System.getenv("PATH");
        if (pathEnv == null || pathEnv.isEmpty()) {
            return null;
        }
        String[] dirs = pathEnv.split(Pattern.quote(File.pathSeparator));
        for (String dir : dirs) {
            if (dir.isEmpty()) {
                continue;
            }
            try {
                Path path = Paths.get(dir, command);
                if (Files.isRegularFile(path) && Files.isExecutable(path)) {
                    return path;
                }
            } catch (Exception ignored) {
            }
        }
        return null;
    }
}
```

## What breaks it (failure modes)

- **Passing absolute path as `argv[0]`** — Passing the resolved full path instead of the user's command name alters `argv[0]`, breaking programs that inspect their own invocation name (e.g., multi-call binaries like BusyBox or automated validation checks expecting the exact program name).
- **Forgetting `inheritIO()`** — Spawning a process without connecting I/O causes the child's `stdout`/`stderr` to be piped into JVM memory buffers. If the OS pipe buffer fills up (~64KB on Linux), the child blocks forever on write (deadlock), and the shell produces no terminal output.
- **Forgetting `waitFor()`** — Not blocking on process completion causes asynchronous race conditions: the shell prints the next `$ ` prompt immediately while the child is still writing output, interleaving prompts and program text unpredictably.
- **Attempting to execute non-executable files or directories** — Attempting to run a file without execute permissions or a directory throws `IOException` (`Permission denied`). Pre-checking `isRegularFile` and `isExecutable` ensures proper fallback error messages (`command not found`) instead of crashing the shell.
- **Command splitting on whitespace breaks quoted arguments** — Simple regex splitting (`\\s+`) breaks when arguments contain internal spaces within quotes (e.g. `echo "hello world"`). Full quote-aware lexical analysis is introduced in later stages.

---

## Tradeoffs

- **`ProcessBuilder.inheritIO()` vs Manual Stream Piping (`Process.getInputStream()` / threads)** — `inheritIO()` lets the OS handle descriptor inheritance natively at the kernel level with zero CPU overhead or buffer starvation risks. Manual piping is only necessary when the shell needs to intercept, redirect, or inspect program output.
- **`ProcessBuilder(String... command)` vs `Runtime.getRuntime().exec(String command)`** — `Runtime.exec(String)` performs crude string tokenization and is prone to injection and quote misinterpretations. `ProcessBuilder` cleanly separates arguments into an immutable array, matching OS-level `execve` parameter vectors.
- **Pre-checking executable existence vs relying on `catch (IOException)`** — Pre-checking using `findExecutable` allows the shell to differentiate between unknown commands (`command not found`) versus execution failures, cleanly maintaining shell contract semantics.

## CLI / Protocol format

- **Command Invocation**:
  ```
  $ <program_name> [arg1] [arg2] ...
  ```
- **Successful Program Output**:
  Streams child process `stdout` and `stderr` directly to terminal, followed by the next shell prompt `$ ` after the process terminates:
  ```
  $ custom_exe_1234 alice
  Program was passed 2 args (including program name).
  Arg #0 (program name): custom_exe_1234
  Arg #1: alice
  Program Signature: 5998595441
  $ 
  ```
- **Unrecognized Command Output**:
  ```
  <input>: command not found
  ```
  Example:
  ```
  $ invalid_program arg1
  invalid_program arg1: command not found
  ```

## Java specifics — lookup, don't memorize

- `ProcessBuilder(String... command)` / `ProcessBuilder(List<String> command)` — Configures a native operating system process specification where element 0 is the executable name and subsequent elements are arguments.
- `ProcessBuilder.inheritIO()` — Sets the subprocess standard I/O streams (`stdin`, `stdout`, `stderr`) to inherit from the current Java process.
- `ProcessBuilder.start()` — Spawns the subprocess in the operating system and returns a `Process` instance representing the running child.
- `Process.waitFor()` — Causes the current thread to block until the subprocess represented by this `Process` object has terminated, returning its integer exit code.

## Rebuild checklist
- [ ] Read and tokenize the user input line into command and argument tokens.
- [ ] Check if the command is a recognized builtin (`exit`, `echo`, `type`).
- [ ] If not a builtin, verify whether the command resolves to an executable file (via PATH or direct path).
- [ ] If executable, construct a `ProcessBuilder` with the command and argument array.
- [ ] Configure `inheritIO()` on the `ProcessBuilder` so child streams connect directly to the terminal.
- [ ] Start the process and wait for completion (`waitFor()`) before reprompting.
- [ ] If not executable or not found, print `<input>: command not found`.

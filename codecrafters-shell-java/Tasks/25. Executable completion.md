# Stage 25: Executable completion

## In one line
Extends raw-mode Tab autocompletion by scanning external executable binaries across all directories listed in the `PATH` environment variable, deduplicating candidate names with builtins, and appending unique matches.

- Why must candidate collection use a set data structure (like `TreeSet`) rather than a simple list?

## The problem it solved
Previously, tab autocompletion only recognized builtin commands (`echo` and `exit`), ignoring all installed system utilities or custom user binaries. In real Unix shells, typing a prefix of an external command like `git`, `custom_tool`, or `grep` and pressing Tab expands to the executable name. Scanning directories in `PATH` bridges the gap between builtin completions and the full executable environment.

## Concepts (the transferable part)
- **[CONCEPT] Executable Candidate Discovery via PATH Search** — The `PATH` environment variable contains an ordered list of directories separated by the OS path separator (`:` on POSIX). For autocompletion, the shell inspects each directory in `PATH`, enumerates entries starting with the prefix, and filters for regular files with execute permissions (`+x`).
- **[CONCEPT] Namespace Unification & Deduplication** — Builtin commands and external binaries exist in the same user-facing command namespace. Collecting matches in a set ensures identical command names found in multiple `PATH` directories (or overriding builtins) are deduplicated, preventing false ambiguity when a single command exists in multiple search paths.
- **[CONCEPT] Non-Blocking Fault-Tolerant Filesystem Traversal** — `PATH` entries frequently contain nonexistent directories, unreadable files, or symlinks. Tab completion must tolerate these without crashing or lagging interactive typing by verifying directory existence and readability before listing.

## What breaks it (failure modes)
- **Treating Subdirectories as Executables** — On Unix, directories usually have execute permissions (`+x` meaning searchable). If the scanner only checks `canExecute()` without checking `isFile()`, directory names will falsely match as command candidates.
- **Crashing on Nonexistent or Unreadable PATH Directories** — If a directory listed in `PATH` does not exist or lacks read permissions, unchecked calls (like `dir.listFiles()`) will return `null` or throw security exceptions.
- **Duplicate Candidates Triggering Bell** — If an executable exists in both `/bin` and `/usr/bin` (common on systems where `/bin` is a symlink or merged with `/usr/bin`), using a `List` would register 2 matches for a single logical binary, causing the shell to emit a bell instead of autocompleting. Using a `Set` deduplicates them.
- **Partial Path Remainder Computation** — The shell must only append the *remainder* of the command (`match.substring(current.length()) + " "`), not the entire command, to avoid corrupting the user's terminal line buffer.

## Tradeoffs
- **On-Demand PATH Scanning vs In-Memory Path Cache** — Scanning `PATH` directories upon each `<TAB>` press avoids maintaining a cache invalidation subsystem when new binaries are installed, with negligible latency on modern OS page caches (~1-5ms). Caching binaries in memory speeds up huge PATH configurations but introduces cache staleness.
- **`TreeSet<String>` vs `HashSet<String>`** — `TreeSet` naturally maintains lexicographical order, which is essential for deterministic selection and multi-candidate listing in subsequent stages.

## CLI / Protocol format
- Single match:
  ```bash
  $ custom<TAB>
  $ custom_executable 
  ```
- No match or ambiguous match:
  ```bash
  $ nonexist<TAB>  # Emits '\u0007' (bell), leaves prompt line intact
  ```

## Java specifics — lookup, don't memorize
- `File.pathSeparator` — Platform-specific path-list separator character (`:` on POSIX, `;` on Windows).
- `File.listFiles()` — Returns an array of `File` objects in a directory, or `null` if the path denotes a non-directory or cannot be read.
- `File.isFile() && File.canExecute()` — Distinguishes regular executable files from directories or non-executable assets.
- `TreeSet<String>` — Sorted, duplicate-free set for storing unique command candidates.

## Rebuild checklist
- [ ] Read `PATH` environment variable via `System.getenv("PATH")`.
- [ ] Split `PATH` by `File.pathSeparator` using `Pattern.quote(File.pathSeparator)`.
- [ ] For each valid directory, inspect files and collect matching executable regular files into a `TreeSet`.
- [ ] Add builtins (`echo`, `exit`) that match prefix into the candidate set.
- [ ] If exactly 1 candidate matches, append remainder + `" "` to buffer, echo to stdout, and `flush()`.
- [ ] If 0 or >1 candidates match, ring terminal bell (`\u0007`) and flush.

# Stage 28: File completion

## In one line
Differentiates command completion from argument autocompletion by detecting whitespace delimiters, querying the current working directory for matching files, and appending a trailing space upon a single match.

## The problem it solved
Previously, autocompletion assumed every `<TAB>` keypress was targeting a command name (builtins or executables in `PATH`). As a result, pressing `<TAB>` after typing a command and starting an argument (e.g. `cat re<TAB>`) failed completely, rang the terminal bell, or matched irrelevant executables in `PATH`. Real-world shells contextually switch completion domains: the first word completes commands, while subsequent arguments complete against filesystem paths.

## Concepts (the transferable part)
- **[CONCEPT] Contextual Completion Dispatch (Token Boundary Detection)** — In a shell line buffer, lexical tokens are delimited by whitespace. A line with no spaces is in the command-head position; a line containing a space transitions the active input cursor into argument position. The target word prefix is isolated as the substring from `lastIndexOf(' ') + 1` to the cursor.
- **[CONCEPT] Filesystem Domain Completion** — Unlike command completion which queries `PATH` directories and internal builtin sets, argument completion queries the current working directory's directory table (`currentDir.toFile().listFiles()`).
- **[CONCEPT] Terminal Token Delimitation** — When an argument completes uniquely to a file name, appending a delimiter (` `) signals to both user and terminal that the token boundary is committed, allowing the user to immediately type subsequent arguments, flags, or redirection operators without an explicit space keystroke.

## What breaks it (failure modes)
- **Whole-Line Prefix Matching Instead of Sub-word Prefix** — Searching for files matching `"cat re"` instead of `"re"` results in 0 matches and an erroneous bell ring.
- **Missing or Extraneous Spaces on Completion Delta** — Emitting the full filename `readme.txt` instead of the delta `adme.txt ` duplicates the typed characters (`readreadme.txt`), while omitting the trailing space requires the user to press space manually.
- **Directory Traversal / Hidden File Leakage** — Including hidden files (`.git`, `.DS_Store`) when the user didn't type a leading `.` clutters candidate sets or corrupts single-match completion.
- **Null Safety on Directory Listing** — Calling `listFiles()` on a directory without read permissions or during filesystem anomalies returns `null`, throwing `NullPointerException` if not guarded.
- **Hardcoding Working Directory** — Querying `System.getProperty("user.dir")` instead of the shell's mutable working directory state (`currentDir`) breaks file completion after `cd` builtin commands.

## Tradeoffs
- **Flat Whitespace Splitting vs Full Shell Tokenizer / Lexer** — Using `lastIndexOf(' ')` is simple and fast for standard single-space commands, but does not account for escaped spaces (`\ `) or quoted arguments (`"foo bar/"`). A full lexical scanner handles quotes and escaping at the cost of parser complexity.
- **Pre-filtering Files vs Loading All Entries** — Filtering during filesystem traversal (`File.isFile()`) minimizes in-memory candidate allocations compared to loading all directory inodes and filtering post-hoc.

## CLI / Protocol format
- Given current working directory contains `grape-48.txt`
- User types `du grape-` and presses `<TAB>`:
  - Input: `du grape-<TAB>`
  - Action: `lastSpace` = 2, `word` = `grape-`. Filesystem scan matches `grape-48.txt`. Single match!
  - Delta emitted: `48.txt `
  - Line buffer updated to: `du grape-48.txt `
  - Terminal display: `$ du grape-48.txt `

## Java specifics — lookup, don't memorize
- `String.lastIndexOf(int ch)` — Returns the index within this string of the last occurrence of the specified character, or -1 if not found.
- `File.listFiles()` — Returns an array of abstract pathnames denoting the files in the directory denoted by this abstract pathname, or null if it cannot be read.
- `File.isFile()` — Tests whether the file denoted by this abstract pathname is a normal file.
- `File.getName()` — Returns the name of the file or directory denoted by this abstract pathname.

# Stage 26: Multiple completions

## In one line
Tracks consecutive Tab keypresses to provide standard two-stage Unix autocompletion: ringing the terminal bell on the first ambiguous Tab press, and listing all alphabetically sorted candidates separated by spaces on the second consecutive Tab press before restoring the prompt and buffer.

## The problem it solved
Previously, when the user pressed `<TAB>` on a prefix matching multiple executables, the shell simply rang the terminal bell (`\u0007`) and did nothing else, leaving the user guessing what valid command names were available. In standard shells (like Bash, Zsh, or Readline), pressing `<TAB>` once rings the bell to notify the user of ambiguity; pressing `<TAB>` immediately a second time displays all matching candidates in alphabetical order and redraws the prompt so the user can complete their command.

## Concepts (the transferable part)
- **[CONCEPT] Two-Stage Keystroke State Machine** — Interactive terminal line editors operate as finite state machines. Distinguishing between a single keystroke event and repeated consecutive keystrokes requires maintaining lightweight transient state (such as `consecutiveTabs` or `lastWasTab`) in the event loop that clears whenever any intervening non-matching event occurs.
- **[CONCEPT] Non-Destructive Terminal Screen Refresh** — Displaying completions requires advancing past the current prompt line with a newline (`\n`), printing candidate matches across or down lines, printing a new prompt line (`$ `), and re-emitting the buffered input (`current`) so the visual terminal state stays in sync with the internal line buffer without losing cursor position or user edits.
- **[CONCEPT] Deterministic Candidate Ordering** — Terminal autocompletion lists must be presented deterministically (alphabetically sorted). Using naturally ordered sets (like `TreeSet`) guarantees sorted, deduplicated output across disparate filesystem directories in `PATH`.

## What breaks it (failure modes)
- **Sticky Tab State on Typing or Deleting** — If typing a regular character or pressing Backspace does not reset `consecutiveTabs` to 0, typing `xyz_` -> `<TAB>` (bell) -> `a` -> `<TAB>` would mistakenly trigger the second-tab candidate listing instead of evaluating `xyz_a` as a new prefix.
- **Desynchronized Line Buffer on Candidate Display** — If the shell re-prints `$ ` + `current` to the terminal but fails to keep `current` in `line` (or accidentally clears `line`), subsequent keypresses or Enter would execute only the newly typed characters rather than the full command.
- **Missing Output Flush on Multi-Line Output** — Output written to `System.out` without explicit `System.out.flush()` remains trapped in the JVM's user-space output buffer, causing automated testers and terminal emulators to time out waiting for candidate output.
- **Third Tab Cycle Handling** — If the user presses `<TAB>` a third time immediately following candidate display, resetting the counter back to 0 ensures the next press behaves predictably (ringing the bell once more rather than printing stale listings or corrupting the screen).

## Tradeoffs
- **Immediate Candidate Display vs Readline Two-Tab Convention** — Some modern shells or completion engines display completions immediately on the first Tab (or via a dropdown menu), whereas standard POSIX Readline uses the two-tab convention to minimize terminal spam when large candidate sets match. Following the two-tab standard adheres to classic shell ergonomics.
- **Full PATH Scan per Tab vs Cached Index** — Scanning directories on the second Tab re-uses the existing candidate discovery logic without maintaining background filesystem watchers, perfectly balancing simplicity with responsive CLI performance.

## CLI / Protocol format
- **First `<TAB>` press (Ambiguous match)**:
  - Input: `xyz_<TAB>`
  - Output: `\u0007` (Terminal Bell)
  - Visual display remains unchanged: `$ xyz_`
- **Second consecutive `<TAB>` press**:
  - Input: `<TAB>`
  - Output:
    ```
    \n
    xyz_bee  xyz_cow  xyz_owl\n
    $ xyz_
    ```
  - Followed immediately by `flush()`.

## Java specifics — lookup, don't memorize
- `String.join("  ", matches)` — Joins elements of an iterable (such as a `Set<String>`) delimited by two spaces.
- `TreeSet<String>` — Implements `NavigableSet`, maintaining elements sorted in their natural lexicographical order.
- `\u0007` — ASCII 7 (BEL), rings the terminal bell or flashes the terminal screen.

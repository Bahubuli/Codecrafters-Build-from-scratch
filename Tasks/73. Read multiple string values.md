# Stage 73: Read Multiple String Values

## In one line
`GET <key>` works correctly for any key in an RDB file containing multiple entries.

## The problem it solved
RDB files typically contain many keys. This stage confirms the parser doesn't confuse offsets or skip entries when reading multi-key files, and that `GET` looks up the correct value for each key regardless of insertion order.

## Concepts (the transferable part)
- **Stateful stream reading** — the `InputStream` position advances with every `in.read()` and `in.readNBytes()`. Once a byte is consumed, it's gone. Correct RDB parsing requires consuming exactly the right bytes for each entry, leaving the stream positioned at the next opcode.
- **Map key lookup is O(1)** — `store.get(key)` doesn't depend on how many keys are in the map; performance is independent of RDB file size.

## What breaks it (failure modes)
- **Misaligned reads** — if any opcode handler consumes too few or too many bytes (e.g., forgetting to skip a size-encoded value in `0xFB`), the next opcode read picks up garbage. The symptom is a cascade of `IOException` or wrong values for all subsequent keys.
- **Integer-encoded keys** — keys, not just values, can be integer-encoded in RDB. `readRdbString` handles both key and value reads identically, so integer keys work automatically.

## Tradeoffs
- **Reading into `byte[]` vs `StringBuilder`** — always read into `byte[]` first, then convert with `new String(bytes, UTF_8)`. Building strings incrementally from `in.read()` char-by-char breaks on multi-byte characters.

## Java specifics — lookup, don't memorize
- `in.readNBytes(len)` — used for string body after size is decoded; returns exactly `len` bytes.
- `store.get(key)` — `ConcurrentHashMap.get` is thread-safe without locks.

## Rebuild checklist
- [ ] Each `0x00` iteration reads: one key string + one value string, no more, no less
- [ ] `readRdbString` always reads exactly `len` bytes after decoding size
- [ ] `GET` handler: `store.get(key)`, check `isExpired()`, return value or `$-1\r\n`

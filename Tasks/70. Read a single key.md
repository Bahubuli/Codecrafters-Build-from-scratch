# Stage 70: Read a Single Key

## In one line
How to parse the RDB binary file format at startup and load keys into the in-memory store.

## The problem it solved
Previously `GET` and `KEYS` only saw keys set during the current session. RDB is Redis's native persistence format — this stage teaches the server to parse it and populate `store` before accepting any connections, so data survives restarts.

## Concepts (the transferable part)
- **Opcode-driven binary parsing** — RDB is a stream of opcode bytes; each byte tells you what follows. Read one byte, branch on its value, consume the right number of bytes, repeat. It's a handwritten state machine over an `InputStream`.
- **Size encoding** — Redis uses a 2-bit prefix to pack lengths into 1, 2, or 5 bytes. Bits 00 = 6-bit length, 01 = 14-bit, 10 = 32-bit, 11 = special (integer stored as string). You must decode this before reading the string body.
- **Loading before accepting connections** — calling `loadRdb()` before `ServerSocket.accept()` ensures no client sees a partially loaded store.

## Wire format / protocol
RDB binary layout (relevant opcodes):
| Opcode | Meaning |
|--------|---------|
| `0xFA` | Auxiliary field (key + value strings — skip) |
| `0xFE` | SELECT DB (size-encoded index — skip) |
| `0xFB` | RESIZE DB (two size-encoded ints — skip) |
| `0xFF` | EOF (stop parsing; 8-byte CRC follows) |
| `0xFC` | Expiry milliseconds (8-byte LE) then type+key+value |
| `0xFD` | Expiry seconds (4-byte LE) then type+key+value |
| `0x00` | String value type (key string + value string) |

## What breaks it (failure modes)
- **File doesn't exist** — `loadRdb()` checks `rdbFile.exists()` and returns early; server starts normally without data.
- **Truncated file** — `readRdbString` throws `IOException` on `-1` byte; caught in the outer try-catch.
- **Header skip must be exactly 9 bytes** — `REDIS` (5) + 4-digit version number. Off-by-one misaligns all subsequent reads.

## Tradeoffs
- **Load-on-start vs lazy loading** — loading everything upfront is simpler and correct for single-instance servers; lazy loading wins for huge datasets.
- **`in.readNBytes(len)` vs manual loop** — `readNBytes` blocks until all bytes arrive; correct for file streams where all bytes are guaranteed available.

## Java specifics — lookup, don't memorize
- `new java.io.File(dir, filename)` — constructs platform-correct path from directory + filename.
- `in.readNBytes(n)` — reads exactly `n` bytes; available since Java 11.
- `(b & 0xC0) >> 6` — extracts the top 2 bits of a byte as an integer 0–3.

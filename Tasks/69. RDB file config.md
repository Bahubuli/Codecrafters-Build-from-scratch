# Stage 69: RDB File Config

## In one line
How to accept and store CLI arguments (`--dir`, `--dbfilename`) so they can be queried via `CONFIG GET`.

## The problem it solved
Redis has persistent storage through RDB snapshots. Before this stage, the server had no way to know where to find or write an RDB file. This stage wires up `--dir` and `--dbfilename` CLI flags and makes them queryable so future stages can actually read the file from the right path.

## Concepts (the transferable part)
- **Config as first-class data** — CLI flags populate static fields, not hardcoded constants. Any command can read those fields; no global reconfiguration needed.
- **RESP array for key-value config responses** — `CONFIG GET` returns `*2\r\n$<keyLen>\r\n<key>\r\n$<valLen>\r\n<val>\r\n`, not a flat string. Client libraries expect paired arrays.
- **`--flag value` arg parsing pattern** — iterate args by index, check for flag string, consume next element, advance `i++` to skip the value.

## Wire format / protocol
`CONFIG GET dir` -> `*2\r\n$3\r\ndir\r\n$<len>\r\n<value>\r\n`
`CONFIG GET dbfilename` -> `*2\r\n$10\r\ndbfilename\r\n$<len>\r\n<value>\r\n`

## What breaks it (failure modes)
- **Unknown param** — return `*0\r\n` (empty array), not an error; some clients probe with arbitrary names.
- **Missing `--dir` with `--dbfilename` set** — `loadRdb()` guards with `if (rdbDir.isEmpty() || rdbDbFilename.isEmpty()) return;`

## Tradeoffs
- **Static fields** vs a `Map<String,String> config` — static fields are simpler for a small known set; a map wins when config keys are dynamic or large.

## Java specifics — lookup, don't memorize
- `args[i + 1]` — peeking one ahead in the args array; always check `i + 1 < args.length` first.
- `"--dir".equalsIgnoreCase(args[i])` — case-insensitive flag matching.

## Rebuild checklist
- [ ] Declare `private static String rdbDir = ""` and `rdbDbFilename = ""`
- [ ] In `main()` loop, handle `--dir` and `--dbfilename` flags with `i++` after consuming value
- [ ] In `handleCommand()`, add `CONFIG` branch: check `parts[1].equalsIgnoreCase("GET")`, match `parts[2]` to `"dir"` or `"dbfilename"`, return RESP `*2` array

# Stage 8: Forwarding Server

## Problem Solved

In real-world networks, local DNS servers frequently act as **DNS Forwarders** (recursive resolvers or split-horizon DNS proxies). Instead of hosting authoritative zone records or performing complex iterative root-to-TLD walking for every client request, a forwarding server relays client queries upstream to designated recursive resolvers (such as `8.8.8.8` or internal enterprise resolvers), collects the returned resource records, and returns the unified response to the client.

In this stage:
- The server accepts a command-line flag `--resolver <ip:port>` pointing to an upstream DNS resolver.
- Upstream resolvers generally conform to strict RFC 1035 operational constraints: they only resolve queries containing a single question ($QDCOUNT = 1$). If an incoming client packet bundles multiple questions, the forwarder must split them into individual single-question queries sent upstream.
- The forwarder parses the answers from each upstream response, merges all answers into a consolidated response matching the original query ID, and delivers the unified DNS packet back to the client.

## Concepts

- **DNS Forwarder / Proxy Architecture**: A lightweight intermediary that accepts client DNS datagrams, translates or splits queries for upstream forwarding, and funnels responses back to the downstream client without maintaining an authoritative zone database.
- **Query Demultiplexing & Response Multiplexing**: While clients may legally transmit multi-question queries, most upstream DNS servers refuse or fail on $QDCOUNT > 1$. The forwarder demultiplexes a multi-question query into $N$ individual single-question queries ($QDCOUNT = 1$) and multiplexes the $N$ upstream answer sets into a single downstream reply ($ANCOUNT = \sum M_i$).
- **Socket Lifecycle & Timeout Handling**: Creating an outbound `DatagramSocket` with a configured timeout (`setSoTimeout`) prevents hanging indefinitely if an upstream resolver drops a UDP packet. Reusing a persistent forwarding socket avoids repeated socket allocation and ephemeral port exhaustion.
- **Cross-Section Record Compression & Pointer Isolation**: Because upstream answers may use compression pointers targeting offsets within their own isolated packets, parsing the upstream packet into structured objects before rebuilding the downstream response decouples internal packet offsets and avoids corrupted pointers.

```
+--------+                 +---------------+                 +--------------------+
| Client |                 | DNS Forwarder |                 | Upstream Resolver  |
+--------+                 +---------------+                 +--------------------+
    |                             |                                     |
    | UDP Query (ID=42, 2 Qs)     |                                     |
    |---------------------------->|                                     |
    |                             | Query 1 (ID=42, Q1)                 |
    |                             |------------------------------------>|
    |                             |                                     |
    |                             | Response 1 (ID=42, Ans1)            |
    |                             |<------------------------------------|
    |                             |                                     |
    |                             | Query 2 (ID=42, Q2)                 |
    |                             |------------------------------------>|
    |                             |                                     |
    |                             | Response 2 (ID=42, Ans2)            |
    |                             |<------------------------------------|
    |                             |                                     |
    | UDP Response (ID=42, 2 Ans) | [Consolidates Q1, Q2 & Ans1, Ans2]  |
    |<----------------------------|                                     |
    |                             |                                     |
```

### Response Header Field Mapping Table

| Header Field | Value in Downstream Reply | Purpose |
|---|---|---|
| `ID` | Client Query `ID` | Correlates reply to client transaction |
| `QR` | `1` | Denotes a response packet |
| `OPCODE` | Client Query `OPCODE` | Preserved from client request |
| `AA` | `0` | Non-authoritative forwarder |
| `TC` | `0` | Not truncated |
| `RD` | Client Query `RD` | Preserves Recursion Desired bit |
| `RA` | `0` | Recursion Available flag |
| `Z` | `0` | Reserved bits |
| `RCODE` | `0` (if `OPCODE==0`) else `4` | Response code |
| `QDCOUNT` | Total client questions count | Matches client query count |
| `ANCOUNT` | Total merged answers count | Sum of answers across upstream replies |
| `NSCOUNT` | `0` | No authority records |
| `ARCOUNT` | `0` | No additional records |

## Failure Modes

- **Upstream Packet Loss / Timeout**: UDP is connectionless and unreliable. An unconfigured or blocking `DatagramSocket.receive()` can hang forever if a packet is lost. Configuring `forwardSocket.setSoTimeout(5000)` ensures resilient recovery.
- **Ephemeral Port Exhaustion**: Opening a new `DatagramSocket()` on every question can rapidly consume local ephemeral ports under high load. Using a shared, long-lived `DatagramSocket` for outbound queries maintains socket pool stability.
- **Pointer Misalignment Across Packets**: If an upstream resolver returns an answer pointing to offset `12` in its own packet, directly copying raw answer bytes into the merged downstream packet causes the pointer to point to invalid or wrong data. Parsing into high-level record objects (`DnsRecord`) and re-serializing solves this cleanly.
- **Port Parsing Errors**: In `--resolver <ip>:<port>`, failing to properly validate or split the argument can throw `NumberFormatException` or `ArrayIndexOutOfBoundsException`.

## Tradeoffs

- **Sequential vs Concurrent Upstream Resolution**: Sending queries sequentially in a loop is simple, deterministic, and avoids thread synchronization overhead. For high-latency upstream resolvers, concurrent resolution via `CompletableFuture` would reduce response latency at the cost of concurrency complexity.
- **Raw Byte Passthrough vs Object Materialization**: Decompressing and deserializing upstream records into Java objects consumes memory allocations, but provides complete immunity to cross-packet compression pointer corruption.

## Java Specifics

- `DatagramSocket.setSoTimeout(int timeout)`: Configures blocking read timeout in milliseconds; throws `SocketTimeoutException` on expiry.
- `InetSocketAddress(InetAddress addr, int port)`: Encapsulates socket endpoint representation for UDP packet routing.
- `Arrays.copyOfRange(byte[] original, int from, int to)`: Extracts exact received datagram slices without trailing padding bytes.

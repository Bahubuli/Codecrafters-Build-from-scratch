# Stage 1: Initialize the .git directory

## In one line
Bootstrapping a Git repository's filesystem skeleton by constructing the `.git` root, `objects/` store, `refs/` directory, and pointing `.git/HEAD` symbolically to `refs/heads/main`.

## Self-test (cover the answers below and answer these first)
- What are the three essential components created in the `.git` directory when initializing an empty repository?
- What does `.git/HEAD` contain in a freshly initialized repository?
- Why is the initial ref pointer formatted as `ref: refs/heads/main\n` rather than storing a commit hash?

## The problem it solved
Before version control operations (staging, committing, branching) can execute, Git requires a well-known directory structure on disk to persist content-addressed objects and branch pointers. Initializing this root establishes the database workspace boundary.

## Concepts (the transferable part)
- **Metadata Encapsulation**: Isolating repository metadata inside a single hidden root folder (`.git`) separates system state cleanly from the working directory without modifying project source files.
- **Symbolic Reference Indirection**: `HEAD` acts as a symbolic ref (`ref: refs/heads/...`), deferring commit hash resolution until an actual commit object exists (solving the "unborn branch" bootstrapping dilemma).
- **Object Store Separation**: `objects/` holds immutable content-addressable storage; `refs/` holds mutable pointer namespaces (`heads/`, `tags/`, `remotes/`).

## What breaks it (failure modes)
- Omitting the trailing newline in `HEAD` (`ref: refs/heads/main\n`), causing parse errors in POSIX-compliant git tools.
- Failing to create parents or directories before creating `HEAD`.
- Writing an empty commit hash to `HEAD` rather than a symbolic ref.

## Tradeoffs
- Flat SQLite database file vs Hierarchical Directory Tree (`.git/objects/`, `refs/`) — Git's directory tree allows atomic writes via temporary files and direct filesystem inspection without requiring a database engine or daemon.

## CLI / Protocol format
- Command: `./your_program.sh init`
- Output: `Initialized git directory`
- Created filesystem hierarchy:
  ```
  .git/
  ├── HEAD (contains: "ref: refs/heads/main\n")
  ├── objects/
  └── refs/
  ```

## Java specifics — lookup, don't memorize
- `new File(root, "objects").mkdirs()` — creates directory and necessary parents.
- `Files.write(head.toPath(), "ref: refs/heads/main\n".getBytes())` — writes bytes to target path.

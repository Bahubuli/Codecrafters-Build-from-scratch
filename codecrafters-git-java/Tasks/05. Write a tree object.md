# Stage 5: Write a tree object

## In one line
Recursively traversing directory entries, writing file contents as blob objects, packing each entry into `<mode> <name>\0<20-byte-sha>` sorted by Git's tree sorting rules, and writing the framed `tree <size>\0` objects from the leaves up to the root.

## Self-test (cover the answers below and answer these first)
- Why must subdirectories be processed before their parent tree object can be written?
- What is the mode string written for a directory in a Git tree object?
- How does Git sort entries when comparing a directory name against a file name that shares the same prefix?

## The problem it solved
Snapshotting a project requires capturing the entire directory tree, not just individual disconnected files. `write-tree` synthesizes individual blobs and nested subtrees into a single root Merkle tree hash that uniquely and immutably identifies the working directory state.

## Concepts (the transferable part)
- **Post-Order Tree Traversal (Bottom-Up Synthesis)**: Because a parent tree object contains the cryptographic hashes of its child trees, child trees must be constructed, serialized, and hashed *first*.
- **Virtual Trailing Slash Sorting**: Git compares entries byte-by-byte, treating directories as if they had an implicit trailing `/` character. This ensures directories sort alongside their contained paths rather than purely by alphabetical character code.
- **Recursive Merkle Tree Composition**: Unchanged subtrees preserve identical SHA-1 hashes, making tree diffing an $O(\text{differences})$ operation rather than an $O(\text{repository size})$ scan.

## What breaks it (failure modes)
- Storing directory mode as `040000` instead of `40000` (Git's internal tree serializer uses `40000` without leading zeros).
- Including the `.git` directory inside the tree object, creating infinite recursion or object store corruption.
- Formatting the SHA-1 as a 40-character hex string instead of 20 raw bytes.
- Sorting entries in reverse or using naive ASCII sorting that misorders directories relative to files with punctuation or extensions.

## Tradeoffs
- Full Recursive Tree Writing vs Index-Staged Trees — The plumbing `git write-tree` reads the staged index (`.git/index`), but reading the working tree recursively directly demonstrates how filesystem hierarchies map into Git's Merkle DAG.

## CLI / Protocol format
- Command: `./your_program.sh write-tree`
- Output: `<40-char-root-tree-sha>\n`
- Uncompressed tree layout:
  ```
  tree <size>\0
  40000 dir1\0<20-byte-sha>
  100644 file.txt\0<20-byte-sha>
  ```

## Java specifics — lookup, don't memorize
- `ByteArrayOutputStream.write(byte[] b)` — concatenates raw bytes cleanly.
- `Character.compare(c1, c2)` — compares characters with Git's virtual slash semantics.

## Rebuild checklist
- [ ] Parse `write-tree`.
- [ ] Recursively traverse working directory, skipping `.git`.
- [ ] For each file: write blob object, collect 20-byte SHA-1 and mode (`100644` or `100755`).
- [ ] For each directory: recurse, collect 20-byte subtree SHA-1 and mode (`40000`).
- [ ] Sort entries with Git's tree ordering comparator.
- [ ] Pack `<mode> <name>\0<20-byte-sha>` into byte stream.
- [ ] Prepend `tree <len>\0`, write compressed object, return SHA-1.
- [ ] Print root tree 40-character hex SHA-1 to stdout.

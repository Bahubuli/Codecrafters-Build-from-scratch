# Stage 6: Create a commit

## In one line
Framing commit metadata (`tree`, `parent`, `author`, `committer`, message) into an uncompressed `commit <size>\0` payload, computing its SHA-1 hash, and persisting it as a zlib-deflated loose object in `.git/objects/`.

## Self-test (cover the answers below and answer these first)
- What is the difference between how hashes are stored in tree objects vs commit objects?
- What separates the commit metadata headers (`author`, `committer`, etc.) from the commit message body?
- Why do Git commits store both an `author` and a `committer` timestamp?

## The problem it solved
Trees capture a static snapshot of the filesystem, but they carry no history, lineage, or authorship. Commit objects wrap a root tree hash in human context (who wrote it, when, why) and cryptographic parent pointers, forming Git's directed acyclic graph (DAG) of project history.

## Concepts (the transferable part)
- **Directed Acyclic Graph (DAG) History**: Each commit stores one or more immutable parent SHA-1 pointers. History is traversed backward from leaf to root. Because SHA-1 covers parent hashes, altering any historical commit alters all descendant hashes (tamper-evident blockchain/Merkle-DAG structure).
- **Text-Based Metadata Serialization**: Unlike tree objects which pack raw binary hashes, commit objects format `tree` and `parent` hashes as 40-character hex strings, followed by RFC 2822-inspired email and UNIX timestamp metadata.
- **Separation of Author vs Committer**: The `author` is the person who originally wrote the changes; the `committer` is the person who applied or merged the commit (allowing patch-based workflows, cherry-picks, and rebases to preserve attribution).

## What breaks it (failure modes)
- Storing the tree or parent SHA as 20 raw binary bytes (like in trees) instead of 40 ASCII hex characters.
- Omitting the blank newline `\n\n` separator between header fields and the commit message.
- Miscalculating the header `<size>` by taking the length of string characters rather than UTF-8 byte count.
- Inverting the order of parent and tree lines.

## Tradeoffs
- Text-formatted commits vs Binary protobufs — Plain text headers make commits human-readable with standard UNIX tools (`git cat-file -p`, `diff`, `grep`), prioritizing inspection and debugging simplicity.

## CLI / Protocol format
- Command: `./your_program.sh commit-tree <tree_sha> -p <parent_sha> -m "<message>"`
- Uncompressed commit object layout:
  ```
  commit <size>\0tree <tree_sha>\n
  parent <parent_sha>\n
  author <name> <<email>> <timestamp> <tz>\n
  committer <name> <<email>> <timestamp> <tz>\n
  \n
  <commit message>\n
  ```

## Java specifics — lookup, don't memorize
- `System.currentTimeMillis() / 1000` — fetches standard seconds-since-epoch UNIX timestamp.
- `String.getBytes(StandardCharsets.UTF_8)` — produces byte buffer for hashing.

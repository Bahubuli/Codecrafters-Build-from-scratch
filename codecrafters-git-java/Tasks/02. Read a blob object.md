# Stage 2: Read a blob object

## In one line
Locating a content-addressed object in `.git/objects/<2-char-prefix>/<38-char-hash>`, decompressing it via Zlib inflation, stripping the `<type> <size>\0` header, and streaming the raw content bytes to stdout without trailing newlines.

## Self-test (cover the answers below and answer these first)
- Why does Git shard the 40-character SHA-1 hash into a 2-character directory and 38-character filename?
- What is the binary wire layout of an uncompressed Git blob object?
- Why must `cat-file -p` write raw bytes to stdout rather than using `System.out.println()`?

## The problem it solved
Git stores files content-addressably as immutable blobs. To reconstruct the exact contents of any file across revisions, Git requires a low-level plumbing utility (`cat-file -p`) that bypasses working tree indexes and directly inspects the underlying object database.

## Concepts (the transferable part)
- **Content-Addressable Storage (CAS)**: Files are named exclusively by the cryptographic hash of their content plus header (`SHA-1(header + content)`). Identical files across commits, branches, or repositories share the exact same object on disk (automatic deduplication).
- **Filesystem Sharding (Fanout)**: Storing millions of files in a single flat directory causes severe performance degradation on most filesystems (directory lock contention and linear scan lookups). Splitting the 40-character hex hash into $16^2 = 256$ subdirectories (`.git/objects/xx/`) bounds directory entry counts.
- **Envelope Framing**: Every Git object begins with an ASCII header `<type> <size>\0` followed immediately by the raw payload bytes, enabling self-describing streaming deserialization.

## What breaks it (failure modes)
- Appending a newline `\n` to the output (e.g. `println` instead of `write`), corrupting binary blobs or exact byte-for-byte reproductions.
- Assuming the header is a fixed size rather than scanning for the null byte delimiter `\0`.
- Decoding raw blob bytes into strings using platform-default charsets instead of emitting raw byte streams.

## Tradeoffs
- Full-file Zlib compression vs Delta compression — Loose objects use simple zlib compression for fast, independent writes; packfiles later introduce cross-object delta compression to minimize disk footprint.

## CLI / Protocol format
- Command: `./your_program.sh cat-file -p <blob_sha>`
- Object path on disk: `.git/objects/<sha[0..1]>/<sha[2..39]>`
- Uncompressed byte format:
  ```
  +------+---+--------+----+---------------------+
  | blob |   | <size> | \0 | <binary payload...> |
  +------+---+--------+----+---------------------+
  ```

## Java specifics — lookup, don't memorize
- `new InflaterInputStream(new FileInputStream(objectFile))` — decompresses zlib-compressed input streams.
- `System.out.write(decompressed, nullIndex + 1, length)` — streams exact raw bytes without newline contamination.

# Stage 3: Print table names

## In one line
Decode table B-tree leaf cells on page 1 via the cell pointer array, unpack SQLite varints and record headers, and extract user table names from the `sqlite_schema` table.

## The problem it solved
Previously, we could only report the total number of cells on page 1 without knowing what data those cells held. Implementing cell and record deserialization allows us to inspect the master schema catalog (`sqlite_schema`), differentiate user tables from internal tables or index definitions, and extract actual table names.

## Concepts (the transferable part)
- **Cell Pointer Array** — An array of 2-byte offsets immediately following the B-tree page header that points to the beginning of each cell on the page, keeping cell keys sorted logically without physically rearranging cell payloads.
- **Variable-Length Integer (Varint)** — A 1-to-9 byte compact integer representation where the high bit (0x80) of the first 8 bytes serves as a continuation flag, saving space for small integer values.
- **Table B-Tree Leaf Cell** — The on-disk structure storing a single table row: payload size (varint), rowid (varint), followed by the payload bytes.
- **Record Serialization Format** — Self-describing row format containing a header (header size + sequence of serial types for each column) followed by contiguous raw column values.
- **Serial Type Codes** — Numerical codes that specify both column data type and byte length (e.g., odd numbers >= 13 represent UTF-8 strings of length `(N - 13) / 2`).

## What breaks it (failure modes)
- **Miscalculating Varint 9th Byte** — The 9th byte of a SQLite varint does NOT use bit 7 as a continuation flag; all 8 bits contribute directly to the value. Masking it with `0x7F` drops the most significant bit.
- **Record Header Boundary Overflow** — Not tracking the starting position of the record header when reading serial types can lead to reading body data as serial type varints. The loop condition must stop when `bytesRead == headerSize`.
- **Including Internal SQLite Tables** — SQLite creates internal metadata tables like `sqlite_sequence` (for autoincrement keys) or `sqlite_stat1`. Failing to exclude tables starting with `sqlite_` pollutes user table listings.
- **Non-Table Schema Entities** — `sqlite_schema` stores indexes, triggers, and views in addition to tables. Failing to verify `type == "table"` erroneously treats indexes as tables.
- **Large Records (Overflow Pages)** — If a row payload exceeds page capacity, SQLite spills data onto overflow pages. For small schema entries this is rare, but general record readers must detect overflow pointers.

## Tradeoffs
- **Sequential Array Scan vs On-the-Fly Byte Streaming** — Reading the entire page into a `byte[]` / `ByteBuffer` simplifies random cell offset lookups compared to repeatedly seeking on disk, at the cost of a few kilobytes of RAM per page.
- **Parsing All Columns vs Skipping Unneeded Columns** — Parsing column serial types and only reading strings for columns 0 (`type`) and 2 (`tbl_name`) avoids unnecessary string allocations for `sql` DDL text or rootpage integers.

## Storage / Protocol format

### Table B-Tree Leaf Page Layout (Page 1)
| Offset (Page 1) | Size | Description |
|---|---|---|
| 0–99 | 100 B | Database File Header |
| 100–107 | 8 B | B-Tree Page Header (`0x0d` leaf page, cell count at 103–104) |
| 108–(108 + 2*N) | 2*N B | Cell Pointer Array (N 2-byte big-endian offsets from page start) |
| ... | ... | Unallocated space |
| Cell Content Area | ... | Leaf cells growing upwards from the bottom of the page |

### Table Leaf Cell Format
| Component | Type | Description |
|---|---|---|
| `payload_size` | Varint (1–9 bytes) | Total number of bytes in the payload |
| `rowid` | Varint (1–9 bytes) | The integer rowid (table primary key) |
| `payload` | Record format | The serialized row data |

### Record Format
1. **Header**:
   - `header_size`: Varint specifying total size of header including this varint.
   - `serial_types`: Varints specifying the serial type for each column.
2. **Body**:
   - Contiguous values for each column in order according to their serial type.

### Serial Type Encoding
| Serial Type `N` | Content | Byte Length |
|---|---|---|
| `0` | NULL | 0 |
| `1` | 8-bit two's complement integer | 1 |
| `2` | 16-bit big-endian integer | 2 |
| `3` | 24-bit big-endian integer | 3 |
| `4` | 32-bit big-endian integer | 4 |
| `5` | 48-bit big-endian integer | 6 |
| `6` | 64-bit big-endian integer | 8 |
| `7` | IEEE 754 64-bit float | 8 |
| `8` | Integer constant 0 | 0 |
| `9` | Integer constant 1 | 0 |
| `>= 12` and even | BLOB | `(N - 12) / 2` |
| `>= 13` and odd | TEXT (UTF-8) | `(N - 13) / 2` |

## Java specifics — lookup, don't memorize
- `ByteBuffer.wrap(byte[] array)` — wraps an in-memory byte array for indexed and relative buffer operations.
- `ByteBuffer.position(int newPosition)` — repositions buffer read cursor to a specified offset within the page.
- `ByteBuffer.get()` — reads the next byte and increments the position by 1.
- `ByteBuffer.getShort(int index)` — reads a 2-byte big-endian short at the specified absolute index without advancing position.
- `Short.toUnsignedInt(short s)` — converts signed 16-bit short to unsigned 32-bit integer (`0` to `65535`).
- `String.join(" ", list)` — joins a collection of strings with a single space delimiter.

# Stage 6: Read data from multiple columns

## In one line
Parse arbitrary comma-separated projection lists in `SELECT` queries, map each requested column to its schema index, unpack record values in physical sequence, and pipe-delimit output in the requested projection order.

## Self-test (cover the answers below and answer these first)
- Why must a query projection maintain an independent column ordering from the physical column ordering stored on disk?
- How does unpacking all column values into a random-access buffer/array prevent corrupting record offsets when projected columns appear out of schema order?
- What happens when a multi-column projection requests both a regular column and an `INTEGER PRIMARY KEY` column?
- Why can't we simply skip forward through serial types when columns are requested in non-monotonic order (e.g. `SELECT col3, col1`)?

## The problem it solved
In Stage 5, our engine only supported extracting a single column and assumed monotonic single-column extraction by skipping preceding bytes up to that target. Real SQL queries request arbitrary subsets of columns in any specified order (e.g., `SELECT name, color FROM apples` or `SELECT color, name FROM apples`). We now decouple the SQL query's projected column list from the physical record serialization order, unpacking record payloads into a random-access row representation and formatting output rows delimited with `|`.

## Concepts (the transferable part)
- **Projection vs Storage Decoupling** — Relational algebra projections (`SELECT c1, c2, ...`) allow clients to request columns in any permutation. Because SQLite physical records always serialize column values in strict schema definition order, query execution requires an index mapping layer (`projection_index -> schema_index`).
- **Full Row Unpacking vs Multi-pass Seeking** — Physical records are length-prefixed and contiguous. Extracting multiple columns in non-consecutive or reverse order requires either decoding all columns sequentially into an in-memory row array or re-seeking the record stream for each column. Sequential unpacking in one pass over the record body is $O(C)$ where $C$ is column count.
- **Pipe-Delimited Output Serialization** — The standard SQLite command-line interface output format (`.mode list`, delimiter `|`) flattens projected column values separated by `|` with null/empty values emitting empty strings between delimiters.
- **INTEGER PRIMARY KEY Projection Harmony** — An `INTEGER PRIMARY KEY` column continues to alias `rowid` (serial type 0 in payload) even when projected alongside standard payload-backed columns, requiring per-column metadata awareness during row extraction.

## What breaks it (failure modes)
- **Non-Monotonic Column Ordering** — A query like `SELECT color, name` requests schema column 2 before schema column 1. Attempting to skip forward through `pageBuffer` without reading or pre-caching will fail because the buffer position cannot go backwards without re-seeking.
- **Whitespace & Quoting in Comma-Separated Columns** — Column lists often have irregular spacing (`SELECT name ,  color`) or identifier quoting (`SELECT "name", `color``). Splitting by `,` requires trimming and quote stripping per token.
- **Null Value Formatting in String.join** — If a column value is `null`, naive `String.join` in Java or formatting routines can inject `"null"` strings or throw exceptions; null columns must be normalized (e.g., empty string `""` or handled cleanly).
- **Schema vs Payload Column Count Mismatch** — In tables altered by `ALTER TABLE ADD COLUMN`, a record on disk may contain fewer serialized values than the current schema definition. Missing trailing columns default to `NULL` (or `rowid` if `INTEGER PRIMARY KEY`).

## Tradeoffs
- **Single-Pass Array Decode vs On-Demand Column Skipping** — Single-pass decoding unpacks all column values into an array `String[numCols]` in a single forward scan. This costs a small temporary array allocation per row but seamlessly handles repeated, omitted, or reordered columns in $O(N)$ time, avoiding complex index backtracking.
- **Simple Comma Tokenization vs SQL AST Parser** — Splitting projected expressions by `,` handles column lists accurately for standard `SELECT` projections without pulling in or writing a complete SQL grammar parser.

## Storage / Protocol format

### SQLite Leaf Record Decoding Stream
```
Cell Offset
  │
  ├─► payload_size (varint)
  ├─► rowid (varint)
  │
  └─► Record Payload
        ├─► Header: [header_size : varint] [serial_type_0] [serial_type_1] ... [serial_type_K]
        │
        └─► Body:   [value_0] [value_1] ... [value_K]
                     │         │             │
                     ▼         ▼             ▼
               recordValues[0], recordValues[1], ... recordValues[K]
```

### Projection Mapping Pipeline
```
SQL Query:   SELECT color, name FROM apples
Schema:      [0: id (PK), 1: name (text), 2: color (text)]
Target Idxs: [2, 1]

Record Payload Body -> Decoded Row Array:
recordValues = ["1", "Granny Smith", "Light Green"]
                      ▲               ▲
                      │               │
Target Idx 2 ─────────┼───────────────┘  ("Light Green")
Target Idx 1 ─────────┘                  ("Granny Smith")

Output: "Light Green|Granny Smith"
```

## Java specifics — lookup, don't memorize
- `String.split(String regex)` — Splits a string around matches of the given regular expression (e.g., `","`).
- `String.join(CharSequence delimiter, Iterable<? extends CharSequence> elements)` — Joins an iterable collection of character sequences into a single string with the given delimiter.
- `Math.max(int a, int b)` — Returns the greater of two `int` values, useful for sizing row value arrays against both schema and payload counts.

## Rebuild checklist
- [ ] Parse projection list by splitting the `SELECT` expression on `,` and normalizing whitespace and identifier quotes.
- [ ] Map each requested column name to its 0-based column index from the table's parsed schema.
- [ ] Detect unknown column names and report an error if any requested column does not exist in the schema.
- [ ] Decode record header serial types and sequentially unpack record body values into an in-memory array.
- [ ] Substitute `rowid` for any requested column identified as `INTEGER PRIMARY KEY` when serial type is 0 or beyond payload size.
- [ ] Assemble the requested column values in query order and format them using `String.join("|", rowValues)`.

# Stage 1: Print page size

## In one line
Extract database page size by reading a 2-byte big-endian unsigned short at byte offset 16 of the 100-byte SQLite database header.

## Self-test (cover the answers below and answer these first)
- Where is the database page size stored in a SQLite file, and what endianness is used?
- What does a page size value of 1 represent in the SQLite database header?
- Why does SQLite store metadata in fixed-size offsets in the file header rather than inside a table?

## The problem it solved
Before this stage, there was no way to inspect the basic block geometry of a SQLite database file. By reading the page size, the engine knows the fixed chunk size by which all B-tree pages and offsets in the file are addressed.

## Concepts (the transferable part)
- **Database Header** — A fixed 100-byte structure at the very beginning of the database file containing global configuration (magic string, page size, file format versions, reserved space).
- **Endianness (Big-Endian)** — Multi-byte numeric fields in SQLite's header and B-tree records are stored most-significant-byte first (network byte order).
- **Page Size Representation** — Represented as a 2-byte integer; 0x0001 is a special sentinel denoting 65536 (2^16), since 65536 cannot fit into a standard 16-bit unsigned integer.

## What breaks it (failure modes)
- Small / Truncated File — If the file has fewer than 18 bytes, attempting to read the header throws an EOF or `IOException`.
- Page size value of 1 — Naive parsing reads `1` instead of `65536`, breaking all subsequent page calculations.
- Signed 16-bit overflow — Java's `short` is signed (-32768 to 32767). A page size of 32768 becomes negative if converted to `int` without unsigned handling (`Short.toUnsignedInt`).

## Tradeoffs
- Fixed-size header at file start vs dynamic metadata block — Fixed-size header allows O(1) instantaneous access without parsing any B-trees or schema tables.

## Storage / Protocol format
| Byte Offset | Size (Bytes) | Description |
|---|---|---|
| 0–15 | 16 | The header string: `"SQLite format 3\000"` |
| 16–17 | 2 | Database page size in bytes (big-endian unsigned short). Must be power of 2 between 512 and 32768 inclusive, or 1 representing 65536 |

## Java specifics — lookup, don't memorize
- `FileInputStream.skip(n)` — advances the file stream position by `n` bytes.
- `ByteBuffer.wrap(bytes).getShort()` — reads two bytes as a big-endian 16-bit short.
- `Short.toUnsignedInt(s)` — converts a signed 16-bit short to an unsigned 32-bit integer.

## Rebuild checklist
- [ ] Open a `FileInputStream` or `RandomAccessFile` for the database file.
- [ ] Skip the 16-byte magic string `"SQLite format 3\0"`.
- [ ] Read 2 bytes into a byte buffer and unpack as big-endian.
- [ ] Convert unsigned short to integer, checking if value is 1 (mapping to 65536).
- [ ] Print `database page size: <size>`.

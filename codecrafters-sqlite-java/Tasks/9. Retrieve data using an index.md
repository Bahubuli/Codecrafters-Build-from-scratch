# Stage 9: Retrieve data using an index

## In one line
Locate secondary index B-trees in `sqlite_schema`, perform $O(\log N)$ range search over index interior (`0x02`) and leaf (`0x0A`) pages to collect matching table `rowid`s, and perform $O(\log N)$ table B-tree point lookups to project results in milliseconds.

## The problem it solved
In Stage 8, executing a query with a `WHERE` clause on a multi-page table required a full table scan ($O(N)$), inspecting every leaf page and decoding every record. On gigabyte-scale tables (e.g. 1GB `companies.db`), a full scan reads hundreds of megabytes from disk and exceeds the strict 3-second runtime budget. By querying secondary index B-trees created on filter columns, we retrieve only the relevant `rowid`s via binary tree search and perform direct point lookups in the table B-tree, reducing disk I/O from $O(N)$ to $O(K \log N)$ where $K$ is the number of matching rows.

## Concepts (the transferable part)
- **Secondary Index B-tree** — A separate B-tree whose keys are composite records `(indexed_column_value, rowid)`. Because `rowid` is appended to the indexed value, every index entry is unique and naturally sorted first by the indexed value and then by `rowid`.
- **Index B-tree Layout (`0x02` Interior, `0x0A` Leaf)**:
  - Unlike table B+trees where row data only exists in leaf pages, index B-trees store index records in both interior cells and leaf cells.
  - Interior cell: `[4-byte leftChildPage, varint payloadSize, record payload (key + rowid)]`.
  - Leaf cell: `[varint payloadSize, record payload (key + rowid)]`.
- **Branch Pruning in Index Interior Pages**:
  - Left child $P_i$ contains keys in the half-open interval $(C_{i-1}, C_i]$.
  - $P_i$ can contain `target` if and only if $C_i \ge target$ and ($i == 0$ or $C_{i-1} \le target$).
  - Once $C_i > target$, no subsequent cell or subtree on this interior page can contain `target`, allowing immediate search termination.
- **Index-to-Table Point Lookup ($O(\log N)$)**:
  - For each `rowid` identified by the index scan, we navigate the table B-tree from root to leaf by comparing `targetRowid` against interior cell routing keys, loading only the specific leaf page containing the target row.

## What breaks it (failure modes)
- **Treating Index Cells like Table Cells** — Table leaf cells (`0x0D`) store `[payloadSize, rowid, payload]`. Index cells (`0x0A` and `0x02`) do NOT store a separate `rowid` field; the `rowid` is serialized as the last column of the payload record itself.
- **Forgetting Interior Index Cell Payloads** — In an index B-tree, an interior cell's record itself can be an exact match for the target value! Ignoring the interior cell's own record loses matching rows.
- **Missing Multi-Value Equality Branches** — When many rows share the same indexed value (e.g. dozens of companies in `"eritrea"`), matches can span across multiple leaves and interior branches. Stopping at the first match or failing to inspect boundary subtrees omits valid rows.
- **Unordered Output** — Queries expect deterministic row emission. Index entries for identical column values are ordered by `rowid`. Sorting collected `rowid`s ensures ascending order and eliminates duplicate lookups.
- **Full Table Scan Fallback** — If no index exists for the `WHERE` column, the engine must gracefully fall back to the recursive `traverseTableBtree` full-scan path rather than failing.

## Tradeoffs
- **Index Scan + Random Table Lookups vs Full Table Scan** — For highly selective queries ($K \ll N$), index lookup reads $O(K \log N)$ pages vs $O(N)$ pages. If $K \approx N$ (low selectivity), a full sequential table scan is faster because sequential I/O avoids repetitive root-to-leaf traversals.
- **Clustered Index vs Secondary Index** — In SQLite, the table B-tree is clustered by `rowid`. Secondary indexes require an extra pointer dereference (index lookup $\to$ rowid $\to$ table lookup). Covering indexes (where all projected columns are in the index) eliminate the secondary table lookup entirely.

## Storage / Protocol format

### Index Page Headers & Cell Structure
```
Interior Index Page (0x02):
  [0x02][freeblock 2B][cellCount 2B][cellContent 2B][frag 1B][rightChildPage 4B]
  Cell pointers: [offset 0][offset 1]... (starts at offset 12)
  Cell: [4-byte leftChildPage][varint payloadSize][Record: header + key + rowid]

Leaf Index Page (0x0A):
  [0x0A][freeblock 2B][cellCount 2B][cellContent 2B][frag 1B]
  Cell pointers: [offset 0][offset 1]... (starts at offset 8)
  Cell: [varint payloadSize][Record: header + key + rowid]
```

### Two-Phase Index-Driven Query Execution
```
Query: SELECT id, name FROM companies WHERE country = 'eritrea'

Phase 1: Index Range Scan (idx_companies_country, rootpage)
  [Root Interior Page 0x02]
       │
       ├─► Left Child (keys <= "brazil")       ──► SKIP
       ├─► Left Child (keys in ("brazil", "eritrea"]) ──► VISIT Leaf Page 0x0A
       │                                                   ├─► Match: rowid 121311
       │                                                   ├─► Match: rowid 2102438
       ├─► Left Child (keys in ("eritrea", "france"]) ──► VISIT Leaf Page 0x0A
       │                                                   ├─► Match: rowid 5729848
       │                                                   ├─► Match: rowid 6634629
       └─► Cell key "france" > "eritrea"       ──► PRUNE REMAINING SUBTREES

  Matched rowids: [121311, 2102438, 5729848, 6634629]

Phase 2: Table Point Lookups (companies, rootpage)
  For each rowid in [121311, 2102438, 5729848, 6634629]:
    Traverse Table B-tree (0x05 -> 0x0D) -> Decode record -> Print "id|name"
```

- [ ] If `query.whereColumn` matches an index, route execution to `searchIndexBtree`.
- [ ] Parse index interior cells (`0x02`): read 4-byte `leftChildPage`, payload size, and record (`key`, `rowid`).
- [ ] Implement branch pruning: visit $P_i$ if $(prevKey \le target \land cellKey \ge target)$, match cell if $cellKey == target$, prune when $cellKey > target$.
- [ ] Parse index leaf cells (`0x0A`): read payload size, unpack record, extract `key` and trailing `rowid`.
- [ ] Deduplicate and sort collected `rowid`s.
- [ ] Implement `findRowByRowid`: traverse table B-tree interior pages (`0x05`) using `targetRowid <= key` branching.
- [ ] At table leaf page (`0x0D`), match cell `rowid == targetRowid`, unpack columns, and print projection.
- [ ] Fall back to full-table scan (`traverseTableBtree`) if no matching index exists.

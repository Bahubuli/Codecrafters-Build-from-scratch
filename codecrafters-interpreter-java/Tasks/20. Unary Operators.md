# Stage 20: Unary Operators

## In one line

## The problem it solved
Before this stage, expressions only supported primary atoms (literals and parenthesized groups). Prepending unary operators such as `-` (arithmetic negation) or `!` (logical NOT) failed syntax validation. This stage introduces unary prefix operators and their recursive nesting.

## Concepts (the transferable part)
- **Operator Precedence in Recursive Descent** — Precedence is established by the order in which parsing methods call each other. Because `unary()` calls `primary()` on the base case, unary operators have higher binding power than binary multiplication, division, addition, or subtraction.
- **Right Associativity of Unary Operators** — Unlike binary operators which are left-associative ($a - b - c = (a - b) - c$), consecutive unary operators associate from right to left ($!-x = !(-(x))$). To reflect this, the recursive descent parser calls `unary()` on the right operand rather than `primary()`.
- **Prefix AST Formatting** — `AstPrinter` formats unary expressions using Lisp-style S-expressions: `(<operator> <operand>)` (e.g. `!true` $\to$ `(! true)`, `-52` $\to$ `(- 52.0)`).

## What breaks it (failure modes)
- **Missing Recursive Call (`primary()` instead of `unary()`)** — If the unary handler calls `primary()` directly for the operand, chained unary operations like `!!true` or `--5` fail to parse. Calling `right = unary()` enables arbitrary chaining.
- **Whitespace Misalignments in AST Output** — The prefix format requires a single space between the operator symbol and the operand: `(! true)`, not `(!true)`.

## Tradeoffs
- **Prefix AST Serialization vs Infix** — S-expression prefix notation unambiguously defines evaluation order without requiring parentheses for precedence, making it ideal for verifying AST structural correctness.

## CLI / Protocol format
- Execution: `./your_program.sh parse <filename>`
- Output format:
  - `stdout`: `(<operator> <operand>)`
  - Examples:
    - Input `!true` $\to$ Output `(! true)`
    - Input `-52` $\to$ Output `(- 52.0)`
    - Input `!(true)` $\to$ Output `(! (group true))`
    - Input `!(!true)` $\to$ Output `(! (! true))`
- Exit code: `0` on success.

## Java specifics — lookup, don't memorize
- `Expr.Unary(Token operator, Expr right)` — AST node storing the prefix operator token and recursive operand.
- `parenthesize(expr.operator.lexeme, expr.right)` — Formats the unary prefix S-expression.

# Stage 45: Variables: Redeclare variables

## In one line
Allowing variable redeclaration in global scope where new declarations overwrite existing bindings, evaluating initializer expressions before rebinding.

## Self-test (cover the answers below and answer these first)
- When executing `var a = a;` globally, what value is read by the initializer?
- Does `Environment.define` check if a variable already exists before adding/replacing the entry?
- Why is global variable redeclaration permitted in scripting languages?

## The problem it solved
In dynamic scripting languages and REPL environments, re-declaring an existing variable identifier with `var x = ...;` is allowed and simply replaces the previous binding. The interpreter must correctly evaluate the right-hand side initializer *before* the variable is defined or overwritten in the environment.

## Concepts (the transferable part)
- **Order of Evaluation in Variable Declarations (`Interpreter.java`)**:
  ```java
  @Override
  public Void visitVarStmt(Stmt.Var stmt) {
      Object value = null;
      if (stmt.initializer != null) {
          value = evaluate(stmt.initializer);
      }

      environment.define(stmt.name.lexeme, value);
      return null;
  }
  ```
  Evaluating `stmt.initializer` before calling `define` ensures that self-referential initializers like `var hello = hello;` look up the previous binding of `hello` in `environment` before replacing it.
- **Unchecked Replacement in Global Map (`Environment.java`)**:
  ```java
  public void define(String name, Object value) {
      values.put(name, value);
  }
  ```
  `Map.put` automatically replaces any previously associated value for that key name.

## What breaks it (failure modes)
- Inserting the new variable into the environment before evaluating the initializer expression.
- Rejecting redeclarations in global scope as errors.

## Tradeoffs
- Permitting global redeclarations makes interactive sessions easy to re-run, but can hide accidental variable shadowing or duplicate declarations in large programs (which is why local variables inside blocks forbid duplicate declarations in the same scope).

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  var a = 1;
  var a = 2;
  print a;
  ```
- Stdout: `2`
- Exit code: `0`

## Java specifics — lookup, don't memorize
- `java.util.Map.put(K key, V value)` associates the specified value with the specified key in this map. If the map previously contained a mapping for the key, the old value is replaced.

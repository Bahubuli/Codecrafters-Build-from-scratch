# Stage 70: Invalid Return

## In one line
Compile-time static tracking of function enclosure via `FunctionType` enum to reject `return` statements outside function bodies.

## Self-test (cover the answers below and answer these first)
- Why cannot the parser alone easily distinguish valid returns inside nested blocks from invalid returns in top-level blocks?
- How does `Resolver` track whether the code being visited is currently inside a function?
- What happens when a function contains a nested block containing a return?

## The problem it solved
`return` transfers control out of a function call frame. When written at top-level or inside a non-function block (e.g. `{ return 1; }` at script level), there is no function call frame to return from. Catching this statically during semantic analysis (resolution) prevents runtime crashes and gives clear, early compiler error diagnostics.

## Concepts (the transferable part)
- **Function Context Tracking**:
  `Resolver` maintains a state variable `currentFunction` of enum type `FunctionType` (`NONE`, `FUNCTION`).
  ```java
  private enum FunctionType {
      NONE,
      FUNCTION
  }

  private FunctionType currentFunction = FunctionType.NONE;
  ```
- **Context Stack via Local Variable**:
  When visiting a function:
  ```java
  FunctionType enclosingFunction = currentFunction;
  currentFunction = type;

  // resolve parameters and body...

  currentFunction = enclosingFunction;
  ```
  This creates a call-stack-like nesting discipline for semantic analysis. Even if functions are nested inside blocks, `currentFunction` accurately reflects whether an active enclosing function exists.
- **Enforcing Return Legality**:
  In `Resolver.visitReturnStmt`:
  ```java
  if (currentFunction == FunctionType.NONE) {
      Main.error(stmt.keyword, "Can't return from top-level code.");
  }
  ```

## What breaks it (failure modes)
- Only checking if `scopes.isEmpty()` for return statements: a block `{ return 1; }` at top-level pushes a scope to `scopes`, but is still top-level code outside any function!
- Failing to restore `currentFunction = enclosingFunction` when exiting a function, which would leave subsequent top-level code believing it is inside a function.
- Permitting return statements in top-level `if` branches or loops.

## Tradeoffs
- Static analysis pass easily distinguishes block scope from function enclosure without polluting runtime call stack logic.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox

    return "not allowed in a block either";

  ```
- Stderr:


## Java specifics — lookup, don't memorize
- Local stack saving: saving `enclosingFunction` as a method-local variable in `resolveFunction` and restoring it at the end avoids needing an explicit `Stack<FunctionType>` collection.

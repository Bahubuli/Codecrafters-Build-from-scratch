# Stage 59: Functions without arguments

## In one line
Declaring, parsing, and interpreting parameterless user-defined functions using `Stmt.Function` and closure-aware `LoxFunction`.

## The problem it solved
Programs need named, reusable blocks of code that can be invoked on demand. We need to parse function declaration syntax (`fun name() { ... }`), bind the resulting function to its identifier in the current scope, and execute the function body in a newly created environment chained to its declaration-time closure.

## Concepts (the transferable part)
- **Function Declaration Grammar**:
  ```
  declaration  → funDecl | varDecl | statement ;
  funDecl      → "fun" function ;
  function     → IDENTIFIER "(" parameters? ")" block ;
  parameters   → IDENTIFIER ( "," IDENTIFIER )* ;
  ```
- **The `Stmt.Function` AST Node**:
  Stores `name` (`Token`), `params` (`List<Token>`), and `body` (`List<Stmt>`).
- **The `LoxFunction` Class**:
  Implements `LoxCallable`. Stores the declaration AST and captures the active lexical `Environment` (closure) where the function was declared:
  ```java
  public class LoxFunction implements LoxCallable {
      private final Stmt.Function declaration;
      private final Environment closure;

      public LoxFunction(Stmt.Function declaration, Environment closure) {
          this.declaration = declaration;
          this.closure = closure;
      }

      @Override
      public int arity() {
          return declaration.params.size();
      }

      @Override
      public Object call(Interpreter interpreter, List<Object> arguments) {
          Environment environment = new Environment(closure);
          for (int i = 0; i < declaration.params.size(); i++) {
              environment.define(declaration.params.get(i).lexeme, arguments.get(i));
          }
          try {
              interpreter.executeBlock(declaration.body, environment);
          } catch (Return returnValue) {
              return returnValue.value;
          }
          return null;
      }

      @Override
      public String toString() {
          return "<fn " + declaration.name.lexeme + ">";
      }
  }
  ```
- **String Representation**:
  When a function object is evaluated and printed directly (`print foo;`), it produces `<fn name>`.

## What breaks it (failure modes)
- Executing the function body in the caller's environment instead of the closure environment (dynamic scoping bug instead of lexical scoping).
- Forgetting to chain the function call's execution environment to `closure`.
- Failing to return `null` (`nil`) when execution reaches the end of the body without an explicit return statement.

## Tradeoffs
- Capturing the environment at definition time enables proper closures and lexical scoping at the expense of holding environment references as long as the function is referenced.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  fun foo() {
    print 7;
  }
  foo();
  ```
- Stdout:
  ```
  7
  ```
- Exit code: `0`

# Stage 50: Else statements

## In one line
Extending `if` conditional evaluation to branch into an `else` block when the condition expression evaluates to falsey (`false` or `nil`).

## Self-test (cover the answers below and answer these first)
- Under what conditions is the `elseBranch` of `Stmt.If` executed?
- Why does recursive descent grammar matching prevent dangling else ambiguities without special backtracking?
- What values trigger the `else` branch in Lox?

## The problem it solved
Two-way branching requires executing an alternative statement or block when the condition predicate evaluates to false. The interpreter must conditionally execute `stmt.elseBranch` if and only if `!isTruthy(evaluate(stmt.condition))` and `stmt.elseBranch != null`.

## Concepts (the transferable part)
- **Grammar with Optional `else`**:
  ```
  ifStmt → "if" "(" expression ")" statement
           ( "else" statement )? ;
  ```
- **Recursive Descent Resolution**:
  ```java
  Stmt thenBranch = statement();
  Stmt elseBranch = null;
  if (match(TokenType.ELSE)) {
      elseBranch = statement();
  }
  return new Stmt.If(condition, thenBranch, elseBranch);
  ```
  Since `ifStatement()` recursively parses its `thenBranch` as a `statement()`, an inner `if` will consume the nearest following `else` token before the outer `if` gets a chance to see it, cleanly resolving the dangling else ambiguity.
- **Executing the Else Branch (`Interpreter.java`)**:
  ```java
  @Override
  public Void visitIfStmt(Stmt.If stmt) {
      if (isTruthy(evaluate(stmt.condition))) {
          execute(stmt.thenBranch);
      } else if (stmt.elseBranch != null) {
          execute(stmt.elseBranch);
      }
      return null;
  }
  ```
  If the condition is truthy, only `thenBranch` runs. If falsey, `thenBranch` is skipped and `elseBranch` runs if present.

## What breaks it (failure modes)
- Treating only `false` as falsey instead of both `false` and `nil`.
- Not null-checking `elseBranch` before invoking `execute()`.
- Prematurely popping scope when the else branch is an unnested statement instead of a block.

## Tradeoffs
- Simple AST-based evaluation executes statements directly via recursion on Java call stack. Does not optimize jump conditions as a bytecode VM would.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  var age = 21;
  if (age > 18) print "adult"; else print "child";
  ```
- Stdout:
  ```
  adult
  ```
- Exit code: `0`

## Java specifics — lookup, don't memorize
- `null` checks protect optional AST branches:
  ```java
  } else if (stmt.elseBranch != null) {
      execute(stmt.elseBranch);
  }
  ```

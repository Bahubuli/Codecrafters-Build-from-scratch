# Stage 03: Scanning: Braces

## In one line
Curly braces `{` and `}` are scanned into `LEFT_BRACE` and `RIGHT_BRACE` tokens, extending block delimiter lexical recognition without enforcing scoping or nesting rules at the scanner layer.

## The problem it solved
Prior to this stage, curly braces `{` and `}` encountered in the source code caused unexpected character errors and set the error flag. This stage introduces lexical tokenization for block delimiters (`LEFT_BRACE` and `RIGHT_BRACE`), enabling the scanner to recognize statement blocks and function bodies as distinct lexical tokens.

## Concepts (the transferable part)
- **Delimiters as Pure Lexical Units** — In a lexical analyzer, tokens are classified purely by character sequences without context or semantics. The scanner does not know or care whether `{` opens a function, a loop body, a class definition, or an invalid expression.
- **Independence of Syntax Validation** — Validating brace matching, block structure, or scoping belongs exclusively to the parser and compiler/interpreter environment, never to the scanner. Mismatched or unbalanced braces are valid tokens, not lexical errors.
- **Single-Character Token Expansion** — Extending the lexical grammar for additional non-overlapping single-character tokens is purely additive with O(1) matching complexity in a switch construct.

## What breaks it (failure modes)
- Confusing lexical errors with syntax errors — Throwing a scanner error on unmatched `{` or unexpected `}` breaks the compilation pipeline, preventing proper error recovery and reporting by the parser.
- Missing break statements in switch — In Java's classic switch syntax, omitting `break` leads to fallthrough bugs (e.g. falling into whitespace or error cases).

## Tradeoffs
- Direct switch expansion vs Table-driven tokenizer — Direct switch cases for single-character tokens keep the scanning loop branch-predictable, zero-allocation, and immediately readable, whereas a table-driven approach introduces indirection without tangible performance benefits for small token sets.

## CLI / Protocol format
- Execution: `./your_program.sh tokenize <filename>`
- Output format: `<token_type> <lexeme> <literal>`
- Example for input `{{}}`:
  ```
  LEFT_BRACE { null
  LEFT_BRACE { null
  RIGHT_BRACE } null
  RIGHT_BRACE } null
  EOF  null
  ```

## Java specifics — lookup, don't memorize
- `switch` statement on `char` primitive — Dispatches on the primitive UTF-16 code unit value without boxing overhead.

# Stage 56: For statements

## In one line
Desugaring C-style `for (init; condition; increment) body` loops into equivalent `while` loops wrapped in a scoping block.

## Self-test (cover the answers below and answer these first)
- Why is `for` implemented via desugaring rather than creating a new AST node and interpreter visitor?
- If the increment clause is present, where does it execute relative to the loop body?
- Why must the entire `for` loop (including its initializer) be wrapped in an outer block?

## The problem it solved
C-style `for` loops provide a concise syntax for iteration with loop variables, conditions, and increments. Adding a bespoke bytecode instruction or interpreter visitor for `for` creates redundant execution semantics already present in `while`, `block`, and expression statements.

## Concepts (the transferable part)
- **Syntactic Sugar / Desugaring**:
  Translating a richer syntactic construct into equivalent combinations of simpler, already existing primitives during the parsing phase.
- **For-to-While Transformation**:
  A `for` loop consists of up to 4 optional components:
  1. `initializer` (var decl, expression statement, or omitted)
  2. `condition` (expression, or defaults to `true`)
  3. `increment` (expression evaluated after each body iteration)
  4. `body` (statement)

  Desugaring sequence:
  ```java
  // 1. If increment exists, append to body
  if (increment != null) {
      body = new Stmt.Block(Arrays.asList(body, new Stmt.Expression(increment)));
  }

  // 2. Wrap in while loop with condition (default true)
  if (condition == null) condition = new Expr.Literal(true);
  body = new Stmt.While(condition, body);

  // 3. If initializer exists, place in enclosing block so loop variable is scoped
  if (initializer != null) {
      body = new Stmt.Block(Arrays.asList(initializer, body));
  }
  ```
- **Lexical Scope Isolation**:
  Wrapping `initializer` and the `while` loop inside an outer block ensures the loop variable is scoped strictly to the loop construct and does not leak into the enclosing environment.

## What breaks it (failure modes)
- Not wrapping `initializer` in a block, which leaks loop variables like `var i = 0` into the parent environment.
- Omitting the default `true` condition when the condition clause is empty (e.g., `for (;;) body`), leading to null pointer exceptions or false terminations.
- Executing the increment before the body instead of after.

## Tradeoffs
- Desugaring keeps the AST lean, minimizes runtime visitor code, and eliminates potential bugs from duplicate control flow implementations.

## Java specifics — lookup, don't memorize
- `Arrays.asList(...)` constructs fixed-size lists suitable for composing AST statement blocks.

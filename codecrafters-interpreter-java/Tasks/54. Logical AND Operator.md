# Stage 54: Logical AND operator

## In one line
Short-circuit evaluation of logical AND expressions returning the first falsey operand or the last truthy operand.

## Self-test (cover the answers below and answer these first)
- In `false and 1`, why is the output `false` and not a type error?
- In `23 and "hello" and 23`, what value is returned and why?
- How does the grammar ensure that `and` binds tighter than `or`?

## The problem it solved
Conjunction requires verifying that multiple conditions are simultaneously true. For safety and performance, if any condition evaluates to a falsey value (`false` or `nil`), subsequent conditions and any associated side effects must not be executed.

## Concepts (the transferable part)
- **Precedence Hierarchy**:
  In Boolean algebra and programming language grammars, AND has higher precedence than OR (analogous to multiplication before addition):
  ```
  logic_or       → logic_and ( "or" logic_and )* ;
  logic_and      → equality ( "and" equality )* ;
  ```
  This ensures expressions like `a and b or c and d` parse as `(a and b) or (c and d)`.
- **Short-circuiting Falsey Values**:
  ```java
  @Override
  public Object visitLogicalExpr(Expr.Logical expr) {
      Object left = evaluate(expr.left);

      if (expr.operator.type == TokenType.OR) {
          if (isTruthy(left)) return left;
      } else { // TokenType.AND
          if (!isTruthy(left)) return left;
      }

      return evaluate(expr.right);
  }
  ```
  When `!isTruthy(left)`, evaluation halts immediately and returns `left`. When `isTruthy(left)`, it proceeds to evaluate `right`.

## What breaks it (failure modes)
- Inverting precedence by placing `or` lower than `equality` without going through `and`.
- Returning boolean `false` instead of `nil` when the falsey operand was `nil`.

## Tradeoffs
- Returning the actual operand value permits chained property access / guard patterns (e.g., `user and user.name`).

## Java specifics — lookup, don't memorize
- In Java, boolean evaluation in `&&` requires `boolean` operands. In Lox, any `Object` is accepted according to Lox truthiness rules (`nil` and `false` are falsey; all else truthy).

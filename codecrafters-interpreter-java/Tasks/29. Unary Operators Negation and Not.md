# Stage 29: Unary Operators: Negation & Not

## In one line
Evaluating unary expressions `-` (arithmetic negation) and `!` (logical NOT) using Lox's truthiness rules.

## Self-test (cover the answers below and answer these first)
- What values are considered falsey in Lox?
- Are numbers or strings like `0` or `""` considered truthy or falsey in Lox?
- How does `visitUnaryExpr()` evaluate its operand before applying the operator?

## The problem it solved
Unary operators evaluate their single right subexpression and transform the result. For arithmetic negation `-`, numbers are negated. For logical negation `!`, truth values are inverted following Lox semantics.

## Concepts (the transferable part)
- **Post-order Evaluation**:
  Unary operators evaluate their operand first (post-order / bottom-up traversal), then perform the operation:
  ```java
  Object right = evaluate(expr.right);
  switch (expr.operator.type) {
      case BANG:
          return !isTruthy(right);
      case MINUS:
          checkNumberOperand(expr.operator, right);
          return -(double) right;
  }
  ```
- **Lox Truthiness**:
  Unlike JavaScript or C, in Lox only `false` and `nil` are falsey. Numbers (including `0`) and strings (including `""`) are truthy:
  ```java
  private boolean isTruthy(Object object) {
      if (object == null) return false;
      if (object instanceof Boolean) return (boolean) object;
      return true;
  }
  ```

## What breaks it (failure modes)
- Treating `0` or `""` as falsey (violating Lox language specification).
- Negating non-number types without type checking (leads to ClassCastException).
- Inverting the precedence of unary operators.

## Tradeoffs
- Strict vs Type-coercive truthiness — Restricting falsiness strictly to `false` and `nil` prevents subtle type coercion bugs common in dynamically typed languages like JavaScript or Python.

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Examples:
  - `-73` $\to$ `-73`
  - `!true` $\to$ `false`
  - `!10.40` $\to$ `false`
  - `!((false))` $\to$ `true`
  - `-(73)` $\to$ `-73`

## Java specifics — lookup, don't memorize
- `-(double) right` — unboxing `Double` to primitive `double` for arithmetic negation.

## The problem it solved
Programs require state: the ability to bind names to values and look them up later in expressions. This stage introduces variable declarations (`var name = expression;`) and variable access identifiers as expressions.

## Concepts (the transferable part)
- **Environment Symbol Table (`Environment.java`)**:
  Manages variable bindings using an associative map and supports lexical scoping chains via an `enclosing` parent reference:
  ```java
  public class Environment {
      final Environment enclosing;
      private final Map<String, Object> values = new HashMap<>();

      public void define(String name, Object value) {
          values.put(name, value);
      }

      public Object get(Token name) {
          if (values.containsKey(name.lexeme)) return values.get(name.lexeme);
          if (enclosing != null) return enclosing.get(name);
          throw new RuntimeError(name, "Undefined variable '" + name.lexeme + "'.");
      }
  }
  ```
- **AST Nodes**:
  - `Stmt.Var(Token name, Expr initializer)`: Declares a variable with an optional initial value.
  - `Expr.Variable(Token name)`: Represents reading the value of a variable by identifier.
- **Parsing Declarations (`Parser.java`)**:
  ```java
  private Stmt varDeclaration() {
      Token name = consume(TokenType.IDENTIFIER, "Expect variable name.");
      Expr initializer = null;
      if (match(TokenType.EQUAL)) {
          initializer = expression();
      }
      consume(TokenType.SEMICOLON, "Expect ';' after variable declaration.");
      return new Stmt.Var(name, initializer);
  }
  ```
- **Primary Expression Identifier Matching**:
  In `primary()`:
  ```java
  if (match(TokenType.IDENTIFIER)) {
      return new Expr.Variable(previous());
  }
  ```

## What breaks it (failure modes)
- Confusing variable identifier resolution with keyword tokens.
- Failing to resolve chained variable references (e.g. `var quz = 76; var baz = quz;`).
- Missing semicolons at the end of `var` declarations.

## Tradeoffs
- Binding variables dynamically in a map vs static stack slots: Simple AST interpreters use a hash map `Environment` for simplicity, whereas bytecode virtual machines compile variable lookups into fixed local stack offsets for orders-of-magnitude speed improvements.

## Java specifics — lookup, don't memorize
- `Map.containsKey(key)` vs `Map.get(key) != null`: Using `containsKey` is critical because a variable explicitly initialized to `nil` will store a `null` value in Java.

# Stage 80: Inheriting Methods

## In one line
Enabling subclasses to inherit and dispatch methods from any ancestor in their class hierarchy by recursively searching the superclass chain during method lookup.

## Self-test (cover the answers below and answer these first)
- When a method is called on a subclass instance, in what order are class method tables searched?
- How does method binding interact with inherited methods (what does `this` refer to)?
- Are constructors (`init`) inherited when a subclass does not define its own initializer?

## The problem it solved
Defining a subclass hierarchy is only half of object-oriented inheritance; the core utility comes from invoking behaviors defined higher up the hierarchy on instances of derived classes, avoiding code duplication across subclasses.

## Concepts (the transferable part)
- **Recursive Method Lookup**:
  When property access `instance.get(name)` does not match an instance field, it delegates to `klass.findMethod(name)`.
  ```java
  public LoxFunction findMethod(String name) {
      if (methods.containsKey(name)) {
          return methods.get(name);
      }
      if (superclass != null) {
          return superclass.findMethod(name);
      }
      return null;
  }
  ```
- **Late Binding of `this`**:
  Even when a method is defined on a superclass (e.g. `Doughnut.cook()`), calling it on a subclass instance (`BostonCream().cook()`) binds `this` to the receiver (`BostonCream` instance) via `method.bind(this)`. Any fields accessed or mutated by the inherited method apply directly to the subclass instance.
- **Initializer Inheritance**:
  `LoxClass.call(...)` and `LoxClass.arity()` invoke `findMethod("init")`. Because `findMethod` traverses superclasses, subclasses without their own `init()` automatically inherit their parent's constructor, parameter count, and initialization logic.

## What breaks it (failure modes)
- Only checking the immediate parent class instead of recursing up multi-level hierarchies (`A < B < C`).
- Binding `this` to an instance of the superclass rather than the actual receiver instance.

## Tradeoffs
- Single-inheritance method lookup is an $O(d)$ linear search where $d$ is inheritance depth, which is very fast and requires no complex method resolution order (MRO) algorithms like C3 linearization needed in multiple inheritance.

## CLI / Protocol format
- Input:
  ```lox
  class Doughnut {
    cook() {
      print "Fry until golden brown.";
    }
  }
  class BostonCream < Doughnut {}
  BostonCream().cook();
  ```
- Output:
  ```
  Fry until golden brown.
  ```
  Exit code: 0

- Input (Multi-level hierarchy):
  ```lox
  class Root {
    getName() { print "Root class"; }
  }
  class Parent < Root {}
  class Child < Parent {}
  Child().getName();
  ```
- Output:
  ```
  Root class
  ```
  Exit code: 0

## Java specifics — lookup, don't memorize
- In Java maps, `methods.containsKey(name)` followed by `methods.get(name)` can be replaced by `LoxFunction method = methods.get(name); if (method != null) return method;` for slight performance gain.

## Rebuild checklist
- [ ] In `LoxClass.findMethod(name)`, query local `methods` map first.
- [ ] If not found and `superclass != null`, call `superclass.findMethod(name)`.
- [ ] In `LoxInstance.get(name)`, look up method using `klass.findMethod(...)` and bind receiver `this`.
- [ ] In `LoxClass.call()`, find `init` using `findMethod("init")` to inherit initializers.

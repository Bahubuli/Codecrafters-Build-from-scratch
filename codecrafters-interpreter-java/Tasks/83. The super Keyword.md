# Stage 83: The super Keyword

## In one line
Resolving and invoking overridden superclass methods via `super.method()` by looking up the superclass and binding `this` from the enclosing lexical scope environments.

## Self-test (cover the answers below and answer these first)
- How does `super.method()` differ from `this.method()` in terms of lookup dispatch?
- Where is the receiver instance (`this`) found when executing a `super` expression?
- Why is `"super"` stored in an environment enclosing the class methods rather than in the instance itself?

## The problem it solved
When a subclass overrides a superclass method, it frequently needs to reuse or extend the parent's implementation (e.g. calling `super.init(...)` or invoking a base calculation). Without `super`, there is no mechanism to bypass the subclass's own overriding method to reach the parent implementation.

## Concepts (the transferable part)
- **Static Resolution of `super` vs Dynamic Dispatch**:
  While `this.method()` performs dynamic method lookup on the runtime class of `this` (which may dispatch to a subclass override), `super.method()` statically identifies the superclass of the class containing the `super` expression.
- **Lexical Environment Setup**:
  In `Resolver.visitClassStmt`:
  ```java
  if (stmt.superclass != null) {
      beginScope();
      scopes.peek().put("super", true);
  }
  beginScope();
  scopes.peek().put("this", true);
  ```
  `"this"` is 1 level deeper than `"super"`.
- **Runtime Evaluation**:
  In `Interpreter.visitSuperExpr(Expr.Super expr)`:
  ```java
  int distance = locals.get(expr);
  LoxClass superclass = (LoxClass) environment.getAt(distance, "super");
  LoxInstance object = (LoxInstance) environment.getAt(distance - 1, "this");

  LoxFunction method = superclass.findMethod(expr.method.lexeme);
  if (method == null) {
      throw new RuntimeError(expr.method, "Undefined property '" + expr.method.lexeme + "'.");
  }
  return method.bind(object);
  ```
  The method found on `superclass` is bound to `object` (`this`), ensuring that any reference to `this` inside the parent's method still refers to the subclass instance.

## What breaks it (failure modes)
- Finding the method starting on `object.klass` instead of `superclass`: creates infinite recursion when overriding methods call `super.method()`.
- Failing to bind the superclass method to the receiver `this`: causes runtime errors when the parent method accesses fields on `this`.

## Tradeoffs
- Because `super` is resolved statically through the scope chain at compile time, inheritance cannot be dynamically altered at runtime.

## CLI / Protocol format
- Input:
  ```lox
  class Doughnut {
    cook() { print "Fry until golden brown."; }
  }
  class BostonCream < Doughnut {
    cook() { super.cook(); }
  }
  BostonCream().cook();
  ```
- Output:
  ```
  Fry until golden brown.
  ```
  Exit code: 0

## Java specifics — lookup, don't memorize
- In Java, `super.method()` invokes `invokespecial` bytecode rather than `invokevirtual`, resolving the method against the direct superclass.

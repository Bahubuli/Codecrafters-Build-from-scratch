# Stage 64: Runtime errors

## In one line
Validating call targets and arity matches at runtime, reporting descriptive errors to `System.err`, and exiting with code 70.

## Self-test (cover the answers below and answer these first)
- What error is thrown when invoking a non-callable value such as a string or number?
- What error is thrown when invoking a function with the wrong number of arguments?
- What exit code does the interpreter return on runtime errors?

## The problem it solved
In a dynamically typed language like Lox, type checks and arity checks on function call invocations cannot generally be performed at compile time because the callee expression evaluates dynamically. The runtime must verify that the callee implements `LoxCallable` and that the passed argument count matches `LoxCallable.arity()`.

## Concepts (the transferable part)
- **Runtime Validation of Call Targets**:
  In `Interpreter.visitCallExpr()`:
  ```java
  if (!(callee instanceof LoxCallable)) {
      throw new RuntimeError(expr.paren, "Can only call functions and classes.");
  }
  ```
- **Arity Validation**:
  ```java
  LoxCallable function = (LoxCallable) callee;
  if (arguments.size() != function.arity()) {
      throw new RuntimeError(expr.paren, "Expected " +
          function.arity() + " arguments but got " +
          arguments.size() + ".");
  }
  ```
- **Diagnostic Output and Exit Codes**:
  - Uncaught runtime errors are caught in `Interpreter.interpret()`:
    ```java
    System.err.println(error.getMessage() + "\n[line " + error.token.line + "]");
    hasRuntimeError = true;
    ```
  - `Main.java` checks `if (interpreter.hasRuntimeError()) System.exit(70);`.

## What breaks it (failure modes)
- Throwing a generic Java `ClassCastException` instead of Lox's `RuntimeError`.
- Printing runtime error messages to `System.out` instead of `System.err`.
- Exiting with code 65 (compile error) instead of 70 (runtime error).

## Tradeoffs
- Checking types and arity at every dynamic call site adds a small interpretation overhead, but ensures strict safety and helpful diagnostics in dynamically typed systems.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  "not a function"();
  ```
- Stderr:
  ```
  Can only call functions and classes.
  [line 1]
  ```
- Exit code: `70`

- `callee instanceof LoxCallable` and `arguments.size() != function.arity()`.

# Stage 39: Print: Generate output

## In one line
Introducing statement syntax (`Stmt`), statement parsing, and executing `print <expr>;` statements via the `run` command.

## The problem it solved
Up to this stage, the interpreter only evaluated bare expressions without semicolons using the `evaluate` command. To support full programs with sequential effects, Lox requires statement grammar. The `print` statement evaluates an expression, formats the result, and writes it to standard output followed by a newline.

## Concepts (the transferable part)
- **Statement Hierarchy (`Stmt.java`)**:
  Statements produce side effects rather than returning values (represented by `Visitor<Void>`):
  ```java
  public abstract class Stmt {
      public interface Visitor<R> {
          R visitExpressionStmt(Expression stmt);
          R visitPrintStmt(Print stmt);
      }
      public abstract <R> R accept(Visitor<R> visitor);
  }
  ```
- **Statement Parsing (`Parser.java`)**:
  ```java
  private Stmt statement() {
      if (match(TokenType.PRINT)) return printStatement();
      return expressionStatement();
  }

  private Stmt printStatement() {
      Expr value = expression();
      consume(TokenType.SEMICOLON, "Expect ';' after value.");
      return new Stmt.Print(value);
  }
  ```
- **Executing Statements (`Interpreter.java`)**:
  ```java
  @Override
  public Void visitPrintStmt(Stmt.Print stmt) {
      Object value = evaluate(stmt.expression);
      System.out.println(stringify(value));
      return null;
  }
  ```
- **Grammar Synchronization**:
  When a parsing error occurs within a statement, the parser discards tokens until a statement boundary (`SEMICOLON`, `CLASS`, `FUN`, `VAR`, `FOR`, `IF`, `WHILE`, `PRINT`, `RETURN`) is found to resume parsing without cascading errors.

## What breaks it (failure modes)
- Forgetting to consume the mandatory trailing `;`.
- Missing expression in `print;` resulting in `NullPointerException` rather than parsing error with exit code 65.
- Printing to `stderr` instead of `stdout` for normal output.

## Tradeoffs
- Statement vs expression-oriented language: In Lox, statements are distinct from expressions and do not yield values, simplifying control flow and evaluation semantics at the cost of expression-oriented flexibility (e.g. Kotlin/Rust `if`/`block` expressions).

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input: `print "Hello, World!";`
- Stdout: `Hello, World!`
- Exit code: `0`

## Java specifics — lookup, don't memorize
- `Visitor<Void>` is idiomatic Java for visitors that return no value (returning `null`).

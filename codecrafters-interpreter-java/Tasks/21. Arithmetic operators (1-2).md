# Stage 21: Arithmetic operators (1/2)

## In one line
Implementing left-associative recursive descent parsing for multiplication (`*`) and division (`/`) via the `factor` grammar production rule to build nested binary AST nodes.

## Self-test (cover the answers below and answer these first)
- Why does recursive descent use a loop (`while (match(...))`) to parse left-associative binary operators instead of direct left-recursion?
- In standard precedence hierarchy, does `factor` call `term` or does `term` call `factor`?
- How does the AST structure for `16 * 38 / 58` reflect left-associativity?

## The problem it solved
Flat token sequences like `16 * 38 / 58` cannot represent operator precedence or associativity. Building an Abstract Syntax Tree (AST) through recursive descent converts linear token streams into hierarchical tree structures where operator precedence and associativity are directly encoded by tree depth.

## Concepts (the transferable part)
- **Grammar Precedence Rules**: Higher-precedence operators sit deeper in the call stack. The grammar rules:
  $$\text{expression} \to \text{equality} \to \text{comparison} \to \text{term} \to \text{factor} \to \text{unary} \to \text{primary}$$
  ensure multiplication and division (`factor`) bind tighter than addition and subtraction (`term`).
- **Left-Associativity via Loops**: Direct left-recursion ($\text{factor} \to \text{factor} \ (\text{'*'} \mid \text{'/'}) \ \text{unary}$) causes infinite call loops in recursive descent parsers. Implementing the rule as a loop:
  ```java
  Expr expr = unary();
  while (match(SLASH, STAR)) {
      Token op = previous();
      Expr right = unary();
      expr = new Expr.Binary(expr, op, right);
  }
  return expr;
  ```
  naturally wraps preceding expressions into the `left` child, guaranteeing left-to-right evaluation: `(/ (* 16.0 38.0) 58.0)`.

## What breaks it (failure modes)
- Right-associative parsing: recursing on the right child (`Expr right = factor()`) turns `16 / 4 / 2` into `16 / (4 / 2) = 8` instead of `(16 / 4) / 2 = 2`.
- Direct left-recursion in recursive descent functions causing `StackOverflowError`.
- Forgetting to advance past operator tokens or not matching EOF properly.

## Tradeoffs
- Recursive Descent vs Parser Generators (Yacc/ANTLR) — Hand-written recursive descent provides granular compiler error messages, precise synchronization recovery, and zero external dependencies, at the cost of boilerplate grammar functions.

## CLI / Protocol format
- Command: `./your_program.sh parse <file.lox>`
- S-expression AST format: `(/ (* 16.0 38.0) 58.0)`

## Java specifics — lookup, don't memorize
- `Expr.Binary(expr, operator, right)` — encapsulates left, operator token, and right subexpressions.
- `match(TokenType... types)` — checks lookahead and advances if matched.

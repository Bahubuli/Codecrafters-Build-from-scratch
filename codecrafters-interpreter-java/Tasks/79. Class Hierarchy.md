# Stage 79: Class Hierarchy

## In one line
Adding grammar and AST support for subclass declarations (`class Sub < Super {}`), storing superclass chains, and preparing resolution and evaluation scopes for inherited methods.

## Self-test (cover the answers below and answer these first)
- How is inheritance specified in Lox syntax?

- What happens at runtime if the evaluated superclass expression is not an instance of `LoxClass`?
- How is the `super` identifier scoped when defining methods in a subclass?

## The problem it solved
Real-world object-oriented programs require code reuse and specialization through inheritance. Previously, classes were isolated definitions; this stage introduces single inheritance via `< Superclass` syntax.

## Concepts (the transferable part)
- **Grammar Extension**:
  Class declaration rule updated to:
  ```ebnf
  classDecl -> "class" IDENTIFIER ( "<" IDENTIFIER )? "{" function* "}" ;
  ```
- **Static Self-Inheritance Validation**:
  In `Resolver.visitClassStmt`:
  ```java
  if (stmt.superclass != null &&
      stmt.name.lexeme.equals(stmt.superclass.name.lexeme)) {
      Main.error(stmt.superclass.name, "A class can't inherit from itself.");
  }
  ```
  Reports error with exit code 65.
- **Lexical Scoping of `super`**:
  If a superclass exists, the resolver and interpreter wrap the class's method definitions in an environment where `"super"` is bound:
  ```java
  if (stmt.superclass != null) {
      environment = new Environment(environment);
      environment.define("super", superclass);
  }
  ```
  This guarantees that methods defined inside the subclass have access to the superclass reference during invocation.
- **Runtime Validation**:
  The superclass variable expression is evaluated. If the resulting object is not a `LoxClass`, a `RuntimeError("Superclass must be a class.")` is thrown (exit code 70).

## What breaks it (failure modes)
- Not unwrapping the enclosing environment after method closures are built: causes environment leakage.
- Forgetting to check if `stmt.superclass.name` matches `stmt.name`: self-inheritance creates reference cycles during method lookup.

## Tradeoffs
- Lox uses single inheritance with `<` rather than multiple inheritance or `extends`, keeping method resolution deterministic and straightforward (walking up the single-parent chain).

## CLI / Protocol format
- Input:
  ```lox
  class Vehicle {}
  class Car < Vehicle {}
  print Car();
  ```
- Output:
  ```
  Car instance
  ```
  Exit code: 0

- Input (Self-inheritance error):
  ```lox
  class A < A {}
  ```
- Output:
  ```
  [line 1] Error at 'A': A class can't inherit from itself.
  ```
  Exit code: 65

## Java specifics — lookup, don't memorize
- `LoxClass(name, superclass, methods)`: storing `final LoxClass superclass` on the class object enables recursive method resolution in `findMethod(name)`.

# Stage 46: Assignment operation

## In one line
Parsing right-associative assignment expressions (`a = b = 1`) and updating existing variable bindings in the environment while yielding the assigned value.

## Self-test (cover the answers below and answer these first)
- Why is assignment an expression rather than a statement in Lox?
- Why is assignment right-associative, and how is that implemented in recursive descent?
- Why does the parser parse the left-hand side as an expression first before checking for `=`?

## The problem it solved
Programs need to mutate existing variable bindings over time. Furthermore, programming languages often allow chained assignments (`a = b = 1`) or embedding assignments inside expressions (`print x = 2;`), requiring assignment to be an expression returning its assigned value.

## Concepts (the transferable part)
- **Grammar & Precedence**:
  Assignment has lower precedence than equality and operators, but is right-associative:
  ```
  expression → assignment ;
  assignment → IDENTIFIER "=" assignment
             | equality ;
  ```
- **Parsing Assignment (`Parser.java`)**:
  In recursive descent parsing, the left-hand side of an assignment is evaluated as a regular expression (`equality()`) first. If an `=` token follows, the left-hand side expression is inspected:
  ```java
  private Expr assignment() {
      Expr expr = equality();

      if (match(TokenType.EQUAL)) {
          Token equals = previous();
          Expr value = assignment(); // right-associative: recursively calls assignment()

          if (expr instanceof Expr.Variable) {
              Token name = ((Expr.Variable) expr).name;
              return new Expr.Assign(name, value);
          }

          error(equals, "Invalid assignment target.");
      }

      return expr;
  }
  ```
  This cleanly handles arbitrary l-values without backtracking.
- **Evaluating Assignment (`Interpreter.java`)**:
  ```java
  @Override
  public Object visitAssignExpr(Expr.Assign expr) {
      Object value = evaluate(expr.value);
      environment.assign(expr.name, value);
      return value;
  }
  ```
  The value evaluated on the RHS is stored via `environment.assign` and returned as the expression's result.

## What breaks it (failure modes)
- Making assignment left-associative instead of right-associative (calling `equality()` on the RHS instead of `assignment()`).
- Returning `null` / `nil` from `visitAssignExpr` instead of returning the assigned value.
- Trying to declare a new variable instead of assigning to an existing binding.

## Tradeoffs
- Assignment as an expression enables idiomatic chaining (`a = b = 0`) and compact patterns (`while ((line = read()) != null)`), but can cause subtle bugs when an assignment `=` is mistakenly typed instead of equality `==`.

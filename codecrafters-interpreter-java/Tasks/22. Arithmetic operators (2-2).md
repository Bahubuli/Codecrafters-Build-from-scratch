# Stage 22: Arithmetic operators (2/2)

## In one line
Implementing left-associative recursive descent parsing for addition (`+`) and subtraction (`-`) via the `term` grammar production rule.

## Self-test (cover the answers below and answer these first)
- Why is `term()` placed above `factor()` in the recursive descent call hierarchy?
- What does the resulting AST look like for expressions containing both addition and multiplication like `1 + 2 * 3`?
- Why do both `term()` and `factor()` use loops instead of recursion on the left operand?

## The problem it solved
Additive operators (`+`, `-`) have lower precedence than multiplicative operators (`*`, `/`). Without layering precedence rules into distinct grammar functions, an expression like `1 + 2 * 3` could be parsed as `(1 + 2) * 3 = 9` instead of `1 + (2 * 3) = 7`.

## Concepts (the transferable part)
- **Precedence Hierarchy via Call Depth**:
  Each grammar rule matches expressions at its precedence level or higher:
  ```java
  private Expr term() {
      Expr expr = factor(); // handles higher-precedence * and /

      while (match(TokenType.MINUS, TokenType.PLUS)) {
          Token operator = previous();
          Expr right = factor();
          expr = new Expr.Binary(expr, operator, right);
      }

      return expr;
  }
  ```
  Because `term()` delegates to `factor()`, multiplication and division subtrees are created first and attached as children of additive nodes.
- **Left-Associativity**:
  `52 + 80 - 94` is evaluated as `(- (+ 52.0 80.0) 94.0)`. The `while` loop repeatedly takes the existing AST node as `left` and binds newly encountered operators and right operands to the outer node.

## What breaks it (failure modes)
- Inverting precedence: if `factor()` called `term()`, addition would bind tighter than multiplication (`2 * 3 + 4` would become `(* 2 (+ 3 4))`).
- Failing to match floating-point vs integer string representations in AST printing.

## Tradeoffs
- Recursive descent layering vs Pratt parsing (top-down operator precedence) — Recursive descent requires one explicit method per precedence level, making grammar relationships clear and easy to follow; Pratt parsing uses precedence tables and binding powers in a single loop, scaling better to dozens of operators.

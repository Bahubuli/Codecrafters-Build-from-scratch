# Stage 61: Syntax errors

## In one line
Catching malformed function declarations and call expressions during parsing, reporting errors to `System.err`, and terminating with exit code 65.

## Self-test (cover the answers below and answer these first)
- What exit code does the interpreter return when a syntax error occurs?
- Where are parse error messages written?
- What happens if a function declaration omits `{` before the body?

## The problem it solved
Compilers and interpreters must reject syntactically invalid programs before execution. Syntactic errors in function declarations (such as missing opening braces, unclosed parameter lists, or missing parameter separators) or invalid call syntax (such as trailing unclosed parentheses or malformed call expressions) must be caught cleanly during the parse phase.

## Concepts (the transferable part)
- **Defensive Recursive Descent Parsing**:
  - `consume()` expects a specific token type and raises a `ParseError` with an informative message if it is not present.
  - In `Parser.function()`:
    ```java
    Token name = consume(TokenType.IDENTIFIER, "Expect " + kind + " name.");
    consume(TokenType.LEFT_PAREN, "Expect '(' after " + kind + " name.");
    // ... parameter parsing ...
    consume(TokenType.RIGHT_PAREN, "Expect ')' after parameters.");
    consume(TokenType.LEFT_BRACE, "Expect '{' before " + kind + " body.");
    ```
- **Error Propagation**:
  The parser records errors via `hasError = true` and reports formatted diagnostics:
  `[line <line>] Error at '<lexeme>': <message>`
- **Phase Separation**:
  `Main.java` checks `if (parser.hasError()) System.exit(65);` after `parseStatements()`, preventing execution of malformed ASTs.

## What breaks it (failure modes)
- Continuing to execute statements after a parse error occurred.
- Printing parse error messages to `System.out` instead of `System.err`.
- Exiting with code 0 or 70 instead of 65 on syntax errors.

## Tradeoffs
- Panic-mode error recovery with `synchronize()` allows detecting multiple syntax errors in a single compiler pass while preventing cascading nonsense errors.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  fun f() 74;
  print f();
  ```
- Stderr:
  ```
  [line 1] Error at '74': Expect '{' before function body.
  ```
- Exit code: `65`

## Java specifics — lookup, don't memorize
- `System.err.println(...)` and `System.exit(65)`.

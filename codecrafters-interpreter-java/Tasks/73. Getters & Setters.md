# Stage 73: Getters & Setters

## In one line
Extending expression AST and runtime with `Expr.Get` (`object.property`) and `Expr.Set` (`object.property = value`) backed by a dynamic property map in `LoxInstance`.

## Self-test (cover the answers below and answer these first)
- Why is property assignment (`expr.property = value`) parsed inside `assignment()` rather than as a separate statement or binary expression?
- Why does the resolver resolve `expr.object` for getters and setters, but not the property name itself?
- What runtime error is thrown when accessing a property on a non-instance or an undefined property?

## The problem it solved
Objects must maintain mutable state. In Lox, instance fields are dynamic: any property can be set on any instance at any time without prior declaration in the class body. The interpreter needs syntactic support for property access (`.`) and property assignment (`.=`), plus runtime storage on each `LoxInstance`.

## Concepts (the transferable part)
- **Get and Set AST Nodes**:
  - `Expr.Get`: represents fetching `name` from `object` (`falcon.speed`).
  - `Expr.Set`: represents assigning `value` to `name` on `object` (`falcon.speed = 75.5`).
- **Parsing Property Assignment**:
  In recursive descent parsing, the left-hand side of `=` is parsed as an expression first. If the left-hand side evaluates to an `Expr.Get`, it is converted into an `Expr.Set`:
  ```java
  Expr expr = or();
  if (match(TokenType.EQUAL)) {
      Token equals = previous();
      Expr value = assignment();
      if (expr instanceof Expr.Variable) {
          Token name = ((Expr.Variable) expr).name;
          return new Expr.Assign(name, value);
      } else if (expr instanceof Expr.Get) {
          Expr.Get get = (Expr.Get) expr;
          return new Expr.Set(get.object, get.name, value);
      }
      error(equals, "Invalid assignment target.");
  }
  ```
- **Parsing Dot Access**:
  Dot access has the same precedence as function calls:
  ```java
  while (true) {
      if (match(TokenType.LEFT_PAREN)) {
          expr = finishCall(expr);
      } else if (match(TokenType.DOT)) {
          Token name = consume(TokenType.IDENTIFIER, "Expect property name after '.'.");
          expr = new Expr.Get(expr, name);
      } else {
          break;
      }
  }
  ```
- **Dynamic Property Map**:
  `LoxInstance` holds `Map<String, Object> fields`:
  - `get(Token name)`: returns the field or throws `RuntimeError` if absent.
  - `set(Token name, Object value)`: updates or inserts the field.

## What breaks it (failure modes)
- Resolving property names statically: properties are dynamically dispatched at runtime on instance maps, so `Resolver` should only resolve the enclosing instance expression `expr.object`, not `expr.name`.
- Accessing properties on non-instances: `object.prop` on a number or string must throw `RuntimeError: Only instances have properties.`

## Tradeoffs
- Dynamic fields per instance provide maximum flexibility and easy implementation at the cost of hidden class optimizations and cache misses typical of shape-less objects.

## CLI / Protocol format
- Input:
  ```lox
  class Spaceship {}
  var falcon = Spaceship();
  falcon.speed = 75.5;
  print falcon.speed;
  ```
- Output:
  ```
  75.5
  ```

## Java specifics — lookup, don't memorize
- `Map.containsKey`: checks whether a field exists, permitting explicit `nil` values to be stored and retrieved without being confused with absent properties.

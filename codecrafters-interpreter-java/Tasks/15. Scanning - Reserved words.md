# Stage 15: Scanning - Reserved words

## In one line
Distinguishing language keywords from user-defined identifiers by querying a reserved-word hash map with the completed identifier lexeme after maximal-munch scanning.

## Self-test (cover the answers below and answer these first)
- Why should keywords be resolved after scanning the entire identifier rather than while characters are being consumed?
- How does the scanner distinguish between a keyword like `var` and an identifier that starts with that keyword like `variable`?
- What happens if an identifier matches the spelling of a keyword but with different letter casing (e.g. `True` vs `true`) in Lox?
- How does a hash map lookup compare to a trie or DFA for reserved-word matching in terms of complexity and developer ergonomics?

## The problem it solved
In Stage 14, every alphanumeric sequence beginning with a letter or underscore was unconditionally mapped to `TokenType.IDENTIFIER`. Consequently, core language syntax keywords (`var`, `if`, `while`, `print`, `fun`, `class`, `return`, `and`, `or`, `true`, `false`, `nil`, `super`, `this`, `else`, `for`) were misidentified as user variable names instead of distinct syntactic constructs.

## Concepts (the transferable part)
- **Maximal Munch & Keyword Resolution** — Identifiers and keywords share the exact same lexical grammar: `[a-zA-Z_][a-zA-Z0-9_]*`. Standard lexer design resolves this collision by scanning the entire token greedily via maximal munch, then performing a dictionary check: if the scanned lexeme is in the language's reserved-word table, it is assigned the corresponding keyword token type; otherwise, it remains a generic identifier.
- **Prefix Isolation** — Scanning the full token before querying the table naturally prevents false positives on prefixes (e.g., `variable` begins with `var`, `orchid` begins with `or`, `forest` begins with `for`). Because the lexer does not terminate at `var`, `variable` is looked up in its entirety and correctly falls back to `TokenType.IDENTIFIER`.
- **Case-Sensitive Lexical Matching** — Lox keywords are strictly lowercase. Exact string comparison ensures that `True`, `TRUE`, or `Var` are treated as valid user identifiers rather than reserved keywords.

## What breaks it (failure modes)
- **Premature Keyword Match (Prefix Hijacking)** — Attempting to match keywords character-by-character without checking if the subsequent character is alphanumeric. For instance, scanning `var` out of `variable` and leaving `iable` as a stray identifier. Scanning until the first non-alphanumeric character guarantees correct token boundaries.
- **Missing Keywords in Dictionary** — Leaving any of the 16 Lox reserved keywords (`and`, `class`, `else`, `false`, `for`, `fun`, `if`, `nil`, `or`, `print`, `return`, `super`, `this`, `true`, `var`, `while`) out of the lookup table causes valid language constructs to be parsed as identifiers, leading to syntax errors during parsing.
- **Modifying the Token Lexeme or Literal** — Like generic identifiers, keyword tokens in Lox preserve their literal source text as the lexeme and have a `null` literal value at scan time.

## Tradeoffs
- **Hash Table Lookup vs Hardcoded Trie / Finite Automaton** — A hash map lookup (`Map<String, TokenType>`) is simple, readable, and takes $O(L)$ where $L$ is the length of the identifier. In high-performance C compilers, a specialized perfect hash function (e.g., `gperf`) or an explicit hardcoded trie avoids string allocation entirely. In Java, the map lookup over the extracted substring is clean, idiomatic, and fast.

## CLI / Protocol format
- Execution: `./your_program.sh tokenize <filename>`
- Output format:
  - `stdout`: `<KEYWORD_TYPE> <lexeme> null` followed by remaining tokens and `EOF  null`.
  - Example: For input `var language = "lox";`, output:
    ```
    VAR var null
    IDENTIFIER language null
    EQUAL = null
    STRING "lox" lox
    SEMICOLON ; null
    EOF  null
    ```
- Exit code: `0` on success.

## Java specifics — lookup, don't memorize
- `static final Map<String, TokenType> keywords = new HashMap<>();` — Static keyword registry initialized once per classloader.
- `keywords.get(text)` — Retrieves the mapped `TokenType` or `null` if the text is not a reserved word.
- `if (type == null) type = TokenType.IDENTIFIER;` — Clean fallback idiom for conditional dictionary lookups.

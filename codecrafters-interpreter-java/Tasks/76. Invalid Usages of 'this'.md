# Stage 76: Invalid Usages of 'this'

## In one line
Validating that `this` expressions only occur within class methods using semantic analysis in the resolver, returning exit code 65 for compile-time errors and 70 for runtime violations.

## Self-test (cover the answers below and answer these first)
- Why is using `this` inside a top-level function or script a static error rather than a runtime error?
- How does the resolver prevent `this` from being resolved outside a class body?
- What happens at runtime if user code attempts to invoke an instance directly, e.g. `this()`?

## The problem it solved
`this` is only meaningful inside the body of a class method where an instance receiver exists. If a user refers to `this` outside of a class method (such as in a global function or at the top-level script), an error must be reported at compile/resolution time with exit code 65. If `this` is used inside a class method but invoked as a function (`this()`) or accesses an uninitialized field (`this.foo`), appropriate runtime errors (exit code 70) must be raised.

## Concepts (the transferable part)
- **Static Class Context Tracking**:
  The `Resolver` tracks whether it is currently analyzing the body of a class using `ClassType currentClass`:
  ```java
  private enum ClassType {
      NONE,
      CLASS
  }
  ```
- **Error Reporting at Resolution Time**:
  When visiting an `Expr.This` node:
  ```java
  @Override
  public Void visitThisExpr(Expr.This expr) {
      if (currentClass == ClassType.NONE) {
          Main.error(expr.keyword, "Can't use 'this' outside of a class.");
          return null;
      }

      resolveLocal(expr, expr.keyword);
      return null;
  }
  ```
- **Exit Code Conventions**:
  - Resolution/Syntax errors report:
    `[line N] Error at 'this': Can't use 'this' outside of a class.`
    and set `hasError = true`, causing process exit with `65`.
  - Calling an instance (`this()`) hits the `LoxCallable` check in `Interpreter.visitCallExpr` and raises `RuntimeError("Can only call functions and classes.")`, exiting with `70`.
  - Accessing an undefined property on `this` raises `RuntimeError("Undefined property '...'.")`, exiting with `70`.

## What breaks it (failure modes)
- Permitting `this` to resolve dynamically as a global variable: leads to confusing `nil` or undefined variable errors at runtime instead of compile-time rejection.
- Not maintaining `currentClass` as a stack/saved value across nested declarations: if a class contains functions, `currentClass` must correctly reflect whether `this` is inside that class context.

## Tradeoffs
- Static detection via `Resolver` catches invalid `this` references before any bytecode or AST evaluation begins, matching standard OOP language semantics (Java, C++, TypeScript).

## CLI / Protocol format
- Input (Static error):
  ```lox
  fun notAMethod() {
    print this;
  }
  ```
- Output:
  ```
  [line 2] Error at 'this': Can't use 'this' outside of a class.
  ```
  Exit code: 65

- Input (Runtime error):
  ```lox
  class Person {
    sayName() {
      print this();
    }
  }
  Person().sayName();
  ```
- Output:
  ```
  Can only call functions and classes.
  [line 3]
  ```
  Exit code: 70

# Stage 23: Comparison operators

## In one line
Implementing left-associative recursive descent parsing for relational comparison operators (`>`, `>=`, `<`, `<=`) via the `comparison` grammar rule.

## Self-test (cover the answers below and answer these first)
- Why does `comparison()` delegate to `term()` instead of directly to `factor()`?
- How does the parser handle chained comparisons like `83 < 99 < 115` without special chaining syntax?
- In Lox grammar, why do comparisons have lower precedence than addition/subtraction?

## The problem it solved
Expressions like `a + 1 < b * 2` mix arithmetic and relational operations. Without enforcing grammar precedence between terms and comparisons, comparison operators might evaluate before arithmetic terms, violating standard mathematical semantics.

## Concepts (the transferable part)
- **Grammar Layering for Comparisons**:
  Comparison operations bind more loosely than arithmetic operators (`term` and `factor`), but tighter than equality (`==`, `!=`):
  $$\text{equality} \to \text{comparison} \to \text{term}$$
  ```java
  private Expr comparison() {
      Expr expr = term(); // Evaluates +, -

      while (match(TokenType.GREATER, TokenType.GREATER_EQUAL, TokenType.LESS, TokenType.LESS_EQUAL)) {
          Token operator = previous();
          Expr right = term();
          expr = new Expr.Binary(expr, operator, right);
      }

      return expr;
  }
  ```
- **Chained Left-Associativity**:
  In Lox, `83 < 99 < 115` is parsed as `(< (< 83.0 99.0) 115.0)`. While at runtime evaluating `true < 115.0` results in a type error, syntactically it is valid grammar.

## What breaks it (failure modes)
- Parsing right-associatively: creating `(< 83.0 (< 99.0 115.0))` instead of nesting on the left.
- Inverting precedence so comparisons bind tighter than addition (`a < b + c` parsed as `(+ (< a b) c)`).

## Tradeoffs
- Chained syntax desugaring vs strict binary parsing — Python allows chained comparisons (`a < b < c` translates to `a < b and b < c`); Lox keeps parsing strictly binary and left-associative.

## CLI / Protocol format
- Command: `./your_program.sh parse <file.lox>`
- Output format: `(< (< 83.0 99.0) 115.0)`

## Java specifics — lookup, don't memorize
- `TokenType.GREATER`, `TokenType.GREATER_EQUAL`, `TokenType.LESS`, `TokenType.LESS_EQUAL` — token types for comparison operators.

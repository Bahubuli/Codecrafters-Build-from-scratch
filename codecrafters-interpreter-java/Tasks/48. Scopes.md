# Stage 48: Scopes

## In one line
Implementing lexical scope hierarchies via linked `Environment` chains, supporting variable shadowing, upward lookups, and runtime errors when accessing out-of-scope variables.

## Self-test (cover the answers below and answer these first)
- How does `Environment` implement lexical scoping using parent pointers?
- What is variable shadowing and how does the environment chain resolve it?
- What happens when code inside an inner block assigns to an outer variable vs declares a new variable?

## The problem it solved
Variables defined inside an inner block must not leak to outer scopes, but statements within an inner block must be able to read and modify variables defined in enclosing scopes. When an inner scope declares a variable with the same name as an outer variable, it shadows the outer binding without overwriting it.

## Concepts (the transferable part)
- **Lexical Environment Chaining (`Environment.java`)**:
  ```java
  public class Environment {
      final Environment enclosing;
      private final Map<String, Object> values = new HashMap<>();

      public Environment() {
          enclosing = null;
      }

      public Environment(Environment enclosing) {
          this.enclosing = enclosing;
      }

      public void define(String name, Object value) {
          values.put(name, value);
      }

      public Object get(Token name) {
          if (values.containsKey(name.lexeme)) {
              return values.get(name.lexeme);
          }
          if (enclosing != null) return enclosing.get(name);
          throw new RuntimeError(name, "Undefined variable '" + name.lexeme + "'.");
      }

      public void assign(Token name, Object value) {
          if (values.containsKey(name.lexeme)) {
              values.put(name.lexeme, value);
              return;
          }
          if (enclosing != null) {
              enclosing.assign(name, value);
              return;
          }
          throw new RuntimeError(name, "Undefined variable '" + name.lexeme + "'.");
      }
  }
  ```
- **Shadowing vs. Assignment**:
  - `define(name, value)` always inserts into the innermost environment (`this.values`), hiding any same-named variable in `enclosing`.
  - `assign(name, value)` searches outward until it finds the existing binding to update. If nowhere in the chain, it throws a `RuntimeError`.
  - `get(name)` searches outward from innermost to outermost (global) scope.

## What breaks it (failure modes)
- Storing all variables in a flat dictionary or failing to restore the enclosing environment on block exit.
- Calling `assign` instead of `define` on `var` statements, which would inadvertently overwrite shadowed outer variables.
- Not searching `enclosing` when resolving variable reads.

## Tradeoffs
- Linked hash maps give an intuitive model matching lexical structure directly.
- Performance penalty: each block entry allocates a heap `HashMap`, and variable lookup requires traversing pointers up the chain ($O(N)$ depth). Production engines flatten scopes into stack frames using static analysis / de Bruijn indices.

## Java specifics — lookup, don't memorize
- Recursive delegation: `if (enclosing != null) return enclosing.get(name);` walks up the linked parent pointers until the global environment (`enclosing == null`) is reached.

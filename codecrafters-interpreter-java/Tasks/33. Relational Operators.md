# Stage 33: Relational Operators

## In one line
Evaluating numeric comparisons (`>`, `>=`, `<`, `<=`) producing Boolean values (`true`/`false`).

- What operand types are supported by comparison operators in Lox?

- How is the boolean result stringified for terminal output?

## The problem it solved
Relational operators compare two numeric expressions and return a boolean truth value. The interpreter verifies that both the left and right operands evaluate to numbers before comparing them using standard IEEE 754 floating-point order.

## Concepts (the transferable part)
- **Numeric Relational Comparison**:
  ```java
  case GREATER:
      checkNumberOperands(expr.operator, left, right);
      return (double) left > (double) right;
  case GREATER_EQUAL:
      checkNumberOperands(expr.operator, left, right);
      return (double) left >= (double) right;
  case LESS:
      checkNumberOperands(expr.operator, left, right);
      return (double) left < (double) right;
  case LESS_EQUAL:
      checkNumberOperands(expr.operator, left, right);
      return (double) left <= (double) right;
  ```
- **Type Checking Before Comparison**:
  Comparing non-numbers (e.g. `true > false` or `"a" < "b"`) throws a runtime error in Lox, ensuring well-defined comparison semantics.

## What breaks it (failure modes)
- Comparing non-Double objects causing unhandled `ClassCastException` instead of Lox `RuntimeError`.
- Reversing operand evaluation order (violating left-to-right evaluation guarantees).
- Inverting inequality boundaries (e.g., misimplementing `>=` or `<=`).

## Tradeoffs
- Lexicographical string comparison vs numbers-only — While languages like JavaScript and Python support lexicographic string comparison with `<`, Lox restricts ordering comparisons strictly to numbers to keep semantics simple.

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Examples:
  - `10 > 5` $\to$ `true`
  - `57 > -65` $\to$ `true`
  - `11 >= 11` $\to$ `true`
  - `(54 - 67) >= -(114 / 57 + 11)` $\to$ `true`

## Java specifics — lookup, don't memorize
- `(double) left >= (double) right` — unboxes `Double` objects to Java primitive `double` before comparison.

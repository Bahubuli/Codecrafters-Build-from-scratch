# Stage 38: Runtime Errors: Relational Operators

## In one line
Enforcing numeric operands on relational comparison operators (`>`, `>=`, `<`, `<=`), rejecting mismatched or non-numeric types with `RuntimeError` and exit code 70.

## Self-test (cover the answers below and answer these first)

- What happens when comparing booleans like `true < false`?

## The problem it solved
Unlike some languages where strings or booleans can be ordered with relational operators, Lox restricts `<`, `<=`, `>`, and `>=` exclusively to numeric operands. Comparing strings, booleans, or nil must raise a `RuntimeError` ("Operands must be numbers.") and terminate with exit code 70.

## Concepts (the transferable part)
- **Relational Operator Guards**:
  ```java
  case GREATER:
      checkNumberOperands(expr.operator, left, right);
      return (double) left > (double) right;
  case GREATER_EQUAL:
      checkNumberOperands(expr.operator, left, right);
      return (double) left >= (double) right;
  case LESS:
      checkNumberOperands(expr.operator, left, right);
      return (double) left < (double) right;
  case LESS_EQUAL:
      checkNumberOperands(expr.operator, left, right);
      return (double) left <= (double) right;
  ```
- **Language Design Philosophy**:
  Lox does not define ordering relations over non-numbers. By disallowing implicit ordering on strings or booleans, Lox prevents subtle bugs arising from unintended coercions or locale-dependent character comparisons.

## What breaks it (failure modes)
- Permitting string comparison with `<` or `>` without explicit specification.
- Failing to invoke `checkNumberOperands` before casting to `(double)`.
- Using syntax error exit code 65 instead of runtime error exit code 70.

## Tradeoffs
- Simplicity and safety over feature richness: String sorting/ordering in standard Lox must be handled explicitly through libraries or user-defined comparator functions rather than built-in operators.

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Input: `17 > "bar"`
- Stderr:
  ```
  Operands must be numbers.
  [line 1]
  ```
- Exit code: `70`

## Java specifics — lookup, don't memorize
- `checkNumberOperands` ensures neither operand is `null`, `String`, or `Boolean` prior to primitive unboxing.

# Stage 47: Block syntax

## In one line
Parsing curly-brace blocks `{ declaration* }` into `Stmt.Block` AST nodes and executing enclosed statements within a new nested lexical environment.

## Self-test (cover the answers below and answer these first)
- How does the grammar differentiate between a statement and a block?
- What happens if an opening `{` is not matched by a closing `}` before EOF?
- How is the interpreter environment saved and restored when entering and exiting a block?

## The problem it solved
Sequences of statements need to be grouped together syntactically as a single statement (for conditional branches, loops, or local scopes). The interpreter must parse `{ ... }` blocks and report syntax errors with exit code 65 if unclosed braces remain at EOF.

## Concepts (the transferable part)
- **Grammar for Blocks**:
  ```
  statement → exprStmt
            | printStmt
            | block ;

  block     → "{" declaration* "}" ;
  ```
- **Parsing Blocks (`Parser.java`)**:
  ```java
  private Stmt statement() {
      if (match(TokenType.PRINT)) return printStatement();
      if (match(TokenType.LEFT_BRACE)) return new Stmt.Block(block());
      return expressionStatement();
  }

  private List<Stmt> block() {
      List<Stmt> statements = new ArrayList<>();

      while (!check(TokenType.RIGHT_BRACE) && !isAtEnd()) {
          statements.add(declaration());
      }

      consume(TokenType.RIGHT_BRACE, "Expect '}' after block.");
      return statements;
  }
  ```
  Declarations continue to be parsed inside the block until a `}` is encountered or EOF is reached.
- **Scoping & Environment Chaining (`Interpreter.java`)**:
  ```java
  @Override
  public Void visitBlockStmt(Stmt.Block stmt) {
      executeBlock(stmt.statements, new Environment(environment));
      return null;
  }

  public void executeBlock(List<Stmt> statements, Environment environment) {
      Environment previous = this.environment;
      try {
          this.environment = environment;

          for (Stmt statement : statements) {
              execute(statement);
          }
      } finally {
          this.environment = previous;
      }
  }
  ```
  Using `try ... finally` guarantees that `this.environment` is restored to `previous` even if a runtime error occurs during statement execution.

## What breaks it (failure modes)
- Forgetting to check `!isAtEnd()` in the block loop, resulting in infinite loops or out-of-bounds access on unterminated blocks.
- Failing to restore the previous environment if an error occurs.
- Failing to exit with code 65 on syntax errors for unclosed blocks.

## Tradeoffs
- Allocating a new `Environment` object per block execution simplifies nested scopes and closures at the cost of heap allocation overhead.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  {
      var foo = "before";
      print foo;
  }
  {
      var foo = "after";
      print foo;
  }
  ```
- Stdout:
  ```
  before
  after
  ```
- Exit code: `0` (or `65` if unclosed block)

## Java specifics — lookup, don't memorize
- The `finally` block in Java executes when control leaves a `try` block for any reason (normal completion, return, or exception).

# Stage 30: Arithmetic Operators (1/2)

## In one line
Evaluating binary arithmetic multiplication (`*`) and division (`/`) on numeric operands.

## The problem it solved
Binary expressions have two child nodes: `left` and `right`. In order to evaluate operations like multiplication (`*`) and division (`/`), the interpreter must evaluate both subexpressions into runtime values, assert type safety, and execute the IEEE 754 arithmetic operation.

## Concepts (the transferable part)
- **Left-to-Right Evaluation Order**:
  In Lox (and Java), binary expressions evaluate their left operand before their right operand:
  ```java
  Object left = evaluate(expr.left);
  Object right = evaluate(expr.right);
  ```
- **Binary Operation Dispatch**:
  ```java
  switch (expr.operator.type) {
      case STAR:
          checkNumberOperands(expr.operator, left, right);
          return (double) left * (double) right;
      case SLASH:
          checkNumberOperands(expr.operator, left, right);
          return (double) left / (double) right;
  }
  ```

## What breaks it (failure modes)
- Reversing operand order for non-commutative operations like division (`right / left` instead of `left / right`).
- Forgetting to evaluate nested expressions within grouped subtrees before calculating binary arithmetic.
- Losing precision by casting to integer instead of `double`.

## Tradeoffs
- Floating-point division by zero — In IEEE 754 arithmetic (Java double), dividing by zero yields `Infinity` or `-Infinity` rather than throwing an exception immediately unless specifically checked.

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Examples:
  - `42 / 5` $\to$ `8.4`
  - `18 * 3 / (3 * 6)` $\to$ `3`
  - `(10.40 * 2) / 2` $\to$ `10.4`

## Java specifics — lookup, don't memorize
- `(double) left * (double) right` — unboxes `Double` objects and executes floating-point multiplication.

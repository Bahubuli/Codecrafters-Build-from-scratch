# Stage 72: Class Instances

## In one line
Making `LoxClass` implement `LoxCallable` to return new `LoxInstance` objects upon invocation `ClassName()`.

## Self-test (cover the answers below and answer these first)
- Why does invoking a class name like a function instantiate an object in Lox?
- How does `LoxInstance` know what class it was instantiated from?
- What is the truthiness and string representation of a class instance?

## The problem it solved
Defining classes is only useful if instances of those classes can be created at runtime. In Lox, class instantiation uses call syntax `ClassName(...)`. By implementing `LoxCallable` on `LoxClass`, calling a class seamlessly constructs and returns a runtime `LoxInstance`.

## Concepts (the transferable part)
- **Class as Factory / Metaclass**:
  In dynamic languages, classes themselves are callable objects. Making `LoxClass` implement `LoxCallable`:
  ```java
  public class LoxClass implements LoxCallable {
      final String name;

      public LoxClass(String name) {
          this.name = name;
      }

      @Override
      public Object call(Interpreter interpreter, List<Object> arguments) {
          LoxInstance instance = new LoxInstance(this);
          return instance;
      }

      @Override
      public int arity() {
          return 0;
      }

      @Override
      public String toString() {
          return name;
      }
  }
  ```
- **Instance Representation (`LoxInstance`)**:
  Represents a concrete instance of a class, holding a reference to its `LoxClass`:
  ```java
  public class LoxInstance {
      private LoxClass klass;

      public LoxInstance(LoxClass klass) {
          this.klass = klass;
      }

      @Override
      public String toString() {
          return klass.name + " instance";
      }
  }
  ```
- **Truthiness**:
  In Lox, only `false` and `nil` are falsey. Any `LoxInstance` is non-null and not a boolean, so expressions like `if (falcon)` evaluate to true.

## What breaks it (failure modes)
- Throwing a runtime error "Can only call functions" when calling a class: `visitCallExpr` must permit any `LoxCallable`.
- Incorrect string formatting: instances must output `<ClassName> instance` (e.g. `Robot instance`).

## Tradeoffs
- Reusing `LoxCallable` for class constructors unifies call dispatch for both functions and class instantiations without needing a distinct `new` keyword or AST node.

## CLI / Protocol format
- Input:
  ```lox
  class Spaceship {}
  var falcon = Spaceship();
  print falcon;
  ```
- Output:
  ```
  Spaceship instance
  ```

## Java specifics — lookup, don't memorize
- Direct interface implementation: implementing `LoxCallable` on `LoxClass` allows `visitCallExpr` in `Interpreter` to handle class instantiation via polymorphism with zero code changes.

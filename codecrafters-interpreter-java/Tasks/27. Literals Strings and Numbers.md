# Stage 27: Literals: Strings & Numbers

## In one line
Formatting and printing runtime string and numeric literals with quotation stripping and clean integer/decimal representation.

## Self-test (cover the answers below and answer these first)
- Why do numbers evaluate to IEEE 754 double precision floats in Lox?
- How does `stringify()` format whole numbers versus fractional numbers (e.g. `10.0` vs `10.4`)?
- Why are quotes omitted when evaluating string literals compared to tokenizing or parsing them?

## The problem it solved
In evaluation mode, literal expressions must render their actual computed values to stdout rather than their AST representations or source lexemes: strings must not have surrounding quotes (`"foo"` $\to$ `foo`), and whole numbers must not have redundant `.0` suffixes (`10` or `10.0` $\to$ `10`).

## Concepts (the transferable part)
- **Runtime Value Representation**:
  - Strings: Stored directly as Java `java.lang.String`. `object.toString()` prints string contents without enclosing quotes.
  - Numbers: Stored as `java.lang.Double`.
- **Number Stringification Formatting**:
  Standard Lox specification converts IEEE 754 doubles to clean string format:
  ```java
  if (object instanceof Double) {
      String text = object.toString();
      if (text.endsWith(".0")) {
          text = text.substring(0, text.length() - 2);
      }
      return text;
  }
  ```

## What breaks it (failure modes)
- Retaining quotes around strings (`"hello"` instead of `hello`).
- Printing `10.0` when evaluating integer literals like `10`.
- Incorrect rounding or truncating necessary decimals (e.g. `10.40` must evaluate to `10.4`).

## Tradeoffs
- Unified double representation — Using double-precision float for all numbers simplifies the runtime type system at the cost of precision for 64-bit integers.

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Examples:
  - `"hello world!"` $\to$ `hello world!`
  - `10.40` $\to$ `10.4`
  - `10` $\to$ `10`

## Java specifics — lookup, don't memorize
- `text.endsWith(".0")` — identifies and strips redundant decimal notation from whole number doubles.

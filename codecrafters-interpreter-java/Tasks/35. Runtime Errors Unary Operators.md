# Stage 35: Runtime Errors: Unary Operators

## In one line
Throwing and catching typed runtime errors (`RuntimeError`, exit code 70) when unary negation (`-`) encounters non-numeric operands.

## Self-test (cover the answers below and answer these first)
- What exit code is returned by Lox when encountering a runtime error vs a syntax error?
- Where are runtime error messages printed (`stdout` or `stderr`)?
- Does unary `!` throw a runtime error if passed a number or string?

## The problem it solved
Syntax errors occur during scanning or parsing (exit code 65). Runtime errors occur dynamically during evaluation when expressions evaluate to values incompatible with the operator (e.g. attempting to negate a string `-"hello"` or boolean `-true`). The interpreter must trap these violations gracefully and exit with code 70.

## Concepts (the transferable part)
- **Runtime Error Representation**:
  ```java
  public class RuntimeError extends RuntimeException {
      public final Token token;
      public RuntimeError(Token token, String message) {
          super(message);
          this.token = token;
      }
  }
  ```
- **Operand Validation**:
  ```java
  private void checkNumberOperand(Token operator, Object operand) {
      if (operand instanceof Double) return;
      throw new RuntimeError(operator, "Operand must be a number.");
  }
  ```
- **Error Reporting Format & Exit Code**:
  When caught by the interpreter:
  ```java
  System.err.println(error.getMessage() + "\n[line " + error.token.line + "]");
  hasRuntimeError = true;
  ```
  Process terminates with exit code `70`.

## What breaks it (failure modes)
- Throwing raw Java `ClassCastException` instead of catching and reporting a user-friendly Lox `RuntimeError`.
- Printing runtime errors to `stdout` rather than `stderr`.
- Exiting with syntax error code 65 instead of runtime error code 70.

## Tradeoffs
- Static type checking vs dynamic runtime exceptions — Lox is dynamically typed, deferring operand type validation until evaluation time, requiring explicit runtime checks in AST visitors.

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Input: `-"hello world!"`
- Stderr:
  ```
  Operand must be a number.
  [line 1]
  ```
- Exit code: `70`

## Java specifics — lookup, don't memorize
- `System.exit(70)` for UNIX `EX_SOFTWARE` exit convention.

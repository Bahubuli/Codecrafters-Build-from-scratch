# Stage 26: Literals: Booleans & Nil

## In one line
Introducing tree-walk AST evaluation via the `evaluate` command using the Visitor pattern, resolving `true`, `false`, and `nil` literals to host language values.

## Self-test (cover the answers below and answer these first)
- How does the Visitor pattern decouple AST node definitions from evaluation logic?
- In Lox, what Java type represents the `nil` literal at runtime?
- How does `stringify()` format `null` values when printing evaluation results?

## The problem it solved
AST generation is only an intermediate representation; the program must actually execute and produce computational results. Implementing an `Interpreter` class using tree-walking interpretation traverses expressions and reduces literal tokens to runtime values.

## Concepts (the transferable part)
- **Visitor Pattern for Evaluation**:
  `Interpreter implements Expr.Visitor<Object>` allows evaluating any `Expr` node dynamically by invoking `expr.accept(this)`:
  ```java
  @Override
  public Object visitLiteralExpr(Expr.Literal expr) {
      return expr.value;
  }
  ```
- **Lox Runtime Value Mapping**:
  - `true` $\to$ `Boolean.TRUE`
  - `false` $\to$ `Boolean.FALSE`
  - `nil` $\to$ `null`
- **Output Stringification**:
  Converting host runtime objects to user-visible Lox representations:
  ```java
  public String stringify(Object object) {
      if (object == null) return "nil";
      ...
      return object.toString();
  }
  ```

## What breaks it (failure modes)
- Printing Java's `"null"` instead of Lox's `"nil"`.
- Failing to handle scanner/parser errors before initiating evaluation (must exit 65 on syntax errors).

## Tradeoffs
- Tree-walk interpreter vs Bytecode VM — Tree-walk interpreters are simple and directly execute AST nodes, but suffer from CPU cache misses and high call-stack overhead compared to bytecode virtual machines (like clox).

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Output: `true`, `false`, or `nil`

## Java specifics — lookup, don't memorize
- `Boolean.TRUE`, `Boolean.FALSE`, `null` — standard Java representations for Lox boolean and nil values.

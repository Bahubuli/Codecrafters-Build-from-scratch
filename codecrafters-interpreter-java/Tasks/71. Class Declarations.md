# Stage 71: Class Declarations

## In one line
Extending grammar, AST, resolver, and interpreter runtime with `LoxClass` to parse and evaluate empty class declarations like first-class variables.

## Self-test (cover the answers below and answer these first)
- Why does Lox treat a class declaration as a statement that binds a class object to a variable in the environment?
- How is the scoping of a class declaration handled across blocks and functions?
- What does printing a `LoxClass` instance output?

## The problem it solved
To support object-oriented programming in Lox, classes must be declared, named, and stored as first-class runtime objects. Before adding methods and instantiation, the interpreter needs to recognize `class Name { ... }`, record the class name in the appropriate lexical scope (global, block, or function), and represent it at runtime.

## Concepts (the transferable part)
- **Class AST Node**:
  A class declaration AST node stores its identifier `name` and a list of method declarations `methods`:
  ```java
  public static class Class extends Stmt {
      public final Token name;
      public final List<Stmt.Function> methods;

      public Class(Token name, List<Stmt.Function> methods) {
          this.name = name;
          this.methods = methods;
      }
      ...
  }
  ```
- **Grammar & Parsing**:
  ```ebnf
  declaration     → classDecl | funDecl | varDecl | statement ;
  classDecl       → "class" IDENTIFIER "{" function* "}" ;
  ```
- **Runtime Representation (`LoxClass`)**:
  A lightweight runtime representation storing the class's name, stringifying to its name:
  ```java
  public class LoxClass {
      final String name;

      public LoxClass(String name) {
          this.name = name;
      }

      @Override
      public String toString() {
          return name;
      }
  }
  ```
- **Two-Stage Binding**:
  In `visitClassStmt`:
  ```java
  environment.define(stmt.name.lexeme, null);
  LoxClass klass = new LoxClass(stmt.name.lexeme);
  environment.assign(stmt.name, klass);
  ```
  This defines the variable first, builds the class representation, and then assigns it, honoring lexical scoping in any block or function scope.

## What breaks it (failure modes)
- Hardcoding classes only into the global environment: classes declared inside a block (`{ class Dinosaur {} }`) or function must obey local scoping and be unreachable once the scope exits.
- Failing to resolve the class name in `Resolver`: `Resolver.visitClassStmt` must declare and define the class name so local variable lookups find the correct scope depth.

## Tradeoffs
- Treating classes as first-class objects stored in standard environment frames reuses all lexical scoping, variable lookup, and closure mechanics without special bytecode or separate type tables.

## CLI / Protocol format
- Input:
  ```lox
  class Robot {}
  print Robot;
  ```
- Output:
  ```
  Robot
  ```

## Java specifics — lookup, don't memorize
- `toString()` override: when `Interpreter.stringify(value)` is called on `LoxClass`, returning `name` naturally produces the expected print output.

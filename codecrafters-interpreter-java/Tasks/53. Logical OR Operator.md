# Stage 53: Logical OR operator

## In one line
Short-circuit evaluation of logical OR expressions returning the first truthy operand or the last falsey operand.

## Self-test (cover the answers below and answer these first)
- Why is `or` represented as a special `Expr.Logical` node rather than a standard `Expr.Binary` node?
- In `false or 41`, what is the result value and why is it not boolean `true`?
- How does short-circuit evaluation avoid executing side effects in the right-hand operand?

## The problem it solved
Unlike binary arithmetic or comparison operators that evaluate both left and right operands eagerly, logical operators (`or`, `and`) require short-circuit evaluation. If the left operand of an `or` is truthy, the right operand must never be evaluated, preserving side effects and avoiding unnecessary computations or errors.

## Concepts (the transferable part)
- **Grammar Precedence**:
  `or` has lower precedence than `and`, equality, and comparisons, but higher precedence than assignment:
  ```
  assignment     → IDENTIFIER "=" assignment
                 | logic_or ;
  logic_or       → logic_and ( "or" logic_and )* ;
  logic_and      → equality ( "and" equality )* ;
  ```
- **Short-circuit Value Semantics**:
  In dynamically typed languages like Python, JavaScript, and Lox, logical operators return the value of the operand itself rather than coercing to boolean:
  ```java
  @Override
  public Object visitLogicalExpr(Expr.Logical expr) {
      Object left = evaluate(expr.left);

      if (expr.operator.type == TokenType.OR) {
          if (isTruthy(left)) return left;
      } else {
          if (!isTruthy(left)) return left;
      }

      return evaluate(expr.right);
  }
  ```
  If `left` is truthy, it returns `left` immediately. Only if `left` is falsey does it evaluate and return `expr.right`.

## What breaks it (failure modes)
- Treating `or` as a normal `Binary` operator: evaluating both operands upfront destroys short-circuit guarantees (e.g., `(a = false) or (b = true) or (a = "hello")` would execute all assignments).
- Converting the return value to a boolean (`true`/`false`) instead of returning the operand object (e.g. returning `true` for `41 or true` instead of `41`).

## Tradeoffs
- Returning the operand value allows idiomatic default values (`var name = input or "default"`) without needing a separate null-coalescing operator.

## Java specifics — lookup, don't memorize
- In Java, boolean short-circuit operators are `||` and `&&`. In Lox AST, `Expr.Logical` models conditional branch evaluation dynamically over `Object`.

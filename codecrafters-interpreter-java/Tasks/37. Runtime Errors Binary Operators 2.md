# Stage 37: Runtime Errors: Binary Operators (2/2)

## In one line
Handling runtime type errors for overloaded binary addition (`+`) and subtraction (`-`), rejecting heterogeneous combinations with exit code 70.

## Self-test (cover the answers below and answer these first)
- Does `"foo" + 42` perform automatic string concatenation in Lox?
- What happens when subtracting two strings `"foo" - "bar"`?
- What exit code is produced when operands to `+` are neither two numbers nor two strings?

## The problem it solved
Binary addition `+` is overloaded in Lox: it accepts either two numbers (for numeric addition) or two strings (for string concatenation). Any other pairing (number + string, string + boolean, boolean + boolean) is invalid. Binary subtraction `-` strictly requires both operands to be numbers. Invalid pairings must raise a `RuntimeError` and terminate with exit code 70.

## Concepts (the transferable part)
- **Overloaded Operator Validation**:
  ```java
  case PLUS:
      if (left instanceof Double && right instanceof Double) {
          return (double) left + (double) right;
      }
      if (left instanceof String && right instanceof String) {
          return (String) left + (String) right;
      }
      throw new RuntimeError(expr.operator, "Operands must be two numbers or two strings.");
  ```
- **Subtraction Operand Validation**:
  ```java
  case MINUS:
      checkNumberOperands(expr.operator, left, right);
      return (double) left - (double) right;
  ```
- **Consistent Failure Semantics**:
  Lox explicitly disallows implicit type coercions common in dynamic scripting languages (e.g. JavaScript or Perl), treating type mismatches as unrecoverable runtime errors.

## What breaks it (failure modes)
- Implicitly calling `.toString()` on a non-string operand when one side is a string.
- Treating boolean values as numbers (e.g. `true == 1`).
- Returning exit code 0 or 65 on type errors instead of 70.

## Tradeoffs
- Disallowing implicit coercion eliminates entire classes of subtle bugs, at the cost of requiring explicit conversion mechanisms (e.g. string formatting).

## CLI / Protocol format
- Command: `./your_program.sh evaluate <file.lox>`
- Input: `17 + "bar"`
- Stderr:
  ```
  Operands must be two numbers or two strings.
  [line 1]
  ```
- Exit code: `70`

## Java specifics — lookup, don't memorize
- Safe multi-type branch: `instanceof Double` vs `instanceof String`.

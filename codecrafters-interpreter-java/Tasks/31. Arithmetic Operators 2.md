# Stage 31: Arithmetic Operators (2/2)

## In one line
Evaluating binary addition (`+`) and subtraction (`-`) across numbers with support for unary nesting and precedence.

## The problem it solved
Binary addition (`+`) and subtraction (`-`) operate at a lower precedence than multiplication and division. The evaluator must recursively resolve subexpressions (including unary negations and groupings), evaluate numeric differences and sums, and cleanly format positive and negative results.

## Concepts (the transferable part)
- **Binary Arithmetic Evaluation**:
  ```java
  case PLUS:
      if (left instanceof Double && right instanceof Double) {
          return (double) left + (double) right;
      }
      if (left instanceof String && right instanceof String) {
          return (String) left + (String) right;
      }
      throw new RuntimeError(expr.operator, "Operands must be two numbers or two strings.");
  case MINUS:
      checkNumberOperands(expr.operator, left, right);
      return (double) left - (double) right;
  ```
- **Associativity & Precedence Realization**:
  The parser constructs left-associative binary AST trees (`(23 + 28) - (-(61 - 99))`), and tree-walk evaluation naturally enforces left-associativity and proper operator precedence through recursive post-order evaluation.

## What breaks it (failure modes)
- Mixing string concatenation and numeric addition without proper type discrimination.
- Retaining trailing `.0` on negative integers (e.g. printing `-24.0` instead of `-24`).
- Evaluating right operands before left operands, breaking side-effect ordering.

## Tradeoffs
- Overloaded `+` operator — Sharing `+` for both numeric addition and string concatenation requires runtime dynamic type inspection before dispatching.

# Stage 49: If statements

## In one line
Adding `Stmt.If` conditional branching to the grammar, AST, and interpreter visitor, evaluating truthiness to execute the then-branch or optional else-branch.

## The problem it solved
Programs need control flow to conditionally execute statements depending on dynamic runtime expressions. The interpreter must parse `if (condition) statement (else statement)?` and execute branches based on whether the condition evaluates to a truthy or falsey value.

## Concepts (the transferable part)
- **Grammar for `if` Statement**:
  ```
  statement → exprStmt
            | ifStmt
            | printStmt
            | block ;

  ifStmt    → "if" "(" expression ")" statement
              ( "else" statement )? ;
  ```
- **Parsing `if` (`Parser.java`)**:
  ```java
  private Stmt ifStatement() {
      consume(TokenType.LEFT_PAREN, "Expect '(' after 'if'.");
      Expr condition = expression();
      consume(TokenType.RIGHT_PAREN, "Expect ')' after if condition.");

      Stmt thenBranch = statement();
      Stmt elseBranch = null;
      if (match(TokenType.ELSE)) {
          elseBranch = statement();
      }

      return new Stmt.If(condition, thenBranch, elseBranch);
  }
  ```
  *Dangling else resolution*: In recursive descent, matching `ELSE` inside `ifStatement()` naturally binds the `else` to the innermost, most recently parsed `if` statement.
- **Executing `if` (`Interpreter.java`)**:
  ```java
  @Override
  public Void visitIfStmt(Stmt.If stmt) {
      if (isTruthy(evaluate(stmt.condition))) {
          execute(stmt.thenBranch);
      } else if (stmt.elseBranch != null) {
          execute(stmt.elseBranch);
      }
      return null;
  }
  ```
  Lox evaluates only the branch that should execute; the untaken branch is never evaluated.

## What breaks it (failure modes)
- Evaluating both branches eagerly instead of conditionally based on the evaluated condition.
- Using Java's boolean equivalence instead of Lox's truthiness rules (in Lox, `nil` and `false` are falsey; all other values including numbers, strings, and zero are truthy).

## Tradeoffs
- Representing statements directly with recursive visits is clean and matches AST semantics, but does not provide jump instructions needed for bytecode compilation.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  var a = false;
  if (a = true) {
      print (a == true);
  }
  ```
- Stdout:
  ```
  true
  ```
- Exit code: `0`

## Java specifics — lookup, don't memorize
- In Java, `boolean isTruthy(Object object)` handles type casting:
  ```java
  if (object == null) return false;
  if (object instanceof Boolean) return (boolean) object;
  return true;
  ```

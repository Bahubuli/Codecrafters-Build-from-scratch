# Stage 32: String Concatenation

## In one line
Overloading the binary `+` operator dynamically at runtime to support both numeric addition and string concatenation.

## The problem it solved
In dynamically typed languages, operators like `+` perform different operations depending on runtime operand types. In Lox, `+` is overloaded to add numbers or concatenate strings, but does not implicitly coerce mixed types.

## Concepts (the transferable part)
- **Dynamic Operator Overloading**:
  Runtime inspection checks the concrete types of evaluated operands:
  ```java
  case PLUS:
      if (left instanceof Double && right instanceof Double) {
          return (double) left + (double) right;
      }
      if (left instanceof String && right instanceof String) {
          return (String) left + (String) right;
      }
      throw new RuntimeError(expr.operator, "Operands must be two numbers or two strings.");
  ```
- **Lox Type Safety**:
  Unlike JavaScript which implicitly coerces `"foo" + 1` into `"foo1"`, Lox strictly requires both operands to be of the same compatible type (both numbers or both strings).

## What breaks it (failure modes)
- Implicitly coercing `null` or numbers to strings via Java's `+` operator when only one operand is a String.
- Wrapping the resulting string in extraneous quotes during output.

## Tradeoffs
- Operator overloading vs dedicated concatenation operator — Some languages (like Lua with `..` or PHP with `.`) use separate operators for strings and numbers to avoid runtime ambiguity and type checking overhead.

- Examples:

# Stage 43: Variables: Runtime Errors

## In one line
Catching undefined variable accesses at runtime, outputting error details to `stderr`, and exiting with code 70.

## Self-test (cover the answers below and answer these first)
- Why is an undeclared variable lookup a runtime error rather than a static compile-time error in Lox?
- What exit code signifies a runtime error in Lox?
- To which stream should runtime errors be printed?

## The problem it solved
In dynamically-typed and dynamically-scoped/declared scripting languages, accessing an identifier that has not been defined in the current or any enclosing lexical environment cannot be resolved. The interpreter must throw a `RuntimeError` rather than silently evaluating to `nil` or crashing with an unhandled Java `NullPointerException`.

## Concepts (the transferable part)
- **Runtime Error vs Syntax Error**:
  - Syntax/lexical error: invalid tokens or grammar (exit code 65).
  - Runtime error: semantic failure during execution, e.g. undefined variable lookup (exit code 70).
- **Environment Lookup Failure**:
  ```java
  public Object get(Token name) {
      if (values.containsKey(name.lexeme)) {
          return values.get(name.lexeme);
      }
      if (enclosing != null) return enclosing.get(name);
      throw new RuntimeError(name, "Undefined variable '" + name.lexeme + "'.");
  }
  ```
- **Error Reporting Format**:
  Output to `System.err`:
  ```
  Undefined variable '<name>'.
  [line <line>]
  ```
  And terminate the process with exit code 70 without evaluating subsequent statements.

## What breaks it (failure modes)
- Returning `nil` or `null` for undefined variables instead of throwing `RuntimeError`.
- Printing runtime errors to `stdout` instead of `stderr`.
- Exiting with code 65 (syntax error) instead of 70 (runtime error).

## Tradeoffs
- Static analysis / resolve pass vs dynamic lookup: Statically checking variable declarations during a resolution pass allows catching undeclared variable bugs before running any statements. However, standard Lox allows forward references inside functions, requiring deferred resolution or runtime checking for globals.

## CLI / Protocol format
- Command: `./your_program.sh run <file.lox>`
- Input:
  ```lox
  print 22;
  print x;
  ```
- Stdout:
  ```
  22
  ```
- Stderr:
  ```
  Undefined variable 'x'.
  [line 2]
  ```
- Exit code: `70`

## Java specifics — lookup, don't memorize
- `System.err.println(...)` directs error output specifically to file descriptor 2 (stderr).

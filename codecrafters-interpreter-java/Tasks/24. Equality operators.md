# Stage 24: Equality operators

## In one line
Implementing left-associative recursive descent parsing for equality operators (`==` and `!=`) via the top-level `equality` binary expression grammar rule.

## Self-test (cover the answers below and answer these first)
- Why does `expression()` directly call `equality()` in the expression grammar?
- How does the parser distinguish between equality comparison `==` and assignment `=`?
- Why do equality operators have lower precedence than relational comparison operators?

## The problem it solved
Expressions such as `a < b == c > d` mix comparison and equality. In standard programming language semantics, relational comparisons (`<`, `>`) bind tighter than equality checks (`==`, `!=`). Organizing grammar rules into a strict precedence hierarchy ensures `(a < b) == (c > d)` rather than `a < (b == c) > d`.

## Concepts (the transferable part)
- **Top Precedence of Binary Expressions**:
  `equality` sits at the top of the binary operator hierarchy:
  $$\text{expression} \to \text{equality} \to \text{comparison} \to \text{term} \to \text{factor} \to \text{unary} \to \text{primary}$$
  ```java
  private Expr equality() {
      Expr expr = comparison();

      while (match(TokenType.BANG_EQUAL, TokenType.EQUAL_EQUAL)) {
          Token operator = previous();
          Expr right = comparison();
          expr = new Expr.Binary(expr, operator, right);
      }

      return expr;
  }
  ```
- **Disambiguating `=` vs `==`**:
  The scanner produces distinct tokens: single `=` produces `TokenType.EQUAL` (used in statements/assignments), while `==` produces `TokenType.EQUAL_EQUAL`. The expression parser only matches `EQUAL_EQUAL` in `equality()`.

## What breaks it (failure modes)
- Mixing up `EQUAL` (`=`) and `EQUAL_EQUAL` (`==`) in `match()`.
- Failing to evaluate operands left-to-right when building AST nodes.

## Tradeoffs
- Strict equality vs type-coercing equality — In Lox, equality is strict and nil-safe without JavaScript-style automatic coercion. In AST representation, literals preserve exact scanned values.

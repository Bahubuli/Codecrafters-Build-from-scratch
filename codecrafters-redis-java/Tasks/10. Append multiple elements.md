# Stage 10: Append multiple elements

---

## What You Have to Do

In this stage, you add support for appending multiple elements in a single `RPUSH` command:

```
RPUSH <key> <element1> <element2> ... [<elementN>]
```

1. **Variadic `RPUSH` Arguments**:
   - `RPUSH` accepts one or more elements in a single command invocation.
   - When creating a **new list** with multiple elements:
     ```
     > RPUSH another_list "bar" "baz"
     (integer) 2
     ```
   - When appending multiple elements to an **existing list**:
     ```
     > RPUSH another_list "foo" "bar" "baz"
     (integer) 5
     ```
   - All elements must be appended in order (from left to right) to the tail of the list.

2. **RESP Wire Protocol Reply**:
   - The response to each command is the new total length of the list returned as a **RESP Integer**:
     ```
     :<length>\r\n
     ```
     For length 3: `:3\r\n`  
     For length 5: `:5\r\n`

---

## Thought Process

**The gap after stage 9:** In stage 9, `RPUSH` was called with a single element (`RPUSH key element`). In real-world Redis, commands frequently accept variable numbers of arguments (variadic arity). Clients leverage this to batch inserts into lists without incurring the network latency of multiple round trips.

**Dynamic Arity in RESP Parsing:**
- In RESP array format `*<n>\r\n`, the array length `n` directly reflects the total number of bulk string arguments provided.
- For `RPUSH <key> <elem1> <elem2> ... <elemM>`, `n` will be $M + 2$ (where `parts[0]` is `"RPUSH"`, `parts[1]` is `<key>`, and `parts[2]` through `parts[n-1]` are the values).
- Our parser collects all array entries into `String[] parts`, so handling multiple elements is straightforward: iterate from index 2 to `parts.length - 1`.

**Atomic Batch Insertion & Thread Safety:**
- In a multithreaded server, if client A pushes `["x", "y"]` and client B pushes `["1", "2"]` to the same list concurrently:
  - If operations are not synchronized atomically per batch, the items could interleave unpredictably (e.g. `["x", "1", "y", "2"]`), and intermediate lengths could leak.
  - By performing the entire insertion loop and size query inside `synchronized (list)`, all elements from a single command are appended contiguously, and the returned integer precisely matches the size after that batch is committed.

## The Solution

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.io.OutputStream;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class Main {
  private static class Entry {
    final String value;
    final Long expiresAt;

    Entry(String value, Long expiresAt) {
      this.value = value;
      this.expiresAt = expiresAt;
    }

    boolean isExpired() {
      return expiresAt != null && System.currentTimeMillis() > expiresAt;
    }
  }

  private static final Map<String, Entry> store = new ConcurrentHashMap<>();
  private static final Map<String, List<String>> listStore = new ConcurrentHashMap<>();

  public static void main(String[] args) {
    System.out.println("Logs from your program will appear here!");

    int port = 6379;

    try {
      ServerSocket serverSocket = new ServerSocket(port);
      serverSocket.setReuseAddress(true);

      while (true) {
        Socket clientSocket = serverSocket.accept();

        new Thread(() -> {
          try {
            OutputStream out = clientSocket.getOutputStream();
            InputStream in = clientSocket.getInputStream();
            BufferedReader reader = new BufferedReader(new InputStreamReader(in));

            while (true) {
              String line = reader.readLine();
              if (line == null) break; // client disconnected

              int n = Integer.parseInt(line.substring(1));

              String[] parts = new String[n];
              for (int i = 0; i < n; i++) {
                reader.readLine();            // Skip "$<len>"
                parts[i] = reader.readLine(); // Payload
              }

              String command = parts[0];

              if (command.equalsIgnoreCase("PING")) {
                out.write("+PONG\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("ECHO")) {
                String arg = parts[1];
                byte[] bytes = arg.getBytes(StandardCharsets.UTF_8);
                String response = "$" + bytes.length + "\r\n" + arg + "\r\n";
                out.write(response.getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("SET")) {
                String key = parts[1];
                String value = parts[2];
                Long expiresAt = null;

                if (parts.length >= 5) {
                  if (parts[3].equalsIgnoreCase("PX")) {
                    long pxMillis = Long.parseLong(parts[4]);
                    expiresAt = System.currentTimeMillis() + pxMillis;
                  } else if (parts[3].equalsIgnoreCase("EX")) {
                    long exSeconds = Long.parseLong(parts[4]);
                    expiresAt = System.currentTimeMillis() + (exSeconds * 1000);
                  }
                }

                store.put(key, new Entry(value, expiresAt));
                out.write("+OK\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("GET")) {
                String key = parts[1];
                Entry entry = store.get(key);

                if (entry != null && !entry.isExpired()) {
                  byte[] bytes = entry.value.getBytes(StandardCharsets.UTF_8);
                  String response = "$" + bytes.length + "\r\n" + entry.value + "\r\n";
                  out.write(response.getBytes(StandardCharsets.UTF_8));
                } else {
                  if (entry != null && entry.isExpired()) {
                    store.remove(key);
                  }
                  out.write("$-1\r\n".getBytes(StandardCharsets.UTF_8));
                }
              } else if (command.equalsIgnoreCase("RPUSH")) {
                if (parts.length < 3) {
                  out.write("-ERR wrong number of arguments for 'rpush' command\r\n".getBytes(StandardCharsets.UTF_8));
                } else {
                  String key = parts[1];
                  List<String> list = listStore.computeIfAbsent(key, k -> Collections.synchronizedList(new ArrayList<>()));
                  int newLength;
                  synchronized (list) {
                    for (int i = 2; i < parts.length; i++) {
                      list.add(parts[i]);
                    }
                    newLength = list.size();
                  }
                  String response = ":" + newLength + "\r\n";
                  out.write(response.getBytes(StandardCharsets.UTF_8));
                }
              }
              out.flush();
            }
          } catch (IOException e) {
            System.out.println("IOException: " + e.getMessage());
          }
        }).start();
      }
    } catch (IOException e) {
      System.out.println("IOException: " + e.getMessage());
    }
  }
}
```

## New Concepts in This Stage

**[CONCEPT] Variadic Arity Commands**  
Many Redis commands support variadic arity (`RPUSH`, `LPUSH`, `SADD`, `MGET`, `MSET`, `DEL`). Rather than requiring clients to issue $K$ individual round-trip commands across the network, the wire protocol permits packaging all values into a single array payload `*<2+K>\r\n`. This dramatically reduces TCP packet overhead and round-trip latency.

**[CONCEPT] Batch Atomicity within a Single Command**  
Even when Redis executes commands in a multithreaded architecture (or under multiple concurrent client threads in our Java implementation), a single command invocation must be atomic. All items specified in `RPUSH key a b c` must be pushed contiguously without another client's `RPUSH` or `LPOP` interleaving in the middle.

**[CONCEPT] Amortized $O(K)$ Insertion Complexity**  
Pushing $K$ elements onto an array-backed list takes $O(K)$ amortized time. In Java's `ArrayList`, resizing happens geometrically (1.5x growth), ensuring that appending multiple items sequentially runs in $O(1)$ amortized time per item.

**[SYNTAX] Java specifics — lookup, don't memorize**  
- `for (int i = 2; i < parts.length; i++)`: Iterating over command argument tokens starting after the command name (`parts[0]`) and key (`parts[1]`).
- `list.size()`: Reads the updated element count after all elements in the loop are appended.

---

## Failure Modes

- **Assuming fixed 3-part argument array**: Hardcoding `list.add(parts[2])` and ignoring `parts[3]...` will drop all subsequent elements, causing tests with multi-element pushes to fail length assertions.
- **Interleaved concurrent writes**: Not wrapping the loop in `synchronized (list)` allows two client threads appending to the same list to interleave items and experience race conditions during backing array growth.
- **Reporting intermediate lengths**: Emitting a response before all elements in `parts` are added results in premature or incorrect integer replies.
- **Off-by-one loop indexing**: Starting iteration at index 1 would incorrectly push the key itself as an element; starting at index 3 would skip the first element.

---

## Tradeoffs — Multi-argument Push vs Pipelining

| Approach | Network Round Trips | Server Atomicity | Client Complexity |
|---|---|---|---|
| **Variadic Command (`RPUSH k a b c`)** | 1 RTT | Fully atomic batch insertion on the key | Low (single command) |
| **Command Pipelining ($N$ x `RPUSH k x`)** | 1 RTT (batched writes) | Non-atomic (other client commands may interleave) | Medium (client manages pipeline buffers) |
| **Sequential Commands ($N$ round-trips)** | $N$ RTTs | Non-atomic across commands | Simplest client code, but high latency bottleneck |

*Conclusion:* Supporting native variadic arguments on collection commands gives clients both minimal network latency and strict batch atomicity.

## How It Flows

```
1. Client sends RPUSH with 3 elements to create a list:
Client -> *5\r\n$5\r\nRPUSH\r\n$8\r\nlist_key\r\n$8\r\nelement1\r\n$8\r\nelement2\r\n$8\r\nelement3\r\n

Server reads:
  n = 5
  parts = ["RPUSH", "list_key", "element1", "element2", "element3"]

Server processing:
  key = "list_key"
  list = listStore.computeIfAbsent("list_key", ...) -> new list
  synchronized(list):
    i=2 -> list.add("element1") -> ["element1"]
    i=3 -> list.add("element2") -> ["element1", "element2"]
    i=4 -> list.add("element3") -> ["element1", "element2", "element3"]
    newLength = 3

Server replies:
  :3\r\n

2. Client sends RPUSH with 2 more elements to append to the existing list:
Client -> *4\r\n$5\r\nRPUSH\r\n$8\r\nlist_key\r\n$8\r\nelement4\r\n$8\r\nelement5\r\n

Server reads:
  n = 4
  parts = ["RPUSH", "list_key", "element4", "element5"]

Server processing:
  key = "list_key"
  list = listStore.computeIfAbsent(...) -> retrieves existing list
  synchronized(list):
    i=2 -> list.add("element4")
    i=3 -> list.add("element5")
    newLength = 5

Server replies:
  :5\r\n
```

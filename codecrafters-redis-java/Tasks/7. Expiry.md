# Stage 7: Expiry

---

## What You Have to Do

Add support for key expiration via the optional `PX` argument in the `SET` command:

```
SET <key> <value> [px <milliseconds>]
```

1. **`SET <key> <value> px <milliseconds>`**
   Sets `<key>` to `<value>` with a Time-To-Live (TTL) of `<milliseconds>`.
   Replies with `+OK\r\n`.
   Arguments are case-insensitive (`px`, `PX`, `Px`).

   ```
   $ redis-cli SET apple banana px 100
   OK
   ```

2. **`GET <key>` behavior**:
   - If queried **before** the TTL expires, return the value as a bulk string:
     ```
     $ redis-cli GET apple
     banana
     ```
   - If queried **after** the TTL expires, treat the key as non-existent and return the null bulk string:
     ```
     $ redis-cli GET apple
     (nil)
     ```
     (Wire output: `$-1\r\n`)

---

## Thought Process

**The gap after stage 6:** In Stage 6, keys persisted indefinitely in the `ConcurrentHashMap`. In real-world caching, memory is finite and data goes stale. Keys must be automatically expired after a duration.

**Passive vs Active Expiration:**
- **Active expiration:** A background timer thread periodically scans keys and deletes expired ones. This frees memory proactively even if keys are never accessed again, but introduces thread scheduling and synchronization complexity.
- **Passive expiration:** When a client sends `GET <key>`, the server checks `System.currentTimeMillis()` against the key's expiry timestamp. If expired, it deletes the key on the spot and returns `(nil)`.

For this stage, **passive expiration** on access is both sufficient and standard in Redis (real Redis uses a hybrid of both passive checks on read and probabilistic active sampling in the background).

**Data Structure Design:**
Instead of storing raw `String` values in `store`, we store a composite `Entry` object containing:
- `value`: the payload string
- `expiresAt`: absolute expiration epoch timestamp (`Long`), or `null` if the key has no expiry.

## The Solution

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.io.OutputStream;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class Main {
  // Value wrapper holding payload and optional expiration timestamp
  private static class Entry {
    final String value;
    final Long expiresAt; // Epoch timestamp in milliseconds; null if persistent

    Entry(String value, Long expiresAt) {
      this.value = value;
      this.expiresAt = expiresAt;
    }

    boolean isExpired() {
      return expiresAt != null && System.currentTimeMillis() > expiresAt;
    }
  }

  private static final Map<String, Entry> store = new ConcurrentHashMap<>();

  public static void main(String[] args) {
    System.out.println("Logs from your program will appear here!");

    int port = 6379;

    try {
      ServerSocket serverSocket = new ServerSocket(port);
      serverSocket.setReuseAddress(true);

      while (true) {
        Socket clientSocket = serverSocket.accept();

        new Thread(() -> {
          try {
            OutputStream out = clientSocket.getOutputStream();
            InputStream in = clientSocket.getInputStream();
            BufferedReader reader = new BufferedReader(new InputStreamReader(in));

            while (true) {
              String line = reader.readLine();
              if (line == null) break; // client disconnected

              int n = Integer.parseInt(line.substring(1));

              String[] parts = new String[n];
              for (int i = 0; i < n; i++) {
                reader.readLine();            // Skip "$<len>"
                parts[i] = reader.readLine(); // Payload
              }

              String command = parts[0];

              if (command.equalsIgnoreCase("PING")) {
                out.write("+PONG\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("ECHO")) {
                String arg = parts[1];
                byte[] bytes = arg.getBytes(StandardCharsets.UTF_8);
                String response = "$" + bytes.length + "\r\n" + arg + "\r\n";
                out.write(response.getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("SET")) {
                String key = parts[1];
                String value = parts[2];
                Long expiresAt = null;

                // Check for optional PX <milliseconds> or EX <seconds>
                if (parts.length >= 5) {
                  if (parts[3].equalsIgnoreCase("PX")) {
                    long pxMillis = Long.parseLong(parts[4]);
                    expiresAt = System.currentTimeMillis() + pxMillis;
                  } else if (parts[3].equalsIgnoreCase("EX")) {
                    long exSeconds = Long.parseLong(parts[4]);
                    expiresAt = System.currentTimeMillis() + (exSeconds * 1000);
                  }
                }

                store.put(key, new Entry(value, expiresAt));
                out.write("+OK\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("GET")) {
                String key = parts[1];
                Entry entry = store.get(key);

                if (entry != null && !entry.isExpired()) {
                  byte[] bytes = entry.value.getBytes(StandardCharsets.UTF_8);
                  String response = "$" + bytes.length + "\r\n" + entry.value + "\r\n";
                  out.write(response.getBytes(StandardCharsets.UTF_8));
                } else {
                  if (entry != null && entry.isExpired()) {
                    store.remove(key); // Passive eviction
                  }
                  out.write("$-1\r\n".getBytes(StandardCharsets.UTF_8));
                }
              }
              out.flush();
            }
          } catch (IOException e) {
            System.out.println("IOException: " + e.getMessage());
          }
        }).start();
      }
    } catch (IOException e) {
      System.out.println("IOException: " + e.getMessage());
    }
  }
}
```

## New Concepts in This Stage

**[CONCEPT] TTL & Expiration as Absolute Deadlines**  
When a client sends a relative TTL (`PX 100` = "live for 100ms from now"), the server must convert that relative duration into an **absolute point in time** (`System.currentTimeMillis() + 100`). Checking expiration becomes a trivial `now > expiresAt` comparison on every subsequent read.

**[CONCEPT] Passive (Lazy) Eviction**  
Memory for an expired key is only reclaimed when a reader tries to access it (`GET`).
- Pros: Zero CPU overhead when idle; no timer threads or complex scheduling.
- Cons: If a key is set with expiry and never queried again, its memory is leaked until the process restarts.

**[CONCEPT] Relative TTL vs Absolute Timestamp**  
Relative durations are client-convenient; absolute timestamps are server-efficient. Converting at write-time means reads do no math other than comparison.

**[SYNTAX] Java specifics — lookup, don't memorize**  
- `System.currentTimeMillis()` — returns current epoch time in milliseconds.
- `Long.parseLong(str)` — parses a decimal string into a 64-bit signed integer.
- `Long` wrapper vs `long` primitive — allows `null` to represent "no expiration set".

---

## Failure Modes

- **Case-sensitive matching on `"PX"`** — clients or testers sending lowercase `"px"` or `"Px"` would bypass the check, storing the key without expiry. Always use `equalsIgnoreCase`.
- **Storing relative duration instead of absolute timestamp** — if you store `100` and check against current time, every key will instantly look expired.
- **Clock skew / wall-clock jumps** — `System.currentTimeMillis()` can jump backwards if NTP adjusts system time. For production interval measurement, monotonic clocks (`System.nanoTime()`) are safer, but for calendar-based TTLs or Redis replication timestamps, epoch millis is standard.
- **Missing `Long.parseLong` error handling** — malformed arguments could trigger `NumberFormatException`.

---

## Tradeoffs — Eviction Strategies

| Eviction Strategy | CPU Cost | Memory Reclaim Latency | Implementation Complexity |
|---|---|---|---|
| **Passive (Lazy)** | Microscopic (on-demand during GET) | Indefinite (only when key is accessed) | Trivial |
| **Active (Background Scanner)** | Periodic CPU spikes (sampling keys) | Fast (within sampling interval) | Moderate (background thread) |
| **Scheduled (Timer Wheel / PriorityQueue)** | High write overhead (inserting timer) | Immediate at exact deadline | High |

*What does real Redis do?*  
Redis runs a passive check on every key read, PLUS an active loop 10 times per second that randomly tests 20 keys with an expiry and purges expired ones until less than 25% of the sampled keys are expired.

## How It Flows

```
T0: SET foo bar px 50
    -> expiresAt = T0 + 50ms
    -> reply "+OK\r\n"

T0 + 20ms: GET foo
    -> (T0 + 20ms) <= expiresAt
    -> not expired -> reply "$3\r\nbar\r\n"

T0 + 60ms: GET foo
    -> (T0 + 60ms) > expiresAt
    -> isExpired() == true
    -> store.remove("foo")
    -> reply "$-1\r\n"
```

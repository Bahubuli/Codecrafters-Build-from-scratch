2. **For a string holding `'A'`, which bit offsets evaluate to 1?**

3. **What does `GETBIT mykey 0` return for the character `'A'`?**
   - *Answer*: `:0\r\n` (the MSB of `01000001` is 0).
4. **Why do Redis bitmap commands and string commands operate seamlessly on the exact same keys?**
   - *Answer*: In Redis, bitmaps are not an isolated data structure or type; they are simply byte buffers (strings) viewed through bitwise offsets.
5. **If a string has length 2 (e.g. `"AB"`), what byte does bit offset 9 access?**
   - *Answer*: Byte 1 (`9 / 8 = 1`, which contains `'B'`) at bit index `7 - (9 % 8) = 6` (the second MSB of byte 1).

## Thought Process & Architectural Model

### 1. Unified Byte Storage

```text
SET mykey "A"
               +-----------------------+
   mykey ----> | Entry                 |
               | - value: "A"          |
               | - rawBytes: [0x41]    |
               +-----------------------+
                            |
   Offset 0 1 2 3 4 5 6 7   |
   Bit:   0 1 0 0 0 0 0 1   |
          | |           |   |
          | +--> bit 1  |<--+ GETBIT mykey 1 -> :1\r\n
          |             |
          +----> bit 0  |<--+ GETBIT mykey 0 -> :0\r\n
                        |
                        +<--+ GETBIT mykey 7 -> :1\r\n
```

### 2. Bitwise Index Calculation

For offset $k$:
$$\text{byteIndex} = \lfloor k / 8 \rfloor$$
$$\text{bitIndex} = 7 - (k \pmod 8)$$
$$\text{bitMask} = 1 \ll \text{bitIndex}$$
$$\text{bit} = (\text{rawBytes}[\text{byteIndex}] \mathbin{\&} \text{bitMask}) \ne 0 \ ? \ 1 : 0$$

For character `'A'` (`0x41` = `01000001`):
- Offset 0: `byteIndex = 0`, `bitIndex = 7`, mask `0x80` (`10000000`) $\rightarrow 0x41 \ \& \ 0x80 = 0 \rightarrow :0\r\n$
- Offset 1: `byteIndex = 0`, `bitIndex = 6`, mask `0x40` (`01000000`) $\rightarrow 0x41 \ \& \ 0x40 = 0x40 \rightarrow :1\r\n$
- Offset 7: `byteIndex = 0`, `bitIndex = 0`, mask `0x01` (`00000001`) $\rightarrow 0x41 \ \& \ 0x01 = 0x01 \rightarrow :1\r\n$

## Concepts

1. **Dual Views of Memory**:
   - Redis does not segregate string values and bitmap values. A string key is simultaneously an array of characters, a bulk binary payload, and a vector of individual bits.
2. **ASCII Encoding and Bitmaps**:
   - Standard ASCII characters occupy single bytes whose 8-bit patterns can be queried or modified bit-by-bit.

## Failure Modes

1. **Encoding Mismatch on String Instantiation**:
   - If strings are encoded into bytes using non-deterministic or lossy charsets, character bit patterns will not match standard ASCII values. `StandardCharsets.ISO_8859_1` guarantees 1:1 mapping.
2. **Out of Range Queries on Strings**:
   - If `GETBIT` is called with offset $\ge \text{len} \times 8$, it must gracefully yield `:0\r\n` without out-of-bounds exceptions.

---

## Tradeoffs

- **Precomputed `rawBytes` vs On-Demand Conversion**:
  - Pre-populating `rawBytes` when constructing `Entry` ensures zero serialization overhead during subsequent `GETBIT` queries.

---

## Java Specifics

- In Java, character `'A'` has unicode codepoint 65 (`0x41`). Conversion to ISO-8859-1 byte array yields byte array `[0x41]`.

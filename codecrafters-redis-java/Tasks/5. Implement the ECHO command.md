## What You Have to Do

Support the `ECHO` command. It takes one argument and sends it straight back, encoded as a RESP **bulk string**.

```
$ redis-cli ECHO hey
hey
```

On the wire, the client sends an `ECHO` as a RESP **array of bulk strings**:

```
*2\r\n$4\r\nECHO\r\n$3\r\nhey\r\n      ==  ["ECHO", "hey"]
```

Your server must reply with the argument as a bulk string:

```
$3\r\nhey\r\n
```

The argument is **random** each run — no hardcoding. Command names are
**case-insensitive** (`ECHO`, `echo`, `EcHo` all count).

---

## Frame (think before coding)

Every stage so far let you cheat: you ignored the client's bytes entirely and
blindly wrote `+PONG\r\n`. **That cheat dies here.** To echo a random argument
back, you must actually *read the bytes the client sent and understand them*.
That means parsing RESP for the first time.

**Questions to answer before you write anything. Guess even if unsure.**

1. The client sends `*2\r\n$4\r\nECHO\r\n$3\r\nhey\r\n`. Walk it left to right and
   say, byte group by byte group, **what each part means**. What does `*2`
   announce? What does `$4` announce? Where do the actual payload bytes live?

2. The previous stages' shortcut was "one `read()` = one message, ignore the
   content." Name the **two** assumptions in that shortcut that RESP parsing
   forces you to confront now.

3. You'll write a parser. **What does it need to return** to the rest of your
   program so the code above it can say "if the command is ECHO, reply with
   argument 1"? Describe the shape of the parsed result, not the Java type.

# Stage 9: Append an element

---

## What You Have to Do

In this stage, you add support for appending elements to an **existing list** using the `RPUSH` command:

```
RPUSH <key> <element> [<element> ...]
```

1. **`RPUSH` on an existing list**:
   - When a client sends `RPUSH` on a list that already exists, the new element is appended to the tail (end) of that existing list.
   - The key's existing elements must remain intact and retain their original order.
   - Example:
     ```
     $ redis-cli RPUSH list_key "element1"
     (integer) 1

     $ redis-cli RPUSH list_key "element2"
     (integer) 2
     ```

2. **RESP Wire Protocol Reply**:
   - The reply is the **new total length of the list** after appending the element(s).
   - Encoded as a **RESP Integer**:
     ```
     :<length>\r\n
     ```
     For length 1: `:1\r\n`  
     For length 2: `:2\r\n`

---

## Thought Process

**The gap after stage 8:** In stage 8, we handled creating a list when the key did not yet exist. In stage 9, we must verify that subsequent `RPUSH` invocations correctly locate the existing list rather than creating a new one or overwriting existing items, preserve item ordering, and return the incrementally increasing length.

**List Mutability & Persistence in Redis:**
- When key `list_key` is first pushed to, it transitions from non-existent to an initialized list containing 1 element (`[element1]`).
- On the next `RPUSH`, the server looks up `list_key`. Finding an existing collection, it mutates the list in place by appending `element2` at the right end (`[element1, element2]`).
- The operation returns the updated size ($2$).

**Concurrency & Thread Safety:**
- Redis is famously single-threaded in its core event loop, but our multi-threaded Java server allows concurrent clients to issue commands simultaneously.
- If two threads issue `RPUSH list_key ...` concurrently:
  - `computeIfAbsent` retrieves the already-existing list instance atomically.
  - Synchronizing on the list instance (`synchronized (list)`) guarantees that `list.add()` and `list.size()` happen atomically, preventing lost updates, race conditions, or corrupted lengths.

## The Solution

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.io.OutputStream;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class Main {
  private static class Entry {
    final String value;
    final Long expiresAt;

    Entry(String value, Long expiresAt) {
      this.value = value;
      this.expiresAt = expiresAt;
    }

    boolean isExpired() {
      return expiresAt != null && System.currentTimeMillis() > expiresAt;
    }
  }

  private static final Map<String, Entry> store = new ConcurrentHashMap<>();
  private static final Map<String, List<String>> listStore = new ConcurrentHashMap<>();

  public static void main(String[] args) {
    System.out.println("Logs from your program will appear here!");

    int port = 6379;

    try {
      ServerSocket serverSocket = new ServerSocket(port);
      serverSocket.setReuseAddress(true);

      while (true) {
        Socket clientSocket = serverSocket.accept();

        new Thread(() -> {
          try {
            OutputStream out = clientSocket.getOutputStream();
            InputStream in = clientSocket.getInputStream();
            BufferedReader reader = new BufferedReader(new InputStreamReader(in));

            while (true) {
              String line = reader.readLine();
              if (line == null) break; // client disconnected

              int n = Integer.parseInt(line.substring(1));

              String[] parts = new String[n];
              for (int i = 0; i < n; i++) {
                reader.readLine();            // Skip "$<len>"
                parts[i] = reader.readLine(); // Payload
              }

              String command = parts[0];

              if (command.equalsIgnoreCase("PING")) {
                out.write("+PONG\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("ECHO")) {
                String arg = parts[1];
                byte[] bytes = arg.getBytes(StandardCharsets.UTF_8);
                String response = "$" + bytes.length + "\r\n" + arg + "\r\n";
                out.write(response.getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("SET")) {
                String key = parts[1];
                String value = parts[2];
                Long expiresAt = null;

                if (parts.length >= 5) {
                  if (parts[3].equalsIgnoreCase("PX")) {
                    long pxMillis = Long.parseLong(parts[4]);
                    expiresAt = System.currentTimeMillis() + pxMillis;
                  } else if (parts[3].equalsIgnoreCase("EX")) {
                    long exSeconds = Long.parseLong(parts[4]);
                    expiresAt = System.currentTimeMillis() + (exSeconds * 1000);
                  }
                }

                store.put(key, new Entry(value, expiresAt));
                out.write("+OK\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("GET")) {
                String key = parts[1];
                Entry entry = store.get(key);

                if (entry != null && !entry.isExpired()) {
                  byte[] bytes = entry.value.getBytes(StandardCharsets.UTF_8);
                  String response = "$" + bytes.length + "\r\n" + entry.value + "\r\n";
                  out.write(response.getBytes(StandardCharsets.UTF_8));
                } else {
                  if (entry != null && entry.isExpired()) {
                    store.remove(key);
                  }
                  out.write("$-1\r\n".getBytes(StandardCharsets.UTF_8));
                }
              } else if (command.equalsIgnoreCase("RPUSH")) {
                if (parts.length < 3) {
                  out.write("-ERR wrong number of arguments for 'rpush' command\r\n".getBytes(StandardCharsets.UTF_8));
                } else {
                  String key = parts[1];
                  List<String> list = listStore.computeIfAbsent(key, k -> Collections.synchronizedList(new ArrayList<>()));
                  int newLength;
                  synchronized (list) {
                    for (int i = 2; i < parts.length; i++) {
                      list.add(parts[i]);
                    }
                    newLength = list.size();
                  }
                  String response = ":" + newLength + "\r\n";
                  out.write(response.getBytes(StandardCharsets.UTF_8));
                }
              }
              out.flush();
            }
          } catch (IOException e) {
            System.out.println("IOException: " + e.getMessage());
          }
        }).start();
      }
    } catch (IOException e) {
      System.out.println("IOException: " + e.getMessage());
    }
  }
}
```

## New Concepts in This Stage

**[CONCEPT] State Persistence across Invocations**  
A key-value store is stateful: subsequent commands operate on the accumulated state left by previous commands. In contrast to stateless HTTP request-response cycles, in Redis, data mutations remain in memory for the lifetime of the process (or until explicit deletion/expiry).

**[CONCEPT] Tail-Append (`RPUSH`) vs Head-Prepend (`LPUSH`)**  
Redis lists are doubly-ended sequences. `RPUSH` appends to the right (tail), maintaining FIFO arrival order when read left-to-right (`LRANGE 0 -1`). In contrast, `LPUSH` prepends to the left (head).

**[CONCEPT] Atomic Mutate-and-Read under Concurrency**  
If thread A appends an item and thread B appends an item at the exact same moment:
- If reading size is separated from appending without locking, thread A might read size after both thread A and thread B have appended, reporting size 2 for the first append instead of size 1.
- By wrapping the append loop and `list.size()` inside `synchronized (list)`, each push operation obtains the exact size immediately following its own batch of appends.

**[SYNTAX] Java specifics — lookup, don't memorize**  
- `computeIfAbsent(key, mappingFunction)`: If the specified key is already associated with a value, `computeIfAbsent` simply returns the existing value without calling the mapping function.
- `List.add(element)`: Appends the specified element to the end of the list ($O(1)$ amortized for `ArrayList`).
- `List.size()`: Returns the number of elements in this list ($O(1)$).

---

## Failure Modes

- **Re-initializing the list on subsequent calls**: If using `listStore.put(key, new ArrayList<>())` instead of checking for existing presence, previous elements are wiped out and length resets to 1.
- **Returning previous length**: Returning `list.size()` *before* adding elements returns 0 instead of 1 on the first append, or 1 instead of 2 on the second.
- **Non-atomic batch push**: When multiple arguments are passed (`RPUSH key a b`), if the size is queried midway through, incorrect partial lengths may be observed.
- **Race conditions with unsynchronized lists**: Multiple client threads modifying `ArrayList` concurrently without synchronization can corrupt internal arrays or trigger `ConcurrentModificationException`.

---

## Tradeoffs — Per-Key Locking vs Global Lock

| Strategy | Concurrency Level | Implementation Complexity | Contention |
|---|---|---|---|
| **Global Lock (`synchronized(listStore)`)** | Low (all keys serialized) | Simplest | High bottleneck under multi-client write load across different keys |
| **Per-List Monitor (`synchronized(list)`)** | High (independent keys run in parallel) | Moderate | Contention only when concurrent clients push to the exact same key |
| **Non-blocking / Lock-Free (e.g. `ConcurrentLinkedQueue`)** | High | High (harder to support random access `LRANGE` by index) | Minimal contention, but indexing is $O(N)$ |

*Our choice:* Per-list monitor (`synchronized(list)`) with `ArrayList` provides $O(1)$ amortized appends, $O(1)$ indexed reads for subsequent stages, and zero contention across different keys.

## How It Flows

```
1. First command:
Client -> *3\r\n$5\r\nRPUSH\r\n$8\r\nlist_key\r\n$8\r\nelement1\r\n
Server:
  - listStore does not contain "list_key"
  - computeIfAbsent creates new synchronized ArrayList
  - synchronized(list) adds "element1" -> list = ["element1"]
  - size = 1
Server -> :1\r\n

2. Second command:
Client -> *3\r\n$5\r\nRPUSH\r\n$8\r\nlist_key\r\n$8\r\nelement2\r\n
Server:
  - listStore already contains "list_key" -> returns existing list instance
  - synchronized(list) adds "element2" -> list = ["element1", "element2"]
  - size = 2
Server -> :2\r\n
```

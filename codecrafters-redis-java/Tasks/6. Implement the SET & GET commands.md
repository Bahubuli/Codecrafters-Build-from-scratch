# Stage 6: Implement the SET & GET commands

---

## What You Have to Do

Support two fundamental data manipulation commands: `SET` and `GET`.

1. **`SET <key> <value>`**
   Stores the string `value` associated with `key`.
   Returns a RESP simple string `+OK\r\n`.

   ```
   $ redis-cli SET foo bar
   OK
   ```

   **Wire input:**
   ```
   *3\r\n$3\r\nSET\r\n$3\r\nfoo\r\n$3\r\nbar\r\n
   ```
   **Wire output:**
   ```
   +OK\r\n
   ```

2. **`GET <key>`**
   Retrieves the value for `key`.
   - If the key exists: returns the value as a RESP bulk string `$<len>\r\n<value>\r\n`.
   - If the key does not exist: returns a RESP **null bulk string** `$-1\r\n`.

   ```
   $ redis-cli GET foo
   bar
   $ redis-cli GET missing
   (nil)
   ```

   **Wire input:**
   ```
   *2\r\n$3\r\nGET\r\n$3\r\nfoo\r\n
   ```
   **Wire output:**
   ```
   $3\r\nbar\r\n
   ```

---

## Thought Process

**The gap after stage 5:** Stage 5 read input and dispatched `PING` and `ECHO`, but the server was strictly **stateless** — each command lived and died within its own loop iteration. To support `SET` and `GET`, the server must remember state across commands and across separate client connections.

**The concurrency reality:** In Stage 4, we spawned an independent thread for each client connection. Now, client thread A might execute `SET foo bar` while client thread B simultaneously executes `GET foo`. If two threads read and modify state at the same time without synchronization, you risk data corruption, lost updates, or race conditions.

**The design:**
1. Maintain an in-memory dictionary shared across all worker threads.
2. Use `ConcurrentHashMap<String, String>` rather than a standard `HashMap` to guarantee thread-safe concurrent reads and writes without manual mutex locking.
3. Handle the null case: when `store.get(key)` returns `null`, emit Redis's protocol representation for non-existent values: `$-1\r\n`.

## The Solution

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.io.OutputStream;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class Main {
  // Shared thread-safe key-value store across all client threads
  private static final Map<String, String> store = new ConcurrentHashMap<>();

  public static void main(String[] args) {
    System.out.println("Logs from your program will appear here!");

    int port = 6379;

    try {
      ServerSocket serverSocket = new ServerSocket(port);
      serverSocket.setReuseAddress(true);

      while (true) {
        Socket clientSocket = serverSocket.accept();

        new Thread(() -> {
          try {
            OutputStream out = clientSocket.getOutputStream();
            InputStream in = clientSocket.getInputStream();
            BufferedReader reader = new BufferedReader(new InputStreamReader(in));

            while (true) {
              String line = reader.readLine();
              if (line == null) break; // client disconnected

              // Array header: "*<count>"
              int n = Integer.parseInt(line.substring(1));

              String[] parts = new String[n];
              for (int i = 0; i < n; i++) {
                reader.readLine();            // Skip "$<length>" prefix
                parts[i] = reader.readLine(); // Payload
              }

              String command = parts[0];

              if (command.equalsIgnoreCase("PING")) {
                out.write("+PONG\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("ECHO")) {
                String arg = parts[1];
                byte[] bytes = arg.getBytes(StandardCharsets.UTF_8);
                String response = "$" + bytes.length + "\r\n" + arg + "\r\n";
                out.write(response.getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("SET")) {
                String key = parts[1];
                String value = parts[2];
                store.put(key, value);
                out.write("+OK\r\n".getBytes(StandardCharsets.UTF_8));
              } else if (command.equalsIgnoreCase("GET")) {
                String key = parts[1];
                String value = store.get(key);
                if (value != null) {
                  byte[] bytes = value.getBytes(StandardCharsets.UTF_8);
                  String response = "$" + bytes.length + "\r\n" + value + "\r\n";
                  out.write(response.getBytes(StandardCharsets.UTF_8));
                } else {
                  // RESP Null Bulk String
                  out.write("$-1\r\n".getBytes(StandardCharsets.UTF_8));
                }
              }
              out.flush();
            }
          } catch (IOException e) {
            System.out.println("IOException: " + e.getMessage());
          }
        }).start();
      }
    } catch (IOException e) {
      System.out.println("IOException: " + e.getMessage());
    }
  }
}
```

## New Concepts in This Stage

**[CONCEPT] State persistence across connection lifecycles**  
Before this stage, state lived on the stack of a worker thread. Stack memory vanishes when a thread terminates or when a loop scope exits. `SET` and `GET` require **heap-allocated, globally accessible state** whose lifecycle transcends any individual TCP socket.

**[CONCEPT] Thread-safety and race conditions**  
When multiple threads access shared mutable data, at least one performing writes:
- A regular `java.util.HashMap` offers zero thread-safety guarantees. Concurrent mutations can corrupt internal bucket lists or trigger infinite loops during rehashing.
- `ConcurrentHashMap` uses fine-grained locking and non-blocking reads (lock-free CAS algorithms), allowing high concurrency without blocking reads while writes occur.

**[CONCEPT] The Null Bulk String (`$-1\r\n`)**  
In RESP, `$` indicates a bulk string followed by length. A negative length `-1` is defined by the Redis specification as the representation for nil / nonexistent values. It prevents ambiguities: an empty string `""` is `$0\r\n\r\n`, whereas a missing key is `$-1\r\n`.

**[SYNTAX] Java specifics — lookup, don't memorize**  
- `ConcurrentHashMap<K, V>` — thread-safe map implementation in `java.util.concurrent`.
- `map.put(key, value)` — stores or replaces a key-value mapping.
- `map.get(key)` — returns the mapped value, or `null` if the mapping does not exist.
- `arg.getBytes(StandardCharsets.UTF_8).length` — gives the exact byte length for UTF-8 encoded payloads.

---

## Failure Modes

- **Using plain `HashMap` across threads** — leads to subtle data races, missed updates, or `ConcurrentModificationException`.
- **Returning an empty string instead of null bulk string on cache miss** — returning `$0\r\n\r\n` tells the client the key exists and its value is `""`. Redis clients treat `nil` and empty string very differently.
- **Forgetting to flush after writing** — response bytes remain stuck in the TCP output buffer, leading to client timeout.
- **Off-by-one or missing arguments** — e.g. receiving a `SET` command without checking array bounds `parts.length >= 3` will throw `ArrayIndexOutOfBoundsException` on malformed client requests.

---

## Tradeoffs — Storage and Concurrency Models

| Approach | Read Latency | Write Latency | Concurrency Safety | Memory Overhead |
|---|---|---|---|---|
| `HashMap` + `synchronized` method | Moderate (coarse lock) | High contention | Safe | Minimal |
| `ConcurrentHashMap` | Fast (lock-free reads) | Low contention (bucket lock) | Safe | Moderate |
| Single-threaded Event Loop (real Redis) | Ultra fast (zero locks) | Ultra fast (zero locks) | Safe (single thread) | Lowest |

*Why does real Redis use a single thread?*  
Because Redis's data structures are in-memory, execution time for commands is microsecond-scale. Avoiding thread synchronization, mutex contention, and context switching altogether yields higher throughput than multi-threaded locking overhead on shared memory.

## How It Flows

```
Client 1: SET "username" "alice"
  -> store.put("username", "alice")
  -> reply: "+OK\r\n"

Client 2: GET "username"
  -> store.get("username") => "alice"
  -> reply: "$5\r\nalice\r\n"

Client 2: GET "password"
  -> store.get("password") => null
  -> reply: "$-1\r\n"
```

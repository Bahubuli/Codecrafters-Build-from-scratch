# Stage 01: Match a literal character

## In one line
A regular expression search tests whether any substring within a target input satisfies the pattern grammar, starting with exact single-character containment.

## Self-test (cover the answers below and answer these first)
- What is the difference between an exact substring match and full-string equality in grep?
- What exit code does standard grep return on match success vs match failure?
- Why must pattern matching handle character encoding and streams cleanly from the start?

## The problem it solved
Before this stage, grep could not evaluate patterns against incoming stdin streams. This stage establishes the CLI interface (`-E <pattern>`), reads standard input line-by-line, tests whether a single literal character exists anywhere in the input line, and signals match status via POSIX exit codes (0 for match, 1 for no match).

## Concepts (the transferable part)
- **Substring Subsumption vs Exact Match** — Unlike equality checking (`input.equals(pattern)`), grep searches for pattern occurrences at any index in the line unless explicitly anchored.
- **Exit Code Signaling** — POSIX utilities communicate boolean query outcomes through process termination status (`0` indicates true/match found, `1` indicates false/no match, `>1` indicates operational error).
- **Stream Ingestion via Stdin** — Grep operates as a pipeline filter reading serialized bytes/text from file descriptor 0 (`System.in`).

## What breaks it (failure modes)
- Empty pattern or empty input line — An empty pattern might match everywhere (or be invalid depending on regex standard); empty input contains no literal characters.
- Non-ASCII / Multibyte characters — Simple byte-level slicing breaks multi-byte UTF-8 code points if not decoding character-by-character.
- Newline characters in stdin — Scanners must handle trailing line breaks without corrupting match boundaries.

## Tradeoffs
- `inputLine.contains(pattern)` vs indexed character iteration — `contains()` leverages optimized SIMD/Boyer-Moore substring routines in the standard library, but an explicit character-by-character cursor is required once regex tokens, quantifiers, and wildcards are introduced.

## CLI / Protocol format
- Command: `./your_program.sh -E <pattern>`
- Stdin: Input line to search against.
- Exit code: `0` if pattern matches, `1` if pattern does not match.

## Java specifics — lookup, don't memorize
- `Scanner.nextLine()` — Reads the current line from standard input up to a line separator.
- `String.contains(CharSequence)` — Returns true if and only if the string contains the specified sequence of char values.
- `System.exit(int status)` — Terminates the currently running Java Virtual Machine with the specified status code.

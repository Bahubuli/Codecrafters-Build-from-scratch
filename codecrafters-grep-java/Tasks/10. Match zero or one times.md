# Stage 10: Match zero or one times

## In one line
The `?` quantifier makes the preceding token optional, matching cardinality $\{0, 1\}$ through greedy forward testing and zero-width fallback.

## Self-test (cover the answers below and answer these first)
- What is the difference between `colou?r` matching "color" vs "colour"?
- Why must the engine try matching 1 character first, and if downstream tokens fail, fall back to matching 0 characters?
- How does `?` interact with line-start `^` and line-end `$` anchors?

## The problem it solved
Before this stage, optional characters (such as American vs British spelling `color`/`colour`, or singular vs plural `dogs?`) required multiple pattern iterations or could not be expressed. The `?` quantifier introduces optionality into regular expressions.

## Concepts (the transferable part)
- **Optionality / Bounded Cardinality** — Cardinality constraint $[0, 1]$.
- **Greedy Branching with Zero-Width Fallback** — Testing 1 occurrence ($textIdx + 1$); if downstream tokens cannot be satisfied, backtracking to 0 occurrences ($textIdx + 0$).
- **Epsilon Transitions** — In automata theory, matching 0 occurrences corresponds to taking an $\epsilon$-transition without consuming an input character from the tape.

## What breaks it (failure modes)
- Greedily consuming a character that downstream tokens need without backtracking to 0 matches.
- Prematurely rejecting when the optional character is absent from the input (forgetting the zero-occurrence path).
- Chained or nested quantifiers without clear token association.

## Tradeoffs
- Greedy exploration (try 1 then 0) vs lazy exploration (try 0 then 1): Standard regex engines are greedy by default, prioritizing the longest match before falling back.

## CLI / Protocol format
- Command: `./your_program.sh -E "dogs?"`
- Stdin: Target input line.
- Exit code: `0` on match, `1` otherwise.

## Java specifics — lookup, don't memorize

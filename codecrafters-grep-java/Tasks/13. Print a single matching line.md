# Stage 13: Print a single matching line

## In one line
Grep filters input streams by evaluating patterns against lines and emitting matched records to stdout while using POSIX exit status codes to report match success or failure.

## Self-test (cover the answers below and answer these first)
- Why does standard grep write matched lines to stdout but signal match presence/absence through exit codes 0 and 1?
- What happens if a program outputs lines to stderr or outputs unmatched lines when matching fails?
- How does outputting matching lines enable Unix pipe compositions (e.g., `cat file | grep pattern | wc -l`)?

## The problem it solved
Previous stages operated purely as predicate testers that returned exit code 0 or 1 without generating any standard output. Real-world grep acts as a stream filter: when a line satisfies the regular expression, it must output the matching line to standard output so downstream pipeline stages can consume it.

## Concepts (the transferable part)
- **Unix Filter Paradigm** — Programs read standard input, apply transformations or predicates, emit passing data to standard output, and signal boolean outcomes via process exit codes (`0` for success/match found, `1` for failure/no match).
- **Line-Oriented Processing** — Text processing tools operate on newline-delimited records, inspecting and filtering individual lines before delegating to the matching engine.
- **Side Effects Decoupled from Engine** — The regex engine (`matchPattern`) remains a pure function returning boolean truth values, while the CLI driver (`Main.main`) coordinates I/O and process exit codes.

## What breaks it (failure modes)
- Spurious stdout on failure — Printing debug text or unmatched lines corrupts downstream Unix pipelines and fails strict output equality tests.
- Trailing newlines or whitespace alterations — Modifying the matched line content instead of emitting the exact input line verbatim.
- Inverted exit codes — Exiting with 0 on no match or 1 on match breaks shell conditionals (`if grep ...`).

## Tradeoffs
- Direct line echoing vs buffered stream emission — Direct `System.out.println(inputLine)` is simple and optimal for single lines, whereas high-throughput multi-line grep will benefit from buffered I/O (`BufferedWriter` or byte buffers).

## CLI / Protocol format
- Command: `./your_program.sh -E "<pattern>"`
- Stdin: Input line to evaluate.
- Stdout: The full input line if it matches the pattern; nothing if it does not match.
- Exit code: `0` if matched, `1` if no match.

## Java specifics — lookup, don't memorize
- `System.out.println(line)` — Emits a string followed by the system line separator to standard output (`stdout`).
- `System.exit(int status)` — Terminates the running Java Virtual Machine with the specified status code (`0` = success, non-zero = failure).

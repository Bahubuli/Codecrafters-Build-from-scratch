# Stage 06: Combining character classes

## In one line
Regular expression patterns are sequences of token predicates evaluated against consecutive input stream positions, shifting the starting window until a match succeeds.

## Self-test (cover the answers below and answer these first)
- Why can't we simply evaluate each token independently against the whole string when tokens appear in sequence?
- How does sliding-window start-position iteration allow matching substrings anywhere in an input line?
- How does the recursive `matchesAt` or tape model advance both the token pointer and text pointer?

## The problem it solved
Previous stages only supported single-token patterns. Real regexes combine literals, digit classes, word classes, and character groups into multi-character sequences like `\d apple` or `\d\d\d apples`. This stage introduces sequential pattern parsing and sliding-window substring evaluation.

## Concepts (the transferable part)
- **Token Stream Lexing** — Translating a raw regex string into an ordered sequence of discrete `Token` objects (e.g. `\d`, ` `, `a`, `p`, `p`, `l`, `e`).
- **Sliding-Window Substring Search** — Testing whether the pattern matches starting at position $i$ for $i \in [0, |text|]$.
- **Sequential Predicate Evaluation** — Matching token $k$ against character $t + k$; if all tokens match, the sequence is accepted.

## What breaks it (failure modes)
- Out-of-bounds text access — When the remaining text is shorter than the remaining tokens, matching must stop immediately without index errors.
- Escaped characters inside sequences — Ensuring `\d` or `\\` are correctly consumed as 2-character tokens rather than literal backslashes.
- Partial matches — E.g. matching `\d apple` against `1 orange`; failing on `'o'` must trigger a reset to the next starting position.

## Tradeoffs
- Recursive `matchesAt` vs iterative pointer loops: Recursive structural matching closely mirrors the formal induction of formal grammars and effortlessly accommodates branching and backtracking in later stages.

## CLI / Protocol format
- Command: `./your_program.sh -E "\d apple"`
- Stdin: Target input line.
- Exit code: `0` on match anywhere in the input line, `1` if no substring satisfies the token sequence.

## Java specifics — lookup, don't memorize
- `java.util.List` / `ArrayList` — Holds the ordered parsed token sequence.
- `String.indexOf(char, fromIndex)` — Finds closing delimiters like `]`.

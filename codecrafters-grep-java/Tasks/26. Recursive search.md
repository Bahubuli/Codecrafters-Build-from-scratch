# Stage 26: Recursive search

## In one line
Traversing nested directory trees upon encountering the `-r` flag, constructing path-relative display identifiers for discovered files, and executing line-by-line pattern matching with `<filepath>:` prefixes.

## The problem it solved
Searching modern source repositories or log archives requires walking entire directory hierarchies rather than explicitly passing each individual file path on the command line. Without recursion support (`-r`), grep would fail or report error diagnostics when pointed at directory arguments. This stage implements depth-first recursive filesystem traversal, collecting all regular files while preserving relative path hierarchies for diagnostic output.

## Concepts (the transferable part)
- **Directory Traversal**: When an argument resolves to a directory and `-r` is enabled, the scanner recursively descends into child directories (`File.listFiles()`), collecting all leaf regular files.
- **Display Path Formatting**: The path prefix printed to stdout must reflect the base directory string specified on the command line joined with the nested subpaths (e.g. `dir/subdir/file.txt`), normalizing path separators across platforms.
- **Unconditional Prefixing in Recursive Mode**: In recursive mode, output lines are prefixed with their originating `<filepath>:` regardless of whether one or many files contain matches, ensuring callers always know which nested file produced the match.

## What breaks it (failure modes)
- Using absolute paths in output — CodeCrafters and Unix grep require the prefix to be relative to the argument passed (e.g. `dir/subdir/file.txt`, not `/full/path/dir/...`).
- Crashing on empty directories or subdirectories with no regular files.
- Using platform-specific Windows backslashes (`\`) instead of forward slashes (`/`), which breaks Unix compatibility expectations.

## Tradeoffs
- Recursive DFS vs Breadth-First Search (BFS) — Simple DFS with sorting is lightweight and guarantees complete traversal with minimal overhead for typical directory tree depths.
- In-memory collection vs Lazy directory stream — Eager collection into a list of file inputs is straightforward and safe when memory limits allow, while keeping line scanning streaming per file.

## CLI / Protocol format
- Command: `./your_program.sh -r -E "<pattern>" <directory_path>`
- Output:
  - `<filepath>:<line>` for all matching lines in all regular files found within `<directory_path>` and its subdirectories.
  - Exits with `0` if at least one matching line is found in any file.
  - Exits with `1` if zero matches are found across all files.

## Java specifics — lookup, don't memorize
- `File.isDirectory()` and `File.isFile()` — inspects filesystem node types.
- `File.listFiles()` — lists immediate children of a directory node.
- `childDisplay.replace('\\', '/')` — normalizes path separators to Unix style.

# Stage 29: Match at least n times

## In one line
Parsing lower-bounded repetition syntax `{n,}` (`min = n`, `max = Integer.MAX_VALUE`) with greedy consumption and backtracking down to the minimum threshold.

## Self-test (cover the answers below and answer these first)
- How does `{n,}` differ from `{n}` and `{n,m}`?
- How is the comma within curly braces `{n,}` disambiguated during regex parsing?
- What occurs when matching downstream pattern nodes fails after consuming maximum characters?

## The problem it solved
Patterns such as matching a minimum number of digits in an account number or requiring multiple consecutive vowels cannot be expressed with fixed `{n}` or unbounded `{0,}` / `{1,}` without manual duplication. The `{n,}` quantifier defines an explicit lower bound $n$ while allowing unbounded additional matching characters.

## Concepts (the transferable part)
- **Lower-Bounded Repetition**: Sets minimum occurrences to $n$ and maximum occurrences to infinity (`Integer.MAX_VALUE`).
- **Greedy Matching with Lower Bound**:
  1. Parse `{n,}` by detecting a trailing comma after the integer bound.
  2. Consume matching characters greedily up to the text boundary.
  3. Verify $\text{count} \ge n$; if not, reject immediately.
  4. Backtrack by testing candidate lengths from $\text{count}$ down to $n$, permitting downstream nodes to succeed.

## What breaks it (failure modes)
- Rejecting input when count strictly exceeds $n$ (treating `{n,}` like `{n}`).
- Misparsing empty upper bounds as `{n,0}` instead of unbounded infinity.
- Stopping at the first match rather than trying greedy maximal spans.

## Tradeoffs
- Integer.MAX_VALUE vs explicit unbounded flag — Using `Integer.MAX_VALUE` allows uniform comparison logic without branch differentiation between bounded and unbounded quantifiers.

## CLI / Protocol format
- Command: `./your_program.sh -E "<pattern_with_{n,}>"`
- Output:
  - Prints matched line(s) to stdout.
  - Exits with `0` on match, `1` on mismatch.

## Java specifics — lookup, don't memorize
- `parts[1].trim().isEmpty()` — detects open upper bound in `{n,}`.
- `Quantifier.atLeast(min)` — instantiates quantifier with `max = Integer.MAX_VALUE`.

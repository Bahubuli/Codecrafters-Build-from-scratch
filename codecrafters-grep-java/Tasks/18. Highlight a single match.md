# Stage 18: Highlight a single match

## In one line
Decoupling pattern search into span coordinates `[start, end)` and decorating matched intervals with terminal ANSI escape sequences (`\033[01;31m` ... `\033[m`) without mutating surrounding content.

## Self-test (cover the answers below and answer these first)
- Why must a search engine return match intervals `[start, end)` rather than just matched substrings when building presentation features like syntax highlighting or line coloring?
- What happens to the terminal session if a program emits an ANSI Select Graphic Rendition (SGR) opening code without a closing reset sequence (`\033[m`)?
- How should grep behave when `--color=always` is supplied on a line that does not match the pattern, regarding stdout output and exit code?

## The problem it solved
Previous stages either output the full unaltered matching line or isolated matched substrings with `-o`. To provide interactive visual feedback, grep supports `--color=always`, which prints the full original line while wrapping the matching substring in ANSI terminal formatting codes (bold red) so the matched portion stands out in terminal emulators.

## Concepts (the transferable part)
- **Span-Based Match Intervals** — Instead of extracting only the matched substring, the core matcher returns index coordinates `[start, end)`. This coordinate-first representation enables consumers (syntax highlighters, linter diagnostics, diff tools) to slice and decorate text non-destructively.
- **In-Band Signaling & ANSI Escape Sequences** — Terminal emulators parse in-band escape characters (ASCII 27 / `\033` / `0x1B`) followed by control sequences (`[01;31m` for bold red, `[m` for attribute reset) to change rendering styles without requiring an out-of-band control channel.
- **Select Graphic Rendition (SGR)** — The ANSI sequence standard for setting text display attributes. `01` sets bold/bright intensity, `31` sets red foreground color, and an empty parameter resets all attributes back to terminal defaults.

## What breaks it (failure modes)
- Omitting the closing reset code (`\033[m`) — The terminal emulator remains in bold red mode for all subsequent terminal output (including the user's prompt and subsequent commands).
- Off-by-one errors in substring slicing — Constructing `line[0..start] + color + match + reset + line[end..]` with incorrect indices either drops characters adjacent to the match or duplicates characters.
- Highlighting multiple occurrences prematurely — In this single-match stage, grep must highlight only the first match span on the line, leaving subsequent identical characters uncolored.
- Printing unmatching lines — If `--color=always` is active but the line does not match, grep must not print the line and must exit with code `1`.

## Tradeoffs
- Span coordinates (`[start, end)`) vs Regex string replacement (`replaceAll`) — Span coordinates cleanly decouple matching logic from string manipulation, avoid infinite replacement loops on empty patterns, and allow fine-grained control over exactly which match occurrence to colorize.
- String concatenation vs StringBuilder — For single-match line decoration, 5-part string concatenation is concise and optimized by javac/JVM, whereas multiple matches benefit from a `StringBuilder`.

## CLI / Protocol format
- Command: `./your_program.sh --color=always -E "<pattern>"`
- Flag parsing: `--color=always`, `--color=auto`, `--color=never` can appear before or after `-E <pattern>`.
- Output formatting:
  - If matching: `prefix + \033[01;31m + match + \033[m + suffix\n`
  - If not matching: empty stdout.
- Exit code:
  - `0` if at least one matching line was found.
  - `1` if zero matching lines were found.

## Java specifics — lookup, don't memorize
- `\033` — Octal escape sequence in Java character and string literals representing ASCII ESC (27 / `0x1B`).
- `line.substring(0, s)` — Returns the slice of `line` from index `0` up to (exclusive) index `s`.
- `List<int[]>` — Lightweight representation of coordinate pairs where each element is `new int[]{start, end}`.

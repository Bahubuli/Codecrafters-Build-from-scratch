# Stage 32: Multiple backreferences

## In one line
Tracking multiple distinct capturing group bindings in an indexed map and resolving arbitrary permutations and repetitions of `\1`, `\2`, ..., `\N` against their corresponding captured values.

## Self-test (cover the answers below and answer these first)
- How are group numbers assigned when multiple capturing groups appear sequentially or in mixed order?
- Can `\2` appear before `\1` in a pattern, such as in `(cat) and (dog) are \2 and \1`?
- Can a single backreference token like `\1` be evaluated multiple times within the same pattern?

## The problem it solved
Structured data formats often validate cross-field consistency across multiple values—for example, key-value swaps (`(\w+)=(\w+) -> \2=\1`), symmetric equations, or duplicated compound tokens (`(\d+) (\w+) ... \1 \2`). Single capture engines fail because they discard or overwrite previous captures upon encountering subsequent groups. Supporting multiple numbered groups enables cross-referencing arbitrarily many captured segments.

## Concepts (the transferable part)
- **Sequential Group Numbering**: Capturing groups are numbered $1, 2, \dots$ strictly according to the order of their opening parentheses `(` during AST parsing.
- **Multivalent Capture Table**: A map structure `Map<Integer, String> capturedGroups` preserves each capture slot independently.
- **Order-Agnostic Dereferencing**: Backreferences `\N` query the map by key $N$. They can appear in any order (e.g. `\2` then `\1`), can be repeated multiple times (e.g. `\1-\1`), and match independently.

## What breaks it (failure modes)
- Group index collisions from resetting the counter per branch instead of keeping global monotonically increasing group IDs.
- In-place mutation of the group map across backtracking paths causing poisoned lookups in alternate branches.
- Off-by-one indexing when assigning group numbers (0-indexed vs 1-based regex standard).

## Tradeoffs
- Persistent/Immutable Map vs Mutable Map with explicit copy — Passing a copy `new HashMap<>(capturedGroups)` on each branch fork ensures clean backtracking isolation without mutation artifacts.

## CLI / Protocol format
- Command: `./your_program.sh -E "(\d+) (\w+) ... \1 \2"`
- Output:
  - Prints matched line(s) to stdout.
  - Exits with `0` on match, `1` on mismatch.

## Java specifics — lookup, don't memorize
- `Map<Integer, String> capturedGroups = new HashMap<>()` — maps 1-based group numbers to captured strings.
- `capturedGroups.get(bn.groupNum)` — retrieves matched text for backreference verification.

## Rebuild checklist
- [ ] Monotonically increment group ID for every `(` encountered.
- [ ] Store group matches by their assigned ID in the capture map.
- [ ] Resolve any `\N` token by looking up key $N$ in `capturedGroups`.
- [ ] Pass isolated capture states across backtracking branches.

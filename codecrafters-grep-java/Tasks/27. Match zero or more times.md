# Stage 27: Match zero or more times

## In one line
Implementing greedy zero-or-more repetition (`*` / Kleene star) with maximal-to-minimal backtracking across tokens and subpatterns.

## Self-test (cover the answers below and answer these first)
- How does the `*` quantifier differ from `+` and `?` in terms of minimum and maximum repetition counts?
- Why must greedy repetition evaluate candidate match lengths in descending order (from maximum matches down to zero)?
- How does backtracking handle subsequent pattern failure after consuming all possible repeated characters?

## The problem it solved
Many search patterns describe entities with variable or optional repeated components (e.g. `ca*t` matching `ct`, `cat`, `caat`, etc.). Without the Kleene star quantifier, regex engines cannot express unbounded repetition that is also permitted to occur zero times, forcing clumsy combinations or failing to match absent tokens.

## Concepts (the transferable part)
- **Kleene Star Semantics**: Matches $\ge 0$ occurrences of the preceding token or capture group.
- **Greedy Backtracking**:
  1. Determine the maximum continuous run of characters matching the token starting from the current index: $k = \text{maxMatch}$.
  2. Attempt to match the remainder of the pattern starting with $end = k$.
  3. If the downstream match fails, backtrack by decrementing $end$ down to $end = \text{textIdx}$ (zero matches).
  4. If any path succeeds, return success; if all lengths fail down to zero matches, report failure.

## What breaks it (failure modes)
- Not testing zero repetitions — failing to backtrack all the way down to $end = \text{textIdx}$ prevents matching cases where the element is completely absent.
- Inverting quantifier precedence — attaching `*` to an entire sequence rather than only the immediate preceding token or parenthesized group.
- Infinite loops on empty matches — when applying repetition to groups or empty subexpressions, forgetting to advance index can trigger non-terminating loops.

## Tradeoffs
- Greedy vs Lazy evaluation — Standard regex quantifiers are greedy by default, maximizing matched characters before backtracking as required by POSIX specifications.
- Recursive backtracking vs NFA state simulation — Recursive backtracking with bounded text length is concise and handles backreferences cleanly.

  - Exits with `0` on match, `1` on mismatch.

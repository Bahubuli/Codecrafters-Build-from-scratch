# Stage 03: Match alphanumeric characters

## In one line
The word character class `\w` matches any single alphanumeric character (`[a-zA-Z0-9]`) or underscore (`_`), standardizing common identifier token matching.

## Self-test (cover the answers below and answer these first)

## The problem it solved
Matching variable names, identifiers, or alphanumeric tokens previously required either repetitive manual alternation or complex branches. The `\w` metacharacter encapsulates alphanumeric characters and underscores into a single character class primitive.

## Concepts (the transferable part)
- **Identifier Semantics in Regex** — `\w` is tailored around programming language identifier syntax, encompassing ASCII letters, digits, and underscores.
- **Set Union in Character Classes** — A character class can be mathematically viewed as the union of sets: $[a-z] \cup [A-Z] \cup [0-9] \cup \{ \_ \}$.
- **Decoupled Evaluation** — By encapsulating the membership check in `WordToken.matches(char c)`, the scanning loop remains completely agnostic to the token's internal logic.

## What breaks it (failure modes)
- Special punctuation and symbols — Characters like `-`, `$`, `@`, `!` are non-word characters and must evaluate to false.
- Whitespace — Spaces, tabs, and newlines must not match `\w`.
- Unicode extensions — In standard ASCII grep, `\w` covers ASCII alphanumeric + `_`.

## Tradeoffs
- `Character.isLetterOrDigit(c) || c == '_'` vs explicit ASCII ranges (`(c >= 'a' && c <= 'z') || ...`): `Character.isLetterOrDigit` is standard Java, while ASCII range checking strictly bounds to 7-bit ASCII.

## CLI / Protocol format
- Command: `./your_program.sh -E "\w"`
- Stdin: Input line to evaluate.
- Exit code: `0` if at least one alphanumeric character or underscore is present, `1` otherwise.

## Java specifics — lookup, don't memorize
- `Character.isLetterOrDigit(char ch)` — Determines if the specified character is a letter or digit.
- Logical OR (`||`) — Short-circuits evaluation when checking `isLetterOrDigit` or `c == '_'`.

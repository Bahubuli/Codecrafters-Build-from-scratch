# Stage 31: Single backreference

## In one line
Capturing matching substrings evaluated inside numbered parentheses groups and dynamically verifying their exact reoccurrence via `\1` backreference tokens during pattern traversal.

## Self-test (cover the answers below and answer these first)
- What is the difference between a grouping parenthesis `(cat|dog)` and a capturing group `(cat)` with a backreference `\1`?
- How does the engine associate `\1` with group ID 1 when multiple alternative branches exist within the group?
- What occurs if a backreference refers to a capturing group that has not yet matched or does not match the text at the target index?

## The problem it solved
Many search queries involve symmetric repetitions or matching pairs—such as paired quotes (`"hello"` or `'hello'`), HTML open/close tags (`<b>bold</b>`), or repeated tokens (`cat and cat`). Standard static regex tokens cannot dynamically inspect what text was consumed earlier. Backreferences solve this by persisting captured group substrings in match state and asserting literal equality against subsequent inputs.

## Concepts (the transferable part)
- **Capturing Groups**: Parenthesized patterns indexed incrementally ($1$-based) based on opening parenthesis appearance order.
- **Match State Context**: Passing a dynamic map (`Map<Integer, String> capturedGroups`) down the backtracking call stack.
- **Backreference Resolution**:
  1. Group $N$ matches a candidate slice $[s, e)$ of the input line.
  2. Map entry `capturedGroups.put(N, inputLine.substring(s, e))` is stored for downstream branch exploration.
  3. When encountering `\N`, retrieve the captured string $S$.
  4. Test `inputLine.startsWith(S, textIdx)`. If true, advance `textIdx + S.length()` and continue downstream; otherwise, backtrack.

## What breaks it (failure modes)
- Statically binding capture strings before exploring greedy branches, causing subsequent tokens to evaluate against stale or partial capture lengths.
- Leaking captured group states across parallel alternative branches without cloning the state map.
- Parsing `\1` as an escaped literal digit `1`.

## Tradeoffs
- Copy-on-write capture map vs Global state backtracking — Creating a lightweight copy `new HashMap<>(capturedGroups)` when entering a group branch guarantees branch isolation without needing explicit unroll/undo operations during backtracking.

## CLI / Protocol format
- Command: `./your_program.sh -E "(pattern) ... \1"`
- Output:
  - Prints matched line(s) to stdout.
  - Exits with `0` on match, `1` on mismatch.

## Java specifics — lookup, don't memorize
- `inputLine.startsWith(captured, textIdx)` — validates backreference text occurrence at current index.
- `new HashMap<>(capturedGroups)` — creates isolated group scope for branching.

# Stage 09: Match one or more times

## In one line
The `+` quantifier matches 1 or more consecutive instances of the immediately preceding token, necessitating greedy consumption with recursive backtracking.

## Self-test (cover the answers below and answer these first)
- Why can a purely greedy matching loop fail without backtracking when subsequent tokens exist?
- What is the minimum count of characters required by `+` to succeed?
- How does `PatternElement` pair a base `Token` with its quantifier cardinality?

## The problem it solved
Before this stage, repeated tokens had to be written out explicitly (e.g. `\d\d\d`). Patterns matching arbitrary-length repetitions (like variable-length numbers `\d+` or elongated words `ca+ts`) were impossible. The `+` operator introduces unbounded positive repetition.

## Concepts (the transferable part)
- **Quantification / Repetition** — Decorating a token with cardinality constraints $[1, \infty)$.
- **Greedy Matching** — Consuming as many matching characters as possible first before attempting subsequent tokens.
- **Recursive Backtracking** — If matching the maximal prefix causes downstream tokens to fail, iteratively relinquishing one matched character at a time down to the minimum requirement (1) to explore alternate parses.

## What breaks it (failure modes)
- Zero matches — `+` requires at least 1 match; failing to match the first character must fail immediately.
- Greedily over-consuming downstream tokens — E.g. `ca+at` matching `caaat`; consuming all three `'a'`s leaves nothing for the explicit literal `a` unless the engine backtracks.
- Quantifying the wrong token — Ensuring `ca+` quantifies only `a`, not `ca`.

## Tradeoffs
- Greedy backtracking vs Thompson NFA: Recursive backtracking with greedy step-down is straightforward to implement and naturally supports future features like backreferences, while maintaining low complexity for grep-style patterns.

## CLI / Protocol format
- Command: `./your_program.sh -E "ca+t"`
- Stdin: Input line to evaluate.
- Exit code: `0` on match, `1` otherwise.

## Java specifics — lookup, don't memorize
- Loop-based greedy expansion: `while (maxMatch < text.length() && token.matches(text.charAt(maxMatch))) maxMatch++;`
- Backtracking decrement loop: `for (int end = maxMatch; end >= textIdx + 1; end--)`

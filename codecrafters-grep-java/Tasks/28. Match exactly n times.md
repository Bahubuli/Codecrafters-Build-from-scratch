# Stage 28: Match exactly n times

## In one line
Parsing the `{n}` quantifier into fixed-bound repetitions (`min = n`, `max = n`) and enforcing exact match counts across literal, character-class, and digit tokens.

## Self-test (cover the answers below and answer these first)
- How does the `{n}` quantifier constrain both the minimum and maximum allowable match lengths?
- Why does `ca{3}t` fail on `caaaat` even though three `a`s are present in the text?
- How does unifying `+`, `?`, `*`, and `{n}` under a single `(min, max)` quantifier model simplify backtracking?

## The problem it solved
Real-world patterns frequently demand precise repetition counts—such as fixed-length identifiers, hexadecimal color codes, or structured timestamps. Without support for `{n}`, expressions would need to replicate identical tokens $n$ times (e.g., `\d\d\d\d` instead of `\d{4}`), leading to unreadable, brittle, and error-prone regular expressions.

## Concepts (the transferable part)
- **Bounded Repetition**: A quantifier specifying `min` and `max` limits. For `{n}`, `min = n` and `max = n`.
- **Greedy Matching with Bounds**:
  1. Consume matching characters up to `max` occurrences.
  2. If the matched count is less than `min`, fail immediately.
  3. Try match lengths starting from `count` down to `min`. For `{n}`, `count` must equal `n`, yielding exactly one candidate match length $n$.
  4. Continue downstream match from `textIdx + n`. If following tokens do not match, the branch fails.

## What breaks it (failure modes)
- Permitting subsequent identical characters when the regex requires a following distinct token (e.g. `ca{3}t` attempting to match `caaaat` by stopping at three `a`s, then finding `'a'` instead of `'t'`).
- Incomplete parsing of the brace construct, confusing `{n}` with literal braces if closing `}` is missing.
- Overflowing when handling multi-digit bounds or negative values.

## Tradeoffs
- Unified `(min, max)` model vs Enum-based special casing — A single numerical `Quantifier` class with `min` and `max` cleanly abstracts `*` (`0..MAX`), `+` (`1..MAX`), `?` (`0..1`), and `{n}` (`n..n`), reducing branch complexity and eliminating code duplication.

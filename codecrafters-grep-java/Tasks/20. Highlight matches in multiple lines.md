# Stage 20: Highlight matches in multiple lines

## In one line
Streaming multi-line text input with `--color=always` by evaluating lines independently, omitting non-matching lines, and decorating all matching spans within matching lines with bold-red ANSI escape sequences.

## Self-test (cover the answers below and answer these first)
- Why must lines that do not match the pattern be completely suppressed from stdout when `--color=always` is enabled?
- How does the streaming loop preserve per-line record boundaries while formatting matches across an arbitrary number of lines?
- What guarantees that match spans on line $N$ do not bleed or offset into line $N+1$?

## The problem it solved
Previous stages verified multi-match highlighting within a single isolated line (`#eq0`). Real-world grep commands filter multi-line files or piped streams: non-matching lines must be filtered out, and every matching line must be printed with all matched occurrences highlighted in ANSI bold red (`\033[01;31m`...`\033[m`).

## Concepts (the transferable part)
- **Predicate Filtering with Formatting** — Combining a record filter (skip record if $\text{predicate}(r) = \text{false}$) with an in-place decorator (splice ANSI formatting sequences around matched intervals).
- **Line State Isolation** — Regex state (line anchors `^`/`$`, coordinate indices, capture group tables) resets completely for each record, preventing state bleeding across records in the stream.
- **Lazy Forward-Scanning Replacement** — Walking matches via index intervals $[s_i, e_i)$ and copying unchanged slices $[e_{i-1}, s_i)$ preserves original whitespace, casing, and characters with $O(L)$ space per line.

## What breaks it (failure modes)
- Printing non-matching lines — Outputting lines without matches (even without highlights) breaks standard grep filtering semantics.
- Partial line highlights — Highlighting only the first match on a multi-match line when multiple matches exist.
- Overwriting exit status — Resetting `matchedAny` per line rather than accumulating `matchedAny |= !spans.isEmpty()` causes the final exit code to reflect only the last line in the stream.

## Tradeoffs
- Stream processing (`Scanner.hasNextLine()`) vs Slurping — Streaming processes infinite or multi-gigabyte inputs without memory exhaustion and begins emitting highlighted lines immediately to downstream pipes.

## CLI / Protocol format
- Command: `./your_program.sh --color=always -E "<pattern>"`
- Stdin: Multi-line text stream.
- Stdout: Only lines containing at least one match, with each match enclosed in `\033[01;31m` and `\033[m`.
- Exit code:
  - `0` if at least one line matched.
  - `1` if zero lines matched.

## Java specifics — lookup, don't memorize
- `StringBuilder.append(CharSequence s, int start, int end)` — Appends a slice of a sequence without allocating intermediate `String` objects.
- `\033[01;31m` — SGR ANSI code for bold bright red foreground text.
- `\033[m` — SGR ANSI reset code.

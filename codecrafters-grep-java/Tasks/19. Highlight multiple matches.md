# Stage 19: Highlight multiple matches

## In one line
Iterating across sorted, disjoint match spans `[start, end)` to interleave uncolored interstitial text slices with ANSI-highlighted match spans in a single forward pass.

## Self-test (cover the answers below and answer these first)
- Why does highlighting multiple matches require maintaining a `lastIdx` cursor as you iterate through the list of spans?
- What happens if match spans overlap, and how does standard non-overlapping tokenization avoid infinite loops or corrupted escape sequences?
- Why is `StringBuilder` with range appends (`sb.append(line, lastIdx, span[0])`) preferable to repeatedly doing substring concatenation inside a loop?

## The problem it solved
In Stage 18, `--color=always` only highlighted the very first match span on a line, leaving subsequent occurrences unformatted. Real-world grep highlights every non-overlapping match occurrence across the entire line. This stage iterates over all discovered match spans, wrapping each matching segment in bold red ANSI escape codes while preserving surrounding and intervening text.

## Concepts (the transferable part)
- **Non-Overlapping Stream Decoration / Gap-and-Span Interleaving** — Slicing a source string into alternating unhighlighted gaps `[lastIdx, span[0])` and highlighted spans `[span[0], span[1])`. Tracking `lastIdx = span[1]` guarantees that every character in the original text is emitted exactly once in linear time $\mathcal{O}(N)$.
- **Forward-Advancing Scanner State** — When finding multiple matches on a line, advancing the scan head past the match end (`start = end`, or `start = start + 1` on empty matches) prevents overlapping decorations or re-matching within the same span.
- **Terminal SGR Re-Entrancy & Reset Boundaries** — Each matched token is cleanly encapsulated with opening (`\033[01;31m`) and closing (`\033[m`) sequences. Closing each match explicitly guarantees that interstitial text remains unstyled and terminal state remains consistent across subsequent output.

## What breaks it (failure modes)
- Dropping interstitial gaps — Forgetting to emit `line.substring(lastIdx, span[0])` drops characters between separate matches (e.g., `"jekyll and hyde"` becoming `"jekyllhyde"`).
- Dropping trailing text — Failing to append `line.substring(lastIdx)` after processing all spans cuts off the remainder of the line after the final match.
- Overlapping / unordered spans — If spans are not sorted or overlap, `lastIdx > span[0]` causes `StringIndexOutOfBoundsException` or reversed text slices. The matcher must produce monotonically increasing, disjoint intervals.
- Infinite loops on zero-width matches — If a pattern can match zero characters (e.g. empty alternation or quantifiers), advancing by `start = end` when `start == end` would loop forever unless guarded by `start = start + 1`.

## Tradeoffs
- Single-pass `StringBuilder` accumulation vs In-place string replacement (`replaceAll`) — String replacement fails when replacement tokens contain substrings that match subsequent replacement patterns or escape sequences; iterating span coordinates preserves source indices and executes in deterministic $\mathcal{O}(N)$ time.
- Eager decoration per line vs AST-based token tree — Building a decorated string using linear index offsets is lightweight and fast for CLI utilities; full AST styling trees are only justified when nested formatting hierarchies or syntax highlighting rules conflict.

## CLI / Protocol format
- Command: `./your_program.sh --color=always -E "<pattern>"`
- Standard Input: Text lines streamed via stdin.
- Standard Output:
  - If matches found: the input line with all matched substrings wrapped in `\033[01;31m` ... `\033[m`.
  - If no match found: no output printed to stdout.
- Exit Code:
  - `0` if at least one match was found.
  - `1` if no match was found.

## Java specifics — lookup, don't memorize
- `StringBuilder.append(CharSequence s, int start, int end)` — Appends a subsequence of `s` directly into the buffer without allocating an intermediate `String` object.
- `String.substring(int beginIndex)` — Returns the remaining suffix of the string from `beginIndex` to length.
- `\033[01;31m` / `\033[m` — ANSI terminal escape sequences for bold red foreground and graphic rendition reset respectively.

## Rebuild checklist
- [ ] Ensure `findMatchSpans` returns all non-overlapping match intervals `[start, end)` across the line.
- [ ] When `--color=always` is active and `spans` is not empty, initialize `StringBuilder sb` and `int lastIdx = 0`.
- [ ] For each `span` in `spans`:
  - Append interstitial gap: `sb.append(line, lastIdx, span[0])`.
  - Append opening color escape: `sb.append("\033[01;31m")`.
  - Append matched token: `sb.append(line, span[0], span[1])`.
  - Append reset escape: `sb.append("\033[m")`.
  - Update `lastIdx = span[1]`.
- [ ] Append trailing text: `sb.append(line.substring(lastIdx))`.
- [ ] Print `sb.toString()` and set `matchedAny = true`.
- [ ] Exit with status code `0` on match, or `1` on no match.

# Stage 11: Wildcard

## In one line
The `.` wildcard metacharacter matches any single character in the input stream other than a newline `\n`.

## Self-test (cover the answers below and answer these first)
- Why does `.` match any character except newline `\n` in standard POSIX/grep?
- How does `.` interact with quantifiers like `.+` and `.?`?
- What distinguishes a literal dot `\.` from a wildcard dot `.`?

## The problem it solved
Before this stage, there was no way to match arbitrary characters without listing every possible symbol. The `.` token serves as a universal single-character placeholder, allowing patterns like `c.t` to match `cat`, `cot`, `c1t`, etc.

## Concepts (the transferable part)
- **Universal Match Predicate** — A token whose predicate returns true for any valid codepoint in the language except the line delimiter: `c != '\n'`.
- **Composition with Quantifiers** — Combined with `+`, `.+` matches any sequence of 1 or more characters (greedy consuming line content).
- **Escaping Metacharacters** — Escaping `\.` yields a `LiteralToken('.')`, whereas unescaped `.` yields `WildcardToken`.

## What breaks it (failure modes)
- Matching newlines — In line-oriented grep, `.` must not bridge lines unless single-line mode (DOTALL) is active.
- Unescaped dot in filename or extension searches — E.g. searching `app.log` matches `appXlog` unless escaped as `app\.log`.
- Greedy runaway with quantifiers — `.+` matching everything to end-of-line unless backtracked.

## Tradeoffs
- Single boolean check `c != '\n'` in `WildcardToken` vs complex charset: In single-line evaluation, testing `c != '\n'` is both optimal and fully compliant with POSIX grep specifications.

## CLI / Protocol format
- Command: `./your_program.sh -E "d.g"`
- Stdin: Target input line.
- Exit code: `0` on match, `1` otherwise.

## Java specifics — lookup, don't memorize
- Predicate implementation:
  ```java
  static class WildcardToken implements Token {
      @Override
      public boolean matches(char c) {
          return c != '\n';
      }
  }
  ```

# Stage 17: Receive metadata

## In one line

## The problem it solved
Magnet links only provide a tracker URL and an info hash. To actually download pieces, a client must know the file length, piece size, and expected SHA-1 hashes. By fetching and assembling the metadata pieces via BEP 9, our client reconstructs the complete torrent info dictionary directly from in-band peer streams.

## Concepts (the transferable part)
- **Concatenated Bencode Framing**: BEP 9 metadata data responses contain two adjacent bencoded dictionaries placed back-to-back in the wire format: ext_id + dict1{msg_type:1, piece:0, total_size:XXXX} + dict2{piece length:..., pieces:...}.
- **Parser Offset Tracking**: A byte-offset-aware bencode parser can parse exactly one valid bencode element, record the byte index at which it stopped, and provide the remaining bytes as the metadata payload.
- **Metadata Verification**: The SHA-1 hash of the raw info dictionary bytes must match the 20-byte info hash supplied in the magnet URI.

## What breaks it (failure modes)
- Trying to decode the entire message payload as a single bencode string — Fails because between the first data header dictionary and the second info dictionary, the parser ends after the first 'e' and ignores the rest or throws errors.
- Missing the 1-byte extension header id — payload[0] is the peer extension message id, so bencode parsing must begin at payload[1].
- Off-by-one byte offsets in raw info dictionary search — counting from parser.getIndex() guarantees exact boundaries without string search ambiguities.

## Tradeoffs
- Stream-composing parser vs Regex/String Search — Byte-accurate bencode parsing with index tracking preserves binary integrity and avoids UTF-8 decoding corruption on raw SHA-1 hashes.

## Wire format / protocol
BEP 9 Metadata Data Message:
`
[Length Prefix: 4 bytes] (Big-endian uint32 = 1 + 1 + len(headerDict) + len(infoDict))
[Message ID: 1 byte = 20]
[Extension Message ID: 1 byte = our_ut_metadata_id]
[Bencoded Header: variable bytes]
  d8:msg_typei1e5:piecei0e10:total_sizei<size>ee
[Bencoded Info Dictionary: variable bytes]
  d4:name...12:piece length...6:pieces...e
`

## Java specifics - lookup, do not memorize
- dataParser.getIndex() — retrieves the current read offset in the byte array after consuming the header dictionary.
- Arrays.copyOfRange(dataPayload, infoStart, dataPayload.length) — slices the torrent info dictionary bytes.

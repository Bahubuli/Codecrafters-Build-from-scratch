# Stage 02: Decode bencoded integers

## In one line
Decoded delimiter-bracketed bencoded integers formatted as `i<number>e` into 64-bit signed numeric values.

## Self-test (cover the answers below and answer these first)
- How does Bencode represent integers and how are the start and end of the integer framed?
- Why must bencode integers be parsed into 64-bit integers (`long`) instead of 32-bit (`int`)?

## The problem it solved
Distributed data structures need a compact, human-readable yet canonical representation for integer values (such as file sizes, piece lengths, timestamps, port numbers, and offsets) without endianness ambiguity. Bencode solves integer encoding by wrapping ASCII-encoded base-10 numbers with an opening `i` and terminating `e` delimiter (`i<number>e`).

## Concepts (the transferable part)
- **Delimiter-Bracketed Framing**: Instead of fixed-width binary encoding (e.g. 4-byte big-endian int) or length-prefixed strings, bencode uses sentinel bookends (`i` to start, `e` to terminate) around variable-length ASCII digits, eliminating endianness concerns across platforms.
- **Stateful Sequential Parsing (Parser Cursor)**: Advancing an index/cursor through an input stream to parse sequential tokens, allowing recursive composition of higher-order data structures (like lists and dictionaries).
- **64-bit Integer Precision**: File lengths and byte offsets in torrent files frequently exceed $2^{31}-1$ bytes (2 GiB), requiring 64-bit integers (`long` in Java) to prevent numeric overflow.

## What breaks it (failure modes)
- Missing closing delimiter `e` — leads to scanning off the end of the buffer or throwing index exceptions.
- Negative zero (`i-0e`) or leading zeros (`i03e`) — invalid under the canonical BEP 3 specification (only `i0e` is permitted).
- 32-bit integer overflow — using `Integer.parseInt` causes `NumberFormatException` when decoding files or piece sizes > 2 GiB.
- Empty payload (`ie`) or non-numeric characters (`i12a3e`) — fails string-to-integer conversion.

## Tradeoffs
- ASCII-encoded decimal vs Raw Binary integers — Raw binary (e.g. 8 bytes fixed) is faster and fixed-size, but ASCII-encoded integers are endianness-independent, inspectable in plaintext, and take fewer bytes for small values (e.g., `i0e` is 3 bytes vs 8 bytes).
- Stateful index cursor vs Splitting/RegEx — Using an advancing parser index enables O(1) space and zero-copy string scanning, which scales cleanly to nested lists and maps without intermediate string allocations.

## Wire format / protocol
`i52e` -> `52`  
`i-52e` -> `-52`  
`i0e` -> `0`  
`i<ASCII base-10 digits>e`

## Java specifics - lookup, do not memorize
- `Long.parseLong(String)` — parses the string argument as a signed decimal `long` (64-bit).
- `String.indexOf(int ch, int fromIndex)` — finds the next occurrence of a character starting from the specified search offset.
- `String.substring(int beginIndex, int endIndex)` — extracts the characters between indices.

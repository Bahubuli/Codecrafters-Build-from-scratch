# Stage 12: Parse magnet link

## In one line
Extracted query parameters from a BitTorrent Magnet URI (BEP 9), isolating the 40-character hexadecimal info hash (`xt`) and URL-decoded tracker rendezvous URL (`tr`).

## The problem it solved
Distributing physical `.torrent` files requires hosting infrastructure and introduces static file overhead. Magnet URIs (BEP 9) allow decentralized file sharing using lightweight URLs that contain only the cryptographic info hash (`xt`), optional display name (`dn`), and optional tracker URL (`tr`), enabling clients to discover peers dynamically and fetch torrent metainfo on the fly over the peer wire protocol.

## Concepts (the transferable part)
- **Uniform Resource Identifier Scheme (BEP 9)**: Magnet links conform to standard URI query string syntax `magnet:?<query_string>`, where key-value pairs are separated by `&` and keys/values are separated by `=`.
- **Exact Topic URN (`urn:btih:`)**: The `xt` parameter specifies the "exact topic", where `urn:btih:` (BitTorrent Info Hash) designates a 40-character hex (or 32-character base32) SHA-1 digest of the torrent's `info` dictionary.
- **Tracker Parameter Encoding (`tr`)**: Because URLs contain reserved characters like `://` and `/`, tracker endpoints are percent-encoded within the magnet query string and must be decoded to yield valid network addresses.

## What breaks it (failure modes)
- Splitting query string on `:` instead of `?` — `magnet:?` uses colon for the scheme but `?` introduces query parameters.
- Forgetting URL decoding on `tr` — tracker URLs with `%3A%2F%2F` will fail DNS or HTTP request parsing if not decoded to `http://`.
- Case mismatch on `info_hash` — hexadecimal info hashes in URIs can be uppercase or lowercase; normalizing to lowercase guarantees consistency across peer handshakes and tracker queries.
- Assuming fixed parameter ordering — query parameters (`xt`, `dn`, `tr`) can appear in any order in a magnet link.

## Tradeoffs
- Magnet links vs Torrent files — Magnet links are compact (can fit in chat messages or QR codes) and resist censorship, but require extra roundtrips (metadata exchange BEP 9) to learn file metadata before downloading can begin.
- Hexadecimal vs Base32 `btih` — v1 supports 40-character hex or 32-character Base32; hex is human-readable and directly aligns with SHA-1 hex digests.

## Wire format / protocol
Example Magnet URI:
```
magnet:?xt=urn:btih:ad42ce8109f54c99613ce38f9b4d87e70f24a165&dn=magnet1.gif&tr=http%3A%2F%2Fbittorrent-test-tracker.codecrafters.io%2Fannounce
```
Parameters:
- `xt`: `urn:btih:<40-char hex info hash>`
- `dn`: display name (e.g. `magnet1.gif`)
- `tr`: tracker URL (percent-encoded)

## Java specifics - lookup, do not memorize
- `uri.substring(uri.indexOf('?') + 1)` — extracts the query substring.
- `URLDecoder.decode(val, StandardCharsets.UTF_8)` — decodes percent-encoded query parameter values into UTF-8 strings.
- `val.substring("urn:btih:".length()).toLowerCase()` — strips URN prefix and normalizes hex casing.

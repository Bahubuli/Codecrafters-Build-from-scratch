# Stage 10: Download a piece

## In one line
Negotiated peer connection states (bitfield, interested, unchoke), requested sub-piece 16 KiB blocks, assembled the complete piece, and verified SHA-1 integrity before saving to disk.

## Self-test (cover the answers below and answer these first)
- What is the difference between a "piece" and a "block" in the BitTorrent protocol?
- What are the message IDs for `unchoke`, `interested`, `request`, and `piece`?

## The problem it solved
Downloading an entire piece (often 256 KiB - 2 MiB) in a single monolithic network frame is impractical due to TCP buffering limits and packet loss. BitTorrent requires dividing pieces into smaller sub-piece transmission units called "blocks" (typically 16 KiB / $2^{14}$ bytes), requesting them via `request` messages, and reassembling received `piece` block payloads in memory before verifying the cryptographic SHA-1 hash.

## Concepts (the transferable part)
- **Two-Tier Chunk Hierarchy (Pieces vs Blocks)**: "Pieces" are the unit of integrity hashing in the `.torrent` metainfo file (each has an SHA-1 hash). "Blocks" (16 KiB) are the unit of network transmission over the wire peer protocol.
- **Stateful Flow Control (Choking & Interest)**: A peer client cannot request blocks until the remote peer transitions from "choked" to "unchoked". The client expresses interest via `interested` (ID 2), and upon receiving `unchoke` (ID 1), begins sending block requests.
- **Block Reassembly via Offset Addressing**: Every `request` and `piece` message includes a zero-based byte offset (`begin`). Blocks can arrive in arbitrary order and are written directly to `pieceData[begin]`.

## What breaks it (failure modes)
- Requesting blocks before `unchoke` — sending block requests while choked results in the remote peer ignoring requests or closing the connection.
- Incomplete block reading over TCP — TCP is a byte stream, not a packet stream; reading a 16 KiB block in a single `read()` call often yields partial data. `readNBytes()` or an accumulation loop is essential.
- Incorrect last block length — requesting standard 16 KiB for the final block when fewer bytes remain in the piece causes the peer to drop the connection.
- Overwriting existing files without parent directories — saving to nested paths like `/tmp/torrents/piece0` fails unless parent directories are created (`Files.createDirectories`).

## Tradeoffs
- Synchronous Request-Response vs Pipelining — Requesting one block at a time is simple and avoids complex buffer management, while pipelining up to 5 concurrent requests minimizes RTT latency over high-ping connections.
- Memory buffering vs Streaming to disk — Buffering 16 KiB - 2 MiB in memory allows easy SHA-1 verification before writing to disk, preventing corrupt data from ever touching the storage layer.

## Wire format / protocol
All peer wire messages use: `<4-byte length prefix><1-byte message ID>[optional payload]`.

```
Interested:  [0, 0, 0, 1] [2]
Unchoke:     [0, 0, 0, 1] [1]
Request:     [0, 0, 0, 13] [6] [4-byte index] [4-byte begin] [4-byte length]
Piece:       [4-byte len]  [7] [4-byte index] [4-byte begin] [block data...]
```

## Java specifics - lookup, do not memorize
- `ByteBuffer.allocate(17).putInt(13).put((byte) 6).putInt(index).putInt(begin).putInt(len)` — packs binary integers and bytes in network byte order (big-endian).
- `ByteBuffer.wrap(payload, offset, 4).getInt()` — unpacks 32-bit big-endian integer from a byte slice.
- `Files.createDirectories(path.getParent())` — safely creates missing directory hierarchies.

## Rebuild checklist
- [ ] Parse torrent to determine file length, piece length, total pieces, and expected piece SHA-1 hash.
- [ ] Calculate target piece size handling the last piece boundary.
- [ ] Connect TCP socket to peer, complete 68-byte handshake.
- [ ] Send `interested` (ID 2) and wait for `unchoke` (ID 1).
- [ ] Loop over 16 KiB blocks, sending `request` (ID 6) for each block.
- [ ] Read `piece` (ID 7) messages and copy block bytes into piece buffer.
- [ ] Verify assembled piece data SHA-1 digest against torrent piece hash.
- [ ] Write verified piece bytes to destination path.

# Stage 07: Advertise skills to the LLM

## In one line
Scanning `.claude/skills/*/SKILL.md` frontmatter and advertising available skills via system prompt progressive disclosure.

## Self-test (cover the answers below and answer these first)
- Why does Claude Code use progressive disclosure for skills instead of loading entire SKILL.md bodies into the prompt upfront?
- How is skill metadata formatted inside SKILL.md, and how is it delimited?
- What are the three levels of progressive disclosure in the Agent Skills standard?
- Where does the system prompt belong in the OpenAI chat completions message list relative to the user's initial query?

## The problem it solved
As an agent acquires more specialized domain skills, each skill includes detailed instructions, examples, and scripts. Inlining all skill bodies into the context window fills token capacity and degrades model attention before the conversation begins. Progressive disclosure solves this by advertising only level-1 metadata (name and description) in the system prompt so the LLM knows what skills exist and when to invoke them.

## Concepts (the transferable part)
- **Progressive Disclosure in Agent Systems**:
  - *Level 1*: Name, description & metadata (~100 tokens per skill) — always included in system prompt context.
  - *Level 2*: Skill body instructions (< 5,000 tokens) — loaded into context only when the skill is activated.
  - *Level 3*: Bundled scripts, schemas, and reference assets — loaded only when referenced by the execution step.
- **YAML Frontmatter Parsing**:
  - Metadata is bounded between triple-dash delimiters (`---`) at the top of markdown documents.
  - Key-value attributes (`name:`, `description:`) provide discovery hooks for tool and capability registries.
- **System Prompt Prefixing**:
  - System role instructions precede user messages in the `messages` array:
    ```json
    [
      { "role": "system", "content": "You have access to the following skills:\n\n- apple: ..." },
      { "role": "user", "content": prompt }
    ]
    ```

## What breaks it (failure modes)
- **Missing or Malformed Delimiters**: Failing to locate both opening and closing `---` markers, leading to full markdown body leakage into the system prompt.
- **Missing Skill Directories**: Crashing if `.claude/skills` does not exist or has empty directories without `SKILL.md`.
- **System Message Placement**: Appending the system prompt after user or assistant messages, violating chat completion role ordering conventions.
- **Quoted YAML Values**: Leaving raw surrounding quotes in descriptions (`"..."` or `'...'`), interfering with string matching in model evaluation.

## Tradeoffs
- **Custom Lightweight YAML Parser vs External Dependency (SnakeYAML)**: A lightweight line parser avoids extra external dependencies and keeps JAR packaging simple for standardized frontmatter schemas.
- **Alphabetical Sorting vs Directory Order**: Sorting skills deterministically by name ensures reproducible prompts across different operating systems and file system implementations.

## CLI / Protocol format
- Skills Directory Structure:
  ```
  .claude/
  └── skills/
      ├── <skill-name>/
      │   └── SKILL.md
  ```
- SKILL.md Layout:
  ```markdown
  ---
  name: <skill-name>
  description: <description text>
  ---
  <unloaded body content>
  ```
- System Prompt Layout:
  ```
  You have access to the following skills:

  - apple: Deploys the apple service to production.
  - grape: Runs the grape test suite and reports failures.
  ```

## Java specifics — lookup, don't memorize
- `Files.list(Path)` — Streams directory entries without recursive traversal.
- `Files.readString(Path)` — Reads file contents directly into a UTF-8 String.
- `ChatCompletionCreateParams.Builder.addSystemMessage(String)` — Prepends a system role message to the chat completions request builder.

# Stage 05: Implement the write tool

## In one line
Defining the JSON Schema specification for the `Write` tool, advertising it alongside `Read`, and implementing file creation and overwrite logic using `Files.writeString()` within the agent execution loop.

- How does the agent handle directory paths when writing a file in a nested folder that does not yet exist?
- Why should the agent create or overwrite files cleanly rather than appending unless explicitly asked?

## The problem it solved
To act as a coding assistant rather than just a passive reader, the agent must be able to mutate the filesystem (create new code files, update config files, and generate artifacts). This stage advertises the `Write` function definition (with `file_path` and `content` properties) to the model and wires up the tool dispatcher to write files directly to disk, returning a success confirmation message back into the conversation context.

## Concepts (the transferable part)
- **Filesystem Mutation as a Model Capability** — Extending model autonomy from read-only inspection to write operations, transforming an informative LLM into an active code generator.
- **Defensive Path Materialization** — Ensuring parent directories exist (`Files.createDirectories(path.getParent())`) before writing files, avoiding unexpected `NoSuchFileException` failures.
- **Observation Feedback for Mutations** — Returning a concise confirmation message (`"File written successfully: ..."` or error details) back to the LLM so it knows the disk mutation succeeded and can proceed with subsequent thoughts or finish.

## What breaks it (failure modes)
- Parent directory does not exist — Writing to `app/components/Button.tsx` when `app/components/` is missing causes an error if parent directories are not created beforehand.
- Incomplete parameter generation — If the LLM generates a tool call missing the `content` field or passes malformed JSON, defensive fallbacks (`argsNode.has("content")`) prevent null pointer exceptions.
- Permission issues — Attempting to write into read-only paths throws `AccessDeniedException`.

## Tradeoffs
- Atomic overwrite vs incremental patch — Overwriting the entire file with `Files.writeString` is simple and reliable for whole files, whereas partial diff patching requires complex line/hunk synchronization.

## CLI / Protocol format
- Tool Declaration:
  ```json
  {
    "type": "function",
    "function": {
      "name": "Write",
      "description": "Write content to a file",
      "parameters": {
        "type": "object",
        "required": ["file_path", "content"],
        "properties": {
          "file_path": { "type": "string", "description": "The path of the file to write to" },
          "content": { "type": "string", "description": "The content to write to the file" }
        }
      }
    }
  }
  ```
- Command: `./your_program.sh -p "Read README.md and create the required file. File should have 1 line. Reply with 'Created the file'"`
- Output: `Created the file` to stdout; requested file created on disk.

## Java specifics — lookup, don't memorize
- `Files.createDirectories(Path)` — Creates the directory and any missing parent directories without throwing an error if the directory already exists.
- `Files.writeString(Path, CharSequence)` — Writes text to a file using UTF-8, creating the file if it does not exist or truncating/overwriting if it does.
- `path.getParent()` — Retrieves parent path, returning null if the path is a bare file name.

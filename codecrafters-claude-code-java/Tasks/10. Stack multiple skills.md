# Stage 10: Stack multiple skills

## In one line
Chaining multiple skill slash commands at the prompt's start, expanding each into sequential user messages sharing common arguments.

## Self-test (cover the answers below and answer these first)
- When multiple slash commands are stacked at the start of a prompt, where does skill expansion terminate?
- How are multiple expanded skill bodies structured within the chat completions request `messages` array?
- What happens if a token beginning with `/` does not correspond to any known skill on disk?
- How are shared arguments delivered to each of the expanded skills?

## The problem it solved
Users frequently need to compose modular workflows (e.g. `/lint /test /deploy`). Manually issuing separate prompts or copy-pasting instructions is cumbersome. Allowing prompts to stack multiple slash commands at the start of an input enables seamless multi-skill composition with shared trailing arguments across each invoked skill.

## Concepts (the transferable part)
- **Token Run Scanning & Boundary Detection**:
  - Linear parsing of whitespace-delimited tokens from the start of the prompt.
  - Successive tokens matching known skills are accumulated into an expansion sequence.
  - The first token that does not resolve to an available skill halts expansion and designates the start of shared argument text.
- **Multi-Message Prompt Composition**:
  - Rather than concatenating disparate skill bodies into one large user message, each skill body is appended as an independent `{ "role": "user", "content": ... }` message.
  - This preserves model instruction separation and avoids token boundary confusion.
- **Shared Argument Broadcast**:
  - The unparsed remainder string is broadcast to each expanded skill template, undergoing identical placeholder substitution (`$ARGUMENTS`, `$0`, etc.).

## What breaks it (failure modes)
- **Premature Argument Truncation**: Consuming tokens that are not valid skills as skill names instead of falling back to treat them as argument text.
- **Body Merging Ambiguity**: Concatenating skill instructions together into a single message without clear boundaries, leading to hallucinated or conflicting model behaviors.
- **Trailing Argument Extraction**: Incorrect substring slicing that strips whitespace or corrupts multi-word parameters.

## Tradeoffs
- **Sequential User Messages vs Single Concatenated Message**: Multiple user messages keep separate skill instructions cleanly isolated in the conversation history, allowing the LLM to process each instruction distinctly.
- **Prefix Expansion vs Arbitrary In-Prompt Expansion**: Restricting skill resolution to the leading token prefix prevents accidental skill triggers inside argument text.

## CLI / Protocol format
- Stacked Command Invocation:
  ```bash
  $ ./your_program.sh -p "/apple /grape 4127"
  ```
- Expansion Resolution:
  - Skill 1: `apple` $\to$ Body substituted with `4127`
  - Skill 2: `grape` $\to$ Body substituted with `4127`
- Resulting Messages Array:
  ```json
  [
    {
      "role": "system",
      "content": "You have access to the following skills:\n\n- apple: ...\n- grape: ..."
    },
    {
      "role": "user",
      "content": "Add this exact line to your response: blueberry-4127"
    },
    {
      "role": "user",
      "content": "Add this exact line to your response: cherry-4127"
    }
  ]
  ```

## Java specifics — lookup, don't memorize
- `Character.isWhitespace(char)` — Detects whitespace boundaries during streaming tokenization.
- `ChatCompletionCreateParams.Builder.addUserMessage(String)` — Can be invoked multiple times in sequence to append multiple user-role messages.

## Rebuild checklist
- [ ] Scan prompt tokens from left to right.
- [ ] For each leading token starting with `/`, check if it matches an existing skill name or directory name.
- [ ] If matched, add skill to `expandedSkills` and advance scanner.
- [ ] On first non-matching token, treat all remaining characters as `sharedArgs` and break.
- [ ] For each matched skill, substitute placeholders with `sharedArgs` and append a distinct user message to the completion builder.
- [ ] If no skills were matched, append the unmodified raw prompt as a single user message.

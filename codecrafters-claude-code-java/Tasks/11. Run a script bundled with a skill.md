# Stage 11: Run a script bundled with a skill

## In one line
Unlocking disclosure level 3 by providing skill location metadata in prompts so the LLM can resolve and execute bundled relative scripts via the Bash tool.

## Self-test (cover the answers below and answer these first)
- What are the three standard subfolders defined for Level 3 progressive disclosure in Agent Skills?
- Why do skills reference bundled scripts using relative paths instead of hardcoded absolute paths?
- How does Claude Code inform the model of the skill directory's relative root within the project?
- How does the model execute the bundled script once given the folder location and relative script path?

## The problem it solved
Complex skills often require deterministic multi-step algorithms, calculations, or platform utilities (e.g. `scripts/checksum.sh`, `scripts/deploy.py`) that cannot or should not be regenerated by the LLM every time. Storing these as executable scripts inside the skill's `scripts/` directory avoids bloating the prompt. However, because skills can be installed anywhere and the program runs from the project root, the LLM needs to know the skill folder location so it can prefix relative paths when executing commands with the Bash tool.

## Concepts (the transferable part)
- **Level-3 Progressive Disclosure (Execution-Time Asset Resolution)**:
  - Level 1: Name & description (advertised in system prompt).
  - Level 2: Skill instructions (`SKILL.md` body loaded on invocation).
  - Level 3: Auxiliary executables (`scripts/`), documentation (`references/`), and templates (`assets/`) executed/loaded strictly on demand.
- **Relocatable Skill Packaging**:
  - Skills must remain portable across environments. Writing script references as `scripts/script.sh` ensures the skill definition is agnostic to installation paths (`.claude/skills/...`, `~/.claude/skills/...`, or plugin registries).
- **Prompt Anchor Framing**:
  - Prepending directory context into the user message:
    ```
    Skill: <name> (located at <path>)
    Paths in the instructions below are relative to that folder.

    <instructions>
    ```
  - This informs the LLM to join the base path with relative paths when constructing tool parameters.

## What breaks it (failure modes)
- **Platform Path Delimiters**: Using Windows backslashes (`\`) inside Bash tool commands on POSIX runner environments instead of standard UNIX forward slashes (`/`).
- **Directory Traversal Desync**: Running scripts from the project root without informing the model of the skill's base directory, causing `scripts/checksum.sh` to fail with "File not found".
- **Executable Permission Failures**: Scripts lacking execute permissions when run directly without `bash <script>` invocation.

## Tradeoffs
- **Model Path Resolution vs Automatic Path Rewriting**: Letting the LLM join the base path and relative paths is robust to diverse command forms (`bash scripts/run.sh`, `python scripts/calc.py`, piping, arguments) compared to fragile regex text rewriting.

## CLI / Protocol format
- Invocation:
  ```bash
  $ ./your_program.sh -p "/apple"
  ```
- User Message Format:
  ```
  Skill: apple (located at .claude/skills/apple)
  Paths in the instructions below are relative to that folder.

  Run `scripts/checksum.sh` using the Bash tool.

  Respond with only the value it prints, and nothing else.
  ```
- Tool Call Generated by Model:
  ```json
  {
    "name": "Bash",
    "arguments": "{\"command\":\"bash .claude/skills/apple/scripts/checksum.sh\"}"
  }
  ```

## Java specifics — lookup, don't memorize
- `Path.resolve(String)` — Joins path segments using platform-appropriate separators.
- `.claude/skills/` prefix formatting — Canonical forward slash paths for POSIX compatibility in shell execution environments.

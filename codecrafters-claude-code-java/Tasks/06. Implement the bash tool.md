# Stage 06: Implement the bash tool

## In one line
Registering the `Bash` tool specification, executing arbitrary shell commands via Java `ProcessBuilder`, capturing combined standard output and error streams, and feeding command execution results back into the agent loop.

## Self-test (cover the answers below and answer these first)
- Why must shell execution capture both `stdout` and `stderr` streams?
- How does `ProcessBuilder` differ when spawning subshells across Windows (`cmd.exe /c`) versus Unix (`bash -c`)?
- What should the tool output be if a command succeeds silently without output (e.g., `rm <file>`)?

## The problem it solved
While direct file reading and writing cover content manipulation, software engineering tasks require running compilers, linters, package managers, git commands, and file deletion. A dedicated `Bash` tool empowers the LLM to invoke arbitrary shell commands in the host environment, capture the command output (or error traces), and iteratively react based on stdout/stderr results.

## Concepts (the transferable part)
- **General-Purpose Process Execution Environment** — Transforming an agent from a restricted filesystem tool user into a full developer by granting shell execution capabilities.
- **Combined Stream Ingestion** — AI models require visibility into both standard output and error streams to diagnose build errors, missing flags, or command syntax issues.
- **Subshell Invocation Paradigm** — Running commands through `bash -c <cmd>` preserves shell expansions, pipelines, and redirection semantics.

## What breaks it (failure modes)
- Blocking / hanging processes — Commands waiting for interactive user input (`stdin`) hang indefinitely unless timeouts or non-interactive flags are used.
- Environment differences — Assuming POSIX utilities on Windows or vice versa. Handling OS differences via `System.getProperty("os.name")` ensures cross-platform capability.
- Working directory drift — Spawning commands in temporary directories causes file mutations to miss the target project directory.

## Tradeoffs
- Direct shell execution vs Sandboxed container — Direct subshell execution allows full native system tooling without overhead, but grants unlimited command execution power requiring appropriate security boundaries in production.

## CLI / Protocol format
- Tool Declaration:
  ```json
  {
    "type": "function",
    "function": {
      "name": "Bash",
      "description": "Execute a shell command",
      "parameters": {
        "type": "object",
        "required": ["command"],
        "properties": {
          "command": { "type": "string", "description": "The command to execute" }
        }
      }
    }
  }
  ```
- Command: `./your_program.sh -p "Delete the old readme file."`
- Output: `Deleted README_old.md` to stdout; `README_old.md` deleted from working directory.

## Java specifics — lookup, don't memorize
- `new ProcessBuilder("bash", "-c", command)` — Configures a process to run the given command string inside a bash subshell.
- `process.getInputStream().readAllBytes()` — Reads all bytes from process stdout.
- `process.getErrorStream().readAllBytes()` — Reads all bytes from process stderr.
- `process.waitFor()` — Causes the current thread to wait until the process has terminated, returning its exit code.

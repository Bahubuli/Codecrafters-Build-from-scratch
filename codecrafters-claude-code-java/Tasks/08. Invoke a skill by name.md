# Stage 08: Invoke a skill by name

## In one line
Triggering level-2 progressive disclosure by parsing `/skill-name` slash commands and loading the corresponding SKILL.md body into the prompt.

## Self-test (cover the answers below and answer these first)
- What signals to Claude Code that a prompt is invoking a skill directly?
- Why must only the invoked skill's body be loaded into the context window rather than all skills' bodies?
- How is the body separated from frontmatter in a SKILL.md file?
- What happens to the other skills in the system prompt when one skill is invoked?

## The problem it solved
Advertising skill names and descriptions in the system prompt (level 1) informs the LLM of available capabilities without exhausting token limits. However, to execute a skill, the model requires its concrete instructional body (level 2). Invoking skills by slash command (`/<skill-name>`) enables targeted disclosure: only the requested skill's instructions are loaded, preventing conflicting directives and keeping the prompt compact.

## Concepts (the transferable part)
- **Level-2 Progressive Disclosure (On-Demand Context Expansion)**:
  - The system prompt retains the concise level-1 list of all available skills.
  - When a slash command `/name` is parsed, the system locates `.claude/skills/<name>/SKILL.md`.
  - The markdown body (everything after the closing frontmatter delimiter `---`) replaces the raw slash command as the user prompt.
- **Slash Command Dispatch**:
  - Prompts beginning with `/` treat the leading token as an execution trigger.
  - Remaining arguments can be passed to parameterize or guide skill execution.
- **Context Isolation**:
  - Only the activated skill's body enters the conversation, keeping distinct task instructions isolated from one another.

## What breaks it (failure modes)
- **Eager Loading / Conflicting Directives**: Loading multiple skill bodies simultaneously creates conflicting instructions that cause the model to fail deterministic tasks.
- **Unescaped or Preserved Frontmatter**: Failing to split off the frontmatter causes metadata keys (`name:`, `description:`) to leak into the prompt body.
- **Missing Slash Command Handling**: Treating `/skill` as literal text without resolving it against `.claude/skills/`.
- **Case Sensitivity Mismatch**: Folder names or frontmatter names differing in case from user input.

## Tradeoffs
- **User Message Replacement vs System Prompt Inlining**: Replacing the user message content with the skill body preserves the role contract and ensures the LLM immediately acts upon the skill instructions.
- **Direct File System Resolution vs In-Memory Registry**: Loading skills from disk on startup matches folder names directly, supporting dynamic skill additions.

## CLI / Protocol format
- Invocation Command:
  ```bash
  $ ./your_program.sh -p "/apple"
  ```
- File Resolution:
  ```
  .claude/skills/apple/SKILL.md
  ```
- Messages Payload:
  ```json
  [
    {
      "role": "system",
      "content": "You have access to the following skills:\n\n- apple: ...\n- grape: ..."
    },
    {
      "role": "user",
      "content": "<body of apple/SKILL.md>"
    }
  ]
  ```

## Java specifics — lookup, don't memorize
- `String.startsWith("/")` — Checks for leading slash command prefix.
- `String.split("\\s+", 2)` — Splits command name from trailing arguments.
- `String.substring(int)` — Truncates delimiter and extracts command name.

# Stage 09: Pass arguments to a skill

## In one line
Substituting `$ARGUMENTS`, `$ARGUMENTS[i]`, and `$i` input placeholders in skill markdown bodies prior to model invocation.

## Self-test (cover the answers below and answer these first)
- What two types of placeholders can be embedded inside a SKILL.md body?
- Why must `$ARGUMENTS[i]` be substituted before substituting raw `$ARGUMENTS`?
- How are skill arguments delimited when passed on the command line?
- What should placeholders be replaced with when a skill is invoked with zero arguments?

## The problem it solved
Static skill bodies can only execute fixed, hardcoded workflows. Real-world tasks (such as deploying to a particular environment or reviewing a specific pull request) require dynamic inputs. Supporting argument substitution allows skill authors to define generic parameterized prompts containing placeholders (`$ARGUMENTS`, `$0`, `$1`, `$ARGUMENTS[0]`) that get populated from command-line arguments at invocation time.

## Concepts (the transferable part)
- **Prompt Templating via Parameterized Placeholders**:
  - Full argument capture: `$ARGUMENTS` receives the entire trailing string.
  - Indexed positional capture: `$ARGUMENTS[i]` and `$i` extract individual whitespace-delimited tokens.
- **Substitution Precedence & Collision Avoidance**:
  - Replacing prefix-overlapping tokens requires careful ordering: replace longer / structured forms (`$ARGUMENTS[0]`) before prefix forms (`$ARGUMENTS`), and before positional forms (`$0`).
- **Graceful Unbound Variable Handling**:
  - If fewer arguments are supplied than the template references, placeholders evaluate to empty strings rather than throwing errors or leaking raw variable names into the LLM context.

## What breaks it (failure modes)
- **Token Clobbering**: Replacing `$ARGUMENTS` before `$ARGUMENTS[0]` turns `$ARGUMENTS[0]` into `<fullArgs>[0]`.
- **Regex Group Escapes**: Failing to use `Matcher.quoteReplacement()` when substituting argument strings that contain characters like `$` or `\`.
- **Missing or Extra Whitespace**: Poor tokenization when splitting multi-word arguments.

## Tradeoffs
- **Regex Token Matching vs Full Macro Engine**: Simple regex pattern replacement covers standard shell-style positional arguments with minimal complexity and zero dependencies.
- **Whitespace Tokenization vs Quoted Shell Parsing**: Following whitespace splitting without complex quote-parsing aligns with the Agent Skills standard specification for basic CLI invocation.

## CLI / Protocol format
- Argument Invocation:
  ```bash
  $ ./your_program.sh -p "/apple staging eu-west"
  ```
- Substitution Mapping:
  - `$ARGUMENTS` $\to$ `"staging eu-west"`
  - `$0` or `$ARGUMENTS[0]` $\to$ `"staging"`
  - `$1` or `$ARGUMENTS[1]` $\to$ `"eu-west"`
- Rendered User Message:
  ```
  Deploy to staging in region eu-west. Full request was: staging eu-west
  ```

## Java specifics — lookup, don't memorize
- `Pattern.compile("\\$ARGUMENTS\\[(\\d+)\\]")` — Regex pattern to extract array-index arguments.
- `Matcher.quoteReplacement(String)` — Safely quotes literal strings for replacement buffers against regex group expansions.
- `Matcher.appendReplacement(StringBuilder, String)` / `Matcher.appendTail(StringBuilder)` — Performs in-place streaming regex substitutions.

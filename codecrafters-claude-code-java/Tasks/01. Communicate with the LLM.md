# Stage 01: Communicate with the LLM

## In one line
Configuring an OpenAI-compatible REST client (`OpenAIClient` via OpenRouter) to dispatch chat completion requests with a user prompt and stream the model's text response to standard output.

## The problem it solved
Building an AI assistant like Claude Code requires a reliable network bridge between local CLI commands and remote LLM inference endpoints. This stage establishes the foundational REST client using `com.openai.client.OpenAIClient`, parses the `-p <prompt>` CLI flag, dispatches a user message to `anthropic/claude-haiku-4.5`, and prints the generated response to `System.out`.

## Concepts (the transferable part)
- **OpenAI-Compatible REST API** — The de facto industry standard wire protocol for chat completions (`/v1/chat/completions`), enabling language models from multiple vendors to be accessed interchangeably via identical JSON payloads and client SDKs.
- **Provider Gateway Abstraction (OpenRouter)** — Routing inference requests through a unified gateway using a custom `baseUrl` and unified authentication token (`apiKey`).
- **Chat Completion Structure** — A completion request encapsulates model selection and an array of conversation turns (`messages`), returning structured `choices` containing role-tagged message payloads.

## What breaks it (failure modes)
- Missing or empty API credentials — Running without `OPENROUTER_API_KEY` prevents authentication, leading to 401 Unauthorized errors.
- Unhandled empty choices — Models returning empty choices or content-filtered outputs will trigger `IndexOutOfBoundsException` or `NoSuchElementException` if not safely unpacked using `Optional` methods like `.orElse("")`.
- Output pollution — Printing debug logs or trailing newlines to `System.out` instead of `System.err` corrupts stdout when callers expect raw model generation.

## Tradeoffs
- Direct Anthropic SDK vs OpenAI Client SDK — The OpenAI client interface (`OpenAIOkHttpClient`) enables effortless switching across arbitrary model providers and proxies (OpenRouter, LiteLLM, Ollama, vLLM) by changing only `baseUrl` and `apiKey`.

## CLI / Protocol format
- Command: `./your_program.sh -p "<prompt>"`
- Environment variables:
  - `OPENROUTER_API_KEY`: API authentication key.
  - `OPENROUTER_BASE_URL`: API gateway URL (default: `https://openrouter.ai/api/v1`).
- Output: Exact response string from model printed to `stdout`.

## Java specifics — lookup, don't memorize
- `OpenAIOkHttpClient.builder()` — Builder pattern for initializing an HTTP client configured with auth headers and base endpoint.
- `ChatCompletionCreateParams.builder()` — Fluent builder constructing request payloads with model identifier and message sequence.
- `Optional.orElse("")` — Safe unwrap preventing null pointer exceptions when message content is null.

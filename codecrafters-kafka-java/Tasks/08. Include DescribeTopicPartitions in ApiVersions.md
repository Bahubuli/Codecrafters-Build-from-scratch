# Stage 08: Include DescribeTopicPartitions in ApiVersions

## In one line
Advertising support for `DescribeTopicPartitions` (API key 75, version range 0–0) alongside `ApiVersions` (API key 18) within the compact `api_keys` array of `ApiVersions` response v4.

## Self-test (cover the answers below and answer these first)
- What is the API key assigned to `DescribeTopicPartitions` in the Kafka binary wire protocol?
- How does the compact array length prefix change when the number of elements increases from 1 to 2?
- Why do Kafka brokers advertise supported version ranges (`min_version` to `max_version`) per API key rather than a single version?
- How does a Kafka client use the `ApiVersions` response to decide which protocol format to use for topic metadata queries?

## The problem it solved
Before this stage, the broker only advertised support for the `ApiVersions` API itself. Clients attempting to query metadata about topics or partition leaders check the broker's advertised capabilities first. Without advertising `DescribeTopicPartitions` (API key 75), clients assume the broker lacks partition discovery support and refuse to initiate partition-level operations.

## Concepts (the transferable part)
- **Capability Negotiation & Protocol Discovery** — In distributed systems, protocol evolution requires discovery before invocation. Clients inspect the broker's `ApiVersions` response map:
  $$\text{negotiated\_version} = \min(\text{client\_max\_version}, \text{broker\_max\_version})$$
  If $\text{negotiated\_version} \ge \text{broker\_min\_version}$, communication proceeds; otherwise, an `UnsupportedVersionException` is raised.
- **Compact Array Scaling** — Adding elements to a compact array:
  - 1 element: encoded length = $1 + 1 = 2$ (`0x02`)
  - 2 elements: encoded length = $2 + 1 = 3$ (`0x03`)
- **API Registry Architecture** — Each entry in `api_keys` specifies:
  - `api_key` (`INT16`)
  - `min_version` (`INT16`)
  - `max_version` (`INT16`)
  - `TAG_BUFFER` (1 byte, `0x00`)

## What breaks it (failure modes)
- **Compact Array Length Mismatch** — Leaving the length prefix as `2` while writing two entries causes the client parser to read only the first entry (`ApiVersions`) and treat the bytes of the second entry (`DescribeTopicPartitions`) as `throttle_time_ms`, failing schema validation.
- **Endianness Errors on API Key (75)** — API key 75 in big-endian hex is `0x004B`. Inverting endianness produces `0x4B00` (19200), an invalid API key.
- **Omitted Tagged Buffers per Entry** — Forgetting `bodyOut.writeByte(0)` on each element shifts the stream alignment for all subsequent array entries.

## Tradeoffs
- **Static Array Serialization vs Dynamic Capability Registry** — Hardcoding capability entries in the stream writer is simple for early stages, but a decoupled registry (e.g. `Map<Short, ApiVersionRange>`) simplifies adding more APIs (`Fetch`, `Produce`, `Metadata`) in upcoming stages.

## CLI / Protocol format
- ApiVersions Response v4 with 2 APIs:
  ```
  +--------------------------------+-------------------+
  | message_size (INT32)           | dynamic (26B)     |
  | correlation_id (INT32)         | <echoed ID>       |
  | error_code (INT16)             | 0 (NO_ERROR)      |
  | api_keys length (U_VARINT)     | 3 (2 items + 1)   |
  |   [0] api_key (INT16)          | 18 (ApiVersions)  |
  |       min_version (INT16)      | 0                 |
  |       max_version (INT16)      | 4                 |
  |       TAG_BUFFER (1B)          | 0                 |
  |   [1] api_key (INT16)          | 75 (DescribeTopic)|
  |       min_version (INT16)      | 0                 |
  |       max_version (INT16)      | 0                 |
  |       TAG_BUFFER (1B)          | 0                 |
  | throttle_time_ms (INT32)       | 0                 |
  | TAG_BUFFER (1B)                | 0                 |
  +--------------------------------+-------------------+
  ```

## Java specifics — lookup, don't memorize
- `writeUnsignedVarint(bodyOut, 3)` — Serializes the compact array length for 2 elements ($2 + 1 = 3$).
- `(short) 75` / `0x004B` — Standard 16-bit integer for DescribeTopicPartitions API key.

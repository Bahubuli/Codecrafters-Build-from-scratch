# Stage 20: Respond for invalid topic or partition

## In one line
Parsing Produce Request v11 and responding with partition error code 3 (`UNKNOWN_TOPIC_OR_PARTITION`) and offset values of `-1` framed in Response Header v1.

## Self-test (cover the answers below and answer these first)
- What wire header version does Produce Request v11 use?

- What is the error code returned for non-existent topics or partitions in the Produce response?

## The problem it solved
When producer clients dispatch produce batches to unknown topics or partitions, the broker must reject them gracefully with standardized error codes rather than silently failing or crashing. This stage implements Produce v11 request parsing and structured error framing.

## Concepts (the transferable part)
- **Produce Protocol Topology (v11)**:
  - Request: Header v2 -> `transactional_id` (`COMPACT_NULLABLE_STRING`), `acks` (`INT16`), `timeout_ms` (`INT32`), `topic_data` (`COMPACT_ARRAY`), `TAG_BUFFER`.
  - Response: Header v1 (`correlation_id` + `TAG_BUFFER`) -> `responses` (`COMPACT_ARRAY`), `throttle_time_ms` (`INT32`), `TAG_BUFFER`.
- **Partition Error Protocol Conventions**:
  - `error_code`: `3` (`UNKNOWN_TOPIC_OR_PARTITION`).
  - `base_offset`: `-1L`.
  - `log_append_time_ms`: `-1L`.
  - `log_start_offset`: `-1L`.
  - `record_errors`: empty compact array (varint `1`).
  - `error_message`: null compact string (varint `0`).

## What breaks it (failure modes)
- **Header Version Mismatch** — Using Response Header v0 instead of v1 (missing the 1-byte tagged buffer following `correlation_id`).
- **Field Order Inversion** — Placing `throttle_time_ms` before `responses` array (in Fetch v16, `throttle_time_ms` comes first; in Produce v11, `responses` comes first).
- **Wrong Offset Sentinels** — Emitting `0L` instead of `-1L` for offsets on failure breaks Kafka client retry logic.

## Tradeoffs
- **Early Rejection vs Journal Allocation** — Validating topic and partition identities before writing to disk prevents corrupting active segment offsets with invalid records.

## CLI / Protocol format
- Produce Response v11:
  ```
  +---------------------------------------+--------------------+
  | correlation_id (INT32)                | <echoed>           |
  | TAG_BUFFER (1B)                       | 0x00               |
  | responses (COMPACT_ARRAY)             |                    |
  |   name (COMPACT_STRING)               | <topic name>       |
  |   partition_responses (COMPACT_ARRAY) |                    |
  |     index (INT32)                     | <partition index>  |
  |     error_code (INT16)                | 3 (UNKNOWN)        |
  |     base_offset (INT64)               | -1                 |
  |     log_append_time_ms (INT64)        | -1                 |
  |     log_start_offset (INT64)          | -1                 |
  |     record_errors (COMPACT_ARRAY)     | 1 (empty)          |
  |     error_message (C_NULL_STRING)     | 0 (null)           |
  |     TAG_BUFFER (1B)                   | 0x00               |
  |   TAG_BUFFER (1B)                     | 0x00               |
  | throttle_time_ms (INT32)              | 0                  |
  | TAG_BUFFER (1B)                       | 0x00               |
  +---------------------------------------+--------------------+
  ```

## Java specifics — lookup, don't memorize
- `bodyOut.writeLong(-1L)` — Encodes the 64-bit `-1` offset indicator.
- `writeUnsignedVarint(bodyOut, 1)` — Encodes an empty compact array ($0 + 1 = 1$).
- `writeUnsignedVarint(bodyOut, 0)` — Encodes null for `COMPACT_NULLABLE_STRING`.

## Rebuild checklist
- [ ] Parse Request Header v2 and body fields (`transactional_id`, `acks`, `timeout_ms`, `topic_data`).
- [ ] For each partition in each topic, prepare a partition response block.
- [ ] Write `error_code = 3`, offsets as `-1L`, empty `record_errors`, null `error_message`.
- [ ] Emit top-level `throttle_time_ms = 0` and appropriate `TAG_BUFFER` bytes.
- [ ] Frame with Response Header v1 and send length-prefixed packet.

# Stage 01: Bind to a port

## In one line
Initializing a TCP `ServerSocket` bound to default Kafka port 9092 with `SO_REUSEADDR` to accept incoming client connections.

## The problem it solved
Before this stage, the process exited immediately without listening for network traffic. Kafka clients and cluster brokers communicate over persistent TCP connections. This stage initializes the server entry point, binding to port 9092 and waiting for incoming client handshakes.

## Concepts (the transferable part)
- **TCP Socket Lifecycle & Server Architecture** — A server socket transitions through OS states: `socket()` $\to$ `bind(IP, port)` $\to$ `listen(backlog)` $\to$ `accept()`. `accept()` blocks until a client completes the three-way TCP handshake (SYN, SYN-ACK, ACK), yielding a dedicated client socket for data exchange.
- **TIME_WAIT and SO_REUSEADDR** — When a TCP connection is closed by the local endpoint, the socket remains in `TIME_WAIT` state for $2 \times \text{MSL}$ (Maximum Segment Lifetime, typically 30–120s) to prevent delayed duplicate packets from corrupting future connections. Enabling `SO_REUSEADDR` permits the socket to bind to a port that is still in `TIME_WAIT`.
- **Kafka Binary Wire Protocol Foundation** — Kafka operates directly on TCP streams. Unlike text-based protocols (HTTP, Redis RESP), Kafka uses length-prefixed binary frames for high-throughput serialization with zero unnecessary protocol overhead.

## What breaks it (failure modes)
- **BindException: Address already in use** — Forgetting `setReuseAddress(true)` before binding can cause crashes if previous test runs or crashed instances leave sockets in `TIME_WAIT`.
- **Port Privilege Restrictions** — Ports $< 1024$ require root/administrator privileges on POSIX systems. Port 9092 is in the unprivileged user range ($> 1024$), allowing non-root execution.
- **Premature Server Termination** — Exiting immediately without calling `accept()` causes client connections to receive `RST` (connection refused) packets.

## Tradeoffs
- **Raw TCP Sockets vs HTTP/REST / gRPC** — Raw TCP requires building protocol framing, message deserialization, and error signaling from scratch. However, it gives Kafka full control over memory layouts (e.g. zero-copy OS `sendfile`), batching efficiency, and compact binary representations.

## CLI / Protocol format
- Default Port: `9092`
- Transport: TCP / IPv4 & IPv6

## Java specifics — lookup, don't memorize
- `ServerSocket(int port)` — Creates and binds a TCP server socket.
- `serverSocket.setReuseAddress(true)` — Enables `SO_REUSEADDR` socket option.
- `serverSocket.accept()` — Blocks until a connection arrives, returning a connected `Socket`.
- `try-with-resources` (`try (ServerSocket s = ...)`) — Automatically calls `.close()` when exiting block.

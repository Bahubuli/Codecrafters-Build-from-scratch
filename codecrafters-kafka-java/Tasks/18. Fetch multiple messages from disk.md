# Stage 18: Fetch multiple messages from disk

## In one line
Streaming all contiguous RecordBatch records from partition segment log files into the Fetch v16 `records` compact byte sequence without needing individual record re-encoding.

## The problem it solved
Real-world partitions store streams of multiple consecutive RecordBatches produced over time. When consumers request data, the broker should transmit all available batches in the requested partition. Because segment files on disk are binary concatenations of RecordBatch payloads, the broker can satisfy multi-batch reads by copying the full segment slice into the response `records` field.

## Concepts (the transferable part)
- **Log Segment File Format** — An active segment file (`00000000000000000000.log`) is an unpadded sequence of consecutive RecordBatches:
  $$\text{Segment File} = \text{RecordBatch}_0 \parallel \text{RecordBatch}_1 \parallel \dots \parallel \text{RecordBatch}_n$$
- **COMPACT_RECORDS for Multi-Batch** — The wire encoding treats multiple batches identically to a single batch:
  $$\text{Varint}(\text{totalBytes} + 1) \parallel \text{all\_batch\_bytes}$$
- **Request Partition Index Matching** — The response partition block must match `partitionIndex` sent in the request.

## What breaks it (failure modes)
- **Attempting to Frame Each Batch Separately** — Adding separate varint lengths before each batch corrupts the Kafka protocol. Only one outer length prefix frames the entire `records` field per partition.
- **Assuming Fixed Partition 0** — Client requests can query any valid partition (e.g. partition 1 or partition 2). Always pass `ftr.partitions` index into `readPartitionLog(ti.name, partitionIndex)`.

## Tradeoffs
- **Full File Ingestion vs Range Slurping** — Reading the entire segment file is optimal when consumer fetch offsets start at 0. As offsets advance, seeking and bounding by `partition_max_bytes` would be required in full-featured implementations.

## CLI / Protocol format
- Request: Fetch v16 for topic ID with multiple messages in partition 0.
- Response partition block:
  ```
  +---------------------------------------+--------------------+
  | partition_index (INT32)               | <request index>    |
  | error_code (INT16)                    | 0 (NO_ERROR)       |
  | high_watermark (INT64)                | 0                  |
  | last_stable_offset (INT64)            | 0                  |
  | log_start_offset (INT64)              | 0                  |
  | aborted_transactions (C_ARRAY)        | 1 (empty)          |
  | preferred_read_replica (INT32)        | 0                  |
  | records (COMPACT_RECORDS)             |                    |
  |   length (U_VARINT)                   | all_bytes.len + 1  |
  |   payload                             | <all batches raw>  |
  | TAG_BUFFER (1B)                       | 0x00               |
  +---------------------------------------+--------------------+
  ```

## Java specifics — lookup, don't memorize
- `Files.readAllBytes(logFile.toPath())` — Reads all concatenated batches into a single contiguous byte array.

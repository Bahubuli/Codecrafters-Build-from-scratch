# Stage 22: Produce a single record

## In one line
Extracting raw RecordBatch bytes from Produce Request v11 and appending them directly to the partition's active log segment on disk.

## The problem it solved
Previous stages verified topic/partition routing and framed protocol responses in memory. This stage bridges network serialization to disk persistence: deserializing incoming `COMPACT_RECORDS` payload and appending the raw Kafka `RecordBatch` bytes into the partition log file (`00000000000000000000.log`).

## Concepts (the transferable part)
- **Zero-Copy Disk Spooling** — In Kafka, record batches received over the wire are already formatted as valid on-disk RecordBatches (magic byte 2, CRC32C, timestamps, attributes). Brokers can write the batch payload directly to the active segment log file with minimal CPU overhead.
- **Log File Directory Structure**:
  - Base log directory: resolved from `server.properties` (`log.dirs` or `log.dir`, defaulting to `/tmp/kraft-combined-logs`).
  - Partition folder: `<topic_name>-<partition_index>`.
  - Segment file: `00000000000000000000.log` (representing base offset 0).

## What breaks it (failure modes)
- **Varint Length Stripping Error** — `COMPACT_RECORDS` specifies length as $L + 1$. Reading $L$ or failing to subtract 1 shifts buffer alignment or introduces corrupted trailer bytes.
- **Directory Creation Failure** — Attempting to open `FileOutputStream` without ensuring parent directories exist (`partitionDir.mkdirs()`).
- **Overwriting Instead of Appending** — Opening `FileOutputStream` with `append = false` overwrites previously persisted records or metadata.

## Tradeoffs
- **Append-Only Write Semantics vs In-Memory Staging** — Writing directly with `FileOutputStream(file, true)` provides atomic durability for the segment file matching Kafka's write path.

## CLI / Protocol format
- Produce Request Partition Layout:
  ```
  partition_index: INT32
  records: COMPACT_RECORDS (varint length + 1, followed by raw RecordBatch bytes)
  TAG_BUFFER: 0x00
  ```
- File written to:
  `<log.dirs>/<topic_name>-<partition_index>/00000000000000000000.log`

## Java specifics — lookup, don't memorize
- `new FileOutputStream(logFile, true)` — Appends bytes to an existing file or creates a new file.
- `in.readFully(records)` — Guarantees all record batch bytes are read before subsequent tagged fields.

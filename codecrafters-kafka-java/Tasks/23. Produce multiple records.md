# Stage 23: Produce multiple records

## In one line
Persisting multi-record RecordBatches directly to partition log files and returning base offset 0 with `NO_ERROR`.

## The problem it solved
Kafka producers batch multiple individual records into a single `RecordBatch` to maximize network throughput and compression efficiency. Brokers receive this multi-record batch over the Produce API and must persist the entire batch intact to disk under the corresponding topic-partition segment log.

## Concepts (the transferable part)
- **Batch-Level Persistence** — Rather than processing and storing each record individually, Kafka stores the entire `RecordBatch` as the fundamental unit of disk I/O.
- **Batch Offset Semantics**:
  - `base_offset`: The logical offset of the first record in the batch (0 for the initial batch).
  - Subsequent records within the batch are addressed via `offsetDelta` relative to `base_offset`.
  - The broker returns `base_offset = 0` in the Produce response for the entire batch.
- **Atomic Log Writes** — Writing the entire multi-record batch buffer in one continuous write ensures atomicity; consumers reading the log will either observe the entire valid batch (passing CRC32C verification) or none of it.

## What breaks it (failure modes)
- **Splitting Batch Buffers** — Trying to parse and re-serialize records individually risking CRC calculation mismatches or field corruptions.
- **Wrong Base Offset** — Emitting the last offset or total record count instead of `base_offset = 0`.
- **Truncated Disk Writes** — Failing to flush the `FileOutputStream` before returning the response packet.

## Tradeoffs
- **Pass-Through Batch Storage vs Deep Record Inspection** — Passing through the client's pre-computed RecordBatch avoids expensive CPU cycles for decoding, re-encoding, and recalculating CRC checksums.

## CLI / Protocol format
- Produce Request Partition Field:
  ```
  partition_index: INT32
  records: COMPACT_RECORDS (varint length + 1, followed by RecordBatch containing N records)
  TAG_BUFFER: 0x00
  ```
- Stored on Disk:
  `<log.dirs>/<topic_name>-<partition_index>/00000000000000000000.log` (exact RecordBatch bytes).

## Java specifics — lookup, don't memorize
- `FileOutputStream.write(records)` — Appends the entire batch atomically to the file descriptor.
- `FileOutputStream.flush()` — Ensures bytes are flushed from user-space buffers to the operating system before responding to the client.
